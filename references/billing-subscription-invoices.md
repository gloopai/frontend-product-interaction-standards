# 计费、套餐、订阅与发票交互规范

适用于管理台中的计费、账单、套餐、订阅、试用、续费、取消订阅、升级/降级套餐、付款方式、支付状态、发票、收据、账单明细、用量、额度、余额、抵扣、优惠券、折扣、税费、退款、开票、重新开票、账单周期、自动续费、账单历史和消费记录。本文件是商业状态、金额快照、订阅生效、权益生效、用量口径、发票产物、支付恢复和移动端恢复路径的唯一事实来源。

普通配置草稿、保存和生效值继续执行 [设置、偏好与配置页交互规范](settings-preferences-configuration.md)。取消、降级、退款、删除付款方式、购买大额额度和高影响账期切换继续执行 [危险操作与恢复交互规范](risk-actions.md)。发票、收据、账单明细、对账单和消费记录下载继续执行 [导出、下载与结果产物交付交互规范](exports-downloads-artifacts.md)。支付、开票、退款、账单同步和用量同步等后台任务继续执行 [异步任务与任务中心交互规范](async-jobs-task-center.md)。账单权限和无泄露继续执行 [权限、租户与可见性交互规范](permissions-tenancy-visibility.md)。金额、价格、税费、折扣、汇率、用量、额度、余额、抵扣、超额费用、席位数、数量、预算和计量周期输入必须同时执行 `references/numeric-amount-inputs.md`；Billing owner 负责商业承诺、价格快照、支付/订阅/发票结果和审计，数字 owner 负责 `numericInputState`、币种/倍率/精度/舍入/边界、草稿解析、粘贴、IME、提交快照和移动端键盘。兼容规则全部执行。

## 范围

本 owner 负责前端如何表达账单主体、套餐、订阅、价格、税费、优惠、试用、付款方式、支付状态、用量、额度、发票、退款和审计之间的状态链。它不定义支付网关、银行卡校验、税务计算、定价策略、货币换算、会计规则、发票法规、退款政策、订阅引擎、计量后端、账单同步任务、风控规则、税号验证、收单通道或第三方 provider API。

本 owner 不定义具体套餐名、价格、优惠券规则、额度模型、发票模板、税率、币种支持、国家/地区合规文案或品牌视觉，也不提供财务、税务或法律建议。

## Owner State

每个计费、订阅、支付、发票或用量页面必须维护 `billingSubscriptionState`。状态至少包含：

| 字段 | 说明 |
| --- | --- |
| `billingOwnerId` | 当前计费 owner 稳定身份，绑定页面、套餐卡、确认面板、支付、发票、用量、请求和审计。 |
| `billingAccountIdentity` | 账单主体、租户/工作区、订阅对象、环境、计费账号、账单权限和展示边界。 |
| `subscriptionVersion` | 当前订阅版本、目标订阅版本、账期、续费时间、取消/降级生效时间和权益版本。 |
| `pricingSnapshot` | 用户确认时看到的套餐、价格、币种、周期、税费、折扣、抵扣、试用、按量计费、预估总额和价格版本。 |
| `entitlementState` | 当前权益、目标权益、试用权益、降级后失去的能力、数据保留、额度和生效状态。 |
| `usageQuotaState` | 用量口径、额度、余额、超额状态、数据延迟、刷新时间、计量周期和估算/最终状态。 |
| `paymentState` | `not-started`、`payment-method-draft`、`payment-method-saved`、`payment-pending`、`payment-succeeded`、`payment-failed`、`requires-action`、`unknown`。 |
| `invoiceState` | `not-generated`、`generating`、`ready`、`downloaded`、`voided`、`refunded`、`expired`、`unavailable`、`unknown`。 |
| `billingChangeIntent` | 升级、降级、取消、续费、切换账期、添加付款方式、删除付款方式、购买额度、应用优惠、退款或重新开票的用户意图。 |
| `riskBinding` | 是否进入 `risk-actions.md`、风险等级、影响范围、确认策略和确认前请求数。 |
| `permissionBoundary` | 查看账单、管理订阅、支付、下载发票、退款、查看用量和审计所需的权限版本与范围。 |
| `auditBinding` | 套餐变更、支付、取消、降级、退款、开票、下载、失败和未知结果的审计身份。 |
| `resultReceipt` | 成功、失败、部分成功、未知、权限拒绝、支付待处理、开票中、退款中和审计回执。 |

## Billing 不是普通设置项

计费、套餐、订阅、付款方式、用量额度和发票不能只按普通设置项展示。套餐展示状态、确认状态、支付状态、订阅生效状态、权益生效状态、用量状态、发票产物状态和审计状态必须分开表达。

付款方式保存成功不等于支付成功。支付成功不等于订阅已生效。订阅已生效不等于所有权益、用量额度、发票和审计都已更新。界面必须说明每一步当前状态和下一步恢复路径，不能把不同业务终态合并成一个成功 Toast、一个 loading 或一个“已保存”状态。

## 价格、账期和权益快照

套餐卡、确认页、支付请求、审计记录和结果回执必须绑定同一个 `pricingSnapshot`。该快照至少包含套餐、价格、币种、周期、税费、折扣、抵扣、试用、按量计费、预估总额、价格版本、租户/工作区和确认时间。

切换套餐、升级、降级、切换月付/年付、应用优惠、购买额度、取消续费或恢复订阅前，必须展示当前套餐、目标套餐、账期、生效时间、权益变化、数据保留、额度变化、费用变化和未知结果处理。展示价、确认价、支付请求价、账单记录和审计价必须能通过 `pricingSnapshot` 对齐。

旧价格、旧优惠、旧估算、旧套餐卡片和旧确认面板在价格版本、权限、租户/工作区、订阅版本、优惠状态或会话变化后必须失效或重算。迟到价格计算、优惠校验、账期切换、浏览器 Back 或 Notification 返回只有在 `billingOwnerId`、`billingAccountIdentity`、`subscriptionVersion`、`pricingSnapshot` 和权限版本仍匹配时才能写回。

## 支付、订阅和权益状态

`paymentState`、订阅状态、`entitlementState`、`usageQuotaState` 和 `invoiceState` 必须分开。支付失败、需要额外动作、支付处理中、支付未知、订阅待生效、权益同步中、发票生成中和用量延迟不能合并成一个 loading、一个成功 Toast 或一个已保存状态。

未知结果不能伪装成支付成功、订阅成功、取消成功、降级成功、退款成功、发票已生成或额度已到账。未知结果必须提供检查最新状态、查看账单历史、进入任务中心、重试支付、更新付款方式、联系支持或查看审计路径，并说明可能的扣费、重复请求和权益影响。

付款方式表单只负责付款方式草稿、保存和校验状态；保存付款方式不代表已经扣费，也不代表订阅已更新。需要额外认证、跳转支付、3DS 或 provider callback 时，必须绑定当前请求身份、账单主体、订阅版本、金额快照和恢复路径。

## 取消、降级、退款和付款方式

取消订阅、取消自动续费、降级套餐、删除付款方式、申请退款、撤销退款、清空余额、购买大额额度、切换账期产生即时收费或失去权益的操作必须进入 `risk-actions.md`。确认前请求数为 0；确认必须说明影响范围、金额、账期、失效时间、权益变化、数据保留、可恢复性、审计回执和未知结果处理。

不得用 Switch/Toggle 直接取消订阅、开启/关闭自动续费、删除付款方式或切换高影响账期。若保留开关视觉，它只能作为打开风险确认承载面的入口；确认通过前不得发送请求，也不得把视觉开关位置当成订阅已生效状态。

退款、撤销退款、购买额度、余额抵扣和追加 seats 必须说明是否会立即收费、是否可退款、何时生效、是否影响当前账期、是否可能重复扣费、是否进入任务中心以及如何查看审计。

## 发票、收据和账单下载

发票、收据、账单明细、对账单、消费记录和税务资料下载必须执行 `exports-downloads-artifacts.md`。下载链接不是权限证明；每次下载必须复核账单权限、租户/工作区、发票身份、订阅版本、文件有效期、请求身份和审计。

旧发票链接、旧收据链接、旧账单导出任务、旧浏览器历史、旧 Notification、旧复制链接和旧 Toast/Notification 必须在权限变化、会话过期、租户/工作区切换、发票状态变化、退款、作废、重新开票或对象删除后失效或重新证明安全。

发票、收据和账单明细列表必须区分 `invoiceState`：`not-generated`、`generating`、`ready`、`downloaded`、`voided`、`refunded`、`expired`、`unavailable` 和 `unknown`。发票生成中、重新开票、退款后作废、过期不可下载和未知结果都不能显示成同一个“可下载”入口。

## 用量、额度和余额

用量、额度、余额、抵扣、试用剩余额度、超额状态和消费记录必须声明计量周期、刷新时间、数据延迟、估算/最终状态、单位、权限范围和适用套餐。用量条不能作为实时额度证明；延迟、估算、部分同步失败或未知结果必须可见。

购买额度、追加 seats、超额付费、恢复额度和余额抵扣必须说明何时生效、是否可退款、是否影响当前账期、是否可能重复扣费以及如何查看审计。额度到账、余额抵扣和用量刷新必须分开表达，不能把支付成功写成额度已经可用。

## 权限、审计与反馈不泄露

无权限用户不得通过套餐卡、价格、折扣、税费、发票列表、支付错误、用量条、账单历史、DOM/ARIA、Toast、Notification、下载链接或审计摘要推断账单主体、付款方式、金额、税号、地址、邮箱、发票编号、内部 ID、支付 provider 对象或旧缓存。

权限、租户/工作区、会话、订阅版本、价格版本、付款方式版本、发票状态、退款状态或账单账户变化后，旧套餐卡、旧确认面板、旧支付按钮、旧付款方式、旧发票链接、旧用量摘要、旧 Toast/Notification、旧审计跳转、旧焦点目标和旧 ARIA 引用必须失效或重算。

套餐变更、支付、取消、降级、退款、开票、下载、失败和未知结果必须绑定 `auditBinding`。审计摘要可以记录动作、主体、目标、订阅版本、价格快照、权限版本、请求身份和结果状态，但不得泄露无权限付款方式、税号、地址、邮箱、发票编号、provider 对象或内部 ID。

Toast、Notification、Snackbar 或浏览器提示不能作为唯一支付失败、支付未知、取消订阅、降级、退款、发票生成失败、发票下载失败、用量同步失败、权限拒绝或部分成功恢复路径。页面内必须有账单状态、订阅状态、付款恢复、任务入口、发票入口、审计入口或支持路径。

## 移动端与可访问性

移动端不得删除当前套餐、目标套餐、金额、币种、账期、税费/折扣摘要、权益变化、用量口径、额度状态、付款方式状态、支付失败恢复、取消/降级影响范围、发票下载、账单历史、审计入口、权限说明和恢复路径。

低高度、虚拟键盘、安全区域、系统字体放大、浏览器 Back、WebView 返回、支付额外认证跳转和触摸长按后，金额、确认按钮、取消路径、错误摘要、账期说明、支付恢复和审计入口仍必须可达。复杂计费流程可以进入 Drawer、Bottom Sheet、分步确认或独立页，但不能删除核心商业承诺和恢复路径。

金额、账期、权益变化、用量延迟、支付结果、发票状态和未知结果必须可读，不能只靠颜色、图标、Tooltip、Toast 或位置表达。屏幕阅读器应能区分支付状态、订阅状态、权益状态、用量状态和发票状态。

## 完成前检查

- 检查计费、套餐、订阅、付款方式、用量额度和发票是否没有被当成普通设置项。
- 检查套餐展示状态、确认状态、支付状态、订阅生效状态、权益生效状态、用量状态、发票产物状态和审计状态是否分开表达。
- 检查付款方式保存成功、支付成功、订阅生效、权益/用量/发票更新是否没有互相替代。
- 检查套餐卡、确认页、支付请求、审计记录和结果回执是否绑定同一个 `pricingSnapshot`。
- 检查升级、降级、切换账期、应用优惠、购买额度、取消续费和恢复订阅前是否展示当前套餐、目标套餐、账期、生效时间、权益变化、数据保留、额度变化、费用变化和未知结果处理。
- 检查旧价格、旧优惠、旧估算、旧套餐卡片、旧确认面板、旧支付按钮、旧付款方式、旧发票链接、旧用量摘要、旧 Toast/Notification、旧审计跳转、旧焦点目标和旧 ARIA 引用是否在权限、租户/工作区、会话、订阅版本、价格版本、付款方式版本、发票状态、退款状态或账单账户变化后失效或重算。
- 检查取消订阅、取消自动续费、降级套餐、删除付款方式、申请退款、撤销退款、清空余额、购买大额额度和高影响账期切换是否进入 `risk-actions.md`，且确认前请求数为 0。
- 检查 Switch/Toggle 是否没有直接取消订阅、开启/关闭自动续费、删除付款方式或切换高影响账期。
- 检查发票、收据、账单明细、对账单、消费记录和税务资料下载是否执行 `exports-downloads-artifacts.md`，且旧链接失效或重新证明安全。
- 检查用量、额度、余额、抵扣、试用剩余额度、超额状态和消费记录是否声明计量周期、刷新时间、数据延迟、估算/最终状态、单位、权限范围和适用套餐。
- 检查无权限界面、Toast、Notification、下载链接和审计摘要是否不泄露账单主体、付款方式、金额、税号、地址、邮箱、发票编号、内部 ID、支付 provider 对象或旧缓存。
- 检查移动端、低高度、虚拟键盘、安全区域、系统字体放大、浏览器 Back、WebView 返回、支付额外认证跳转和触摸长按后，金额、账期、权益、用量、支付恢复、发票下载、审计入口、权限说明和恢复路径仍可达。
- 真实浏览器、移动端设备、屏幕阅读器、真实支付 provider、真实支付额外认证、真实发票下载、真实退款/取消/降级任务、真实权限切换、真实会话过期、真实账单同步和真实审计写入未实际执行时，必须明确标为**未验证**，并列出所需验证。
