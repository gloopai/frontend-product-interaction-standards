# 响应式与自适应交互规范

适用于需要在 PC、平板、移动端、横竖屏、不同断点或输入方式之间适配的全部前端界面。本文件是跨端产品交互与验收规则的唯一事实来源；它与组件专项规范同时适用。

## 核心原则

1. PC 与移动端必须提供一致的核心业务能力、数据结果、权限判断、校验、错误处理、安全确认和状态反馈；不要求像素级一致。
2. 不得以空间不足或“移动端精简”为由删除关键内容或操作。低频、次要能力可以折叠、收纳或转换形态，但不得彻底删除，并必须保持可发现、可访问且能在合理步骤内找到。
3. 组件可以跨端改变布局和交互形态，但不得改变业务语义、提交结果、默认值或风险等级；不得仅用 `display: none` 隐藏仍需用户访问的能力。
4. 适配基于可用空间、内容需求、输入能力和用户偏好，而不只依赖设备名称或 User-Agent。断点应由内容无法保持可用的时刻决定，不能机械绑定设备型号。

移动端 App Shell、应用外框、管理台外框、全局导航、侧边导航、顶部导航、用户菜单、工作区/租户切换、全局搜索入口、通知入口和移动端导航 Drawer 必须同时执行 `references/app-shell-navigation.md`；本文件负责断点、触控、安全区域和形态转换，`app-shell-navigation.md` 负责外框级 owner、当前位置、全局入口和上下文切换不丢失。

移动端字段说明、帮助文本、placeholder、字段 label、必填/选填、单位、格式示例、空值说明、权限原因、只读原因和禁用原因必须同时执行 `references/field-guidance-help-text.md`；本文件负责断点、触摸、虚拟键盘、安全区域和布局可达性，`field-guidance-help-text.md` 负责说明语义、hover-only 替代路径和旧描述引用清理。

移动端关键词搜索输入、搜索框、筛选搜索、防抖搜索和 IME 搜索必须同时执行 `references/keyword-search-inputs.md`；虚拟键盘、safe-area、动态 viewport、缩放和断点转换不得删除或遮挡输入、清空、提交、取消/返回、错误说明、权限原因、loading、结果摘要和恢复路径。

移动端列表结果、分页、页大小、排序、刷新、自动刷新、结果摘要、过期数据和错误恢复必须同时执行 `references/list-result-controls.md`；断点、底部分页、固定工具栏、虚拟键盘和 safe-area 不得删除或完全遮挡排序、分页、刷新、结果摘要、错误说明、权限原因、过期说明和恢复路径。

移动端 Tabs、标签页、页面内视图切换、横向滚动标签、Segmented Control 承载、Select 承载、Action Sheet 承载或 Drawer 承载必须同时执行 `references/tab-view-navigation.md`；断点转换不得改变 `activeTabId`、URL、权限、dirty 语义、panelState、未保存保护或焦点返回。

移动端 Accordion、Collapse、Disclosure、折叠面板、展开收起和嵌套折叠必须同时执行 `references/disclosure-accordions.md`；断点转换不得删除标题、当前展开状态、错误摘要、权限原因、恢复入口、核心操作、未保存保护或焦点返回。

移动端详情预览、侧边预览、行预览、记录预览、快速查看、只读预览和 Master-Detail 必须同时执行 `references/preview-pane.md`；桌面侧边预览或分栏预览可转换为底部 Drawer、全屏 Drawer 或独立详情页，但不得删除返回列表、当前预览目标、安全标题、权限原因、错误状态、主要只读信息和恢复入口，也不得把预览转换成编辑表单。

移动端卡片列表、卡片式结果、资源卡片、模板卡片、应用卡片、项目卡片、卡片网格、移动端结果卡片和 Kanban-lite 必须同时执行 `references/card-list-results.md`；列数、最小宽度、长标题、翻译扩展、200% 缩放、低高度、虚拟键盘、安全区域、选择摘要、主要操作、分页/刷新和恢复入口不得因卡片化而丢失。

移动端概览页、仪表盘首页、管理台首页、运营看板、业务看板、指标总览、报表总览和 dashboard landing 必须同时执行 `references/overview-dashboard-pages.md`；模块可重排、折叠或分组，但不得删除页面标题、全局筛选摘要、时间范围、KPI 口径、告警、权限原因、数据延迟、刷新状态、主要图表摘要、明细/导出入口和恢复路径。

移动端审批、待办审批、批量审批、审批意见、审批附件、审批历史、转交、加签、委托和催办必须同时执行 `references/approval-workflows.md`；响应式 owner 负责形态转换和可达性，`approval-workflows.md` 负责当前节点、意见要求、附件状态、结果、通知、审计和恢复路径保留。

## 跨端形态与状态延续

0. 承载面决策必须输出最终形态、触发条件、状态延续策略、关闭路径和验证边界。不得把所有移动端 Dialog 一刀切改成 Bottom Sheet，不得把所有 Select 一刀切改成 Drawer，也不得把需要稳定路由、刷新恢复、深链、多人协作或长时间编辑的任务塞进 Dialog 或 Bottom Sheet。合理形态应随任务复杂度、风险、内容长度、输入方式、视口高度、虚拟键盘、安全区域、底部操作、权限/审计回执和恢复路径共同决定。
1. 内容较多的桌面 Dialog 可在窄屏转换为底部或全屏 Drawer；桌面侧边 Drawer 可转换为全宽侧边或底部 Drawer。转换后仍必须保留标题、关闭路径、焦点、遮罩、滚动、提交和错误语义，并同时执行两类专项规则中兼容的不变量。
   底部 Drawer / Bottom Sheet 可以保留左右边距、顶部圆角和底部安全区域适配；这些视觉差异不改变它的模态 Drawer 语义。只要它从底部进入并覆盖当前任务，就必须执行 Drawer 的完整遮罩、背景隔离、页面滚动锁、焦点陷阱、固定标题/关闭、固定底部操作、内容区滚动、遮罩点击不关闭、拖拽不关闭和 disposal 规则。
2. 初次打开时，以当前视口下最终渲染形态的专项入场动画为准：最终为 Dialog 时仅使用 Dialog 的淡入与缩放动画；最终为 Drawer 时仅使用对应边缘的 Drawer 平移动画。不得把两套进入或退出动画叠加为同一次打开或关闭。
3. 已打开实例因实时断点变化而转换形态时，必须保持同一实例、状态与焦点，不得卸载或重建；不得同时播放 Dialog 和 Drawer 的进入/退出动画。此时使用无入场/退场动画的布局转换，继续保留遮罩、背景隔离、滚动锁和异步状态；`prefers-reduced-motion: reduce` 仍然适用。随后关闭时，只能使用关闭开始时当前渲染形态的专项退出动画。
4. Hover Tooltip、Popover 和菜单必须有点击与键盘访问路径；重要信息不得仅依赖 Hover。自绘单选 Select、Combobox 或选项列表发生跨端转换时，必须同时执行 [可搜索单选 Select / Combobox 交互规范](selects-comboboxes.md)：PC 初次打开采用该规范的 Select 浮层动画，移动端最终形态为 Drawer 时采用 Drawer 动画。已打开实例实时断点转换时保持单实例，保留选择值、草稿、搜索、错误和焦点返回，且不得叠加两套动画。
   Dialog 内 Select / Combobox / Dropdown popup 在移动端、窄屏、低高度或虚拟键盘下若会被裁切、遮挡底部操作或需要更大触控目标，应转换为 Select Drawer；转换不得改变已提交值、提交草稿、重置搜索、重复请求、重复遮罩、重复焦点陷阱、重复滚动锁或重复动画。
   移动端 Dialog 与其内部 Select 可以分别转换：任务承载层可从 Dialog 转为 Bottom Sheet，字段选项层可从 popup 转为 Select Drawer。两者不得各自创建互相竞争的遮罩、滚动锁或焦点陷阱；当前最上层层级负责交互，关闭后焦点按触发链逐层返回。若 Bottom Sheet 内继续使用非模态 Select popup 会遮挡确认按钮或被虚拟键盘挤压，必须优先转 Select Drawer；若任务本身也无法在 Bottom Sheet 内保持标题、正文、错误和操作可达，则升级为全屏 Drawer 或独立页。
   Bottom Sheet 保留右边距、左右边距、顶部圆角或底部安全区域时，外观仍只是任务承载层的视觉外框；遮罩覆盖、背景隔离、页面滚动锁、焦点陷阱、固定标题/关闭、固定底部操作和 disposal 不能因为“看起来不像全宽抽屉”而降级。字段选项层的 Select Drawer 不能复用外层底部确认按钮作为选择提交，也不能把 options 直接铺在外层 Dialog 内容滚动区中；字段选项层必须拥有独立滚动边界，不能与外层 Bottom Sheet 正文共用滚动容器、滚动位置、滚动阴影或滚动清理。
   Bottom Sheet 的最大高度、底部偏移、左右边距和右边距必须基于动态视口与 safe-area 计算，不能写成只适合某个机型的固定像素。底部操作区必须始终高于正文滚动区和字段选项层的视觉边界；虚拟键盘、横屏低高度、系统字体放大或浏览器工具栏变化后，确认、取消、关闭、错误摘要和当前焦点项仍必须可见且可达。
5. 宽表格可转换为卡片、优先级列、详情展开或受控横向滚动；字段和操作不得无入口地消失。桌面导航可转换为导航 Drawer；并排表单可变为单列，但当前页面、字段顺序、关联关系、帮助文本和错误归属必须清楚且一致。
6. 拖拽、滑动、长按或精确指针操作必须提供简单点击或键盘替代方式，复杂手势不得成为关键任务的唯一完成路径。
7. 调整窗口、旋转设备或断点切换时，不得丢失未提交表单、筛选、搜索词、分页、选中项、展开项、上传进度或业务上下文。路由、查询参数、浏览器前进后退和返回列表的状态恢复必须在两端一致。
8. 已打开浮层发生形态转换时，只保留一个活动实例；不得产生重复遮罩、请求、回调、焦点陷阱或滚动锁。若精确焦点节点仍存活则保留焦点；否则只移动一次到组件专项规范定义的目标形态等价控制器（Select 见 [可搜索单选 Select / Combobox 交互规范](selects-comboboxes.md)）。提交、上传或不可中断工作不得被形态切换中断或错误恢复为可操作状态。关闭开始后必须冻结该 closing 实例的渲染形态，后续断点变化不得启动形态转换、第二个退出动画、重建实例或额外清理；在同一个关闭动画完成、DOM 卸载和仅一次幂等清理前，持续保留遮罩、背景隔离、滚动锁、焦点约束和异步状态。
9. 路由变化或拥有浮层的组件卸载时，该实例必须立即进入 disposal（处置态），不等待退出动画，不再接受关闭、形态转换或新异步工作。处置必须取消或失效该实例的旧请求、待执行重试与防抖工作、动画完成处理器、监听器和所有过期回调；随后移除该实例 DOM，并且每个实例只释放自己持有的遮罩、背景隔离、页面滚动锁、焦点约束及其他资源，均不得影响仍存活或随后激活的实例。若旧触发元素正随路由或拥有组件移除，不得把焦点返回该元素；新路由提交后，由新路由自身的焦点策略把焦点移动一次到合理目标，例如页面主标题、主内容容器或首个主要操作。

## 布局、视口与输入

1. 支持常见桌面、笔记本、平板、窄屏手机、横屏手机和低高度视口。除宽度外，必须考虑视口高度、浏览器缩放、系统字体放大、横竖屏、动态浏览器工具栏、虚拟键盘与安全区域。
2. 浏览器缩放到 200% 时，核心内容和操作仍须可访问；关键流程不得要求双向滚动。固定顶部栏、底栏和浮动操作不得完全遮挡聚焦元素、错误信息或主操作。
3. 使用动态视口单位时提供合理回退，并处理 `safe-area-inset-top`、`safe-area-inset-right`、`safe-area-inset-bottom` 与 `safe-area-inset-left`。页面应有清晰可预期的主滚动关系；嵌套滚动不得使内容或操作不可达。横向滚动仅用于确有必要的数据结构，且关键身份信息与操作仍须可定位。
4. 不假设桌面设备只有鼠标，也不假设移动设备只有触摸。同一界面必须支持键盘、鼠标、触摸和辅助技术的合理组合；核心操作可由键盘完成且焦点清晰，触摸目标和间距不依赖精确点击。
5. Hover 补充内容必须支持键盘 Focus；可交互浮层还须允许指针移入且不会意外消失。设备切换输入方式时，界面不得锁定为仅触摸或仅鼠标状态。

## 内容与国际化

1. 标题、金额、状态、错误和主要操作优先展示；次要信息即使折叠也必须可发现。折叠入口使用描述性名称，不能只用缺少可访问名称的省略号图标。
2. 支持长标题、长单词、系统字体放大和翻译文本扩展；不得因截断而丢失关键含义或操作。重要信息不得只由图标、位置、颜色或 Hover 表达。

## 验收与报告

每次改动执行与其相关的检查，并至少覆盖适用的桌面 `1440×900`、`1280×720`，平板横竖屏，常见窄屏、低高度和横屏手机，200% 缩放，键盘、鼠标、触摸，虚拟键盘开关，动态视口和四向安全区域，Reduced Motion、高对比度或等价可视性，长文本/字体放大/国际化文本，以及断点切换期间的未保存表单、活动筛选、打开浮层、上传或加载请求。对于可转换的 Dialog 或 Drawer，初次打开时必须确认最终渲染形态只播放其专项入场动画，且没有叠加另一形态动画；还必须分别在关闭前改变断点、关闭开始后改变断点，验证只发生一个与关闭开始时渲染形态对应的退出动画、一次 DOM 卸载和一次清理序列。关闭开始后改变断点时，必须观察 Dialog 与 Drawer 的遮罩、背景隔离、滚动锁、焦点约束和异步状态仍持续到该唯一关闭动画完成、DOM 卸载和清理为止。对于移动端 Bottom Sheet 内 Select，必须打开 options 并验证字段选项层转 Select Drawer 后，外层任务承载层的确认、取消、关闭、错误、脏状态和底部操作不被覆盖、不被复用、不被重置。

对 route/unmount disposal 进行可执行检查：在旧请求、重试、防抖、动画完成处理器和监听器均待处理时触发路由变化及拥有组件卸载，记录 disposal 进入时点、取消/失效结果、DOM 移除、每类资源的实例 ID 与释放计数以及全部 `focus` 事件。确认旧回调之后到达也不能改变新实例或新路由；旧实例只释放自己的每项资源一次；焦点不返回将移除的旧 trigger；新路由提交后仅由其焦点策略移动一次到已记录的合理新路由目标。

未实际执行的交互、输入方式或视口检查必须明确报告为未验证，并说明所需验证；不得将未执行的检查写成已通过。

## 范围与参考

本规范定义产品交互和验收，不规定 CSS 框架、组件库或目录结构；不禁止合理的跨端形态转换，但禁止以移动端精简为由彻底删除仍有业务价值的能力。

- [W3C WCAG 2.2](https://www.w3.org/TR/WCAG22/)：Reflow、Resize Text、Focus Not Obscured、Keyboard、Dragging Movements、Target Size 与 Status Messages。
- [WAI-ARIA Authoring Practices Guide](https://www.w3.org/WAI/ARIA/apg/)：Dialog、Combobox、Menu、Tabs、Grid 与 Tooltip 等组件模式。
