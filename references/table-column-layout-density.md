# 表格列设置、列布局与密度交互规范

适用于管理台中的列设置、列显示、列隐藏、列顺序、列宽调整、固定列、冻结列、列分组、列密度、紧凑模式、舒适模式、重置列、恢复默认列、保存列布局、列配置抽屉、表格密度切换，以及 column settings、column visibility、column order、column resize、column width、pinned column、fixed column、frozen column、column density、table density、compact table、comfortable table 和 reset columns。

本文件是表格列布局与密度 owner。表格列配置不是“把列数组存到 localStorage”，也不是“工具栏里一个列设置按钮”。表格展示、行选择、分页、排序、批量和结果状态继续执行 `references/data-tables.md`；保存视图、共享视图和布局预设继续执行 `references/saved-views-layout-presets.md`；列设置入口、密度入口和工具栏收纳继续执行 `references/page-toolbars-actions.md`；列标题长文本、单元格截断和固定列阴影继续执行 `references/text-overflow-truncation.md` 与表格 owner；权限、移动端和反馈继续执行对应 owner。本文件负责列配置草稿、应用快照、可见性、顺序、宽度、固定、密度、持久化、权限收敛和跨端布局转换。

## 范围与边界

本 owner 覆盖：

- 列显示/隐藏、列顺序、列宽、固定列、列分组、列密度、重置默认、保存列布局、应用个人列偏好、移动端列收纳和列配置承载面。
- 列设置面板、列配置 Drawer、列管理独立页、密度切换器、列拖拽排序、列宽拖拽、键盘替代、重置/恢复默认、保存/取消、权限降级和旧布局失效。
- 表格、报表、审计日志、成员列表、任务列表、文件列表、计费列表和配置列表中的列布局策略。

本 owner 不覆盖：

- 表格数据请求、排序算法、分页协议、行选择、批量操作、ARIA Grid 结构、列单元格业务渲染、后端字段权限、具体 CSS token 或组件库 API。
- 卡片视图字段布局；卡片式结果继续执行 `references/card-list-results.md`。若表格列配置会同步影响卡片字段显示，必须明确转交视图/布局 owner。

## `tableColumnLayoutState`

每个支持列设置、列宽、固定列或密度切换的表格必须声明 `tableColumnLayoutState`：

| 字段 | 语义 |
| --- | --- |
| `columnLayoutOwnerId` | 当前列布局 owner 稳定身份。 |
| `tableBinding` | 表格 owner、结果 owner、数据集版本、表格能力档位和当前视图身份。 |
| `columnRegistry` | 所有可配置列的稳定 ID、字段来源、默认顺序、默认宽度、最小/最大宽度、是否必显、是否可固定、是否可隐藏、权限边界和敏感等级。 |
| `draftLayout` | 用户正在编辑但尚未应用的列显隐、顺序、宽度、固定和密度草稿。 |
| `appliedLayout` | 当前表格实际使用的列布局快照。 |
| `persistedLayout` | 已保存到个人偏好、团队视图、系统预设或 URL 的布局快照及版本。 |
| `densityPolicy` | `compact`、`comfortable`、`spacious` 或业务扩展密度的行高、触控目标、信息量和可访问性边界。 |
| `widthPolicy` | 自动宽度、手动宽度、最小/最大宽度、溢出、横向滚动、固定列阴影和重算触发。 |
| `pinningPolicy` | 左固定、右固定、禁止固定、固定列上限、固定列与操作列/选择列/展开列的顺序边界。 |
| `orderingPolicy` | 列重排方式、键盘替代、必显列位置、分组列、权限隐藏列和冲突处理。 |
| `resetPolicy` | 重置当前草稿、恢复个人默认、恢复团队默认、恢复系统默认和清空本地临时布局的区别。 |
| `persistencePolicy` | 是否自动保存、显式保存、保存到哪里、是否影响当前视图、是否进入 `saved-views-layout-presets.md`。 |
| `permissionBoundary` | 字段可见性、列名、列值、列数量、旧列配置和无泄露策略。 |
| `feedbackBinding` | 应用、保存、重置、恢复默认、失败、未知结果和权限降级的结果 owner。 |
| `responsivePolicy` | 移动端列收纳、关键列保留、横向滚动、密度降级、列设置承载面和安全区域策略。 |
| `focusAnnouncementPolicy` | 打开列设置、应用布局、保存失败、权限降级、重置和断点转换的焦点/公告策略。 |
| `lifecycleDisposal` | 表格卸载、数据集变化、权限变化、视图切换、保存视图应用、路由变化和迟到保存结果的清理规则。 |
| `runtimeVerification` | 真实浏览器、键盘、读屏、触摸、拖拽、横向滚动、固定列、缩放、移动端、权限切换和视图恢复验证状态；未执行必须标为未验证。 |

不得只用列数组、localStorage、CSS class、组件库默认 column picker、隐藏 DOM、媒体查询或保存视图名称替代 `tableColumnLayoutState`。

## 草稿、应用和持久化分离

列配置必须区分 `draftLayout`、`appliedLayout` 和 `persistedLayout`。打开列设置、勾选列、拖动顺序、调整宽度和切换密度只改变草稿；只有明确“应用”后才改变当前表格；只有明确“保存”或产品声明自动保存后才改变持久化布局。

保存视图不是应用列草稿。若用户在列设置 Drawer 中改了草稿又点击“保存视图”，界面必须明确保存的是当前已应用布局，还是要求先应用草稿，不能静默把未确认草稿写入团队视图、URL 或导出范围。

取消列设置必须丢弃未应用草稿，不得改变表格列、URL、保存视图、导出范围、选择范围或焦点目标。迟到的保存、重置或视图应用结果必须匹配 `columnLayoutOwnerId`、表格身份、视图版本、权限版本和布局版本。

## 列可见性、必显列和权限

列隐藏不是字段无权限。用户隐藏列表示个人布局选择；权限隐藏表示当前账号不可见；必显列表示产品要求该列在当前任务中必须保留。三者的 DOM、菜单项、保存视图、导出字段和无泄露策略不同。

关键身份列、状态列、错误列、选择列、操作列、审计必要列和恢复入口列不得被用户隐藏到任务不可完成。若允许隐藏，必须提供等价摘要、详情入口、错误入口或恢复路径，并在移动端保留核心识别能力。

无权限列不得出现在列设置面板、列数量、列顺序、已隐藏列表、保存视图字段、导出字段、ARIA label、Tooltip、旧布局、URL 或本地缓存中。权限降级后，旧列名、旧列宽、旧固定状态、旧排序、旧单元格内容和旧保存视图必须失效、过滤或要求重新确认。

## 顺序、宽度、固定列和横向滚动

列顺序必须基于稳定列 ID，而不是当前数组下标、可见 index、DOM 顺序或拖拽瞬间位置。拖拽重排必须有键盘替代；移动端可以用上移/下移按钮或独立列管理页替代拖拽。

列宽必须有最小/最大边界。用户拖动列宽不能让列标题、字段值、排序按钮、筛选入口、错误图标、复制入口、行操作、选择框或固定列阴影完全不可达。自动宽度和手动宽度切换必须说明谁是当前 owner。

固定列必须声明左/右边界、上限、与选择列/展开列/操作列的相对顺序、阴影和横向滚动同步。固定列不得遮挡中间列内容、Tooltip、Dropdown、Dialog/Drawer 内浮层、焦点环或移动端安全区域。

## 密度和信息量

密度切换不能只改行高。`compact`、`comfortable`、`spacious` 必须声明行高、触控目标、单元格 padding、换行/截断、图标按钮命中区、错误/状态可见性和读屏顺序。紧凑模式不得删除状态、错误、单位、禁用原因、行操作、选择摘要或恢复入口。

移动端或触控设备可以限制紧凑密度，但必须说明原因，并保留可达的信息量。系统字体放大、200% 缩放、低高度视口和长文本下，密度切换不能让行操作、分页、错误和恢复入口被固定区遮挡。

## 重置、恢复默认和保存视图

重置当前草稿、恢复当前表格默认、恢复个人默认、恢复团队默认、恢复系统默认和清空本地临时布局是不同意图。每个意图必须说明影响范围、是否立即应用、是否持久化、是否影响当前保存视图、是否影响其他用户。

覆盖团队视图、共享列布局、设为默认布局、恢复团队默认或删除布局预设可能影响他人时，必须进入 `references/risk-actions.md`。确认前请求数为 0，并说明影响范围、版本、权限和未知结果处理。

保存列布局到视图时，必须同时执行 `references/saved-views-layout-presets.md`。列布局 owner 提供可持久化的 `appliedLayout`；保存视图 owner 负责视图身份、共享范围、默认策略、审计和结果回执。

## 移动端、可访问性和生命周期

移动端不得删除关键列识别、状态、错误、权限原因、恢复入口、列设置入口、当前密度说明或重置/恢复路径。可以将低频列设置放入 Drawer、Bottom Sheet 或独立页；复杂列管理、共享默认和团队布局建议进入独立页或全屏 Drawer。

列设置面板必须有可访问名称、当前作用范围、列计数、已选状态、必显/禁用原因和可操作说明。列拖拽、列宽调整和固定列配置必须提供键盘替代或等价按钮。状态变化、应用成功、保存失败、权限降级和重置必须由唯一 owner 公告。

路由变化、表格 owner 卸载、数据集版本变化、权限变化、保存视图应用或断点转换后，旧列配置草稿、旧 DOM、旧宽度测量、旧拖拽句柄、旧固定列阴影、旧 local cache、旧 aria-describedby、旧焦点任务和迟到保存结果必须取消、失效或重算。

## 完成前检查

1. **owner 声明**：每个支持列设置、列宽、固定列或密度切换的表格声明 `tableColumnLayoutState`。
2. **草稿/应用/持久化分离**：`draftLayout`、`appliedLayout` 和 `persistedLayout` 分离；取消草稿不改变表格、URL、保存视图、导出范围或选择范围。
3. **列身份**：列顺序、宽度、固定和权限基于稳定列 ID，不基于数组下标、可见 index 或 DOM 顺序。
4. **权限无泄露**：无权限列不出现在列设置、列数量、已隐藏列表、保存视图、导出字段、ARIA、Tooltip、旧布局、URL 或缓存。
5. **必显与关键能力**：身份列、状态列、错误列、选择列、操作列、审计必要列和恢复入口列不会被隐藏到任务不可完成。
6. **宽度和固定列**：列宽有最小/最大边界；固定列不遮挡内容、浮层、焦点环或安全区域。
7. **密度**：紧凑模式不删除状态、错误、单位、禁用原因、行操作、选择摘要或恢复入口。
8. **重置语义**：重置草稿、恢复个人默认、恢复团队默认、恢复系统默认和清空本地布局没有混用。
9. **保存视图转交**：保存列布局到视图时读取已应用布局，并执行 `saved-views-layout-presets.md`；未应用草稿不会静默保存。
10. **运行时报告**：真实浏览器、键盘、读屏、触摸、拖拽、横向滚动、固定列、缩放、移动端、权限切换和视图恢复未执行时必须标为**未验证**，并写明所需环境。
