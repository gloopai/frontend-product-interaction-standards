# 记录新增/编辑承载面交互规范

适用于列表、表格、卡片列表、管理列表、报表明细和详情页中触发的新增记录、编辑记录、复制创建、批量配置编辑和记录配置流程。本文件是“记录编辑应该由哪个承载面负责”的唯一事实来源。

本规范只定义编辑承载面选择、列表入口、返回、权限复核和反内嵌边界；表单字段、校验、dirty、提交、错误摘要和失败恢复仍由 [表单状态、校验与错误交互规范](forms.md) 负责。选择 Dialog 时执行 [Dialog 交互规范](dialogs.md)，选择 Drawer 时执行 [Drawer 交互规范](drawers.md)，来源列表执行 [数据表格交互规范](data-tables.md)，跨端变化执行 [响应式与自适应交互规范](responsive-adaptive.md)。后台、管理台、SaaS console 或内部工具还必须执行 [管理台完整治理交互规范](admin-console.md)。

## 范围与术语

记录编辑是指会创建、修改或复制业务记录的完整编辑会话，包括新增、编辑、复制创建、批量配置、资源配置和需要保存字段值的设置流程。记录编辑不是单次命令式操作；“启用”“停用”“重发”“归档”这类不暴露字段控件的按钮属于行操作或风险操作。

列表包括原生表格、ARIA Grid、卡片列表、虚拟列表、报表明细、管理列表和任何以多条记录为主要内容的结果区域。

列表中的详情预览、侧边预览、行预览、记录预览、快速查看、只读预览和 Master-Detail 归 `references/preview-pane.md`；预览面板只能展示只读内容和操作入口，不得承载新增、编辑、复制创建、批量配置、字段保存、行内保存或完整字段编辑表单。编辑入口只能从预览转交到本文件规定的 Dialog、Drawer 或独立页。

编辑承载面只能是：

- `dialog`：模态 Dialog。
- `drawer`：模态 Drawer / Sheet。
- `page`：独立页面、独立路由或等价的完整编辑工作区。

## RES-SCOPE 范围与禁止项

| 规则 ID | 规则 |
| --- | --- |
| `RES-SCOPE-01` | 列表只负责浏览、筛选、排序、分页、选择、只读详情预览、状态反馈和操作入口；不得成为新增或编辑记录的表单 owner。 |
| `RES-SCOPE-02` | 新增记录、编辑记录、复制创建、批量配置编辑和记录配置必须离开列表内容流，进入 Dialog、Drawer 或独立页。 |
| `RES-SCOPE-03` | 禁止列表内嵌完整表单，包括表格行下展开表单、卡片项内部字段、列表顶部/底部新增表单、筛选区域混入业务编辑字段、批量工具栏直接承载编辑字段。 |
| `RES-SCOPE-04` | 禁止常驻可编辑列表、表格编辑矩阵、单元格编辑和 spreadsheet-like 编辑。列表行不得直接渲染 input、textarea、select、combobox、日期选择器、排序输入、开关式字段编辑控件或每行“保存”按钮。 |
| `RES-SCOPE-05` | 排序、状态、分类、标签等小型字段也不得在列表单元格中直接可改。需要快捷修改时，列表只放操作入口，例如“调整排序”“修改状态”“编辑标签”，随后进入 Dialog、Drawer 或独立页。 |
| `RES-SCOPE-06` | 纯命令式行操作可以保留在列表中，例如启用、停用、重发、归档；但它不得暴露字段编辑控件，不产生 dirty 长会话，并按风险等级执行对应确认、请求身份、结果回执和失败恢复。 |
| `RES-SCOPE-07` | 报表和仪表盘默认只读展示；未被产品显式声明为记录编辑场景时，不得从明细表、图表或指标卡自动推导新增、编辑、行内保存或批量编辑入口。 |

## RES-CHOICE 承载面选择

默认选择独立页。只有能证明编辑会话较短、状态边界简单且不需要独立路由时，才可降级为 Drawer 或 Dialog。

| 规则 ID | 承载面 | 适用条件 | 禁用条件 |
| --- | --- | --- | --- |
| `RES-CHOICE-01` | 独立页 | 多字段、多步骤、复杂校验、强权限/审计、深链接、刷新恢复、协作、文件上传、复杂关联数据、移动端主流程、需要长期编辑或跨团队共享链接。 | 只有极轻量短流程且产品明确不需要深链、刷新恢复和长期引用时，可选择 Drawer 或 Dialog。 |
| `RES-CHOICE-02` | Drawer | 需要保留来源列表上下文；字段中等；编辑时需要参考当前记录摘要或邻近列表状态；提交后返回同一列表上下文。 | 多步骤复杂流程、高风险强审计、需要独立 URL、刷新恢复、移动端无法稳定承载、或会话需要长期保存时。 |
| `RES-CHOICE-03` | Dialog | 低复杂度、少字段、短流程、提交快、失败恢复简单、不需要深链、不需要长期引用列表上下文。 | 字段多、内容需要长滚动、多步骤、异步校验多、权限/审计强、移动端键盘遮挡明显、需要可分享 URL 或刷新恢复时。 |
| `RES-CHOICE-04` | 响应式转换 | 同一编辑会话可在 Dialog、Drawer 和独立页之间按断点或能力声明转换，但必须保持同一业务会话、同一表单状态和同一提交边界。 | 断点变化不得把已打开编辑会话重建为列表内表单，也不得丢失 dirty、错误、提交、权限或焦点上下文。 |

选择顺序必须先判断是否需要独立页，再判断 Drawer，最后才判断 Dialog。不得为了减少页面跳转而把复杂编辑压入 Dialog；不得为了保留列表可见而把编辑字段塞回列表。

## RES-STATE 编辑承载面状态

每个记录编辑入口必须创建独立的 `editSurfaceState`，不能复用列表行、筛选栏、表格选择或行菜单状态。

| 字段 | 最低要求 |
| --- | --- |
| `surfaceId` | 当前编辑承载面实例 ID，不可与列表 owner ID 混用。 |
| `mode` | `create`、`edit`、`copy-create`、`batch-config` 或产品声明的记录配置模式。 |
| `surfaceType` | `dialog`、`drawer` 或 `page`。 |
| `sourceListSnapshot` | 来源列表的查询、筛选、排序、分页、滚动锚点、焦点触发器和能力声明快照。 |
| `recordIdentity` | 新增时为目标集合和预填来源；编辑时为稳定记录 ID、版本、租户/工作区和权限范围。 |
| `permissionVersion` | 打开、提交和返回时用于复核的权限/租户/工作区/角色版本。 |
| `formSessionId` | 表单 owner 的 live session 身份；字段状态、dirty、错误和提交由该会话维护。 |
| `returnStrategy` | 成功、取消、失败、权限变化、记录不存在、版本冲突和来源列表不可恢复时的返回策略。 |
| `runtimeVerification` | 浏览器、键盘、屏幕阅读器、触摸、断点和真实组件运行时验证状态；未执行时必须标为未验证。 |

## RES-LIST 列表入口与返回

| 规则 ID | 规则 |
| --- | --- |
| `RES-LIST-01` | 列表中的“新增”“编辑”“复制创建”“配置”“批量编辑”只能是入口，不承载字段值、dirty、校验或保存按钮。 |
| `RES-LIST-02` | 触发编辑前冻结来源列表快照；打开承载面后，列表查询、分页、选择、菜单和编辑会话分别由各自 owner 管理，不得共享可变状态。 |
| `RES-LIST-03` | 编辑成功、取消、失败或关闭返回列表时，必须重新校验权限、数据版本、列表范围和记录可见性；旧行、旧菜单、旧选择、旧下载入口或旧保存按钮不得直接回放。 |
| `RES-LIST-04` | 成功后可以刷新列表、局部更新、跳转详情或保持当前位置，但产品必须显式声明；未声明时默认重新查询并安全恢复焦点。 |
| `RES-LIST-05` | 来源记录被删除、权限降级、租户切换或筛选范围变化后，返回必须进入安全替代内容、重新定位或页面级恢复流程，不能把编辑前记录继续作为可编辑对象展示。 |
| `RES-LIST-06` | 批量配置编辑必须绑定不可变范围快照、权限版本和结果回执；不得把批量字段常驻在工具栏、表头或列表顶部并直接保存。 |

## RES-FORM 与表单 owner 的关系

| 规则 ID | 规则 |
| --- | --- |
| `RES-FORM-01` | 记录编辑字段值、`initialValue`、dirty、touched、validation generation、`submitSnapshot`、`submitId`、错误摘要和失败恢复都由表单 owner 维护。 |
| `RES-FORM-02` | 列表 owner 不得读取未提交字段草稿来改变查询、排序、选择、行展示或批量范围；只有提交成功且通过返回策略复核后，列表才可刷新或局部更新。 |
| `RES-FORM-03` | 未保存更改离开确认归表单和当前承载面共同执行；列表滚动、翻页或刷新不得静默丢弃编辑会话。 |
| `RES-FORM-04` | 请求失败后承载面保持打开并保留草稿、错误和恢复路径；不得用关闭 Dialog/Drawer、回到列表或 Toast 替代错误恢复。 |

## RES-AUDIT 管理台权限、风险与审计

| 规则 ID | 规则 |
| --- | --- |
| `RES-AUDIT-01` | 管理台记录编辑必须声明 `consoleSurface=record-editor` 或来源 `record-list` 到编辑承载面的转换，并保留页面级权限、风险、审计和反馈 owner。 |
| `RES-AUDIT-02` | 提交前复核租户、工作区、角色、权限版本、记录版本和字段权限；复核失败不得继续提交旧快照。 |
| `RES-AUDIT-03` | 高风险编辑、批量配置、权限变更、停用、删除、敏感字段修改和影响范围不明确的操作必须声明风险级别、请求身份、结果回执和审计回执。 |
| `RES-AUDIT-04` | Toast 只能辅助反馈，不能作为编辑成功、失败、审计或恢复的唯一结果；页面、承载面或任务中心必须有可定位回执。 |

## RES-RSP 响应式与跨端

| 规则 ID | 规则 |
| --- | --- |
| `RES-RSP-01` | 移动端、窄屏、低高度、200% 缩放、虚拟键盘和安全区域下，编辑字段、错误摘要、提交、取消、恢复和未保存确认必须可达。 |
| `RES-RSP-02` | 桌面 Drawer 可在移动端转换为全屏或底部 Drawer，复杂编辑可转换为独立页；转换不得重建表单会话或退化为列表内编辑。 |
| `RES-RSP-03` | 触摸端不得依赖拖拽、滑动、长按或精确点击完成关键编辑；必须有清晰按钮或键盘路径。 |

## 可执行验收场景

每个验收均须记录初始状态、事件序列、预期状态、DOM/ARIA、事件日志和运行时验证边界；未实际执行浏览器、屏幕阅读器、触摸设备、真实组件或断点验证时，必须标为“未验证”。

### RES-A1：列表不承载记录编辑

- 初始状态：列表展示多条记录，具有新增、编辑或配置需求。
- 事件序列：尝试在表格行、卡片项、筛选区、工具栏、列表顶部或列表底部放置编辑字段。
- 预期状态：方案失败；列表只保留操作入口，字段编辑进入 Dialog、Drawer 或独立页。
- DOM/ARIA：列表行内不存在 input、textarea、select、combobox、日期选择器、排序输入、字段开关或行内保存按钮。
- 事件日志：记录禁止原因、目标承载面和 `editSurfaceState.surfaceType`。

### RES-A2：常驻可编辑列表负例

- 初始状态：多条记录需要维护标题、描述、正文、分类、状态和排序。
- 事件序列：把每行渲染为标题输入框、描述 textarea、正文 textarea、分类输入、状态下拉、排序输入和“保存”按钮。
- 预期状态：方案失败；该形态是常驻可编辑列表，必须改为列表只读展示加编辑入口，或进入专门排序/批量配置承载面。
- DOM/ARIA：列表单元格仅展示只读值和入口；每行保存按钮数量为 0。
- 事件日志：记录 `inlineEditableControls=0`、`rowSaveButtons=0`、`editSurfaceState` 已创建。

### RES-A3：承载面选择

- 初始状态：产品声明记录编辑字段数量、复杂度、权限/审计、深链、刷新恢复和移动端需求。
- 事件序列：按顺序判断独立页、Drawer、Dialog。
- 预期状态：多字段、多步骤、强审计或需要深链时选择独立页；需要保留列表上下文且复杂度中等时选择 Drawer；低复杂短流程才选择 Dialog。
- DOM/ARIA：所选承载面执行其组件 owner 的角色、名称、焦点、关闭、滚动和错误恢复规则。
- 事件日志：记录选择依据和被排除承载面的禁用原因。

### RES-A4：返回列表复核

- 初始状态：从列表进入编辑承载面，保留 `sourceListSnapshot`、`recordIdentity` 和 `permissionVersion`。
- 事件序列：编辑成功、取消、失败、权限变化、记录版本冲突或来源列表范围变化后返回。
- 预期状态：重新校验权限、数据版本、记录可见性和列表位置；旧菜单、旧选择、旧下载入口和旧行编辑状态不回放。
- DOM/ARIA：焦点只恢复到仍存在且仍有权限的入口；否则迁移到页面级合理目标。
- 事件日志：记录复核、刷新/局部更新策略、焦点目标和旧状态清理。

### RES-A5：管理台审计边界

- 初始状态：后台或 SaaS console 中从 `record-list` 进入 `record-editor`。
- 事件序列：提交高风险字段、批量配置、权限相关修改或敏感字段修改。
- 预期状态：提交前复核权限和版本；请求身份、结果回执、审计回执和失败恢复可定位；Toast 不作为唯一回执。
- DOM/ARIA：确认、错误和结果回执执行 Dialog/Drawer/Form/Admin owner；运行时未验证则标注未验证。
- 事件日志：记录请求身份、权限版本、结果状态、审计可用性和恢复入口。

## 完成前检查

- 检查列表、表格、卡片列表和报表明细中是否存在字段编辑控件、行内保存按钮、展开编辑表单或常驻可编辑矩阵；存在即失败。
- 检查每个新增/编辑入口是否声明 Dialog、Drawer 或独立页，并说明选择依据和禁用其他承载面的原因。
- 检查 `editSurfaceState` 是否包含来源列表快照、记录身份、权限版本、表单会话、返回策略和验证边界。
- 检查返回列表是否重新校验权限、数据版本、记录可见性、旧选择、旧菜单、旧下载入口和焦点目标。
- 检查 Dialog / Drawer / Page 是否同时执行对应组件 owner、表单 owner、响应式 owner；管理台场景还要执行权限、风险、审计和反馈 owner。
- 未实际执行浏览器、键盘、屏幕阅读器、触摸设备、断点或真实组件运行时检查时，必须明确标为未验证，并列出所需验证。
