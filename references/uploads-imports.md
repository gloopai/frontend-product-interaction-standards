# 上传与导入交互规范

## 范围

适用于前端页面、管理台、业务表单、Dialog、Drawer、列表工具栏和任务中心中的文件上传、附件上传、拖拽上传、批量上传、模板下载、结构化数据导入、导入预检、字段映射、上传进度、取消上传、重试上传、错误明细下载和导入结果查看。

本文件是上传与导入文件交互的唯一事实来源。它定义文件如何被选择、校验、上传、预检、确认、执行、取消、重试、展示结果和恢复错误。文件库、媒体资产管理、在线预览、图片裁剪、音视频转码、对象存储协议、后端解析算法、病毒扫描和 CDN 策略不属于本 owner。

## 与组件 owner 的关系

表单内文件字段读取 `forms.md`；选择文件、上传、取消、重试、确认导入和下载错误明细按钮读取 `buttons.md`；上传或导入流程放入 Dialog / Drawer 时读取 `dialogs.md` / `drawers.md`；预检表、错误明细表和结果明细表读取 `data-tables.md`；管理台权限、租户、风险、审计、任务中心和全局反馈读取 `admin-console.md`；移动端、触摸、虚拟键盘、安全区域和能力折叠读取 `responsive-adaptive.md`。当本文件与组件 owner 都适用时，两者都执行；冲突时停止并请用户裁决。

Upload / Import owner 不重新定义表单提交、按钮层级、容器关闭、数据表格分页、管理台审计或响应式布局的完整规则；它定义文件生命周期、上传会话、导入预检、错误明细和结果恢复的产品交互边界。

## 场景与状态模型

每个上传或导入入口必须声明一个 `uploadSurface`：`standalone-upload`、`form-file-field`、`avatar-upload`、`attachment-list`、`bulk-upload`、`data-import`、`import-preflight`、`import-job-result` 或 `error-report-download`。结构化导入同时声明 `importFlowState`，普通上传可只声明上传会话。

每个上传 owner 维护 `uploadSessionState`，至少包含：

| 字段 | 语义 |
| --- | --- |
| `sessionId` | 当前上传会话身份；路由、容器、字段 owner 或导入候选重建时更新。 |
| `sourceOwner` | 触发来源，例如独立上传区、表单字段、Dialog、Drawer、列表工具栏或导入流程。 |
| `acceptedPolicy` | 文件类型、大小、数量、来源、租户/工作区、权限和业务约束的不可变快照。 |
| `fileItems` | 每个文件的稳定身份、名称、大小、MIME/扩展名、来源、本地校验、上传阶段、错误和结果。 |
| `queuePhase` | `idle`、`validating`、`ready`、`uploading`、`paused`、`completed`、`partial-failed`、`failed`、`cancelled`、`disposed`。 |
| `requestIdentity` | 上传或导入请求的幂等键、权限版本、租户/工作区、文件快照、导入配置快照和来源操作。 |
| `resultOwner` | 成功、失败、部分成功、未知结果、过期和恢复入口的 primary owner。 |

上传状态不能只绑定到按钮 loading、表单 submitting、React 组件局部 loading 或任务中心文本。按钮可以触发上传，表单可以读取文件字段值，管理台可以接管异步任务，但文件队列、文件级错误、进度、取消、重试和文件引用有效性必须由上传 owner 明确持有。

## UPL-SCOPE 范围和术语

| 规则 ID | 规则 |
| --- | --- |
| UPL-SCOPE-01 | 上传入口必须说明文件用途、允许类型、大小上限、数量上限、是否覆盖、是否会创建/更新/删除数据，以及上传或导入后的下一步。 |
| UPL-SCOPE-02 | “上传文件”只表示文件内容或文件引用进入系统；“导入数据”表示系统会解析文件并创建、更新、跳过或拒绝业务记录，两者不得混用结果文案。 |
| UPL-SCOPE-03 | 导入、覆盖导入、批量更新、权限相关上传、敏感文件上传和错误明细下载默认是管理台风险或敏感结果访问，必须与 Admin owner 的权限、审计和回执组合。 |
| UPL-SCOPE-04 | 文件 owner 不得把组件库默认上传行为视为规范；若默认行为不能满足本文件，必须配置、封装或替换。 |

对应验收：UPL-A1、UPL-A10。

## UPL-PICK 文件选择、拖拽与本地校验

文件选择入口必须有可见名称和帮助文本。帮助文本至少说明文件类型、大小、数量和关键限制；如果导入需要模板，上传前必须提供模板下载或模板说明。拖拽上传不能是唯一入口；必须提供等价的选择文件按钮。

浏览器 `accept` 只能作为选择器提示，不能作为唯一校验。选择、拖拽、粘贴、重新选择、移动端文件选择器和程序传入文件都必须进入同一校验管线。校验至少覆盖类型、扩展名、大小、数量、空文件、重复文件、文件名冲突、权限、租户/工作区和业务可解析性；需要服务端判断的内容必须显式进入上传后预检或服务端校验状态。

| 规则 ID | 规则 |
| --- | --- |
| UPL-PICK-01 | 文件入口必须同时支持键盘可达的选择文件按钮；拖拽、粘贴或点击区域只能作为增强能力。 |
| UPL-PICK-02 | `accept`、文件扩展名、MIME、大小和数量限制必须有同源校验规则；`accept` 只能作为选择器提示，不能作为唯一校验。 |
| UPL-PICK-03 | 无效文件不得进入待上传请求队列。若产品保留无效文件在 UI 中展示，必须标记为 invalid，并提供删除、重新选择或查看原因。 |
| UPL-PICK-04 | 多文件选择必须逐项展示文件名、大小、校验状态和可恢复动作；不能只显示“已选择 N 个文件”。 |
| UPL-PICK-05 | 重复文件、同名文件或覆盖候选必须明确处理策略：拒绝、替换、保留两个版本或要求用户确认。 |
| UPL-PICK-06 | 重新选择文件必须生成新的文件项身份或明确替换旧项；旧文件的校验、上传、错误和结果不得写回新文件。 |

对应验收：UPL-A1、UPL-A2。

## UPL-STATE 上传会话、队列与进度

上传会话必须区分本地校验、待上传、上传中、上传成功、上传失败、部分失败、取消、未知结果、文件引用过期和会话已处置。单文件上传也必须有明确状态，不能只靠按钮 disabled 或 spinner 暗示。

多文件上传必须同时展示整体状态和每个文件状态。进度可用时展示真实进度；进度不可用时不能伪造百分比，应显示排队、处理中、等待服务端确认或未知进度。上传完成后，结果 owner 必须说明文件是否已经可用于当前任务，或是否仍需用户提交表单/确认导入。

| 规则 ID | 规则 |
| --- | --- |
| UPL-STATE-01 | 每个文件项必须有稳定身份，迟到校验、迟到上传结果和重试结果只能写回同一 live `sessionId` 与同一文件项。 |
| UPL-STATE-02 | `queuePhase` 和每个 `fileItem.phase` 必须可观察；不得把整体 loading 当成唯一状态。 |
| UPL-STATE-03 | 进度未知时必须展示未知进度或处理中状态，不得伪造百分比或直接跳到成功。 |
| UPL-STATE-04 | 部分失败时，成功文件、失败文件、可重试文件和需重新选择文件必须可区分。 |
| UPL-STATE-05 | 文件引用过期、上传凭证过期或任务结果过期时，必须撤销旧引用并提供重新上传、重新生成或联系管理员等适用恢复路径。 |

对应验收：UPL-A2、UPL-A3。

## UPL-ASYNC 取消、重试、防重复与迟到结果

上传和导入的触发必须冻结 `requestIdentity`。点击、Enter、Space、触摸、拖拽完成回调、自动重试和事件重放都必须进入同一去重门禁，不能产生重复上传或重复导入任务。请求是否已经发送、服务端是否接受、任务是否排队和结果是否可知必须分开表达。

取消分为客户端取消意图、客户端停止等待、取消请求已发送、服务端确认取消和取消失败。用户关闭 Dialog、离开页面或点击取消，只能说明客户端停止等待或已请求取消；如果请求已经发送，不得直接把服务端任务写成已取消。关闭容器也不能删除任务中心中仍在执行的服务端任务。

| 规则 ID | 规则 |
| --- | --- |
| UPL-ASYNC-01 | 同一上传或导入意图的重复点击、Enter、Space、触摸或事件重放必须复用同一 `requestIdentity` 或被拒绝，不能发送多个等价请求。 |
| UPL-ASYNC-02 | 取消 UI、关闭容器、路由离开或浏览器返回不得直接把服务端任务写成已取消；只有服务端终态确认后才能展示服务端已取消。 |
| UPL-ASYNC-03 | 迟到结果必须验证 live `sessionId`、文件项身份、导入任务身份、权限版本和当前 owner 后才可写回。 |
| UPL-ASYNC-04 | 重试必须声明范围：仅失败文件、全部文件、重新预检、重新确认导入或重新下载错误明细。 |
| UPL-ASYNC-05 | 重试复用幂等键或创建新幂等键必须由产品声明；不得让重复触发隐式改变执行范围。 |
| UPL-ASYNC-06 | 上传失败必须保留用户可恢复上下文；不得默认清空文件列表、关闭容器或跳转离开。 |

对应验收：UPL-A3、UPL-A4、UPL-A10。

## UPL-FORM 表单内上传

文件作为表单字段时，Form owner 仍管理可见 label、字段帮助、dirty/touched、错误摘要、提交快照、未保存更改和失败恢复；Upload owner 管理文件选择、文件项、上传队列、文件级错误、上传结果和文件引用有效性。

表单必须声明文件字段提交策略：

- `upload-before-submit`：文件先上传，只有成功且仍有效的文件引用进入 `submitSnapshot`。
- `upload-during-submit`：文件上传与表单提交共享一次不可变提交快照，失败时保留草稿和文件队列。
- `local-draft-until-submit`：文件只作为本地草稿，用户显式提交后才进入上传或导入流程。

| 规则 ID | 规则 |
| --- | --- |
| UPL-FORM-01 | 文件字段的值必须区分本地文件、上传中引用、已上传有效引用、失败文件、已删除旧文件和过期引用。 |
| UPL-FORM-02 | 删除、替换、重新选择或上传成功必须按 Form owner 重算 dirty/touched；不能因为文件名相同就复用旧字段有效性。 |
| UPL-FORM-03 | 表单提交快照只能包含当前策略允许的文件值；已知 invalid、上传失败或过期文件不得进入有效 payload。 |
| UPL-FORM-04 | 表单 reset 或 route/unmount 只能释放该表单会话拥有的上传资源，不能影响其他存活上传会话、任务中心任务或已独立提交的导入任务。 |
| UPL-FORM-05 | 服务端文件字段错误必须绑定 `sessionId`、字段身份、提交快照和文件项身份；用户替换或删除文件后旧错误失效。 |
| UPL-FORM-06 | 上传中的文件字段若阻止离开，必须由 Form/Dialog/Drawer owner 的未保存或不可安全中断策略表达，不能由按钮 loading 隐式改写关闭路径。 |

对应验收：UPL-A5、UPL-A10。

## IMP-FLOW 导入模板、预检、映射与确认

结构化导入必须显式分阶段：模板下载、文件选择、本地校验、上传、预检、字段映射或规则确认、确认导入、执行任务、结果回执。简单导入可以合并视觉步骤，但不能省略状态和决策边界。

模板下载必须说明适用版本、字段、示例、限制和权限范围。模板下载不是永久安全链接；权限、租户/工作区或模板版本变化后必须重新证明可下载。

预检结果必须区分格式错误、字段缺失、字段映射不完整、重复数据、权限不可执行、将被跳过的数据、警告和可继续风险。存在阻断错误时不得进入确认导入；存在警告或跳过数据时必须说明影响范围，由用户显式确认后才继续。

| 规则 ID | 规则 |
| --- | --- |
| IMP-FLOW-01 | 导入流程必须有 `importFlowState`，至少记录模板版本、文件身份、预检结果、字段映射、导入配置、确认状态、任务身份和结果。 |
| IMP-FLOW-02 | 未完成本地校验和服务端预检前，不得进入确认导入；存在阻断错误时不得发送导入执行请求。 |
| IMP-FLOW-03 | 字段映射、跳过规则、覆盖策略、去重策略和权限版本必须进入导入快照。 |
| IMP-FLOW-04 | 确认导入后，编辑映射、替换文件、切换租户/工作区或权限版本变化不得改写已发送任务；必须新建导入意图或终止当前候选。 |
| IMP-FLOW-05 | 导入确认必须说明将创建、更新、跳过、覆盖、删除或忽略的数据范围；高风险导入必须进入 Admin risk owner。 |
| IMP-FLOW-06 | 导入流程离开、关闭或刷新时，必须说明候选是否仅客户端丢弃、任务是否仍在服务端执行，以及如何在任务中心继续查看。 |

对应验收：UPL-A6、UPL-A7、UPL-A10。

## IMP-RESULT 任务结果、部分成功与错误明细

导入结果至少区分成功、部分成功、失败、取消、未知结果、过期和无权限查看结果。未知结果不得伪装为成功或失败，必须提供检查最新状态、进入任务中心或联系支持的路径。

部分成功不能只用 Toast 表示；必须展示成功数、失败数、跳过数、影响范围、下一步和错误明细入口。错误明细可能包含敏感数据，下载前必须复核权限、租户/工作区、任务身份和文件有效期。

| 规则 ID | 规则 |
| --- | --- |
| IMP-RESULT-01 | 成功、部分成功、失败、取消、未知、过期和无权限必须是互斥可观察结果状态。 |
| IMP-RESULT-02 | 部分成功必须展示成功、失败、跳过和未处理的数量及影响范围；Toast 不能作为唯一回执。 |
| IMP-RESULT-03 | 错误明细下载前必须复核权限、租户/工作区、任务身份和文件有效期；旧链接不得在权限或任务状态变化后继续暴露。 |
| IMP-RESULT-04 | 错误明细应避免泄露无权访问对象的敏感字段；无法安全展示时，提供安全摘要和申请权限路径。 |
| IMP-RESULT-05 | 下载错误明细、重新导入、重试失败行、查看任务详情和返回来源列表必须说明使用的筛选、映射和任务快照。 |
| IMP-RESULT-06 | 导入结果影响列表或报表时，刷新、保留当前筛选、跳转新记录或下载结果的 owner 必须明确；不得由 Toast 隐式决定。 |

对应验收：UPL-A7、UPL-A8、UPL-A10。

## UPL-PERM 权限、安全和审计

上传与导入必须绑定权限版本、租户/工作区、来源页面、发起者、目标范围和文件摘要或不可逆标识。权限、租户、工作区、角色或权限版本变化时，未完成上传、导入确认、任务结果、错误明细和下载入口都必须重新证明安全；无法证明时先隐藏、失效或替换为安全说明。

| 规则 ID | 规则 |
| --- | --- |
| UPL-PERM-01 | 权限不足状态必须解释可恢复原因，但不得泄露敏感对象名称、数量、字段、文件名或错误明细。 |
| UPL-PERM-02 | 敏感文件上传、覆盖导入、批量创建/更新/删除和权限相关导入必须声明风险级别、影响范围、确认策略、请求身份和审计回执。 |
| UPL-PERM-03 | 审计至少记录发起者、时间、租户/工作区、目标范围、文件摘要或不可逆标识、配置快照、请求身份和结果。 |
| UPL-PERM-04 | 文件访问 URL、模板下载 URL 和错误明细 URL 必须有有效期或权限复核机制；不得把旧 URL 当作长期授权。 |
| UPL-PERM-05 | 权限降级必须清理待上传队列、确认面板、旧下载入口、错误明细、任务操作和敏感文件名；焦点只迁移一次。 |

对应验收：UPL-A8、UPL-A10。

## UPL-A11Y 可访问性

上传入口必须有可访问名称；文件要求、帮助文本和错误信息必须通过稳定描述关联到入口或文件项。文件项列表需要可键盘浏览，删除、重试、取消、查看错误、确认导入和下载错误明细都必须可键盘触发。

状态变化由唯一 owner 公告。开始上传、上传失败、上传成功、部分失败、预检完成、导入任务创建、任务部分成功和错误明细可下载应有非重复的可感知反馈；完整错误不能在文件项、摘要和 Toast 中重复播报。

| 规则 ID | 规则 |
| --- | --- |
| UPL-A11Y-01 | 拖拽区域必须有等价键盘入口，且焦点样式可见。 |
| UPL-A11Y-02 | 文件要求、文件级错误和导入预检错误必须能被辅助技术发现；错误文本不得只存在于颜色、图标或 hover tooltip。 |
| UPL-A11Y-03 | 进度和结果公告必须去重；同一完整消息只能由一个 primary owner 播报。 |
| UPL-A11Y-04 | 删除文件、取消上传、重试失败文件、确认导入和下载错误明细的按钮必须有动作对象。 |
| UPL-A11Y-05 | 预检表和错误明细表中的错误导航必须把焦点移动到可修复项、字段映射或安全摘要。 |

对应验收：UPL-A9、UPL-A10。

## UPL-RSP 响应式与移动端

PC、平板和移动端的核心上传与导入能力必须一致。移动端可以把低频说明、预检详情或错误明细筛选折叠进 Drawer 或详情页，但不能删除选择文件、查看错误、删除文件、重试、确认导入、取消意图、任务详情和下载错误明细等核心路径。

低高度、动态 viewport、虚拟键盘、四向 safe area、系统字体放大和 200% 缩放下，文件入口、文件要求、阻断错误、进度、恢复动作和确认操作必须可达。移动端平台文件选择器能力差异不能成为删除上传入口或跳过本地校验的理由。

| 规则 ID | 规则 |
| --- | --- |
| UPL-RSP-01 | 移动端不得只保留拖拽上传；必须提供可触控、可键盘或平台等价的文件选择入口。 |
| UPL-RSP-02 | 多文件列表在窄屏可改为卡片或分组，但每个文件的状态、错误和恢复动作不能消失。 |
| UPL-RSP-03 | 导入预检和错误明细在窄屏可分步展示，但阻断错误、警告确认、字段映射和结果回执不能被省略。 |
| UPL-RSP-04 | 虚拟键盘和安全区域不得完全遮挡确认导入、取消、重试、删除文件或错误恢复入口。 |

对应验收：UPL-A9、UPL-A10。

## 可执行验收检查

下列检查以可观察状态、DOM 属性、事件日志和结果快照断言；未实际执行时必须报告为**未验证**及所需环境。

1. **文件选择和本地校验**：记录 `{sessionId, acceptedPolicy, fileItems}`。通过点击、键盘、拖拽、粘贴和移动端选择器分别传入合法文件、类型不符、大小超限、数量超限、空文件、重复文件和同名文件；断言所有来源进入同一校验管线，`accept` 只作为选择器提示，invalid 文件不进入待上传请求队列，并显示可访问原因和删除/重新选择路径。
2. **上传会话和文件项身份**：选择文件 A 后立刻替换为文件 B，再让 A 的校验和上传结果迟到返回；断言迟到结果因 `sessionId` 或文件项身份不匹配而不能写回 B。多文件上传断言每个文件有稳定身份、名称、大小、校验状态、上传阶段、错误和结果。
3. **队列、进度和部分失败**：构造已排队、上传中、未知进度、成功、失败、部分失败、引用过期状态；断言整体 `queuePhase` 和每个 `fileItem.phase` 可观察。未知进度不显示伪造百分比；部分失败区分成功、失败、可重试和需重新选择文件。
4. **防重复、取消和迟到结果**：对同一上传或导入意图连续点击、Enter、Space、触摸和事件重放；断言只产生一个 `requestIdentity` 或重复意图被拒绝。请求发送后关闭容器、路由离开和点击取消；断言 UI 只展示客户端停止等待或取消请求已发送，不得直接把服务端任务写成已取消。随后交付迟到成功、失败和取消结果，断言只有 live session、任务身份、权限版本和 owner 匹配时才写回。
5. **重试范围和失败恢复**：分别执行仅失败文件、全部文件、重新预检、重新确认导入和重新下载错误明细；断言 UI 明确说明重试范围，幂等键复用或新建策略明确，失败保留文件列表、用户配置、字段映射、错误和恢复入口，不默认清空、关闭或跳转。
6. **表单内文件字段**：在 `upload-before-submit`、`upload-during-submit` 和 `local-draft-until-submit` 三种策略下，选择、删除、替换、上传成功、上传失败、引用过期和表单提交；断言 Form owner 的 dirty/touched、错误摘要和 `submitSnapshot` 与文件字段状态一致，invalid、失败或过期文件不进入有效 payload。reset 或 route/unmount 只释放本表单会话资源，不影响其他上传会话或已提交任务。
7. **导入预检、字段映射和确认**：下载模板、上传结构化文件、执行预检，分别返回格式错误、字段缺失、映射不完整、重复数据、权限不可执行、跳过数据、警告和可继续风险；断言阻断错误不允许确认导入，警告和跳过数据需显式确认。确认后编辑映射、替换文件、切换租户或权限版本变化；断言不会改写已发送任务，只能新建导入意图或终止候选。
8. **导入结果和错误明细**：构造成功、部分成功、失败、取消、未知、过期和无权限结果；断言状态互斥。部分成功展示成功数、失败数、跳过数、影响范围、下一步和错误明细入口，Toast 不能作为唯一回执。下载错误明细前复核权限、租户/工作区、任务身份和文件有效期；权限变化或任务过期后旧链接失效。
9. **权限、安全和审计**：在上传中、预检后、确认导入前、任务执行中和结果页切换权限、租户、工作区和角色；断言待上传队列、确认面板、旧下载入口、错误明细、任务操作和敏感文件名被隐藏、失效或替换安全说明。高风险导入和敏感上传记录风险级别、影响范围、确认策略、请求身份和审计回执。
10. **可访问性、移动端和运行时报告**：检查上传入口的可访问名称、帮助/错误描述关联、键盘顺序、焦点样式、状态公告去重、文件项操作按钮动作对象、预检表错误导航。于 200% 缩放、字体放大、低高度、动态 viewport、虚拟键盘、四向 safe area、触摸和移动窄屏下，断言选择文件、删除文件、查看错误、重试、确认导入、取消意图、任务详情和下载错误明细可达，且拖拽不是唯一入口。上述运行时、辅助技术和真实视口检查未实际执行时，报告必须逐项标为**未验证**，并写明所需浏览器、设备/viewport、输入方式及辅助技术环境。
