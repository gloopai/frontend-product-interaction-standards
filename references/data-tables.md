# 数据表格查询、展示与导航交互规范

适用于只读报表、带单行操作的管理列表和显式启用批量能力的数据表格。本文件是数据表格查询、展示、导航、列、语义与焦点规则的 owner；筛选字段自身的值、校验与错误继续由 [表单规范](forms.md) 负责，自绘 Select / Combobox 的草稿、提交值和弹层由 [Select / Combobox 规范](selects-comboboxes.md) 负责，跨端布局由 [响应式与自适应规范](responsive-adaptive.md) 负责。

本阶段只建立选择和操作能力所依赖的查询与展示基础。选择范围、批量执行终态、响应式等价转换及 route/unmount 生命周期在后续规则中扩展，不能从本文件未定义的细节自行推断。

## 范围、排除项与规则记法

第一版覆盖数据表格结构、能力档位、状态分组、筛选、排序、页码分页、上一页/下一页游标分页、加载与错误状态、列显示/固定/受限宽度、原生 Table / ARIA Grid 选择条件、键盘模型和焦点恢复。

第一版排除行内编辑、树形表格、拖拽行排序、透视表、加载更多、无限滚动、用户拖拽改变列顺序和个人布局持久化。

下表和后续各表中的“规则”列是本阶段硬规则全集。每条规则都具有稳定 ID，并在“验收”列映射到本文件末尾的可执行检查；新增硬规则时要同时新增或扩展对应验收。

| ID | 规则 | 验收 |
| --- | --- | --- |
| `DT-SCOPE-01` | 第一版只提供上列能力；排除项不得以隐藏配置、实验入口或未声明键盘路径混入。 | `A01` |
| `DT-SCOPE-02` | 表格 owner 只接收筛选控件已经提交的业务值；字段内部草稿、校验、Select 查询和 popup 状态仍归对应专项 owner。 | `A05`、`A06` |

## 能力档位

每个表格实例以 `capabilityTier` 显式声明一个档位；权限解析后的 `resolvedTier` 才决定可渲染能力。

| ID | 规则 | 验收 |
| --- | --- | --- |
| `DT-CAP-01` | `capabilityTier` 只能是 `display`、`row-action` 或 `bulk-action`，不得按页面名称、是否出现复选框或后端返回内容临时猜测。 | `A01` |
| `DT-CAP-02` | `display` 只展示、查询与导航；不得渲染选择列、行选择控件、批量入口或空批量工具栏。 | `A01` |
| `DT-CAP-03` | `row-action` 可以提供行跳转、详情或单行操作，但不得因此获得多选、表头全选或批量工具栏。行跳转与行内控件保持独立，不能把含多个控件的整行包装成一个大链接。 | `A01`、`A18` |
| `DT-CAP-04` | 只有 `bulk-action` 可以渲染选择与批量操作的结构；本阶段仅保留对应状态槽，不定义选择范围或执行终态。 | `A01`、`A03` |
| `DT-CAP-05` | 权限变化可以把实例降到更低档位；提交降级时一次性移除所有越权入口、选择列和空工具栏，清理它们持有的交互状态，并把失去目标的焦点按 `DT-FOC-02` 迁移。不得只禁用控件而留下无恢复路径的界面。 | `A02`、`A21` |

## 状态模型与查询提交门禁

表格实例使用稳定 `ownerId`，并维护以下四组正交状态。字段名可以按框架适配，但语义和转换不能合并。

| 状态组 | 最少内容 |
| --- | --- |
| 查询状态 `queryState` | `appliedFilters`、`sortRules`、`pagination`、`pageSize`、查询快照 `querySnapshot`、`snapshotId`、可选 `datasetVersion`、请求代次 `requestGeneration`、`requestPhase`、`queryError`、`stale` |
| 展示状态 `viewState` | `visibleColumnIds`、`pinnedColumnIds`、`columnWidths`、`density`、当前结果行与结果摘要 |
| 交互状态 `interactionState` | `focusIntent`、当前焦点的 `recordId` / `columnId`、展开行、打开的单行操作、已声明但尚未扩展的选择槽 |
| 操作状态 `operationState` | 当前单行或批量意图的阶段、受影响记录标识、错误 owner 与恢复入口；详细执行契约留给后续规则 |

| ID | 规则 | 验收 |
| --- | --- | --- |
| `DT-STATE-01` | 四组状态分别拥有写入者；查询响应不得直接改写草稿筛选，列变化不得隐式改查询，焦点变化不得改业务结果，操作反馈不得伪装成查询错误。 | `A03` |
| `DT-STATE-02` | `requestPhase` 至少区分 `idle`、`initial-loading`、`ready`、`refreshing`、`initial-error` 和 `refresh-error`；不得用单一 `loading` / `error` 同时代表首次加载、刷新和操作状态。 | `A03`、`A13`、`A14` |
| `DT-REQ-01` | 每次准备发出查询时，先把已应用筛选、完整排序（含稳定次序键及空值/区域规则）、分页模式与位置、页大小、权限范围和适用数据集版本冻结为不可变 `querySnapshot`，生成 `snapshotId`，再把 `requestGeneration` 严格加一。发出后任何状态变化不得修改该快照。 | `A04`、`A05` |
| `DT-REQ-02` | 查询响应只有同时满足 `(a)` 当前 owner 仍 live 且 `ownerId` 相同、`(b)` 响应 generation 等于当前 `requestGeneration`、`(c)` 响应 `snapshotId` 等于当前 `snapshotId` 时，才可提交行、总数/游标、错误、`requestPhase` 或 `stale`。任一不匹配都只记录 `response-discarded`。 | `A04` |
| `DT-REQ-03` | 取消旧请求只用于节省资源，不能替代 `DT-REQ-02` 的三重提交门禁；已取消但迟到的响应仍需经过同一判断。 | `A04` |
| `DT-REQ-04` | 应用/移除筛选、提交排序、翻页、改变页大小、显式刷新或失效页恢复都建立新快照并递增代次；单纯编辑筛选草稿、改变焦点、开关行详情或调整列展示不发查询。 | `A05`、`A06`、`A16` |

## 首次加载、刷新、过期、错误与空状态

结果容器是查询状态和查询错误的 primary owner。筛选字段错误仍归字段；单行或批量操作错误不写入 `queryError`。

| ID | 规则 | 验收 |
| --- | --- | --- |
| `DT-DATA-01` | 仅在首次加载且没有可用结果时显示与最终表格结构相符的骨架或占位；结果容器设置 `aria-busy="true"`，不得渲染可操作的假数据。 | `A13` |
| `DT-DATA-02` | 刷新时保留上次成功的行、列、分页上下文和焦点意图，设置 `requestPhase: refreshing`、`aria-busy="true"` 并阻止同一快照重复刷新；旧行不能伪装成新响应。 | `A13` |
| `DT-DATA-03` | 首次加载失败且没有可用结果时进入 `initial-error`，以结果区域内的文本错误和可聚焦重试入口替代不可用表格；重试创建新代次。 | `A14` |
| `DT-DATA-04` | 刷新失败时保留旧行并进入 `refresh-error`，设置 `stale: true`，显示“数据可能已过期”的结果区域消息和重试入口；不得清空表格、分页或焦点上下文。 | `A14` |
| `DT-DATA-05` | 已应用筛选产生零结果时显示“当前条件无匹配”并提供调整或清除筛选入口；数据源本身为空时显示与能力档位相符的独立空数据集状态。两者不得共用含糊的“暂无数据”。 | `A15` |
| `DT-DATA-06` | 查询开始、结果数量/位置变化、失效页恢复和查询失败由结果 owner 各发一次简短状态公告；同一完整错误消息不得同时由筛选字段、结果摘要和全局 live region 重复播报。 | `A14`、`A15` |

## 焦点意图与恢复

`focusIntent` 至少记录 `{sourceEvent, recordId?, columnId?, controlId?, fallbackId}`。记录和列都使用数据层稳定标识，不能用当前数组索引或第几个 DOM 子节点恢复焦点。

| ID | 规则 | 验收 |
| --- | --- | --- |
| `DT-FOC-01` | 后台刷新或同页结果重取后，原 `recordId + columnId + controlId` 仍存在且可聚焦时保持或仅一次恢复该目标；不得因为行排序位置变化而聚焦相同索引的另一条记录。 | `A20` |
| `DT-FOC-02` | 精确目标消失时，按已记录策略依次选择同记录等价控件、同列最近记录、结果摘要/标题或当前分页控件；最终目标必须存活、可感知且与事件相关，不能落到 `document.body`、文档根节点或已移除元素。 | `A20`、`A21` |
| `DT-FOC-03` | 编辑筛选草稿、应用筛选和提交排序时，发请求本身不抢走仍存活的触发控件焦点；若结果提交移除了焦点目标，才按 `DT-FOC-02` 迁移一次。 | `A21` |
| `DT-FOC-04` | 用户触发翻页时记录分页来源；匹配响应提交后，焦点移动一次到结果摘要/标题，除非产品显式保留了仍存活且语义未变的分页触发器。失效页自动恢复不得产生第二次抢焦点。 | `A10`、`A11`、`A12`、`A21` |

## 可执行验收

每个检查记录 `{ownerId, snapshotId, requestGeneration, event, sourceId, targetId, recordId, columnId, phase, accepted, reason}`。异步检查要能手动控制响应顺序；DOM 检查使用真实可聚焦元素与可访问性树。以下断言是静态文档之外的可执行契约。

### `A01` 能力档位与范围

- **初始状态**：分别创建 `display`、`row-action`、`bulk-action` 三个 live owner，并向配置注入所有第一版排除能力。
- **事件序列**：渲染三个实例；尝试打开行详情、行操作、选择入口、列顺序拖拽、“加载更多”和个人布局保存。
- **预期状态**：三个 `resolvedTier` 与声明一致；`display` 不产生选择/操作状态，`row-action` 只产生单行意图，`bulk-action` 仅出现待后续扩展的选择/操作槽；所有排除能力的事件数为 0。
- **DOM / ARIA**：`display` 没有选择列、选择控件和批量工具栏；`row-action` 没有多选/全选/批量工具栏且整行不是单一大链接；只有 `bulk-action` 有对应结构。不存在加载更多、无限滚动、列顺序拖拽或布局持久化入口。
- **事件日志**：每实例一条 `tier-resolved`；排除能力的 handler、请求和状态写入均为 0。

### `A02` 权限降级

- **初始状态**：`bulk-action` 表格有选择列、可用批量工具栏，焦点位于将失权的控件。
- **事件序列**：提交权限变化，把 `resolvedTier` 依次降为 `row-action`、`display`。
- **预期状态**：每次降级原子移除越权交互状态；焦点按 `DT-FOC-02` 仅迁移一次，保留查询和可读结果。
- **DOM / ARIA**：没有空工具栏、空选择列、仅解释不提供恢复路径的 disabled 控件或指向已移除节点的 ARIA 引用。
- **事件日志**：每次降级各一条 `tier-downgraded` 和最多一条 `focus-migrated`；旧控件后续事件写入为 0。

### `A03` 四组状态与阶段

- **初始状态**：为四组状态安装独立 reducer / store writer 和写入审计。
- **事件序列**：依次发起查询、调整列宽、移动焦点、触发单行意图、让查询失败。
- **预期状态**：每个事件只改所属状态及明确派生值；请求阶段依次出现 `initial-loading` / `ready` 或 `initial-error`，已有结果刷新时出现 `refreshing` / `refresh-error`。
- **DOM / ARIA**：查询错误只在结果 owner；操作区域、筛选字段和列控制不会错误显示同一查询错误。
- **事件日志**：任何跨 owner 未声明写入令检查失败；不得只记录笼统 `loading=true` 或 `error=true`。

### `A04` 快速请求竞态

- **初始状态**：live owner 为 `O1`，当前结果 `R0`、generation 0。
- **事件序列**：连续提交筛选 `S1`、排序 `S2`、翻页 `S3`，得到 generation 1/2/3 和三个不可变快照；按 `S2 → S1 → S3` 返回，再交付一个 ownerId 为 `O0` 的迟到响应；另重复一次已取消的 `S1` 响应。
- **预期状态**：只有 generation 3、snapshot `S3`、owner `O1` 的响应更新行、分页、错误和阶段；所有快照内容在发出后保持字节/语义不变。
- **DOM / ARIA**：最终只显示 `S3` 行与摘要，`aria-busy` 随 `S3` 终态解除；旧错误或结果不闪回。
- **事件日志**：三次请求各一条 `request-started`；`S3` 一条 `response-accepted`，其余逐条 `response-discarded` 并记录 generation / snapshot / owner 不匹配原因；取消不改变结论。

### `A05` 查询事件矩阵

- **初始状态**：记录当前快照、generation、页码 4（另跑一次游标中段）、筛选草稿和已应用条件。
- **事件序列**：编辑草稿、改变焦点、开关详情、调整列；再依次应用筛选、提交排序、翻页、改变页大小、显式刷新和触发失效页恢复。
- **预期状态**：前四项 generation 与请求数不变；后六类事件各建立不可变快照并使 generation 恰好加一。筛选/排序/页大小按规则回到起点，普通翻页使用目标位置。
- **DOM / ARIA**：草稿编辑不改变结果摘要；提交事件后摘要标识新条件正在加载，不能把旧行标成已匹配新条件。
- **事件日志**：非查询事件 `request-started=0`；每个查询事件 `snapshot-created=1`、`request-started=1`。

### `A06` 筛选草稿、应用、重置与 URL

- **初始状态**：`defaultFilters={status: active}`，一个 `immediate` 的已提交状态值、一个 `explicit` 的多字段草稿，并含 `urlSafe`、`sensitive` 与自由文本敏感值。
- **事件序列**：只编辑复合控件内部 query / active option；提交 immediate 值；编辑 explicit 草稿后点击应用；点击重置两次；序列化 URL。
- **预期状态**：内部草稿不改表格 `filterDraft` / `appliedFilters` 或请求；immediate 仅在字段提交值后应用；explicit 仅点击应用后生效；第一次重置恢复 `defaultFilters` 并请求，第二次语义相同不请求。
- **DOM / ARIA**：结果摘要只显示已应用条件；URL 只含 `urlSafe` 值，路径、查询串、片段、标题和分析事件中均无敏感值。
- **事件日志**：合法值每次应用恰好一个快照/请求；未提交 query、无变化重置和非法字段值请求数为 0。

### `A07` 已应用条件可见与移除

- **初始状态**：有三个已应用条件，其中一个筛选控件折叠。
- **事件序列**：聚焦条件摘要，分别移除可见条件和折叠条件。
- **预期状态**：每次移除更新 `appliedFilters`，回到分页起点并请求；其他条件保留。
- **DOM / ARIA**：三个条件均有可访问名称和独立移除按钮；折叠条件仍在摘要中可发现；移除后不残留陈旧描述关系。
- **事件日志**：每次 `filter-removed`、`snapshot-created`、`request-started` 各 1。

### `A08` 稳定排序与跨页完整性

- **初始状态**：数据含相同业务排序值、null、不同大小写和区域字符；保存完整记录 ID 集合。
- **事件序列**：按声明的空值/大小写/区域规则和稳定次序键取完所有页；重复查询；再提交另一排序。
- **预期状态**：相同主值始终按稳定次序键排列；重复查询顺序相同；新排序回到第一个有效位置。
- **DOM / ARIA**：结果摘要和排序状态与实际顺序一致。
- **事件日志**：每个快照记录完整排序；跨页 ID 并集等于基线集合，交集无重复，遗漏数和重复数均为 0。

### `A09` 单列/多列排序语义

- **初始状态**：一列不可排序、两列可排序；分别以 `single`、`multiple` 渲染。
- **事件序列**：键盘激活各表头排序按钮，循环方向并在多列模式改变优先级。
- **预期状态**：single 新列替换旧业务排序；multiple 保留明确优先级；不可排序列不触发事件。
- **DOM / ARIA**：按钮有“按 X 升序/降序”等名称；不可排序列无按钮和 `aria-sort`；原生表格只有主排序列设置正确 `aria-sort`，多列其余优先级由可访问文本说明。
- **事件日志**：每次有效提交一个 `sort-committed` 和一个请求；不可排序列请求数为 0。

### `A10` 页码分页边界

- **初始状态**：可靠总数 95、pageSize 10；分别位于第 1、5、10 页。
- **事件序列**：键盘激活上一页、下一页、直接页码和越界页码；控制响应返回。
- **预期状态**：合法目标建立新快照；首页上一页、末页下一页和越界目标不请求；匹配响应后按 `DT-FOC-04` 聚焦。
- **DOM / ARIA**：显示当前页、10 总页和结果范围；边界按钮为原生 disabled；当前页以 `aria-current="page"` 或等价语义标识。
- **事件日志**：每个合法目标一个 `page-change` / 请求 / 结果焦点事件；边界和越界请求为 0。

### `A11` 游标分页边界

- **初始状态**：分别构造仅 next、prev+next、仅 prev、无游标四种响应。
- **事件序列**：激活上一页/下一页并返回对应游标结果；尝试随机跳页、加载更多和滚到底自动请求。
- **预期状态**：只使用服务端提供的方向游标；缺失方向不请求；不存在总页数或随机位置状态。
- **DOM / ARIA**：只有上一页/下一页，缺失方向原生 disabled；没有虚构页码、加载更多或无限滚动哨兵。
- **事件日志**：每次允许导航一个请求并记录使用的游标；随机跳页、加载更多、滚动触发请求均为 0。

### `A12` 页大小与失效页恢复

- **初始状态**：页码位于第 6 页，另建游标中段；配置允许页大小 10/25/50。
- **事件序列**：选择 25；提交非法 30；删除导致页码末页变 4；让游标服务端返回当前位置失效及最近有效位置；重复送达失效响应。
- **预期状态**：25 回到起点并请求，30 保持旧值且不请求；页码只恢复到第 4 页一次，游标只回退一次；重复响应不再循环。
- **DOM / ARIA**：页大小控件有名称和当前值；恢复后可见新位置并仅一次播报；焦点按来源策略只移动一次。
- **事件日志**：每次有效页大小变化一个请求；每次失效场景 `invalid-page-detected=1`、`page-recovery-requested=1`、`page-recovered=1`。

### `A13` 首次加载与刷新

- **初始状态**：场景一无结果；场景二有上次成功行、分页和焦点意图。
- **事件序列**：开始首次加载；成功后开始刷新并重复触发同一刷新；提交新结果。
- **预期状态**：首次为 `initial-loading`；刷新为 `refreshing` 且旧上下文保留；重复刷新不新增请求；匹配成功后为 `ready`、`stale: false`。
- **DOM / ARIA**：首次仅有不可操作骨架且结果容器 `aria-busy=true`；刷新仍显示旧行并 busy；提交后替换为新行且 busy=false。
- **事件日志**：每个意图最多一个请求；骨架中的链接、按钮和选择控件数为 0。

### `A14` 初次失败与刷新失败

- **初始状态**：分别从无结果首次加载和有 `R0` 的刷新开始。
- **事件序列**：返回失败；聚焦并激活重试；让重试成功。
- **预期状态**：首次失败为 `initial-error` 且无假表格；刷新失败为 `refresh-error`、`stale: true` 并保留 `R0`、分页和焦点意图；重试使用新代次。
- **DOM / ARIA**：错误和重试位于结果 owner；刷新错误明确说明可能过期；同一完整错误只出现/公告一次。
- **事件日志**：每次失败一个 `query-failed`、一个终态公告；每次重试一个新快照/代次/请求，旧响应不能清错。

### `A15` 筛选零结果、空数据集与错误 owner

- **初始状态**：同一实例分别返回 `(total=0, appliedFilters 非默认)` 与 `(total=0, 无有效筛选)`；另注入字段错误、查询错误和操作错误。
- **事件序列**：提交结果并激活各恢复入口。
- **预期状态**：前者进入筛选零结果并可调整/清除条件，后者进入独立空数据集状态；三类错误只写各自 owner。
- **DOM / ARIA**：零结果文案提及当前条件，空数据集文案匹配能力档位；完整错误不在字段、结果和操作区重复。
- **事件日志**：每个状态一次公告；错误审计中每个 `errorId` 只有一个 `primaryOwnerId` 和一条完整公告。

### `A16` 列显示与依赖迁移

- **初始状态**：稳定列 ID 包含关键列、普通列、当前排序列、焦点列和已打开操作列。
- **事件序列**：尝试隐藏关键列；依次隐藏普通列、排序列、焦点列和操作列；再显示；调整密度。
- **预期状态**：关键列被拒绝并说明原因；普通列直接隐藏；其余列只有在排序取消/迁移、焦点迁移、操作关闭/迁移成功后隐藏。所有展示变化不改快照/generation。
- **DOM / ARIA**：隐藏列的 header/cell/ARIA 引用和 Grid 导航目标一致消失；恢复后 header 关联有效，无陈旧 DOM ID；关键列控制为可感知 disabled。
- **事件日志**：每次依赖按 `dependency-migrated → column-hidden` 排序；无法迁移时只有 `column-hide-rejected`；查询请求数为 0。

### `A17` 固定列与键盘宽度

- **初始状态**：窄容器含多列固定列、长内容与一个 `min=120,max=360,step=20` 的可调列。
- **事件序列**：横向滚动并聚焦边界单元格、打开菜单/错误；制造遮挡；对调整柄使用左右键、Home、End，并用指针越界拖动。
- **预期状态**：遮挡时解除最低优先级固定状态但列仍可见；宽度始终截停在 120–360，Home=120、End=360；不创建查询。
- **DOM / ARIA**：焦点环、菜单、错误和滚动边界不被固定列覆盖；调整柄可聚焦且暴露列名、当前值、最小/最大值。
- **事件日志**：每次实际宽度变化一个 `column-width-changed`；自动解固定一个 `column-unpinned-for-visibility`；请求数为 0。

### `A18` 原生 Table 语义与键盘

- **初始状态**：分别渲染只读表格和含链接、按钮、行菜单触发器的 `row-action` 表格。
- **事件序列**：用可访问性树检查名称/header 关联；从表格前一路 Tab 到表格后；按方向键、Home/End/Page Up/Page Down。
- **预期状态**：焦点只进入真实控件并保持视觉/DOM 顺序；表格不拦截导航键；行菜单和行跳转各自触发，不互相触发。
- **DOM / ARIA**：根为 `<table>`，有名称/说明，`th` scope 或等价关联正确；静态 cell 无 `tabindex=0`；整行不是包含多个控件的大链接。
- **事件日志**：静态单元格 focus 数为 0；方向/分页键的表格自定义 handler 数为 0；每个控件激活只触发自己的动作一次。

### `A19` ARIA Grid 语义与键盘

- **初始状态**：以明确二维导航需求渲染 20×8 Grid，其中部分单元格含文本输入和按钮；另渲染一个无二维需求却请求 Grid 的配置。
- **事件序列**：Tab 进入；逐项执行四方向、Home/End、Ctrl/Command+Home/End、Page Up/Down；Enter/F2 进入控件，编辑后 Escape；Tab/Shift+Tab 离开。
- **预期状态**：所有键得到规则定义的唯一目标并在边界截停；交互模式保留控件原生编辑语义；无二维需求的配置回退原生 Table。
- **DOM / ARIA**：Grid 有名称及正确 row/column/gridcell 语义；任一时刻只有一个活动单元格/单一 Tab 入口，active 引用只指向已渲染节点。
- **事件日志**：每键最多一个 `grid-active-cell-changed`；进入/退出交互模式各一次；静态单元格不进入逐个 Tab 顺序。

### `A20` 稳定标识焦点恢复

- **初始状态**：焦点位于 `{recordId:R7,columnId:status,controlId:details}`，记录其数组索引。
- **事件序列**：刷新后把 R7 移到另一索引但保留目标；再刷新并移除精确控件；再移除 R7。
- **预期状态**：第一次保持/恢复 R7 的同一逻辑控件；第二次移到 R7 的等价控件；第三次按策略移到 status 列最近记录或结果摘要，均只一次。
- **DOM / ARIA**：每次目标均存活、可聚焦并具有名称；焦点从不落到旧索引的其他记录、body、文档根或已移除节点。
- **事件日志**：每轮最多一条 `focus-restored` / `focus-migrated`，记录稳定 ID 和选择该 fallback 的原因。

### `A21` 事件来源与目标消失

- **初始状态**：分别把焦点放在筛选应用按钮、排序按钮、分页按钮、将隐藏列控件和将因权限降级移除的控件。
- **事件序列**：提交对应事件并控制结果到达；令一半场景保留原节点、一半移除目标；为分页触发失效页自动恢复。
- **预期状态**：筛选/排序发请求不抢仍存活焦点；目标消失才迁移一次。翻页匹配响应后按声明策略聚焦摘要/标题或保留语义未变的触发器；自动恢复不再二次聚焦。列隐藏与权限降级先迁移再移除。
- **DOM / ARIA**：最终 activeElement 是事件相关、存活且有名称的目标；无指向已移除列/控件的 ARIA 引用。
- **事件日志**：每个用户意图最多一次最终 `focus`；旧响应、失效页恢复和依赖清理均不得增加计数。

### `A22` 验收覆盖与运行时报告

- **初始状态**：收集本文件全部 `DT-*` 规则 ID 和 `A01` 至 `A21` 的执行清单。
- **事件序列**：静态检查每个规则 ID 至少被一个验收引用；运行已具备环境的检查，并把未运行项标记状态。
- **预期状态**：不存在无验收映射的硬规则；浏览器、屏幕阅读器、键盘、真实数据竞态或组件运行时未实际执行的项目保持 `未验证`。
- **DOM / ARIA**：只有真实运行并保存断言结果的场景可标记通过；静态 `rg` 或 Markdown 审查不能替代交互/辅助技术结果。
- **事件日志**：报告为每项保存命令/环境、时间、结果和证据位置；不得把 `not-run` 计为 pass。
