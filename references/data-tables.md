# 数据表格交互规范

适用于只读报表、带单行操作的管理列表和显式启用批量能力的数据表格。本文件是数据表格查询、展示、导航、选择、批量操作、响应式等价、无障碍与生命周期规则的 owner；筛选字段自身的值、校验与错误继续由 [表单规范](forms.md) 负责，自绘 Select / Combobox 的草稿、提交值和弹层由 [Select / Combobox 规范](selects-comboboxes.md) 负责，跨端布局同时执行 [响应式与自适应规范](responsive-adaptive.md)。

本文件完整定义第一版的数据表格生命周期。未在能力档位、查询快照、选择快照、操作快照、响应式转换或 disposal 规则中声明的行为，不能由页面名称、组件默认值或迟到回调自行推断。

## 范围、排除项与规则记法

第一版覆盖数据表格结构、能力档位、状态分组、筛选、排序、页码分页、上一页/下一页游标分页、加载与错误状态、列显示/固定/受限宽度、当前页与全部筛选结果选择、批量终态和恢复、原生 Table / ARIA Grid 选择条件、键盘模型、焦点恢复、响应式等价、无障碍与 disposal。

第一版排除行内编辑、树形表格、拖拽行排序、透视表、加载更多、无限滚动、用户拖拽改变列顺序和个人布局持久化。

下表和后续各表中的“规则”列是本文件硬规则全集。每条规则都具有稳定 ID，并在“验收”列映射到本文件末尾的可执行检查；新增硬规则时要同时新增或扩展对应验收。

| ID | 规则 | 验收 |
| --- | --- | --- |
| `DT-SCOPE-01` | 第一版只提供上列能力；排除项不得以隐藏配置、实验入口或未声明键盘路径混入。 | `A01` |
| `DT-SCOPE-02` | 表格 owner 只接收筛选控件已经提交的业务值；字段内部草稿、校验、Select 查询和 popup 状态仍归对应专项 owner。 | `A05`、`A06` |

## 能力档位

每个表格实例以 `capabilityTier` 显式声明一个档位；权限解析后的 `resolvedTier` 才决定可渲染能力。

| ID | 规则 | 验收 |
| --- | --- | --- |
| `DT-CAP-01` | `capabilityTier` 只能是 `display`、`row-action` 或 `bulk-action`，不得按页面名称、是否出现复选框或后端返回内容临时猜测。 | `A01` |
| `DT-CAP-02` | `display` 只展示、查询与导航；不得渲染选择列、行选择控件、批量入口或空批量工具栏。 | `A01` |
| `DT-CAP-03` | `row-action` 可以提供行跳转、详情或单行操作，但不得因此获得多选、表头全选或批量工具栏。行跳转与行内控件保持独立，不能把含多个控件的整行包装成一个大链接。 | `A01`、`A18` |
| `DT-CAP-04` | 只有 `bulk-action` 可以渲染选择与批量操作的结构；能力档位解析只建立对应状态槽，选择范围与执行终态必须由 `DT-SEL-*` 和 `DT-OP-*` 规则显式定义，不得从档位名称自行推断。 | `A01`、`A03`、`A23`、`A26` |
| `DT-CAP-05` | 权限变化可以把实例降到更低档位；提交降级时一次性移除所有越权入口、选择列和空工具栏，清理它们持有的交互状态，并把失去目标的焦点按 `DT-FOC-02` 迁移。不得只禁用控件而留下无恢复路径的界面。 | `A02`、`A21` |

## 状态模型与查询提交门禁

表格实例使用稳定 `ownerId`，并维护以下四组正交状态。字段名可以按框架适配，但语义和转换不能合并。

| 状态组 | 最少内容 |
| --- | --- |
| 查询状态 `queryState` | `appliedFilters`、`sortRules`、`pagination`、`pageSize`、查询快照 `querySnapshot`、`snapshotId`、可选 `datasetVersion`、请求代次 `requestGeneration`、`requestPhase`、`queryError`、`stale` |
| 展示状态 `viewState` | `visibleColumnIds`、`pinnedColumnIds`、`columnWidths`、`density`、当前结果行与结果摘要 |
| 交互状态 `interactionState` | `focusIntent`、当前焦点的 `recordId` / `columnId`、展开行、打开的单行操作、选择模式、选择代次、稳定记录 ID、全部筛选结果范围、排除项与显示数量 |
| 操作状态 `operationState` | 当前单行或批量意图的阶段、不可变操作快照、操作代次、幂等键、成功项、失败项、冲突、错误 owner、恢复入口与结果焦点意图 |

| ID | 规则 | 验收 |
| --- | --- | --- |
| `DT-STATE-01` | 四组状态分别拥有写入者；查询响应不得直接改写草稿筛选，列变化不得隐式改查询，焦点变化不得改业务结果，操作反馈不得伪装成查询错误。 | `A03` |
| `DT-STATE-02` | `requestPhase` 至少区分 `idle`、`initial-loading`、`ready`、`refreshing`、`initial-error` 和 `refresh-error`；不得用单一 `loading` / `error` 同时代表首次加载、刷新和操作状态。 | `A03`、`A13`、`A14` |
| `DT-REQ-01` | 每次准备发出查询时，先把已应用筛选、完整排序（含稳定次序键及空值/区域规则）、分页模式与位置、页大小、权限范围和适用数据集版本冻结为不可变 `querySnapshot`，生成 `snapshotId`，再把 `requestGeneration` 严格加一。发出后任何状态变化不得修改该快照。 | `A04`、`A05` |
| `DT-REQ-02` | 查询响应只有同时满足 `(a)` 当前 owner 仍 live 且 `ownerId` 相同、`(b)` 响应 generation 等于当前 `requestGeneration`、`(c)` 响应 `snapshotId` 等于当前 `snapshotId` 时，才可提交行、总数/游标、错误、`requestPhase` 或 `stale`。任一不匹配都只记录 `response-discarded`。 | `A04` |
| `DT-REQ-03` | 取消旧请求只用于节省资源，不能替代 `DT-REQ-02` 的三重提交门禁；已取消但迟到的响应仍需经过同一判断。 | `A04` |
| `DT-REQ-04` | 应用/移除筛选、提交排序、翻页、改变页大小、被接受的显式刷新或失效页恢复都建立新快照并递增代次；单纯编辑筛选草稿、改变焦点、开关行详情或调整列展示不发查询。 | `A05`、`A06`、`A16` |
| `DT-REQ-05` | 显式刷新先根据已应用筛选、排序、分页、页大小、权限范围、适用数据版本和刷新原因形成查询意图键；同一 in-flight 查询意图在创建快照前合并到当前工作，不新增 `snapshotId`、`requestGeneration`、请求或开始公告。只有当前同键意图终结，或 `intentKey` 变化（即使旧键意图仍 in-flight）时，下一次刷新才可被接受；被接受后必须建立新快照、递增代次、发出新请求和一次开始公告，不得因存在任意 in-flight 请求而全局合并。 | `A05`、`A13` |

## 筛选

| ID | 规则 | 验收 |
| --- | --- | --- |
| `DT-FIL-01` | `filterDraft` 与 `appliedFilters` 分离；草稿只接收字段 owner 已提交、但尚未应用到查询的业务值，不接收 Select 查询、active option 等控件内部状态。结果标题、数量、请求参数和 URL 只反映 `appliedFilters`。 | `A06` |
| `DT-FIL-02` | 每个筛选器在产品配置中声明 `applyMode: immediate | explicit`。低成本简单筛选可在已提交值变化后即时应用；复杂或多字段筛选使用明确“应用”操作。两种模式都只能在字段 owner 提交合法业务值后创建查询。 | `A06` |
| `DT-FIL-03` | “重置”恢复产品声明的 `defaultFilters`，而不是含糊地清空所有值；只有重置后的条件与当前 `appliedFilters` 语义不同时才发新查询。 | `A06` |
| `DT-FIL-04` | 所有已应用条件持续可见、具可访问名称并可单独移除；移除也是一次应用事件。隐藏在折叠区域的条件仍要在摘要中可发现。 | `A07` |
| `DT-FIL-05` | 只有明确标记 `urlSafe` 的已应用条件可序列化到 URL；账号、令牌、个人识别、自由文本中的敏感值和产品标记 `sensitive` 的条件不得进入路径、查询串、片段、标题或分析日志。 | `A06` |
| `DT-FIL-06` | 应用、移除或有效重置筛选时，页码分页回到第 1 页，游标分页回到初始游标，然后创建新查询快照；界面同时更新可见条件摘要，不能在旧结果上静默显示新条件已生效。 | `A05`、`A07` |

## 排序

| ID | 规则 | 验收 |
| --- | --- | --- |
| `DT-SORT-01` | 表格配置声明可排序列、默认排序、当前方向以及 `single` 或 `multiple` 模式；多列模式同时显示并播报优先级，单列模式提交新列时替换旧业务排序。 | `A08`、`A09` |
| `DT-SORT-02` | 不可排序列不渲染排序按钮，也不设置 `aria-sort`。可排序表头使用有可访问名称的真实按钮；原生表格只在当前主排序表头设置正确 `aria-sort`，其他表头不伪造状态。 | `A09` |
| `DT-SORT-03` | 所有分页查询使用稳定排序：业务排序键之后追加不重复且不可变的稳定次序键。产品/后端同时声明空值位置、大小写及区域/自然排序规则，并把它们冻结进快照；不得依赖当前数据库偶然顺序。 | `A08` |
| `DT-SORT-04` | 提交不同排序时，页码分页回到第 1 页、游标分页回到初始游标，再创建新快照；只有全部页面绑定同一不可变 `datasetVersion` 或等价服务端快照时，才可断言稳定排序后的跨页记录无重复或遗漏。 | `A05`、`A08` |
| `DT-SORT-05` | 页间响应的数据版本与首个已接受页面不一致时，当前分页链立即失效并标为 `stale`，停止拼接或继续导航，回到第一个有效位置重新开始。服务端不提供一致性版本/快照能力时，界面不得承诺跨页零重复遗漏；检测到页间数据变化后采用同一失效与重启路径。 | `A08` |

## 分页

| ID | 规则 | 验收 |
| --- | --- | --- |
| `DT-PAG-01` | 每个实例显式选择 `numbered` 页码分页或 `cursor` 游标分页；同一查询快照内不得混用两种位置语义。 | `A10`、`A11` |
| `DT-PAG-02` | 页码分页只在总数可靠时提供直接页码和跳转；可见当前页、总页数与结果范围，首页/末页边界控件使用原生 `disabled`。请求页超过服务端最新末页时执行 `DT-PAG-05`。 | `A10` |
| `DT-PAG-03` | 游标分页只提供接口支持的“上一页”和“下一页”，保存每个方向所需游标；没有对应游标时原生禁用该方向。不得虚构总页数、随机跳页、加载更多或无限滚动。 | `A11` |
| `DT-PAG-04` | 改变 `pageSize` 后回到第一个有效位置并建立新快照；控件显示当前值和可访问名称，服务端拒绝的值不能成为当前页大小。 | `A12` |
| `DT-PAG-05` | 删除或数据变化使当前页失效时，页码模式请求最近有效页（不小于 1），游标模式回退到服务端返回的最近有效前向位置或初始游标；恢复只执行一次，成功后简短播报新位置，不能在空的无效页循环重试。 | `A12` |

## 首次加载、刷新、过期、错误与空状态

结果容器是查询状态和查询错误的 primary owner。筛选字段错误仍归字段；单行或批量操作错误不写入 `queryError`。

| ID | 规则 | 验收 |
| --- | --- | --- |
| `DT-DATA-01` | 仅在首次加载且没有可用结果时显示与最终表格结构相符的骨架或占位；结果容器设置 `aria-busy="true"`，不得渲染可操作的假数据。 | `A13` |
| `DT-DATA-02` | 刷新时保留上次成功的行、列、分页上下文和焦点意图，并设置 `requestPhase: refreshing`、`aria-busy="true"`；同一 in-flight 查询意图按 `DT-REQ-05` 在创建快照前合并，旧行不能伪装成新响应。 | `A13` |
| `DT-DATA-03` | 首次加载失败且没有可用结果时进入 `initial-error`，以结果区域内的文本错误和可聚焦重试入口替代不可用表格；重试创建新代次。 | `A14` |
| `DT-DATA-04` | 刷新失败时保留旧行并进入 `refresh-error`，设置 `stale: true`，显示“数据可能已过期”的结果区域消息和重试入口；不得清空表格、分页或焦点上下文。 | `A14` |
| `DT-DATA-05` | 已应用筛选产生零结果时显示“当前条件无匹配”并提供调整或清除筛选入口；数据源本身为空时显示与能力档位相符的独立空数据集状态。两者不得共用含糊的“暂无数据”。 | `A15` |
| `DT-DATA-06` | `[a]` 每个被接受的查询开始由结果 owner 公告一次；`[b]` 每个已接受且改变结果数量或位置的响应由结果 owner 公告一次；`[c]` 每次成功的失效页恢复由结果 owner 公告一次；`[d]` 每个已接受的查询失败由结果 owner 公告一次；`[e]` 同一完整错误消息不得同时由筛选字段、结果摘要和全局 live region 重复播报。 | `A12`、`A13`、`A14`、`A15` |

## 当前页与全部筛选结果选择

选择只由 `bulk-action` 表格的交互 owner 写入。`selectionSnapshot` 与请求使用的 `querySnapshot` 分离：前者冻结用户确认的业务范围，后者可以随合法分页建立新快照；两者通过稳定范围键、权限范围和数据版本核对。

| ID | 规则 | 验收 |
| --- | --- | --- |
| `DT-SEL-01` | `[a]` 只有 `resolvedTier=bulk-action` 的 live owner 可以建立选择状态；`[b]` 初始选择模式必须是 `page`；`[c]` `page` 模式只能选择当前页中明确可选记录的稳定 ID；`[d]` 不可选记录不得进入选择或数量，并要在其禁用控件上提供可感知原因。 | `A23` |
| `DT-SEL-02` | `[a]` 表头复选框只表达当前页可选记录，不得表达整个数据集；`[b]` 当前页全部可选记录已选时为选中；`[c]` 仅部分已选时为混合态；`[d]` 有可选记录但无记录被选时为未选；`[e]` 表头和行复选框必须暴露范围、记录身份、当前状态与当前页已选/可选数量；`[f]` 当前页零可选记录时表头必须为 `unchecked`、原生或等价 `disabled`，并以可感知文本说明无可选记录的原因。 | `A23`、`A34` |
| `DT-SEL-03` | `[a]` “全部筛选结果”只能由产品显式启用；`[b]` 用户先完成当前页选择后，界面才可提供独立的二次范围操作；`[c]` 二次操作必须明确显示将选择的全部筛选结果数量与筛选范围；`[d]` 用户确认后建立不可变 `selectionSnapshot`，冻结来源 `querySnapshot`、范围键、已应用筛选、权限范围、数据版本、可选总数，并把 `excludedIds` 作为该快照内部字段初始化为空集合；不得把排除项另存为可独立漂移的 sibling 状态；`[e]` 界面持续显示模式、范围、已选数量与排除数量；`[f]` 单一 `allSelected=true` 或只保存数量不能代表该模式。 | `A24`、`A34` |
| `DT-SEL-04` | `[a]` 全部筛选结果模式中取消某记录时，创建新的不可变后继 `selectionSnapshot`，把其稳定 ID 加入 `selectionSnapshot.excludedIds`；重新选择时同样创建后继快照并只移除该 ID，先前快照保持不变；`[b]` 可见已选数量等于当前 `selectionSnapshot.eligibleTotal` 减去其中仍有效的 `excludedIds` 数量；`[c]` 普通翻页只有在范围键、权限范围和数据版本均未变化时才保留该模式和当前选择快照身份；`[d]` 任一页面的表头复选框仍只按该页可选记录和当前 `selectionSnapshot.excludedIds` 计算三态。 | `A24` |
| `DT-SEL-05` | `[a]` `page` 模式在应用/移除/重置筛选、提交排序、翻页、改变页大小、权限范围变化或数据集版本变化提交时清除；`[b]` 全部筛选结果模式可跨普通翻页保留，但不得跨范围键、权限范围或数据版本变化静默保留；`[c]` 已应用筛选、权限范围或数据集版本变化时，旧全部范围立即失效、阻止操作并清除；`[d]` 仅排序变化时，旧全部范围进入待重新确认态，用户确认新范围和数量并绑定新查询快照前不得操作，取消确认则清除；`[e]` 同范围内记录资格变化时只移除失效 ID、更新数量并由选择 owner 简短公告一次。 | `A25`、`A34` |
| `DT-SEL-06` | `[a]` 每个被接受的选择意图严格递增 `selectionGeneration`，先前快照保持不可变；意图改变全部筛选结果范围、排除项或可选总数时必须创建新的不可变后继 `selectionSnapshot`，不得原地修改当前快照；`[b]` 异步选择协调回调只有 owner live、`ownerId` 与 `selectionGeneration` 同时匹配时才能提交；`[c]` 旧查询、旧操作或迟到协调结果不得覆盖更新选择，只记录 `selection-result-discarded`；`[d]` 操作结果只有捕获的选择代次仍为当前代次时才可调整当前选择，否则只写自己的操作结果 owner。 | `A24`、`A25`、`A26` |

## 批量操作快照、终态与恢复

批量请求冻结用户确认时的选择语义。执行结果属于自己的操作 owner，不借用 `queryError`，也不能通过修改仍在使用的 `selectionSnapshot` 来解释服务端结果。

| ID | 规则 | 验收 |
| --- | --- | --- |
| `DT-OP-01` | `[a]` 只有非空、有效且不处于待重新确认态的选择可以开始批量意图；`[b]` 开始时建立不可变操作快照，冻结 `ownerId`、`operationId`、操作代次、操作类型、选择代次、选择模式、稳定记录 ID 或全部范围快照、排除项、预计数量、权限范围与数据版本；`[c]` 确认、执行或后续界面选择变化不得修改该操作快照；`[d]` 请求必须携带操作快照身份和本次尝试的幂等键。 | `A26` |

## 可执行验收

每个运行时检查记录 `{ownerId, lifecycleToken, snapshotId, requestGeneration, selectionSnapshotId, selectionGeneration, operationCaseId, selectionSnapshotFixtureId, viewportCaseId, presentation, operationSnapshotId, operationId, operationGeneration, expectedCount, adjudicatedCount, successIds, failedIds, adjudicatedIds, announcementOwnerId, event, sourceId, targetId, recordId, columnId, phase, accepted, reason}`；每个应用检查记录 `{applicationCaseId, ruleFamily, applicability, observablePredicate, outputLocation, decisionOwner}`。异步检查要能手动控制查询、选择协调与操作响应顺序；DOM 检查使用真实可聚焦元素与可访问性树。以下断言是静态文档之外的可执行契约。

### `A01` 能力档位与范围

- **初始状态**：分别创建显式声明为 `display`、`row-action`、`bulk-action` 的三个 live owner；同时提供互相冲突的页面名称、无关复选框和后端能力提示，并经普通配置、隐藏配置、实验 flag 和未声明键盘事件四条路径注入所有第一版排除能力。
- **事件序列**：渲染三个实例并尝试各自允许的详情、单行操作和选择入口，改变页面名称、无关复选框和后端提示后再次渲染；随后经四条注入路径逐项尝试进入行内编辑、展开树表层级、拖拽行排序、切换透视表、点击“加载更多”、触发无限滚动哨兵、拖拽改变列顺序和保存个人布局。
- **预期状态**：三个 `resolvedTier` 与声明一致；`display` 不产生选择/操作状态，`row-action` 只产生单行意图，`bulk-action` 建立由 `DT-SEL-*` / `DT-OP-*` 约束的选择与操作槽。行内编辑、树表、行拖拽、透视、加载更多、无限滚动、列顺序拖拽和布局持久化八项能力的状态写入分别为 0。
- **DOM / ARIA**：`display` 没有选择列、选择控件和批量工具栏；`row-action` 没有多选/全选/批量工具栏且整行不是单一大链接；只有 `bulk-action` 有对应结构。结果表格/Grid 子树内的行内编辑 `input`、`textarea`、`contenteditable` 与编辑按钮数均为 0；`treegrid`、行拖拽柄、透视控制、“加载更多”、无限滚动哨兵、列顺序拖拽柄和布局持久化入口分别不存在。
- **事件日志**：每实例只按显式声明记录一条 `tier-resolved`，页面名称、无关复选框和后端提示变化均不改变它；八项排除能力的普通配置、隐藏配置、实验 flag 和未声明键盘路径分别断言 handler 调用数为 0、请求数为 0、状态写入数为 0，其中行内编辑 handler 和编辑状态写入单独计数并均为 0。

### `A02` 权限降级

- **初始状态**：`bulk-action` 表格有选择列、可用批量工具栏，焦点位于将失权的控件。
- **事件序列**：提交权限变化，把 `resolvedTier` 依次降为 `row-action`、`display`。
- **预期状态**：每次降级原子移除越权交互状态；焦点按 `DT-FOC-02` 仅迁移一次，保留查询和可读结果。
- **DOM / ARIA**：没有空工具栏、空选择列、仅解释不提供恢复路径的 disabled 控件或指向已移除节点的 ARIA 引用。
- **事件日志**：每次降级各一条 `tier-downgraded` 和最多一条 `focus-migrated`；旧控件后续事件写入为 0。

### `A03` 四组状态与阶段

- **初始状态**：为四组状态提供可区分的状态写入入口与转换审计；`bulk-action` 仅由能力解析建立空选择/操作槽；实现可以使用任意框架或状态机制，检查不依赖 reducer、store 或特定 API。
- **事件序列**：依次发起查询、调整列宽、移动焦点、触发单行意图、让查询失败；再按 `DT-SEL-*` / `DT-OP-*` 完成一次有效选择和批量意图，并尝试绕过规则直接注入未定义范围与终态。
- **预期状态**：每个事件只改所属状态及明确派生值；请求阶段依次出现 `initial-loading` / `ready` 或 `initial-error`，已有结果刷新时出现 `refreshing` / `refresh-error`；选择范围和批量终态只由显式规则转换建立，能力档位名称本身不生成二者。
- **DOM / ARIA**：查询错误只在结果 owner；操作区域、筛选字段和列控制不会错误显示同一查询错误。
- **事件日志**：任何跨 owner 未声明写入令检查失败；不得只记录笼统 `loading=true` 或 `error=true`；直接注入未定义范围/终态的状态写入、DOM 和公告计数均为 0。

### `A04` 快速请求竞态

- **初始状态**：live owner 为 `O1`，当前结果 `R0`、generation 0。

- **预期状态**：只有 generation 3、snapshot `S3`、owner `O1` 的响应更新行、分页、错误和阶段；所有快照内容在发出后保持字节/语义不变。

- **事件日志**：三次请求各一条 `request-started`；`S3` 一条 `response-accepted`，其余逐条 `response-discarded` 并记录 generation / snapshot / owner 不匹配原因；取消不改变结论。

### `A05` 查询事件矩阵

- **初始状态**：记录当前快照、generation、页码 4（另跑一次游标中段）、筛选草稿和已应用条件；权限范围为 `P1`，显式刷新前记下 `intentKey=K1`。
- **事件序列**：编辑草稿、改变焦点、开关详情、调整列；再依次应用筛选、提交排序、翻页、改变页大小；双击显式刷新并在 `K1` 仍 in-flight 时再用键盘触发同一刷新；保持 `K1` 在途，把权限范围从 `P1` 更新为 `P2`，得到 `intentKey=K2` 并立即再次触发显式刷新。让 `K1` 返回 `rows=[R-P1]`、`summary="S-P1"`，让 `K2` 返回可区分的 `rows=[R-P2]`、`summary="S-P2"`，依次交付 `K1` 迟到响应和 `K2` 响应；触发失效页恢复；待 `K2` 终结后再次显式刷新。
- **预期状态**：前四项 generation 与请求数不变；应用筛选、排序、翻页、页大小、第一次 `K1` 刷新、在途期间的 `K2` 刷新、失效页恢复和 `K2` 终结后的刷新各建立一个不可变快照并使 generation 恰好加一。in-flight 的第二次同键 `K1` 刷新在创建快照前合并，`snapshotId`、generation、请求和开始公告均保持第一次刷新后的值；`K2 != K1` 时即使 `K1` 仍 in-flight 也接受 `K2`，不得被全局合并。新建的 `K2 querySnapshot.permissionScope` 等于 `P2`，`K2` 实际请求参数中的 `permissionScope` 也等于 `P2`，二者均不沿用 `P1`。`K1` 迟到响应因门禁不匹配丢弃，只有 `K2` 可提交。筛选/排序/页大小按规则回到起点，普通翻页使用目标位置。
- **DOM / ARIA**：草稿编辑不改变结果摘要；提交事件后摘要标识新条件正在加载，不能把旧行标成已匹配新条件。两个响应交付后，最终结果 DOM 只包含 `R-P2` 且不包含 `R-P1`，最终可见摘要为 `S-P2` 且不是 `S-P1`，证明可见结果只来自 `K2`。
- **事件日志**：非查询事件 `request-started=0`；每个被接受的查询意图 `snapshot-created=1`、`request-started=1`。第二次同键 `K1` 刷新只记录 `query-intent-merged=1`，并断言 `snapshot-created=0`、generation 增量 0、`request-started=0`、开始公告 0。旧刷新仍 in-flight 时，`K2` 触发区间精确断言 `snapshot-created=1`、generation 增量 `+1`、`request-started=1`、由结果 owner 发出的 `query-start-announcement=1`，且 `query-intent-merged=0`；`K2` 的 `snapshot-created` 与 `request-started` 日志分别保存 `permissionScope=P2`。`K1` 迟到响应记录 `response-discarded=1` 且行/摘要提交计数为 0，`K2` 记录 `response-accepted=1` 且行/摘要提交各 1。

### `A08` 稳定排序与跨页完整性

- **预期状态**：相同 generation 在各自 `ownerId + lifecycleToken` 命名空间内合法，不要求跨实例唯一；交叉响应被丢弃且只有 O2 全匹配结果提交；O1 事件不改 O2；无策略不恢复，校验失败拒绝，校验通过只恢复查询/滚动并建立全新 owner/token，首个请求代次可与旧值相等但只在新命名空间内判定；旧选择、排除、权限、菜单和操作快照不回放。
- **DOM / ARIA**：O1 disposal 不移除 O2 DOM/popup/ARIA；焦点不因同名控件落到 O2；恢复实例的名称和引用只指向新节点。
- **事件日志**：仅 `ownerId`、`lifecycleToken`、`announcementOwnerId` 两两不等，三类 generation 标量及恢复实例首个请求代次数值相等；交叉响应 discarded=1 且 O1→O2 状态写入=0；O2 六项门禁 accepted=1；恢复前权限/版本/位置校验有记录，旧交互/操作恢复=0。

### `A37` 具体场景应用完整性

- **初始状态**：在不附带覆盖提示、诊断结论或期望答案的条件下，分别以真实用户需求启动三个全新隔离会话：只读报表、单行操作列表、批量操作表格；每个会话只获得本 owner、skill 入口和对应场景需求，不继承其他会话上下文。
- **事件序列**：保存每次派发的实际参数、工具返回的 canonical task identity 和原始完成 payload；对三份答复逐项解析能力声明与应用检查清单，把每个适用规则族映射到正文位置；核对每个“不适用”的可观察谓词；解析批量场景的状态结构与转换；以 UTF-8 保存 raw payload，并按审计报告声明的换行归一化和边界提取协议重算 SHA-256。
- **预期状态**：三份答复都声明 `capabilityTier`、`resolvedTier`、唯一分页模式和可选能力开关；每个 owner 规则族恰有“适用”或“不适用”结论，适用族正文位置非空且没有被提示词未点名而省略，不适用只用于确实未启用的可选能力并有可观察依据；共同规则族全为适用。批量答复把 `excludedIds` 冻结在 `selectionSnapshot` 内部、初始为空，并以不可变后继快照表达增加/移除排除项；sibling `excludedIds`、原地修改或翻页重建快照均令检查失败。局部枚举/策略只作为产品配置或实现细节且不与 owner 行为冲突；没有封闭枚举本身不构成失败。
- **DOM / ARIA**：三份答复对其适用能力明确给出语义、键盘、焦点、响应式可达性、ARIA/公告、disposal 与实例隔离约束；只有场景确无对应可选能力且 DOM、状态和事件入口均不存在时才允许不适用。
- **事件日志**：审计记录实际 spawn 参数、返回的 canonical identity、原始 completion envelope/payload 证据和可重复 SHA-256 命令，不虚构 opaque ID 或时间；三份答复每个适用维度均为 pass，不适用维度均有谓词，适用未映射数为 0。浏览器、辅助技术、键盘、触摸、真实竞态或组件运行时未执行时仍为“未验证”，不得计入 pass。

### `A38` 查询相邻规则族不得合并省略

- **初始状态**：复用 `A37` 的三份 fresh 答复；为查询、筛选、排序、分页和数据状态分别建立独立 `ruleFamily` 审计记录，并为筛选七项、排序四项和分页六项建立逐项定位清单。
- **事件序列**：先核对应用清单是否把五族逐行判定，再按正文位置逐项定位：筛选的 draft/applied、apply mode、default reset、分页复位、摘要/移除、URL 安全、字段错误 owner；排序的固定/交互能力、当前实际业务键/方向、空值、大小写、locale/自然排序、唯一稳定键、查询转换/回起点、DOM/ARIA/键盘/焦点；numbered 分页的可靠总数、当前/总页/范围、直接页码、校验跳页、原生边界禁用、页大小、回第 1 页、失效页单次恢复，或 cursor 分页的不透明双向游标、受支持方向、缺失方向禁用、四类禁止入口、回初始游标、失效游标单次恢复，另定位 DOM/键盘与单次焦点。对不适用项反查对应 DOM、状态、handler 与请求入口均为零。
- **预期状态**：三个场景的五族独立记录均存在；display 与 bulk 的筛选适用项、三个场景的当前实际稳定比较值以及各自分页全部可定位，row 的筛选不适用具有四类零入口证据；没有用“查询规则已覆盖”“后续配置”或一个模式的分页内容替代相邻族/另一模式义务。局部实现枚举只按行为冲突判定。
- **DOM / ARIA**：交互筛选、排序和分页分别具有自身的名称、状态、键盘和焦点约束；固定排序无伪交互按钮；不适用能力不遗留空控制器或隐藏 handler。
- **事件日志**：每个子项记录 `outputLocation`；适用未定位数必须为 0，不适用但存在入口数必须为 0；任一非零都使对应场景失败，不能由其他规则族通过抵消。
