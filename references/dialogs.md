# Dialog 交互规范

适用于所有 Dialog、Modal、对话框及具有相同行为的弹出层。本文件是 Dialog 完整规则、验收标准与参考资料的唯一事实来源。

## 遮罩与滚动

1. 点击遮罩层不得改变 Dialog 的打开状态。不得添加通过遮罩点击关闭的事件；使用第三方组件时，必须关闭其“点击遮罩关闭”选项。Dialog 只能通过明确的弹窗内操作关闭，例如关闭、取消、确认或业务操作。
2. Dialog 外框必须保持不可滚动。内容超过视口可用高度时，应限制 Dialog 高度并仅让内容区域纵向滚动；标题、底部和操作区域保留在固定外框内。
3. 遮罩层必须覆盖整个浏览器视口，包括 Dialog 父布局容器以外的区域。必要时将其挂载或传送到应用根节点，并采用相对于视口的固定定位与正确层级。遮罩不得被页面区块、面板、带变换的祖先元素或其他局部容器裁切或限制。

## 动画

4. 打开时，遮罩淡入，Dialog 淡入并从 `scale(0.96)` 过渡到 `scale(1)`，时长为 `200ms ease-out`。
5. 关闭时按相反方向播放 `150ms ease-in`；动画完成后才能卸载 DOM。
6. 动画期间必须屏蔽重复打开或关闭。关闭结束前保持遮罩、焦点约束和滚动锁定；点击遮罩始终不能触发关闭或关闭动画。
7. 在 `prefers-reduced-motion: reduce` 下禁用缩放，淡入淡出不超过 `50ms`，或直接切换。

## 焦点与键盘

8. 打开后将焦点移到 Dialog 内最合理的元素：普通表单聚焦首个合理操作元素；长内容聚焦标题或顶部静态元素；不可逆危险操作优先聚焦破坏性最低的操作。
9. `Tab` 和 `Shift + Tab` 的焦点循环必须限制在当前活动 Dialog 内。
10. 关闭动画完成后，焦点返回触发元素；触发元素不存在时，移到后续流程中合理的元素。
11. 默认支持 `Escape` 关闭最上层 Dialog，一次只关闭一层。正在提交、流程不可中断或存在未保存内容时，可以禁用 Escape 或先显示二次确认。

## 语义与背景隔离

12. Dialog 打开时，背景内容必须对鼠标、触摸、键盘和辅助技术均不可交互，使用原生模态能力或 `inert` 等等价机制。
13. 使用原生 `<dialog>`，或使用 `role="dialog"` 与 `aria-modal="true"`。
14. 必须提供可访问名称：优先使用可见标题和 `aria-labelledby`；无可见标题时才能使用 `aria-label`。复杂结构内容不得将全部正文塞入 `aria-describedby`。
15. 必须提供可见、可聚焦且有可访问名称的关闭、取消、确认或等价操作。
16. 所有允许用户主动退出的普通 Dialog，右上角必须提供始终可见的关闭按钮；底部的取消、关闭、确认或其他操作不能替代该按钮。关闭按钮应位于固定标题区域，内容滚动、标题换行、移动端布局和低高度视口下均不得被遮挡或滚出视口；应使用明确的关闭图标，提供 `aria-label="关闭"`，支持键盘聚焦，并具有足够的点击或触摸区域。点击后执行与取消操作一致的安全关闭流程。仅在提交中不可中断、强制确认、安全校验或其他业务明确禁止退出的场景中，才允许隐藏或禁用该按钮；实现必须明确表达原因，不能由开发者或 Agent 自行省略。

## 多层 Dialog

17. 同一时间只有最上层 Dialog 可以交互；下层 Dialog 和页面背景保持 `inert`。
18. 关闭最上层后，焦点返回下层 Dialog 中的触发元素。
19. 使用统一层级体系，不能依赖页面局部随意设置 `z-index`。

## 异步、错误与重复操作

20. 异步提交期间防止重复提交、重复关闭和重复回调。
21. loading 状态必须保留按钮可访问名称，并让辅助技术获得必要状态。
22. 请求失败后 Dialog 保持打开，以文本描述错误，并将焦点或错误摘要引导到合理位置；不能在用户来不及读取错误时自动关闭。
23. 业务禁止中断时，明确禁用相关关闭方式并向用户表达当前状态。

## 响应式与清理

24. 在放大、移动端、低高度视口和虚拟键盘出现时，所有内容和操作仍必须可访问。
25. 聚焦元素不能被固定标题、底部或虚拟键盘完全遮挡。
26. 不依赖固定像素高度；使用动态视口单位时提供合理回退。
27. 关闭、路由变化或组件卸载时，完整清理滚动锁定、`inert`、焦点约束、事件监听器和动画状态。
28. 再次打开时不得残留意外的遮罩、loading、错误或关闭状态。

## 推荐设计

- 破坏性操作的主按钮与取消按钮保持稳定顺序。
- 标题准确描述任务，避免只写“提示”或“信息”。
- 再次打开时默认清理旧错误和 loading，除非业务明确要求保留。
- 简单确认框避免嵌套复杂导航。

## 完成前检查

- 实际点击遮罩，确认 Dialog 不关闭，并验证明确关闭操作仍然有效。
- 验证打开初始焦点、`Tab` / `Shift + Tab` 焦点循环、关闭后的焦点返回，以及 Escape 的最上层关闭与例外处理。
- 验证背景 `inert`、可访问角色和名称；确认普通 Dialog 右上角关闭按钮始终可见、可聚焦、可通过键盘与指针触发，并执行与取消一致的安全关闭流程；同时验证多层 Dialog 的最上层隔离与焦点返回。
- 验证只有业务明确禁止退出的 Dialog 才隐藏或禁用右上角关闭按钮，并确认界面能够说明原因；不能把底部取消、关闭或确认按钮当作省略右上角关闭按钮的依据。
- 使用足以溢出的长内容，检查只有内容区域滚动；在桌面、移动端、低高度、缩放和虚拟键盘视口检查遮罩覆盖与可访问性。
- 验证打开/关闭动画、快速连续操作和 `prefers-reduced-motion`；关闭动画结束前遮罩、焦点约束和滚动锁定仍有效。
- 验证异步重复提交、失败错误、不可中断状态，以及路由变化、组件卸载和多次打开后的资源清理。
- 检查第三方组件默认配置没有重新启用遮罩关闭或外框滚动。
- 未实际执行的交互或视口检查必须明确标为未验证，并说明所需验证。
