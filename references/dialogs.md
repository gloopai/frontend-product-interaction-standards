# Dialog 交互规范

适用于所有 Dialog、Modal、对话框及具有相同行为的弹出层。本文件是 Dialog 完整规则、验收标准与参考资料的唯一事实来源。

Dialog 内或 Dialog 打开/关闭/提交/取消/帮助使用快捷键、热键、组合键或键盘命令时，必须同时执行 `references/keyboard-shortcuts-commands.md`；本文件继续负责模态语义、焦点陷阱、Escape/关闭、遮罩、滚动和 disposal，`keyboard-shortcuts-commands.md` 负责快捷键作用域、最上层优先级、输入保护、冲突、可发现性和旧监听器清理。

涉及跨端形态或视口适配时，还必须执行 [响应式与自适应交互规范](responsive-adaptive.md)。兼容规则全部执行；一方更严格且不冲突时，执行更严格规则。Dialog/Drawer 的形态专属动画、边缘和几何规则不以“更严格”裁定：初次打开采用当前视口最终渲染形态的专项动画，已打开实例实时转换时保持单实例并进行无入场/退场的布局转换，具体执行 `responsive-adaptive.md` 的跨端形态规则。

## 遮罩与滚动

1. 点击遮罩层不得改变 Dialog 的打开状态。不得添加通过遮罩点击关闭的事件；使用第三方组件时，必须关闭其“点击遮罩关闭”选项。Dialog 只能通过明确的弹窗内操作关闭，例如关闭、取消、确认或业务操作。
2. Dialog 外框必须保持不可滚动。内容超过视口可用高度时，应限制 Dialog 高度并仅让内容区域纵向滚动；标题、底部和操作区域保留在固定外框内。
3. 遮罩层必须覆盖整个浏览器视口，包括 Dialog 父布局容器以外的区域。必要时将其挂载或传送到应用根节点，并采用相对于视口的固定定位与正确层级。遮罩不得被页面区块、面板、带变换的祖先元素或其他局部容器裁切或限制。

## 动画

4. 打开时，遮罩淡入，Dialog 淡入并从 `scale(0.96)` 过渡到 `scale(1)`，时长为 `200ms ease-out`。
5. 关闭时按相反方向播放 `150ms ease-in`；动画完成后才能卸载 DOM。
6. 动画期间必须屏蔽重复打开或关闭。普通关闭从关闭请求开始，直至关闭动画完成且 Dialog DOM 已移除前，必须持续保持遮罩、焦点约束、背景隔离和页面滚动锁定；点击遮罩始终不能触发关闭或关闭动画。
7. 在 `prefers-reduced-motion: reduce` 下禁用缩放，淡入淡出不超过 `50ms`，或直接切换。

## 焦点与键盘

8. 打开后将焦点移到 Dialog 内最合理的元素：普通表单聚焦首个合理操作元素；长内容聚焦标题或顶部静态元素；不可逆危险操作优先聚焦破坏性最低的操作。
9. `Tab` 和 `Shift + Tab` 的焦点循环必须限制在当前活动 Dialog 内。
10. 普通关闭必须遵循唯一可观察顺序：专项退出动画完成 → Dialog DOM 移除 → 当前实例持有的焦点约束、遮罩、背景隔离和页面滚动锁定等模态保护释放 → 恢复焦点，且恰好一次。焦点返回触发元素；多层叠加时返回仍存活下层中的触发控件；触发元素不存在时移到后续流程中合理的元素。不得在 DOM 移除前释放保护、提前恢复焦点或因多个清理/动画回调重复恢复。路由变化或拥有组件卸载执行第 27 条的 disposal 例外，不恢复到将被移除的旧触发元素。
11. 默认支持 `Escape` 关闭最上层 Dialog，一次只关闭一层。正在提交、流程不可中断或存在未保存内容时，可以禁用 Escape 或先显示二次确认。

## 语义与背景隔离

12. Dialog 打开并开始模态活动时，当前活动实例必须取得页面滚动锁定；背景内容必须对鼠标、触摸、键盘和辅助技术均不可交互，使用原生模态能力或 `inert` 等等价机制。页面滚动锁定与背景隔离属于同一实例的模态保护，不能委托给未定义的外层。
13. 使用原生 `<dialog>`，或使用 `role="dialog"` 与 `aria-modal="true"`。
14. 必须提供可访问名称：优先使用可见标题和 `aria-labelledby`；无可见标题时才能使用 `aria-label`。复杂结构内容不得将全部正文塞入 `aria-describedby`。
15. 必须提供可见、可聚焦且有可访问名称的关闭、取消、确认或等价操作。
16. 所有允许用户主动退出的普通 Dialog，右上角必须提供始终可见的关闭按钮；底部的取消、关闭、确认或其他操作不能替代该按钮。关闭按钮应位于固定标题区域，内容滚动、标题换行、移动端布局和低高度视口下均不得被遮挡或滚出视口；应使用明确的关闭图标，提供 `aria-label="关闭"`，支持键盘聚焦，并具有足够的点击或触摸区域。点击后执行与取消操作一致的安全关闭流程。仅在提交中不可中断、强制确认、安全校验或其他业务明确禁止退出的场景中，才允许隐藏或禁用该按钮；实现必须明确表达原因，不能由开发者或 Agent 自行省略。

## 多层 Dialog

17. 同一时间只有最上层 Dialog 可以交互；下层 Dialog 和页面背景保持 `inert`。
18. 普通关闭最上层后，按第 10 条的唯一顺序将焦点恰好一次返回仍存活下层 Dialog 中的触发控件。
19. 使用统一层级体系，不能依赖页面局部随意设置 `z-index`。

## 异步、错误与重复操作

20. 异步提交期间防止重复提交、重复关闭和重复回调。
21. loading 状态必须保留按钮可访问名称，并让辅助技术获得必要状态。
22. 请求失败后 Dialog 保持打开，以文本描述错误，并将焦点或错误摘要引导到合理位置；不能在用户来不及读取错误时自动关闭。
23. 业务禁止中断时，明确禁用相关关闭方式并向用户表达当前状态。

## 响应式与清理

24. 在放大、移动端、低高度视口和虚拟键盘出现时，所有内容和操作仍必须可访问。
25. 聚焦元素不能被固定标题、底部或虚拟键盘完全遮挡。
26. 不依赖固定像素高度；使用动态视口单位时提供合理回退。
27. 普通关闭只按第 10 条的顺序完成，当前实例仅清理自己持有的资源且每项只释放一次。路由变化或拥有该 Dialog 的组件卸载时，当前实例立即进入 disposal，不等待退出动画，也不运行普通关闭的焦点恢复；共享的请求、重试/防抖、动画完成回调、监听器、过期回调和新路由焦点规则以 [响应式与自适应交互规范](responsive-adaptive.md)「跨端形态与状态延续」第 9 条为准，且无论此前是否发生形态转换都适用。该实例移除自身 DOM，只释放自己持有的页面滚动锁定、`inert`、焦点约束、遮罩、监听器和动画状态，不得清除其他存活实例的保护，也不得留下背景隔离或滚动锁定。
28. 再次打开时只清理先前实例的残留状态，不得清除当前活动实例持有的遮罩、背景隔离、页面滚动锁定、焦点约束或异步状态；不得残留意外的 loading、错误或关闭状态。

## 推荐设计

- Dialog、Bottom Sheet、全屏 Drawer 和独立页的承载面选择必须先判断任务复杂度、字段数量、选择器数量、风险等级、是否需要上下文对照、是否会触发虚拟键盘、是否有固定底部操作和当前可用视口。短确认、短提示和无表单轻任务可继续使用居中 Dialog；中等复杂度任务在移动端优先转换为底部 Drawer / Bottom Sheet；长表单、多步骤、高风险、强上下文编辑或需要稳定 URL / 刷新的任务必须升级为全屏 Drawer 或独立页。不得只因为组件库提供 Dialog 就把所有新增、编辑和配置任务都塞进 Dialog，也不得只因为移动端空间有限就删除字段、取消、确认、错误摘要、未保存保护或恢复路径。
- Dialog 内 Select / Combobox / Dropdown popup 不得被 Dialog 内容滚动区、Dialog 外框、固定页脚、局部容器、`overflow` 或 `transform` 裁切。不得为了 Select popup 展开而让 Dialog 外框滚动；PC / 宽屏应通过应用根或当前模态层专用 popup root、统一层级、锚点定位、空间不足时向上翻转、最大高度限制和仅 options 区滚动来解决。popup 不得遮挡 Dialog 主要确认按钮；空间不足时必须翻转、限高或按 Select/Responsive owner 转换为 Drawer。
- Dialog 内嵌 popup 的层级必须归属当前最上层模态实例：popup root 与锚点定位、collision 计算、滚动监听和关闭清理均由该 Dialog 实例登记。不得只通过临时提高 `z-index` 解决截图式遮挡；不得让 popup 穿透到更上层 Dialog/Drawer、被固定页脚覆盖、覆盖主要操作且无可见避让策略，或在 Dialog 内容滚动后脱离 trigger。锚点滚出当前内容视窗、Dialog 关闭、路由卸载或更上层模态打开时，该 popup 必须关闭或转换为合法承载形态，并同步清理 ARIA 引用。
- Dialog 内 Select popup 边界与固定底部操作区之间必须保留可感知安全间距。不能让 options 底边、选中行高亮、滚动阴影或列表边框贴住取消/确认按钮所在操作区；若可用空间不足以同时保留安全间距、可读选项高度和主要操作可达性，必须向上翻转、缩短 options 区、转换为 Select Drawer，或把任务承载层升级为更合适的 Bottom Sheet / 全屏 Drawer / 独立页。
- 对截图型页脚冲突，验收不能只看“选项还能点击”。必须记录 trigger、popup、选中高亮行、滚动阴影、底部操作区和安全区域的可视矩形，并断言 popup/options 与底部操作区之间存在设计系统定义的最小间距；选中高亮行不得与取消、确认或错误摘要发生视觉相交，也不得依赖透明覆盖、负 margin、压缩行高或隐藏阴影来制造“看起来没挡住”的效果。
- 移动端内容较多、有表单、有 Select、有虚拟键盘、有固定底部操作或空间不足的复杂 Dialog，可转换为底部 Drawer / Bottom Sheet。即使视觉上保留左右边距、右边距、顶部圆角或底部安全区域，它仍必须执行 Drawer 的遮罩、背景隔离、页面滚动锁、焦点陷阱、固定标题/关闭、固定底部操作、内容区滚动、遮罩点击不关闭、拖拽不关闭和 disposal 规则；左右边距或右边距只是视觉外框，不得被解释为页面仍可交互、遮罩只覆盖局部区域或允许背景滚动。
- 移动端 Bottom Sheet 形态应优先解决输入、选择和确认动作互相遮挡的问题：标题、关闭按钮和底部操作固定；正文与选项列表只在内部滚动；底部操作区必须计入 `safe-area-inset-bottom`、虚拟键盘和动态视口变化。确认按钮不得被 Select popup、键盘、Toast 或系统安全区域遮挡；若无法同时满足，应把 Select 升级为 Select Drawer 或把整个任务升级为全屏 Drawer/独立页。
- 若截图型问题表现为 Dialog 内 Select options 向下展开后与固定页脚或确认按钮贴边、压盖、被截断，不能以“看起来还能选”为通过；必须证明 popup root、锚点重算、向上翻转、最大高度、options-only scroll、页脚避让、ARIA 引用清理和移动端 Select Drawer 转换均有效。
- 破坏性操作的主按钮与取消按钮保持稳定顺序。
- 标题准确描述任务，避免只写“提示”或“信息”。
- 再次打开时默认清理旧错误和 loading，除非业务明确要求保留。
- 简单确认框避免嵌套复杂导航。

## 完成前检查

- 实际点击遮罩，确认 Dialog 不关闭，并验证明确关闭操作仍然有效。
- 验证打开初始焦点、`Tab` / `Shift + Tab` 焦点循环、关闭后的焦点返回，以及 Escape 的最上层关闭与例外处理。
- 验证背景 `inert`、可访问角色和名称；确认普通 Dialog 右上角关闭按钮始终可见、可聚焦、可通过键盘与指针触发，并执行与取消一致的安全关闭流程；同时验证多层 Dialog 的最上层隔离与焦点返回。
- 验证只有业务明确禁止退出的 Dialog 才隐藏或禁用右上角关闭按钮，并确认界面能够说明原因；不能把底部取消、关闭或确认按钮当作省略右上角关闭按钮的依据。
- 使用足以溢出的长内容，检查只有内容区域滚动；在桌面、移动端、低高度、缩放和虚拟键盘视口检查遮罩覆盖与可访问性。
- 在 Dialog 内打开 Select / Combobox / Dropdown，确认 popup 未被内容滚动区、外框、固定页脚、局部容器、`overflow` 或 `transform` 裁切；确认 Dialog 外框没有因为 popup 展开而变成可滚动；空间不足时 popup 向上翻转、限高、仅 options 区滚动或转换为 Drawer，并且不遮挡主要确认按钮。
- 对锚点靠近底部操作区的 Select，记录 trigger、popup、选中高亮行、滚动阴影、底部操作区、安全区域和虚拟键盘后的可视矩形；断言 selected option 高亮、列表边框与滚动阴影均不与取消、确认、错误摘要或安全区域相交，且避让距离不是通过覆盖、透明、负 margin 或压缩触摸目标伪造。
- 在 Dialog 内容滚动、锚点接近页脚、锚点接近视口上下边、打开更上层模态、路由卸载和 Dialog 关闭时验证内嵌 popup：定位随锚点重算或安全关闭，ARIA 引用不指向已卸载节点，临时层级不穿透更上层模态，也不遗留事件监听、定位任务或 popup DOM。
- 在窄屏、低高度、虚拟键盘和四向安全区域下验证 Bottom Sheet：左右边距、右边距和圆角只属于视觉样式；标题、关闭、内容滚动、底部操作、Select Drawer 转换、遮罩点击不关闭、拖拽不关闭、焦点陷阱和 disposal 全部按 Drawer 语义工作，且遮罩仍覆盖完整视口、背景不可交互、页面不可滚动。
- 验证打开/关闭动画、快速连续操作和 `prefers-reduced-motion`；实际观察 Dialog 打开期间及关闭动画期间的页面滚动，确认关闭动画结束且 DOM 移除前遮罩、背景隔离、焦点约束和页面滚动锁定仍有效。
- 记录普通关闭的动画完成、DOM 移除、当前实例焦点约束/遮罩/背景隔离/滚动锁释放和 `focus` 事件；断言严格按该顺序发生，每项释放计数为 1，焦点恢复计数也为 1。叠加两层时关闭上层，确认唯一焦点目标是仍存活下层中的触发控件。
- 验证异步重复提交、失败错误、不可中断状态，以及路由变化、组件卸载和多次打开后的资源清理。
- 在请求、重试/防抖和关闭动画回调待处理时触发路由变化及拥有组件卸载；记录 disposal、取消/失效回调、DOM 移除和资源释放，确认旧回调不再生效、每个实例只释放自己的资源、不会聚焦即将移除的旧触发元素，并且不会遗留 `inert` 或页面滚动锁定。
- 先让旧实例开始关闭，再激活一个新实例，随后交付旧实例的延迟清理/动画完成回调；确认该旧回调不能移除新实例的遮罩、背景隔离、页面滚动锁定、焦点约束或异步状态，且新实例仍可继续完成任务。
- 检查第三方组件默认配置没有重新启用遮罩关闭或外框滚动。
- 未实际执行的交互或视口检查必须明确标为未验证，并说明所需验证。
