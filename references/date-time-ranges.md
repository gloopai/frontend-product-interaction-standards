# 日期、时间、时间范围与时区交互规范

本文件是 Date Picker、Time Picker、Date Range Picker、DateTime Range Picker、快捷范围、相对时间、时区展示和时间快照的唯一 owner。它适用于筛选、表单、报表、导出、审计日志、任务中心、计划任务、过期时间和数据刷新时间。

日期时间值必须声明展示时区、存储/请求时区、边界语义和粒度。不得使用含糊本地字符串作为业务时间、请求时间、报表时间或审计时间。

本规范不替代表单、查询条件、管理台、浮层或响应式规范；当这些规范涉及日期时间语义时，本文件提供更严格的横切约束。

## 状态模型

每个日期时间控件必须声明 `dateTimeState`，至少包含：

| 字段 | 要求 |
| --- | --- |
| `dateTimeOwnerId` | 控件 owner ID；同一页面有多个日期时间控件时不得共用隐式全局状态。 |
| `valueKind` | 声明 `date`、`time`、`datetime`、`dateRange`、`datetimeRange`、`month`、`quarter`、`year` 或 `relativeRange`。 |
| `inputMode` | 声明 `calendar`、`text`、`select`、`segmentedPreset` 或 `mixed`，并说明键盘和触摸路径。 |
| `displayTimezone` | 用户看到、理解和确认的时区；不得省略。 |
| `storageTimezone` | 请求、存储、导出或审计使用的时区、UTC 策略或服务端转换策略。 |
| `rangeBoundary` | 声明 `[start, end)`、`[start, end]`、`(start, end]`、单点值或业务定义的开放范围。 |
| `granularity` | 声明 `minute`、`hour`、`day`、`week`、`month`、`quarter` 或 `year`。 |
| `presetPolicy` | 声明快捷范围列表、是否允许自定义、是否允许相对范围和默认选中策略。 |
| `relativeAnchor` | 快捷范围应用时冻结的基准时间；未应用的预览不得写入已应用查询。 |
| `validationState` | 记录空值、必填缺失、部分范围、格式错误、越界、`end < start`、DST 冲突和权限范围冲突。 |
| `urlSerialization` | 声明是否 `urlSafe`、格式版本、编码方式、时区恢复和失效恢复策略。 |
| `requestBinding` | 声明请求字段、格式、边界转换、幂等快照和响应写回匹配规则。 |
| `localePolicy` | 声明展示格式、输入格式、周起始日、12/24 小时制、语言环境和业务日历来源。 |

## 原子规则

| ID | 规则 |
| --- | --- |
| DTR-SCOPE-01 | 日期、时间、日期范围、时间范围、日期时间、日期时间范围、月、季度、年、快捷时间和相对范围都必须归属 `dateTimeState`。 |
| DTR-SCOPE-02 | 日期格式化、边界转换、快捷范围计算、时区转换和请求绑定不得散落在页面组件、表格列、导出按钮或请求函数中。 |
| DTR-SCOPE-03 | 涉及业务范围、权限范围、导出范围、审计范围或报表口径时，必须能回溯当时应用的日期时间快照。 |
| DTR-SCOPE-04 | 日期时间 owner 不负责决定业务是否允许某个日期；业务不可选规则必须作为能力或约束输入，并进入 `validationState`。 |
| DTR-SCOPE-05 | 同一页面中筛选、图表、指标卡、明细表和导出任务共享范围时，必须引用同一日期时间快照，不得各自重新计算。 |
| DTR-STATE-01 | 输入草稿、文本编辑值、弹层焦点、hover 日期、键盘高亮、快捷项预览和已提交业务值必须分离。 |
| DTR-STATE-02 | 部分范围不得触发查询、报表刷新、导出、审计过滤或 URL 写入；除非业务 owner 明确声明开放开始或开放结束。 |
| DTR-STATE-03 | 关闭弹层、Escape、点击取消、断点转换或失焦不得静默提交日期时间值。 |
| DTR-STATE-04 | 清空、重置、取消和应用是四个不同意图；清空移除当前值，重置恢复默认值，取消回到进入编辑前快照，应用提交合法业务值。 |
| DTR-STATE-05 | 控件内部状态不得污染表单 dirty/touched、筛选 `appliedFilters`、URL、请求或报表摘要，直到 owner 明确提交合法值。 |
| DTR-RANGE-01 | 范围推荐使用 `[start, end)`；使用其他边界时必须声明 inclusive/exclusive 规则和转换依据。 |
| DTR-RANGE-02 | 按日、周、月、季度或年展示的范围必须声明结束边界是否转换到下一粒度起点；不得靠 `23:59:59` 或毫秒补丁表达整天。 |
| DTR-RANGE-03 | `end < start` 必须进入字段错误，不得自动交换开始和结束，不得只禁用提交按钮。 |
| DTR-RANGE-04 | 开放范围必须在标签、摘要、请求和导出快照中明确写出“从某时起”或“直到某时止”。 |
| DTR-RANGE-05 | 范围摘要必须包含起止值、粒度和必要时区；不得只显示“已选择范围”或省略号。 |
| DTR-PRESET-01 | 今天、昨天、本周、本月、近 7 天和近 30 天必须声明业务时区、周起始日和粒度。 |
| DTR-PRESET-02 | 快捷范围必须冻结应用时的 `relativeAnchor`；今天、昨天、本周、本月、近 7 天和近 30 天不得在同一已应用查询中随时间漂移。 |
| DTR-PRESET-03 | 重新点击快捷项、刷新页面、浏览器返回或从 URL 恢复时，必须明确是恢复原快照还是按当前时间重新计算。 |
| DTR-PRESET-04 | 快捷项预览不得等于应用；只有用户触发应用或 owner 声明即时应用后，才可更新业务结果。 |
| DTR-PRESET-05 | 快捷范围与自定义范围切换时，必须保留或明确丢弃草稿，并给出可理解状态；不得半提交旧自定义值。 |
| DTR-TZ-01 | `displayTimezone` 与 `storageTimezone` 必须同时存在；不得使用含糊本地字符串。 |
| DTR-TZ-02 | 请求绑定必须声明是否发送 UTC、带 offset 的 ISO 字符串、日期字符串、业务时区标识或服务端预设键。 |
| DTR-TZ-03 | 跨 DST 的不存在本地时间、重复本地时间和跨日期边界必须进入可见校验或明确转换策略。 |
| DTR-TZ-04 | 报表、导出、审计日志、任务回执和过期时间必须展示使用的时区；不能只显示无时区时间戳。 |
| DTR-TZ-05 | 用户可切换时区时，必须说明切换会重解释已选本地时间还是保持绝对瞬间不变。 |
| DTR-VALID-01 | 空值、必填缺失、部分范围、格式错误、越界、不可选日期、`end < start`、DST 冲突和权限范围冲突必须有可区分错误。 |
| DTR-VALID-02 | 错误归属日期时间控件 owner，并进入字段错误、错误摘要或区域反馈；不能只靠 Toast 或禁用提交按钮解释。 |
| DTR-VALID-03 | 文本输入必须声明可接受格式和解析失败恢复；解析失败不得猜测用户意图并提交最接近日期。 |
| DTR-VALID-04 | 业务不可选日期、权限不可见范围和数据尚未产生范围必须可发现、可访问，并说明下一步。 |
| DTR-VALID-05 | 校验失败后修正任一端点，只能清除与该字段相关的错误，不得清除仍存在的范围、时区或权限错误。 |
| DTR-URL-01 | 只有明确 `urlSafe` 的日期时间值可以进入 URL；敏感时间范围、权限范围和临时预览不得进入 URL。 |
| DTR-URL-02 | URL 日期时间值必须带格式版本、时区或可还原时区策略；不得只放无版本本地字符串。 |
| DTR-URL-03 | URL 恢复出的值必须经过同一 `validationState` 与权限校验，不能直接写入已应用业务值。 |
| DTR-URL-04 | 无效、过期、权限不可用或业务日历变化导致无法恢复的时间值，必须进入可见失效状态并提供移除、替换或回到默认路径。 |
| DTR-URL-05 | 浏览器 Back/Forward 必须恢复日期时间快照、摘要、请求绑定和结果区域；不得只恢复输入框文本。 |
| DTR-REPORT-01 | 报表、导出和审计必须携带范围快照、时区、数据延迟和刷新时间。 |
| DTR-REPORT-02 | 指标卡、图表、明细表、导出任务和页面摘要必须共享同一日期时间快照。 |
| DTR-REPORT-03 | 导出任务必须记录提交时的日期时间范围、筛选快照、时区、生成时间、过期时间和下载身份。 |
| DTR-REPORT-04 | 审计日志必须区分事件发生时间、写入时间、展示时区和筛选范围。 |
| DTR-REPORT-05 | 用户可见文案使用“今天”“昨天”“近 7 天”等相对时间时，报表、审计、导出和回执中必须补充绝对日期。 |
| DTR-A11Y-01 | 日期时间字段必须有可访问标签、格式提示、错误说明和键盘路径。 |
| DTR-A11Y-02 | 范围选择必须让读屏可理解开始、结束、当前焦点日期、已选范围和错误状态。 |
| DTR-A11Y-03 | Calendar、Time Picker、快捷项和应用按钮必须支持键盘操作，不得只有鼠标或触摸路径。 |
| DTR-A11Y-04 | 禁用日期、不可选范围、时区说明和数据延迟不能只靠颜色或 hover tooltip 表达。 |
| DTR-A11Y-05 | 打开、关闭、切换月份、选择开始、选择结束、应用和错误变化必须有合理焦点和公告策略。 |
| DTR-RSP-01 | 移动端可以把复杂日期时间 Dialog 转换为 Bottom Drawer、Bottom Sheet 或独立页，但必须保留同一 owner 状态。 |
| DTR-RSP-02 | 移动端不得删除清空、重置、快捷范围、错误说明或时区说明。 |
| DTR-RSP-03 | Select、Calendar、Time Picker 等子浮层在移动端转换为底部选择器时，必须继承原 owner 的 `selectedValue`、`query`、`activeOption`、`validationState` 和提交边界。 |
| DTR-RSP-04 | 窄屏、低高度、软键盘和安全区域下，底部操作、错误说明、月份切换和时区说明必须可见或可达。 |
| DTR-RSP-05 | PC 使用 popup 时，popup 不得被父容器、Dialog、表格滚动区、固定列、固定页脚、`overflow` 或 `transform` 裁切。 |
| DTR-LIFE-01 | 已应用时间范围进入请求前必须生成快照；响应只能写回匹配快照的结果区域。 |
| DTR-LIFE-02 | 刷新、重试、导出、切换分页、切换报表 tab 和浏览器返回必须复用或显式替换同一日期时间快照。 |
| DTR-LIFE-03 | 页面卸载、弹层关闭或控件销毁必须清理定时器、异步解析、定位监听和过期 popup。 |
| DTR-LIFE-04 | 权限、业务日历、数据版本或时区策略变化后，旧日期时间快照必须重新校验或进入失效状态。 |
| DTR-LIFE-05 | 未执行点击、键盘、滚动、视口、时区、DST 和请求绑定检查时，必须明确标为未验证。 |

## 场景化要求

### 查询筛选

- 日期时间筛选继承 `query-filters.md` 的 `filterDraft` 与 `appliedFilters` 分离规则。
- 未完整范围、快捷项预览、文本解析中状态和 popup 焦点不得写入结果查询。
- 应用后摘要必须包含范围、粒度和必要时区；清空与重置必须表现为不同意图。

### 表单字段

- 日期时间字段继承 `forms.md` 的 dirty/touched、错误摘要、提交快照和未保存离开规则。
- 文本输入和组件选择必须落入同一 `validationState`；不得一边输入非法文本，一边提交上一次合法值而不提示。
- 必填日期为空、部分范围和 `end < start` 必须进入字段错误与表单错误摘要。

### 报表、导出和审计

- 报表默认展示只读结果；选择时间范围只是改变结果快照，不应引入无关行选择或批量动作。
- 报表、导出和审计必须携带范围快照、时区、数据延迟和刷新时间，并能让用户离线阅读时理解“今天”“近 7 天”的绝对日期。
- 导出下载入口必须绑定提交时的时间范围、权限、请求身份和过期时间，权限或任务过期后旧链接失效。

### 计划任务和过期时间

- 单点时间必须声明是绝对瞬间、业务本地时间还是周期规则。
- 过期时间必须展示时区，并说明已过期、即将过期、权限变化或服务不可用时的恢复路径。
- 重复计划不得只存储下一次执行时间；必须声明周期、时区、DST 处理和错过执行的恢复策略。

### 移动端转换

- 复杂日期范围、日期时间范围和带快捷项的控件，在移动端优先考虑 Bottom Drawer、Bottom Sheet 或独立页。
- 转换时只改变承载面，不改变 `dateTimeState`、提交边界、错误恢复和 URL/request 语义。
- 底部弹出形态应使用安全区域内边距，固定标题和操作区，内容区域滚动；不得让整个外框滚动后丢失应用按钮。

## 完成前检查

1. 是否声明 `dateTimeState` 及其全部必要字段。
2. 是否明确 `displayTimezone`、`storageTimezone`、`rangeBoundary` 和 `granularity`。
3. 是否使用或显式替代 `[start, end)`。
4. 快捷范围是否冻结 `relativeAnchor`，并避免已应用查询随时间漂移。
5. 部分范围、`end < start`、DST、权限范围和不可选日期是否可见报错。
6. URL 中是否只包含 `urlSafe` 且可恢复的日期时间值。
7. 报表、导出和审计是否携带范围快照、时区、数据延迟和刷新时间。
8. 移动端是否保留清空、重置、快捷范围、错误说明、时区说明和提交边界。
9. 关闭、取消、断点转换、卸载和请求返回是否不会静默提交或写回过期快照。
10. 未实际执行运行时检查时，是否明确标为未验证。
