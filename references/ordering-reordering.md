# 排序与重排交互规范

适用于排序、手动排序、人工排序、调整排序、展示顺序、显示顺序、拖拽排序、拖动排序、重排、重新排序、上移、下移、置顶、置底、移到顶部、移到底部、排序模式、保存顺序、顺序冲突、order、ordering、reorder、reordering、manual order、custom order、display order、sort order、drag reorder、drag and drop reorder、move up、move down、pin to top、send to bottom 和 save order。

本文件是人工排序与重排 owner。它负责排序范围、可排序对象、草稿顺序、提交快照、拖拽与键盘替代、分页/筛选/权限/数据版本冲突、保存结果、移动端承载和生命周期清理。查询排序、列排序、服务端 sort 参数、分页和结果摘要读取 `references/data-tables.md` 与 `references/list-result-controls.md`；列表内编辑禁止和记录编辑承载面读取 `references/record-editing-surfaces.md`；卡片列表排序入口读取 `references/card-list-results.md`；页面工具栏入口读取 `references/page-toolbars-actions.md`；按钮语义、loading 和防重复读取 `references/buttons.md`；危险或高影响批量顺序变更读取 `references/risk-actions.md`；权限无泄露读取 `references/permissions-tenancy-visibility.md`；响应式、触摸、拖拽替代和安全区域读取 `references/responsive-adaptive.md`；管理台治理读取 `references/admin-console.md`。

## 范围与边界

排序与重排不是列表内编辑，也不是查询排序。它是用户显式改变业务展示顺序、优先级、排列位置或分组内顺序的独立操作。

本 owner 不覆盖普通表头升降序、查询条件 sort、列显示顺序、看板复杂工作流、画布节点布局、树节点父子关系编辑、CSS flex/order、纯视觉动画或后端排序算法。它只定义前端如何安全承载人工顺序调整。

## `orderingReorderingState`

每个人工排序、拖拽重排、上移/下移、置顶/置底或保存顺序流程必须声明 `orderingReorderingState`，至少包含：

| 字段 | 语义 |
| --- | --- |
| `orderingOwnerId` | 当前排序/重排 owner 的稳定身份。 |
| `orderingSurface` | `inline-reorder-mode`、`dialog`、`drawer`、`page`、`bulk-reorder`、`group-reorder` 或产品声明的承载面。 |
| `scopeBinding` | 排序作用范围：当前分组、当前列表、当前已应用筛选、全部结果、当前页面、跨页集合或产品声明范围。 |
| `sourceSnapshot` | 进入排序时冻结的查询、筛选、搜索、分页、分组、数据版本、权限版本和租户/工作区快照。 |
| `itemIdentityMap` | 每个可排序对象的稳定 ID、安全名称、当前位置、分组、权限、版本和不可排序原因。 |
| `draftOrder` | 用户正在调整的草稿顺序、移动历史、临时位置和未保存状态。 |
| `committedOrderSnapshot` | 提交请求冻结的最终顺序、影响范围、版本、幂等键和目标集合。 |
| `movementPolicy` | 拖拽、上移、下移、置顶、置底、输入序号禁用/例外、分组内/跨组移动和边界规则。 |
| `inputAlternativePolicy` | 鼠标、触摸、键盘、按钮、屏幕阅读器和无拖拽环境下的等价操作。 |
| `submitPolicy` | 保存、取消、应用、重置、保存并返回、失败保留草稿和防重复请求策略。 |
| `conflictPolicy` | 筛选/搜索/分页/权限/数据版本/对象删除/并发排序变化后的失效、合并、刷新或重新确认策略。 |
| `permissionBoundary` | 可见对象、可移动对象、禁用原因、旧顺序、无权限占位、DOM/ARIA 和请求参数无泄露边界。 |
| `feedbackBinding` | 未保存提示、移动公告、保存中、成功、失败、部分成功、冲突、未知结果和恢复入口 owner。 |
| `responsivePolicy` | 移动端、低高度、虚拟键盘、触摸、200% 缩放、安全区域、长标题和单手操作策略。 |
| `focusAnnouncementPolicy` | 进入/退出排序模式、移动项、冲突、保存结果、重排后焦点和读屏公告策略。 |
| `lifecycleDisposal` | route/unmount、权限变化、断点转换、列表刷新、对象删除、拖拽取消和旧回调清理。 |
| `runtimeVerification` | 真实浏览器、键盘、读屏、触摸、拖拽、权限变化、断点转换、移动端和真实数据竞态验证状态；未执行必须标为未验证。 |

不得只用 `sort`、`order`、`sortIndex`、`position`、`items`、`onDragEnd`、数组下标、DOM 顺序、CSS `order` 或拖拽库状态替代 `orderingReorderingState`。

## 禁止项和 owner 边界

列表、表格或卡片中不得常驻排序输入、每行保存按钮或 spreadsheet-like 排序矩阵。需要调整排序时，只能提供“调整排序”“进入排序模式”“上移”“下移”“置顶”“置底”等明确入口，并由 `orderingReorderingState` 接管。

| 规则 ID | 规则 |
| --- | --- |
| `OR-SCOPE-01` | 人工排序与表头查询排序必须分开；查询排序只改变结果读取顺序，人工排序会改变业务展示顺序或优先级。 |
| `OR-SCOPE-02` | 排序、状态、分类、标签等小型字段也不得在列表单元格中直接可改；排序输入常驻列表即失败。 |
| `OR-SCOPE-03` | 当前页局部重排不得伪装成全部结果、全部分组或全局顺序已更新；范围不明确时不得启用保存。 |
| `OR-SCOPE-04` | 排序入口只能作为入口；保存顺序、冲突、失败、权限和恢复必须归 reorder owner，不得由按钮、Toast 或拖拽库回调单独承担。 |

## 承载面选择

排序承载面必须根据范围、数量、风险、移动端和恢复要求选择，不得因为实现方便而把序号输入框塞回列表。

| 规则 ID | 承载面 | 适用条件 | 禁用条件 |
| --- | --- | --- | --- |
| `OR-SURFACE-01` | `inline-reorder-mode` | 同一当前结果页或单个分组内少量对象，进入明确排序模式后隐藏或冻结普通行操作，并有保存/取消。 | 跨页、跨筛选、跨分组、强审计、对象多、移动端难操作或需要深链恢复。 |
| `OR-SURFACE-02` | `dialog` | 少量对象、低风险、短流程、无复杂冲突，只需确认顺序。 | 低高度、对象多、需要长滚动、拖拽复杂、移动端键盘/触摸困难或需要任务中心恢复。 |
| `OR-SURFACE-03` | `drawer` | 需要保留来源列表上下文、对象中等、需要解释冲突或支持移动端底部/全屏承载。 | 跨页大范围、多分组强审计、需要 URL、协作或长时间编辑。 |
| `OR-SURFACE-04` | `page` | 跨页、跨分组、大量对象、强审计、复杂冲突、协作、深链、刷新恢复或移动端主流程。 | 只有当前页少量低风险对象时可降级为轻量承载。 |

## 草稿、移动和提交

进入排序流程时必须冻结 `sourceSnapshot`。用户移动对象只改变 `draftOrder`，不会立即提交业务顺序。保存时冻结 `committedOrderSnapshot`；之后的拖拽、点击、键盘重复触发或迟到回调不得修改该快照。

| 规则 ID | 规则 |
| --- | --- |
| `OR-DRAFT-01` | 进入排序后创建独立草稿；普通列表查询、分页、选择、菜单和排序草稿不得共享可变数组。 |
| `OR-DRAFT-02` | 上移、下移、置顶、置底、拖拽和键盘移动都必须经过同一移动门禁，更新同一 `draftOrder`。 |
| `OR-DRAFT-03` | 移动不可排序对象、无权限对象、分组边界外对象、被删除对象或当前筛选外对象必须失败并说明原因。 |
| `OR-SUBMIT-01` | 保存前必须证明 `draftOrder` 覆盖提交范围内全部必需对象，没有重复、缺失、外部 ID 或无权限对象。 |
| `OR-SUBMIT-02` | 保存请求必须携带 `committedOrderSnapshot`、幂等键、权限版本、数据版本、范围和发起者；重复触发不得发送第二个等价请求。 |
| `OR-SUBMIT-03` | 保存失败、冲突或未知结果必须保留草稿、影响范围、错误原因和恢复入口；不得关闭承载面或只给 Toast。 |

## 拖拽、键盘和替代路径

拖拽不能是唯一排序方式。每个可排序对象必须至少提供按钮或键盘方式完成等价移动；触摸端、读屏和无精确指针环境必须可完成同一核心任务。

| 规则 ID | 规则 |
| --- | --- |
| `OR-INPUT-01` | 拖拽 handle 必须有可访问名称，说明对象、当前位置和可移动方向；整行拖拽不得吞掉行内按钮、链接、菜单或选择控件。 |
| `OR-INPUT-02` | 键盘或按钮替代必须支持上移、下移、置顶、置底或产品声明的等价移动；禁用方向必须说明边界原因。 |
| `OR-INPUT-03` | 移动后必须可见且可访问地公告对象名称、新位置、总数、分组和未保存状态，且公告不得重复。 |
| `OR-INPUT-04` | 拖拽取消、Escape、触摸中断、滚动中断或断点转换不得提交顺序；只能回到上一次有效 `draftOrder`。 |

## 范围、分页、筛选和冲突

人工排序必须说明作用范围。当前页、当前分组、全部筛选结果、全局集合和跨分组顺序是不同范围，不能共用保存文案或请求。

| 规则 ID | 规则 |
| --- | --- |
| `OR-RANGE-01` | `scopeBinding` 必须可见说明作用范围；排序保存按钮文案和确认文案必须包含范围或对象摘要。 |
| `OR-RANGE-02` | 分页列表只允许当前页内排序时，必须明确“仅调整当前页/当前分组”；不得影响或承诺其他页。 |
| `OR-RANGE-03` | 全部结果或跨页排序必须由服务端快照、全量排序页面、任务流程或分组范围证明支持；否则请求数为 0。 |
| `OR-CONFLICT-01` | 筛选、搜索、分页、分组、权限、租户/工作区、数据版本或对象集合变化后，旧排序草稿必须失效、刷新或要求重新确认。 |
| `OR-CONFLICT-02` | 并发排序、对象新增/删除、不可排序原因变化或服务端拒绝部分对象时，不得把结果伪装成成功；必须进入冲突、部分成功或未知结果恢复。 |

## 权限、风险和反馈

无权限或权限降级不得泄露旧顺序、旧对象名称、旧分组、旧数量、旧拖拽 handle、旧禁用原因、旧保存按钮或旧 ARIA label。

| 规则 ID | 规则 |
| --- | --- |
| `OR-PERM-01` | 可见、可排序、可保存和可恢复是不同权限；可见对象不自动可移动，可移动对象不自动可保存。 |
| `OR-PERM-02` | 权限待解析时显示安全状态，不得先渲染旧顺序、旧对象名、旧拖拽 handle 或旧保存入口。 |
| `OR-RISK-01` | 会影响大量对象、跨分组、跨租户/工作区、公开展示、业务优先级或不可自动恢复的重排必须进入风险确认或任务流程。 |
| `OR-FEEDBACK-01` | 保存成功、失败、部分成功、冲突、未知结果和恢复必须有页面内或承载面内回执；Toast 不能作为唯一反馈。 |

## 移动端与响应式

移动端可以使用 Drawer、全屏排序页、上移/下移按钮组、分组列表或分步排序，但不得删除排序范围、当前位置、移动路径、保存/取消、冲突说明、权限原因和恢复入口。

| 规则 ID | 规则 |
| --- | --- |
| `OR-RSP-01` | 触摸拖拽目标必须足够明确，但拖拽仍不能是唯一方式；低高度、单手、横屏和 200% 缩放下替代按钮必须可达。 |
| `OR-RSP-02` | 移动端底部保存栏、虚拟键盘、浏览器工具栏和 safe-area 不得遮挡当前移动对象、错误、保存、取消或恢复路径。 |
| `OR-RSP-03` | 断点转换保持同一 `orderingOwnerId`、`sourceSnapshot`、`draftOrder`、未保存状态和焦点；不得重建后丢失草稿或提交旧顺序。 |

## 生命周期和清理

route/unmount、权限变化、断点转换、列表刷新、对象删除、拖拽取消或 owner 卸载后，旧排序草稿、旧拖拽会话、旧保存请求、旧冲突说明、旧焦点目标和旧 ARIA 引用必须失效或重算。

| 规则 ID | 规则 |
| --- | --- |
| `OR-LIFE-01` | 旧保存响应只有同时匹配 owner、范围、幂等键、权限版本、数据版本和提交快照时才能写回。 |
| `OR-LIFE-02` | disposal 必须释放拖拽监听、键盘快捷键、滚动锁、测量任务、保存回调、公告回调和焦点任务，且只释放本 owner 持有资源。 |
| `OR-A11Y-01` | 排序区域必须有可访问名称；每个可移动项必须暴露名称、当前位置、总数、分组和可移动方向。 |
| `OR-A11Y-02` | 焦点顺序必须跟随当前草稿顺序或提供稳定解释；移动后焦点留在被移动对象的等价控制上。 |

## 完成前检查

1. 是否声明 `orderingReorderingState` 及全部字段。
2. 是否确认列表、表格或卡片中没有常驻排序输入、每行保存按钮或 spreadsheet-like 排序矩阵。
3. 是否区分人工排序与表头查询排序，且保存文案说明 `scopeBinding`。
4. 是否进入明确排序模式、Dialog、Drawer 或独立页，而不是在列表内容流中直接编辑排序。
5. 是否为拖拽提供键盘或按钮替代路径，并公告对象、新位置、总数、分组和未保存状态。
6. 是否在保存前验证 `draftOrder` 没有重复、缺失、外部 ID、无权限对象或范围不匹配。
7. 筛选、搜索、分页、分组、权限、租户/工作区、数据版本或对象集合变化后，旧排序草稿、旧保存请求、旧焦点和旧 ARIA 是否失效或重新确认。
8. 移动端是否保留排序范围、当前位置、移动路径、保存/取消、冲突说明、权限原因和恢复入口。
9. 真实浏览器、键盘、读屏、触摸、拖拽、权限变化、断点转换、移动端和真实数据竞态未实际执行时，是否明确标为未验证并列出所需验证。
