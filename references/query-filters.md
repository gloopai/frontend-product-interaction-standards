# 查询条件与筛选交互规范

## 范围

适用于列表、表格、卡片列表、报表、审计日志、任务中心、文件管理、管理台记录页和内部工具中的查询条件区、筛选区、过滤栏、关键词搜索、高级筛选、更多筛选、移动端筛选 Drawer、已应用条件摘要、筛选标签、重置筛选、清空筛选和 URL 筛选。

本文件是用户如何形成可复现查询意图的唯一事实来源。它定义查询条件草稿、已应用条件、默认条件、应用模式、重置/清空/移除、URL 同步、敏感值、权限收敛、移动端承载和可访问性。全站搜索、命令面板、复杂查询语言编辑器、SQL/DSL、BI 自由分析器、AI 自然语言检索和搜索排序算法不属于本 owner。

## 与组件 owner 的关系

表格、分页、排序、结果、选择和批量操作读取 `data-tables.md`；筛选字段的 label、校验、错误和字段状态读取 `forms.md`；自绘 Select / Combobox 的 `query`、active option、popup 状态和已提交值读取 `selects-comboboxes.md`；应用、重置、清空、移除、打开更多筛选和移动端筛选按钮读取 `buttons.md`；高级筛选 Dialog 或筛选 Drawer 读取 `dialogs.md` / `drawers.md`；管理台权限、租户/工作区、导出、审计和批量范围读取 `admin-console.md`；断点、触摸、虚拟键盘和安全区域读取 `responsive-adaptive.md`。当本文件与组件 owner 都适用时，两者都执行；冲突时停止并请用户裁决。

多值筛选、标签筛选、可创建标签筛选、收件人/成员筛选和批量粘贴筛选值必须同时执行 `references/multi-select-tag-inputs.md`；本文件继续负责筛选草稿、已应用条件、URL 安全、重置和应用边界。

关键词搜索、搜索输入、搜索框、文本搜索、列表搜索、表格搜索、报表搜索、局部搜索、页面内搜索、筛选搜索、即时搜索、防抖搜索、搜索清空、搜索重置、IME 搜索和搜索 URL 必须执行 `references/keyword-search-inputs.md`；本文件继续负责筛选草稿、已应用条件、URL 安全、重置和查询意图。

概览页、仪表盘首页、管理台首页、运营看板、业务看板、指标总览、报表总览和 dashboard landing 的全局筛选必须同时执行 `references/overview-dashboard-pages.md`；本文件负责筛选草稿/应用边界，`overview-dashboard-pages.md` 负责已应用筛选如何生成页面级 `dataSnapshot` 并分发给 KPI、图表、明细和导出。

结果分页、排序、刷新和结果摘要由 `references/list-result-controls.md` 读取已应用查询快照；query-filters 只输出 `appliedFilters`，不得让结果控制读取 `filterDraft` 或字段内部草稿。

高级筛选折叠、更多筛选折叠和筛选错误详情必须同时执行 `references/disclosure-accordions.md`；折叠 owner 不得隐藏已应用条件、筛选草稿状态、字段错误、权限原因或清空/恢复入口。

Query Filter owner 不重新定义字段内部交互、表格请求结果、排序分页、Dialog/Drawer 关闭或管理台审计。它只负责把用户编辑的条件变成明确、可解释、可复现且安全的 `queryIntent`。

## 场景与状态模型

每个查询条件区声明 `queryFilterSurface`：`list-filter-bar`、`report-filter-panel`、`audit-log-filter`、`task-filter`、`mobile-filter-drawer`、`advanced-filter-dialog`、`saved-view-filter` 或 `url-restored-filter`。

每个查询条件区维护 `queryFilterState`，至少包含：

| 字段 | 语义 |
| --- | --- |
| `filterOwnerId` | 当前条件区稳定身份。 |
| `filterDraft` | 用户正在编辑、尚未应用到结果的业务条件草稿。 |
| `appliedFilters` | 已应用到结果、URL、标题、结果摘要和请求快照的条件。 |
| `defaultFilters` | 产品声明的默认条件；重置恢复它，而不是含糊清空。 |
| `filterSchema` | 每个条件的类型、应用模式、默认值、敏感性、URL 策略、权限和可见性。 |
| `queryIntent` | 本次应用、移除、重置、清空、刷新或返回恢复形成的查询意图。 |
| `urlState` | 可安全序列化到 URL 的已应用条件、版本和解析结果。 |
| `requestBinding` | 交给结果 owner 的查询快照引用、权限版本、租户/工作区和请求代次。 |

`filterDraft` 与 `appliedFilters` 必须分离。结果标题、数量、空状态、URL、导出范围、批量范围和请求参数只能反映 `appliedFilters`；正在编辑的草稿不得伪装成已经生效。

## QF-SCOPE 范围和术语

| 规则 ID | 规则 |
| --- | --- |
| QF-SCOPE-01 | 查询条件区必须声明它控制的结果 owner、适用数据范围和是否影响导出、批量操作或报表口径。 |
| QF-SCOPE-02 | “搜索”表示关键词或文本条件，“筛选/过滤”表示结构化条件，“查询”表示已应用条件、排序、分页和权限范围共同形成的数据意图；三者不得混用结果文案。 |
| QF-SCOPE-03 | 查询条件区 owner 只输出已应用业务条件和 `queryIntent`；结果请求、分页、排序、选择失效和表格错误仍归结果 owner。 |
| QF-SCOPE-04 | 组件库默认输入即请求、默认清空、默认 URL 同步或默认折叠行为不能降低本文件规则；冲突时必须配置、封装或替换。 |

对应验收：QF-A1、QF-A10。

## QF-STATE 查询条件状态

条件状态分为字段内部状态、条件草稿、已应用条件和结果查询快照。字段内部状态由字段 owner 管理；查询条件区只接收字段已经提交的业务值作为 `filterDraft`。Select / Combobox 的 `query`、active option、popup 草稿、hover 状态、搜索 loading 和搜索错误不得进入 `filterDraft`、`appliedFilters`、URL 或结果摘要。

| 规则 ID | 规则 |
| --- | --- |
| QF-STATE-01 | `filterDraft` 与 `appliedFilters` 必须分离，并记录各自来源、版本和最后修改意图。 |
| QF-STATE-02 | 字段内部草稿不得进入 `filterDraft`、`appliedFilters`、URL 或结果摘要；只有字段 owner 提交的合法业务值才能进入筛选草稿。 |
| QF-STATE-03 | `defaultFilters` 必须由产品声明，并区分可清空默认、强制默认和权限派生默认。 |
| QF-STATE-04 | `filterSchema` 必须声明每个条件的类型、`applyMode`、默认值、`urlSafe`、`sensitive`、权限、可见性和序列化规则。 |
| QF-STATE-05 | 权限、租户/工作区、角色或数据范围变化后，必须重新解析 `filterSchema`、`defaultFilters`、`filterDraft` 和 `appliedFilters`。 |

对应验收：QF-A1、QF-A2、QF-A8。

## QF-APPLY 应用模式、请求意图和防重复

每个条件必须声明 `applyMode: immediate | explicit`。即时模式适用于低成本、单字段、无强组合依赖、不会造成明显请求压力且不影响敏感范围的条件；显式模式适用于多字段组合、日期范围、复杂 Select、远程选项、昂贵请求、敏感条件、会重置选择或影响批量范围的条件。

即时模式不等于输入每个字符都请求。关键词搜索必须声明最小输入策略、防抖、清空策略和提交边界；日期范围两端合法且完整后才可应用；Select 只有明确提交 `selectedValue` 后才可应用；远程条件请求失败时不得把未完成值写成已应用。

| 规则 ID | 规则 |
| --- | --- |
| QF-APPLY-01 | 每个条件必须声明 `applyMode: immediate | explicit`；未声明时不得发查询。 |
| QF-APPLY-02 | `immediate` 只在字段 owner 已提交合法业务值后创建 `queryIntent`；输入过程、Select 查询和未完整日期范围不发结果查询。 |
| QF-APPLY-03 | `explicit` 模式下，编辑草稿不改变结果、URL、标题、数量、导出范围或批量范围；只有应用操作才提交。 |
| QF-APPLY-04 | 每次应用、移除、有效重置、有效清空、URL 恢复或显式刷新都创建不可变 `queryIntent`，包含来源、已应用条件、权限版本、租户/工作区、默认版本和 URL 版本。 |
| QF-APPLY-05 | 重复点击“应用”、Enter、Space、触摸或事件重放不得形成多个等价 `queryIntent`；同一 in-flight 意图必须合并或拒绝。 |
| QF-APPLY-06 | 应用条件时，页码分页回到第 1 页，游标分页回到初始游标；已有选择、批量范围和行操作快照按结果 owner 规则失效。 |

对应验收：QF-A2、QF-A3、QF-A10。

## QF-RESET 默认值、重置、清空和单项移除

“重置”“清空”“移除”必须是三个不同意图。“重置”恢复 `defaultFilters`；“清空”移除所有可清空的非强制条件；“移除单项”只移除该已应用条件。若产品只有默认条件，不得把“重置”写成清空所有条件；若存在租户、权限、数据范围、强制时间窗口或合规条件，它们不能被清空。

| 规则 ID | 规则 |
| --- | --- |
| QF-RESET-01 | “重置”恢复 `defaultFilters`，而不是含糊清空全部条件。 |
| QF-RESET-02 | “清空”只移除可清空条件；强制条件、权限派生条件和产品声明的不可清空条件必须保留并可解释。 |
| QF-RESET-03 | 单项移除必须只移除目标条件，并创建新的 `queryIntent`；不得顺带清空同组其他条件，除非该组规则明确声明。 |
| QF-RESET-04 | 重置、清空或移除后若与当前 `appliedFilters` 语义相同，不得发新查询；但应给出可感知的无变化反馈或保持按钮禁用原因。 |
| QF-RESET-05 | 默认条件、强制条件和用户已应用条件必须在摘要中可区分，不能都显示成普通用户筛选。 |

对应验收：QF-A4、QF-A10。

## QF-SUMMARY 已应用条件摘要、chips 和折叠筛选

已应用条件必须持续可见或在摘要中可发现。主筛选区可折叠更多条件，但折叠头必须显示已应用数量、摘要或 chips。用户不能被迫展开所有面板才知道结果为什么被过滤。

| 规则 ID | 规则 |
| --- | --- |
| QF-SUMMARY-01 | 已应用条件必须持续可见或在摘要中可发现；隐藏在折叠区的已应用条件仍需显示数量、摘要或 chips。 |
| QF-SUMMARY-02 | 每个已应用条件 chip 必须有可访问名称，说明条件名、当前值和移除动作对象。 |
| QF-SUMMARY-03 | 默认条件、权限派生条件和用户条件需要不同展示或说明；不可移除条件不能渲染可点击删除图标。 |
| QF-SUMMARY-04 | 条件值过长、多个值、日期范围、失效值和无权限值必须有可理解摘要；不得只显示省略号或内部 ID。 |
| QF-SUMMARY-05 | 空结果时必须区分“当前条件无匹配”和“数据源本身为空”，并提供调整、清空可清空条件或恢复默认条件路径。 |

对应验收：QF-A5、QF-A10。

## QF-URL URL 同步、返回恢复和敏感值

只有明确 `urlSafe` 的已应用条件可以进入 URL。账号、令牌、个人识别、敏感自由文本、内部权限范围、密钥、邮箱、手机号、精确地址和产品标记 `sensitive` 的条件不得进入路径、查询串、片段、标题、剪贴板分享文本、日志或 analytics。

URL 状态必须版本化。页面初始化、刷新、浏览器前进/后退和打开分享链接时，必须按 `urlState.version` 解析；合法且可用的值进入 `appliedFilters`，过期、无权限、无效或已删除选项进入可见失效状态，并提供移除、替换或回到默认条件路径。

| 规则 ID | 规则 |
| --- | --- |
| QF-URL-01 | 只有明确 `urlSafe` 的已应用条件可以进入 URL；`sensitive` 条件不得进入 URL、标题、日志或 analytics。 |
| QF-URL-02 | URL 序列化使用稳定键名、版本和可逆编码；不得依赖字段展示文案或 option label 作为唯一身份。 |
| QF-URL-03 | 浏览器返回/前进必须恢复对应 `appliedFilters` 和结果查询意图；不得只改 URL 而不改结果，或只改结果而不改条件摘要。 |
| QF-URL-04 | 不得静默忽略 URL 中的已知条件；无效、过期、无权限或已删除选项必须进入可见失效状态，并提供恢复路径。 |
| QF-URL-05 | 分享链接若不包含敏感或会话条件，必须说明这些条件不会随链接恢复。 |

对应验收：QF-A6、QF-A10。

## QF-PERM 权限、租户和管理台安全

权限、租户/工作区、角色、数据范围或权限版本变化时，查询条件区必须重新解析可见条件、可选值、默认值、已应用条件和 URL 状态。无权条件、敏感值、旧租户选项和旧 URL 状态不能继续暴露。无法证明安全时，先隐藏、失效或替换为安全说明。

| 规则 ID | 规则 |
| --- | --- |
| QF-PERM-01 | 权限降级后，旧筛选值、旧选项标签、旧搜索建议、旧 URL 参数和旧 chips 不得继续泄露敏感对象。 |
| QF-PERM-02 | 权限派生条件必须进入 `queryIntent`，但不得作为可清空用户条件展示。 |
| QF-PERM-03 | 导出、批量操作、审计日志和任务中心读取的是 `appliedFilters` 与结果 owner 的查询快照，不得读取正在编辑的 `filterDraft`。 |
| QF-PERM-04 | 无权限或范围失效状态必须说明恢复路径，但不得泄露无权访问对象名称、数量、字段或内部 ID。 |
| QF-PERM-05 | 权限变化导致条件失效时，焦点只迁移一次到安全说明、摘要或首个可修复条件；旧异步回调不得抢回焦点。 |

对应验收：QF-A7、QF-A8、QF-A10。

## QF-A11Y 可访问性

筛选字段必须有可见 label 或等价可访问名称；帮助、错误和约束文本通过稳定描述关联到字段。应用、重置、清空、打开更多筛选、移除 chip 和移动端筛选按钮必须有动作对象。状态变化由唯一 owner 公告，避免字段错误、结果摘要和全局 live region 重复播报同一完整消息。

| 规则 ID | 规则 |
| --- | --- |
| QF-A11Y-01 | 查询条件区必须有可感知区域名称，说明它控制哪个结果区域。 |
| QF-A11Y-02 | 每个字段、chip 和操作按钮必须有可访问名称；错误不得只存在于颜色、图标或 hover tooltip。 |
| QF-A11Y-03 | 应用、重置、清空、移除和 URL 恢复结果必须由唯一 owner 以非重复方式公告。 |
| QF-A11Y-04 | 键盘顺序必须覆盖字段、更多筛选、应用、重置/清空、已应用 chips、结果摘要和恢复入口。 |
| QF-A11Y-05 | 折叠更多筛选时，触发器必须暴露展开状态和已应用隐藏条件数量。 |

对应验收：QF-A9、QF-A10。

## QF-RSP 响应式与移动端

PC、平板和移动端的核心查询能力必须一致。移动端可把复杂筛选放入 Drawer 或独立筛选页，低频条件可以折叠，但移动端不得删除核心筛选能力：查看已应用条件、编辑条件、应用、重置/清空、单项移除、查看错误、取消/返回结果和恢复默认条件都必须可达。

| 规则 ID | 规则 |
| --- | --- |
| QF-RSP-01 | 移动端不得删除筛选、应用、重置/清空、已应用摘要、单项移除或错误恢复能力。 |
| QF-RSP-02 | 筛选 Drawer 或独立页关闭时，未应用草稿不得静默影响结果；必须保留草稿、丢弃草稿或提示用户应用/放弃，且策略明确。 |
| QF-RSP-03 | 虚拟键盘、低高度、动态 viewport、四向 safe area 和 200% 缩放下，当前字段、错误、应用按钮和取消/返回路径必须可达。 |
| QF-RSP-04 | 窄屏条件摘要可压缩为 chips 横滚、摘要文本或“已应用 N 项”，但不能只显示内部 ID 或完全隐藏。 |

对应验收：QF-A9、QF-A10。

## 可执行验收检查

下列检查以可观察状态、URL、DOM 属性、事件日志和结果快照断言；未实际执行时必须报告为**未验证**及所需环境。

1. **状态分离与字段提交边界**：记录 `{filterOwnerId, filterDraft, appliedFilters, defaultFilters, filterSchema}`。编辑文本、日期范围和 Select；断言字段内部草稿、Select `query`、active option 和 popup 状态不进入 `filterDraft`、`appliedFilters`、URL 或结果摘要。只有字段 owner 提交合法业务值后，才进入 `filterDraft`。
2. **应用模式和请求意图**：为每个条件声明 `applyMode: immediate | explicit`。即时条件在合法业务值提交后才创建一次 `queryIntent`；显式条件编辑草稿时不改变结果、URL、标题、数量、导出范围或批量范围。重复点击、Enter、Space、触摸和事件重放只创建一个等价意图或被拒绝。
3. **结果绑定和分页重置**：应用、移除、有效重置、有效清空、URL 恢复和显式刷新时，断言 `queryIntent` 冻结已应用条件、权限版本、租户/工作区、默认版本和 URL 版本。结果 owner 建立查询快照；页码回到第 1 页，游标回到初始游标，旧选择和批量范围按结果 owner 失效。
4. **重置、清空和移除**：构造默认条件、强制条件、权限派生条件和用户条件；断言重置恢复 `defaultFilters`，清空只移除可清空条件，单项移除只移除目标条件。无语义变化时不发新查询，并提供无变化反馈或禁用原因。
5. **已应用摘要和折叠筛选**：应用主条件和折叠区条件；断言已应用条件持续可见或在摘要中可发现，折叠触发器暴露已应用隐藏条件数量，每个 chip 有条件名、当前值和移除动作对象。默认、权限派生和用户条件可区分，失效值不显示内部 ID。
6. **URL 安全和返回恢复**：只把 `urlSafe` 且非 `sensitive` 的已应用条件序列化到 URL。测试刷新、分享链接、浏览器返回/前进、过期 option、无权限 option 和已删除 option；断言 URL、`appliedFilters`、摘要和结果同步恢复。不得静默忽略 URL 中的已知条件；无效条件进入可见失效状态并提供移除、替换或恢复默认路径。
7. **权限、租户和安全收敛**：在编辑草稿、已应用条件、URL 恢复、导出前和批量操作前切换权限、租户/工作区、角色和数据范围；断言旧筛选值、旧 option label、旧搜索建议、旧 URL 参数和旧 chips 被隐藏、失效或替换安全说明。导出和批量只读取 `appliedFilters` 与结果查询快照，不读取 `filterDraft`。
8. **迟到回调和焦点**：在远程 option、URL 解析、权限复核和结果请求待处理时触发 route/unmount 或 owner 重建；断言旧回调不能写回新条件区、URL、摘要或焦点。权限变化导致条件失效时，焦点只迁移一次到安全说明、摘要或首个可修复条件。
9. **可访问性和键盘**：检查条件区区域名称、字段 label、帮助/错误描述关联、chip 可访问名称、按钮动作对象、折叠触发器展开状态和隐藏条件数量。键盘顺序覆盖字段、更多筛选、应用、重置/清空、chips、结果摘要和恢复入口；完整错误或状态消息只由一个 owner 播报。
10. **移动端和运行时报告**：在移动窄屏、筛选 Drawer、200% 缩放、字体放大、低高度、动态 viewport、虚拟键盘、四向 safe area 和触摸输入下，断言查看已应用条件、编辑条件、应用、重置/清空、单项移除、查看错误、取消/返回和恢复默认条件都可达。上述运行时、辅助技术和真实视口检查未实际执行时，报告必须逐项标为**未验证**，并写明所需浏览器、设备/viewport、输入方式及辅助技术环境。
