# Drawer 交互规范

适用于从左、右、上、下进入的模态 Drawer、Sheet 及抽屉式面板。本文件是抽屉完整规则、验收标准与参考资料的唯一事实来源。普通非模态侧栏、固定导航栏和无覆盖关系的页面分栏不应被错误地当作模态抽屉。

列表或表格的详情预览、侧边预览、行预览、记录预览、快速查看、只读预览和 Master-Detail 归 `references/preview-pane.md`；当这些预览在移动端或窄屏转换为底部 Drawer、全屏 Drawer 或其他模态覆盖层时，本文件负责遮罩、背景隔离、滚动锁、焦点陷阱、固定标题/关闭、底部安全区域和 disposal，`preview-pane.md` 继续负责预览目标、只读边界、迟到响应和权限无泄露。

涉及跨端形态或视口适配时，还必须执行 [响应式与自适应交互规范](responsive-adaptive.md)。兼容规则全部执行；一方更严格且不冲突时，执行更严格规则。Dialog/Drawer 的形态专属动画、边缘和几何规则不以“更严格”裁定：初次打开采用当前视口最终渲染形态的专项动画，已打开实例实时转换时保持单实例并进行无入场/退场的布局转换，具体执行 `responsive-adaptive.md` 的跨端形态规则。

自绘可搜索单选 Select / Combobox 转为移动端 Drawer 时，还必须完整执行 [可搜索单选 Select / Combobox 交互规范](selects-comboboxes.md)。关闭路径、遮罩、滚动、焦点、背景隔离、固定关闭按钮、层级和清理适用本文件的 Drawer 硬性规则；`selectedValue`、`query`、`activeOption`、选择提交、搜索与高亮状态适用 Select 状态规则。两类规则兼容时同时执行，不得用 Drawer 的关闭或动画实现改变已选值、查询或高亮的提交边界。

## 模态边界、遮罩与关闭

1. 模态抽屉的遮罩必须覆盖完整浏览器视口；将其挂载到应用根节点或等效不受局部容器、定位上下文及 `transform` 裁切的位置，并使用 `position: fixed; inset: 0` 与统一层级体系。
2. 点击遮罩不得关闭抽屉，也不得启动关闭动画。不得添加 backdrop 点击关闭处理；第三方组件必须禁用相应默认选项。
3. 拖拽、滑动、拖拽条及其他手势均不得关闭抽屉。除第 15 条规定的、业务允许时由 `Escape` 关闭最上层抽屉这一键盘路径外，抽屉关闭只能由内部的关闭按钮、取消、确认或明确业务操作触发；遮罩、拖拽和滑动绝不构成关闭路径。
4. 每个允许用户退出的普通抽屉都必须在固定标题区右上角保留始终可见、可聚焦的关闭按钮，使用清晰的关闭图标和 `aria-label="关闭"`，并提供足够的指针和触摸目标。页脚的取消、关闭、确认或其他操作不能替代该按钮。
5. 只有提交不可中断、强制确认、安全流程禁止退出或其他已记录的业务规则才可隐藏或禁用关闭按钮；必须向用户表达不能退出的原因，并同步禁用其他不安全关闭路径。

## 布局、滚动和四个方向

6. 抽屉外框必须保持非滚动（例如 `overflow: hidden`）；应约束可用尺寸，并且仅内容区域纵向滚动（`overflow-y: auto`）。标题、右上角关闭按钮、底部操作和必要状态区域固定在外框内，不得随长内容滚出视口。
7. 左抽屉固定于视口左边缘，从左向右进入、向左退出；右抽屉固定于视口右边缘，从右向左进入、向右退出。
8. 上抽屉固定于视口顶部，从上向下进入、向上退出；下抽屉固定于视口底部，从下向上进入、向下退出。
9. 左右抽屉限制宽度并使用可用视口高度；上下抽屉限制高度并使用可用视口宽度。不得依赖会令内容或操作不可达的固定像素高度。
10. 必须在移动端、浏览器缩放、低高度视口、动态视口单位和虚拟键盘场景中保持所有内容与操作可达。顶部、底部、左侧和右侧抽屉分别处理对应的 `safe-area-inset-*` 安全区域；聚焦元素不得被固定区域或键盘完全遮挡。

## 动画与减少动态效果

11. 打开时遮罩淡入，抽屉从所属边缘外沿平移至最终位置，使用 `200ms ease-out`。关闭时反向平移并淡出，使用 `150ms ease-in`，且仅在动画完成后卸载。
12. 打开或关闭动画期间必须阻止重复打开、关闭和回调执行。关闭动画结束前继续保留遮罩、焦点约束、背景隔离和页面滚动锁定。
13. 在 `prefers-reduced-motion: reduce` 下取消位移动画；淡入淡出最多 `50ms`，或直接切换状态。

## 焦点、键盘、语义与背景隔离

14. 打开后把焦点放在合适的抽屉内目标：普通表单的首个合理操作、长内容的标题或顶部静态元素、不可逆操作的风险最低选项。`Tab` 与 `Shift + Tab` 必须仅在最上层抽屉内循环。
15. `Escape` 默认只关闭最上层抽屉。提交中、不可中断流程或存在未保存内容时，必须禁用 Escape 或先进行确认。
16. 普通关闭必须遵循唯一可观察顺序：专项退出动画完成 → Drawer DOM 移除 → 当前实例持有的焦点约束、遮罩、背景隔离和页面滚动锁定等模态保护释放 → 恢复焦点，且恰好一次。焦点返回触发元素；多层叠加时返回仍存活下层中的触发控件；触发元素不存在时移到后续流程中合理的目标。不得在 DOM 移除前释放保护、提前恢复焦点或因多个清理/动画回调重复恢复。路由变化或拥有组件卸载执行第 22 条的 disposal 例外，不恢复到将被移除的旧触发元素。
17. 模态抽屉使用原生模态能力，或使用 `role="dialog"`、`aria-modal="true"` 与可访问名称。优先以可见标题配合 `aria-labelledby`；仅无可见标题时使用 `aria-label`。不得将复杂全文放进 `aria-describedby`。
18. 打开模态抽屉时，页面背景必须对指针、触摸、键盘和辅助技术都不可用，使用原生模态能力、`inert` 或等效机制，同时锁定页面滚动。非模态抽屉不得误标 `aria-modal="true"`，也不得无故隔离背景。
19. 多层抽屉或抽屉与 Dialog 叠加时，只有最上层可交互；所有下层及页面背景保持隔离。普通关闭最上层后，按第 16 条的唯一顺序将焦点恰好一次返回仍存活下层中的触发控件。不得依靠局部任意 `z-index`，应使用共享层级系统。

## 异步状态、错误与清理

20. 异步工作期间，防止重复提交、关闭和回调。加载控件必须保留可访问名称，并向辅助技术暴露所需状态。
21. 请求失败后抽屉必须保持打开，显示可读的文本错误，并将焦点引导到合理位置或错误摘要。不得在用户有机会阅读错误前自动关闭。
22. 新实例激活前，必须清理上一次实例残留的遮罩、loading、错误、关闭和动画状态，以及不应继续存在的监听器或副作用；旧实例的延迟回调不得清除新实例的保护或状态。当前抽屉打开期间，必须为当前实例建立并保留页面滚动锁定、背景隔离（包括 `inert`）、焦点陷阱和所需监听器；不得因“重新打开”清除这些当前有效的保护。普通关闭只按第 16 条的顺序完成，当前实例仅清理自己持有的资源且每项只释放一次。路由变化或拥有该 Drawer 的组件卸载时，当前实例立即进入 disposal，不等待退出动画，也不运行普通关闭的焦点恢复；共享的请求、重试/防抖、动画完成回调、监听器、过期回调和新路由焦点规则以 [响应式与自适应交互规范](responsive-adaptive.md)「跨端形态与状态延续」第 9 条为准，且无论此前是否发生形态转换都适用。该实例移除自身 DOM，只释放自己持有的滚动锁定、背景隔离、焦点陷阱、遮罩、监听器、动画及临时状态，不得清除其他存活实例的保护。

## 完成前检查

- 分别验证左抽屉、右抽屉、上抽屉和下抽屉的进入、退出方向、时长以及 `prefers-reduced-motion` 行为。
- 点击遮罩并执行拖拽或滑动，确认抽屉保持打开；再验证内部关闭按钮、取消、确认和 Escape 的允许与禁止场景。
- 使用足以溢出的长内容，确认仅内容区域滚动，固定标题、右上角关闭按钮、底部操作和状态区域始终可见。
- 验证遮罩完整覆盖视口、页面滚动锁定、背景隔离、焦点进入/循环/返回、可访问角色和名称，以及多层抽屉的最上层隔离与焦点返回。
- 记录普通关闭的动画完成、DOM 移除、当前实例焦点约束/遮罩/背景隔离/滚动锁释放和 `focus` 事件；断言严格按该顺序发生，每项释放计数为 1，焦点恢复计数也为 1。叠加两层时关闭上层，确认唯一焦点目标是仍存活下层中的触发控件。
- 在桌面、移动端、缩放、低高度、动态视口、虚拟键盘和安全区域设备中验证内容和操作均可访问。
- 验证快速连续操作、异步重复提交、失败错误、不可中断状态，以及关闭和多次打开后的资源清理；让旧实例延迟清理在新实例激活后到达，确认不能清除新实例的模态保护或异步状态。
- 在请求、重试/防抖和关闭动画回调待处理时触发路由变化及拥有组件卸载；记录 disposal、取消/失效回调、DOM 移除和资源释放，确认旧回调不再生效、每个实例只释放自己的资源、不会聚焦即将移除的旧触发元素，并且不会遗留 `inert`、滚动锁、焦点陷阱或遮罩。
- 未实际执行的交互或视口检查必须明确报告为未验证，并列出所需检查。
