# 回收站、软删除、归档恢复与保留期交互规范

适用于管理台中的删除后恢复、软删除、回收站、垃圾箱、归档列表、已删除列表、恢复记录、撤销删除、永久删除、清空回收站、保留期、到期清理、冻结保留、法律保留、删除审计、恢复审计，以及 trash、recycle bin、soft delete、restore、undo delete、permanent delete、retention、retention period、archive restore、deleted items、purge 和 legal hold。

本文件是删除后对象生命周期与恢复承载 owner。删除不是一个按钮点击，也不是一个 Toast。危险确认、强确认、输入确认和影响范围继续执行 `references/risk-actions.md`；状态流转、启停、归档和恢复继续执行 `references/status-lifecycle-transitions.md`；行操作/批量操作入口继续执行 `references/row-contextual-actions.md` 与 `references/bulk-actions-batch-operations.md`；列表、筛选、空态、权限、审计、异步任务和全局反馈继续执行对应 owner。本文件负责删除后对象是否还存在、在哪个范围可见、多久可恢复、如何恢复、何时永久删除、旧入口如何失效、审计如何追溯。

## 范围与边界

本 owner 覆盖：

- 单条和批量 soft delete、move to trash、archive、restore、undo delete、permanent delete、purge、empty trash、retention expired、legal hold、删除排队和恢复排队。
- 已删除/已归档视图、回收站入口、恢复入口、永久删除入口、保留期说明、到期倒计时、恢复冲突、部分恢复、恢复权限、删除审计和恢复审计。
- 删除后列表、详情、预览、搜索、导出、任务中心、通知、URL、浏览器返回和移动端承载的状态收敛。

本 owner 不覆盖：

- 后端数据保留策略、备份系统、合规法律解释、物理存储清理、数据库事务或审计存储实现。
- 普通禁用/启用、发布/下线、审批通过/驳回的完整状态机；这些继续由 `references/status-lifecycle-transitions.md` 拥有。若状态会导致“隐藏、保留期、恢复、永久删除”，则同时执行本文件。

## `trashRestoreState`

每个可删除、可归档、可恢复或可永久删除的对象范围必须声明 `trashRestoreState`：

| 字段 | 语义 |
| --- | --- |
| `trashOwnerId` | 当前删除后生命周期 owner 的稳定身份。 |
| `objectIdentity` | 对象类型、对象 ID、租户/工作区、版本、父子关系和可安全展示名称。 |
| `lifecycleKind` | `soft-delete`、`archive`、`disable-with-restore`、`purge`、`retention-expire` 或业务扩展类型。 |
| `deletedState` | `active`、`delete-pending`、`deleted-restorable`、`archived-restorable`、`restore-pending`、`restored`、`purge-pending`、`purged`、`retention-expired`、`legal-hold`、`unknown`。 |
| `sourceSnapshot` | 删除或归档发生时的列表、筛选、详情、权限、对象版本、选择范围和发起入口快照。 |
| `retentionPolicy` | 保留时长、到期时间、是否可延长、是否受法律保留/合规冻结影响、到期后动作和展示时区。 |
| `restorePolicy` | 谁能恢复、可恢复到哪里、恢复前检查、冲突处理、父级缺失处理、字段/关系恢复策略和部分恢复策略。 |
| `purgePolicy` | 永久删除、清空回收站、过期清理、确认策略、不可恢复说明、异步任务和审计要求。 |
| `visibilityPolicy` | active 列表、归档列表、回收站、搜索、详情、预览、关联对象和导出中如何展示或隐藏。 |
| `availabilityMap` | 恢复、永久删除、查看审计、下载错误明细、返回原位置和联系管理员的可见/禁用/只读状态。 |
| `permissionBoundary` | 查看已删除对象、查看数量、恢复、永久删除、查看审计和导出的权限版本。 |
| `requestIdentity` | 删除、恢复、永久删除、撤销、批量恢复和清理任务的幂等键、权限版本、目标快照和发起者。 |
| `resultReceipt` | 删除、恢复、永久删除、部分成功、未知结果、到期清理和任务结果的页面内回执。 |
| `auditBinding` | 删除原因、操作者、目标快照、保留期、恢复结果、永久删除结果和追溯链路。 |
| `feedbackBinding` | Toast、Banner、Inline 状态、回收站入口、任务中心、错误恢复和撤销窗口的关系。 |
| `navigationBinding` | 返回原列表、打开回收站、详情刷新、URL 恢复、浏览器 Back 和焦点恢复。 |
| `responsivePolicy` | 移动端回收站入口、恢复/永久删除操作、保留期说明、批量结果和安全区域策略。 |
| `lifecycleDisposal` | 权限变化、租户切换、对象版本变化、保留期到期、路由变化和 owner 卸载时的旧状态清理。 |
| `runtimeVerification` | 真实浏览器、键盘、读屏、移动端、权限切换、迟到响应、保留期到期、批量部分成功和审计追溯验证状态；未执行必须标为未验证。 |

不得只用 `deleted: true`、`archived: true`、列表过滤、Toast 撤销、隐藏行、状态标签、404 页面或后端最终状态替代 `trashRestoreState`。

## 删除、归档、禁用和永久删除语义

删除、归档、禁用和永久删除不是同一件事。软删除表示对象仍在系统内并可能恢复；归档表示对象不在默认工作流内但通常仍可查；禁用表示能力或账号暂不可用；永久删除表示对象不可恢复或只能通过外部合规流程处理。界面文案、入口、筛选、审计和恢复路径不得混用这些状态。

删除请求已发送不等于对象已删除；删除成功不等于对象已永久删除；归档成功不等于不可见；Toast 撤销不等于完整恢复能力。每个终态必须有页面内 `resultReceipt`，并说明对象当前在哪里、还能不能恢复、保留多久、下一步是什么。

## 回收站、已删除视图和恢复入口

若产品承诺可恢复，必须提供可发现的恢复入口，不能只依赖短暂 Toast、浏览器历史、旧列表行或客服说明。恢复入口可以在回收站、已删除视图、详情页、审计详情、任务结果或权限允许的全局搜索中出现，但必须绑定同一 `trashRestoreState`。

回收站和已删除视图必须说明范围：当前租户/工作区、对象类型、时间范围、保留期、权限过滤、数量可信度和是否包含批量删除任务。筛选、分页、排序、结果摘要和空态必须读取对应 owner；无结果不能写成“没有删除过任何内容”，除非权限和范围能证明。

恢复必须先检查对象版本、父级/依赖是否存在、名称/唯一键是否冲突、权限是否仍允许、关联对象是否可见、状态机是否允许、保留期是否未过和 legal hold 是否影响。冲突时不得静默覆盖当前对象；必须提供改名、选择新父级、跳过冲突项、查看失败明细或重新发起流程。

## 保留期、到期和永久删除

保留期必须用绝对时间、展示时区和规则来源表达，不能只写“30 天后删除”而不说明起算点。若保留期可能受套餐、合规、法律保留、管理员策略、对象类型或任务延迟影响，必须可见说明。

到期清理、清空回收站和永久删除必须进入 `references/risk-actions.md`。确认前请求数为 0；确认必须说明不可恢复性、影响范围、对象数量、权限范围、审计结果和未知结果处理。永久删除进行中不得把对象写成已不存在；必须区分 `purge-pending`、`purged`、`unknown` 和 `retention-expired`。

legal hold 或合规冻结优先于用户删除和到期清理。处于 legal hold 的对象不得展示可执行永久删除；如果说明具体原因会泄露敏感信息，应显示安全泛化说明。

## 列表、搜索、导出和旧入口收敛

对象进入 deleted、archived、purge-pending 或 purged 后，旧列表行、旧详情、旧预览、旧下载链接、旧复制链接、旧菜单项、旧批量选择、旧导出范围、旧搜索结果、旧 URL、旧 Toast/Notification、旧 aria-label 和旧焦点目标必须失效或重算。

默认 active 列表不得继续展示已删除对象，除非产品明确有“包含已删除”筛选且权限允许。搜索结果必须区分 active、archived、deleted-restorable 和 purged；无权限用户不得通过搜索命中、数量、状态标签、文件名、路径、父子关系或旧缓存推断已删除对象存在。

导出、下载错误明细、批量恢复报告和审计导出必须复核当前权限、租户/工作区、保留期、对象状态、敏感字段和请求身份。旧导出不得在对象永久删除或权限降级后继续可用，除非独立合规策略明确允许且已说明。

## 权限、安全和审计

查看已删除对象、恢复、永久删除、查看删除原因、查看操作者和导出审计是不同权限。禁用恢复按钮不是安全边界；无权限时 DOM、state、handler、request、菜单项和旧快捷键入口必须为 0 或替换为安全说明。

无权限状态不得泄露已删除对象名称、数量、字段、文件名、路径、父子关系、删除原因、操作者、删除时间、保留期、恢复状态、内部 ID、旧 URL、旧 aria-label、旧 tooltip、旧错误明细或旧缓存。

无权限状态不得泄露已删除对象名称、数量、字段、文件名、路径、删除原因、操作者、删除时间、保留期、恢复状态、内部 ID、旧 URL、旧 aria-label、旧 tooltip、旧错误明细或旧缓存。

删除、恢复、永久删除、清空回收站、保留期到期和 legal hold 变化必须绑定 `auditBinding`。Toast、Notification 或 Snackbar 不能作为唯一审计回执、唯一恢复入口、唯一失败说明或唯一未知结果处理。

## 批量、部分成功和异步任务

批量删除、批量恢复、批量永久删除和清空回收站必须冻结目标集合、筛选范围、权限版本、保留期规则和请求身份。当前可见行循环执行不得伪装成“全部筛选结果”。

部分成功必须说明成功、失败、跳过、冲突、无权限、已过期、legal hold 和未知范围；必须提供错误明细、重试失败项、返回回收站、查看任务或导出报告路径。Toast 不能作为唯一批量结果回执。

长耗时删除、恢复或永久删除必须进入任务中心；关闭 Dialog、Drawer、Toast、来源页面或移动端系统返回，只表示客户端停止等待，不表示任务取消或完成。

## 移动端与可访问性

移动端不得删除回收站入口、已删除/归档范围、保留期说明、恢复、永久删除、冲突说明、失败明细、权限原因、审计入口、返回原列表和任务中心入口。可以把低频筛选、批量错误详情和审计追溯放入 Drawer / Bottom Sheet，但核心恢复能力必须可达。

回收站、删除结果、恢复结果、保留期到期、legal hold、部分成功和未知结果必须由唯一 owner 公告。焦点应进入结果回执、错误摘要、回收站标题、冲突列表或恢复入口，且只迁移一次。

低高度、虚拟键盘、动态 viewport、四向 safe area、系统字体放大、200% 缩放、触摸、浏览器 Back、WebView 返回和移动端系统返回下，恢复入口、永久删除确认、保留期说明、错误明细和返回路径必须可达。

## 完成前检查

1. **owner 声明**：每个可删除、可归档、可恢复或可永久删除对象范围声明 `trashRestoreState`。
2. **语义区分**：soft delete、archive、disable、restore、permanent delete、purge、retention expired 和 legal hold 没有混用。
3. **恢复入口**：承诺可恢复时，恢复入口不只存在于 Toast、旧列表行或浏览器历史。
4. **保留期**：保留期展示绝对时间、时区、起算点、规则来源、到期动作和 legal hold 影响。
5. **永久删除风险**：清空回收站、永久删除和到期清理进入 `risk-actions.md`，确认前请求数为 0。
6. **恢复前检查**：恢复前检查版本、父级、唯一键、权限、状态机、保留期、关联对象和冲突。
7. **旧入口清理**：旧列表行、详情、预览、下载、复制、菜单、批量选择、导出、搜索、URL、Toast、ARIA 和焦点目标失效或重算。
8. **权限无泄露**：无权限不泄露已删除对象名称、数量、字段、文件名、路径、删除原因、操作者、删除时间、保留期、内部 ID 或旧缓存。
9. **批量和任务**：批量目标范围冻结，部分成功可恢复，长任务进入任务中心，关闭界面不伪装成任务完成或取消。
10. **运行时报告**：真实浏览器、键盘、读屏、移动端、权限切换、迟到响应、保留期到期、批量部分成功、任务中心和审计追溯未执行时必须标为**未验证**，并写明所需环境。
