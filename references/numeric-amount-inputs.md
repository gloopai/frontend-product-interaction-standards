# 数字、金额、比例与配额输入交互规范

适用于管理台中的数字输入、金额输入、百分比输入、费率输入、用量额度、数量、排序序号、权重、阈值、折扣、税率、汇率、单价、余额、库存、并发数、超时时长、保留天数、存储容量、席位数、API 调用额度、预算上限、告警阈值，以及 number input、amount input、currency input、percent input、ratio input、quota input、quantity input、numeric stepper、decimal input 和 unit input。

本文件是数字型输入 owner。数字字段不是普通文本框加 `type=number`。它必须证明用户输入的文本、解析后的数值、业务单位、精度、舍入、边界、展示格式、提交快照和服务端权威值之间的关系。通用字段值、dirty、校验、提交和错误摘要继续执行 `references/forms.md`；字段 label、单位、格式示例、帮助文本和只读/禁用原因继续执行 `references/field-guidance-help-text.md`；金额、套餐、发票和用量商业承诺继续执行 `references/billing-subscription-invoices.md`；危险额度、扣费、清零和不可逆阈值变更继续执行 `references/risk-actions.md`；按钮、保存区、权限、移动端和响应式继续执行对应 owner。

## 范围与边界

本 owner 覆盖：

- 数字输入草稿、解析、格式化、精度、舍入、单位、币种、比例、范围、步进、最小/最大值、软上限/硬上限和服务端回填。
- 空值、0、负数、小数、千分位、百分号、货币符号、单位后缀、科学计数法、全角数字、中文输入法、复制粘贴、移动端数字键盘和读屏表达。
- 数字字段在表单、设置页、计费页、筛选条件、批量配置、图表配置、报表配置和行/卡片编辑入口中的交互约束。

本 owner 不覆盖：

- 数据库字段类型、后端计费引擎、真实汇率、税务规则、财务入账或业务指标口径。
- 图表坐标轴展示、只读指标卡和报表数字展示；这些继续执行 `references/charts-visualization.md`、`references/information-display.md` 或 `references/overview-dashboard-pages.md`。若这些展示提供可编辑阈值或预算入口，必须回到本文件。

## `numericInputState`

每个数字型字段必须声明 `numericInputState`：

| 字段 | 语义 |
| --- | --- |
| `numericOwnerId` | 当前数字字段稳定身份。 |
| `fieldIdentity` | 字段业务身份、租户/工作区、对象、版本和权限边界。 |
| `valueKind` | `integer`、`decimal`、`money`、`percent`、`ratio`、`quota`、`duration`、`size`、`count`、`weight`、`order` 或业务扩展类型。 |
| `draftText` | 用户当前看到和编辑的原始文本；允许短暂处于不可提交状态。 |
| `parsedValue` | 当前草稿可解析时得到的规范数值；不可解析时为 invalid，而不是 0。 |
| `committedValue` | 当前已被表单或筛选 owner 接收的业务值。 |
| `displayFormat` | 千分位、小数位、币种符号、百分号、单位、负数和空值展示规则。 |
| `unitBinding` | 单位、币种、倍率、百分比基准、存储单位、时间单位和是否可切换。 |
| `precisionPolicy` | 最大小数位、最小步长、舍入方式、截断方式和提交前/展示后是否允许差异。 |
| `rangePolicy` | 硬最小/最大值、软建议范围、业务阈值、0/负数允许性和边界来源。 |
| `stepperPolicy` | 加减按钮、键盘上下、长按、滚轮和触摸步进策略。 |
| `normalizationPolicy` | 粘贴、全角数字、空格、分隔符、货币符号、百分号、单位后缀和本地化小数点的处理。 |
| `validationBinding` | 同步校验、异步校验、服务端校验、跨字段依赖和错误 owner。 |
| `submitSnapshotPolicy` | 提交时冻结的数值、单位、精度、版本、原始文本和幂等身份。 |
| `permissionBoundary` | 可查看、可编辑、可提交、可查看具体金额/额度/阈值的权限版本。 |
| `feedbackBinding` | 字段错误、保存结果、乐观更新、未知结果和恢复入口的 owner。 |
| `responsivePolicy` | 移动端键盘、单位显示、步进按钮、错误文本、固定保存区和 safe-area 策略。 |
| `focusAnnouncementPolicy` | 格式化、错误、单位变化、边界修正、服务端回填和提交结果的焦点/公告策略。 |
| `lifecycleDisposal` | 字段卸载、权限变化、单位变化、路由变化、表单重建和迟到校验的清理规则。 |
| `runtimeVerification` | 真实浏览器、键盘、读屏、移动端、输入法、粘贴、缩放、权限切换和服务端回填验证状态；未执行必须标为未验证。 |

不得只用 `Number(value)`、`parseFloat`、`input[type=number]`、正则替换、展示字符串、placeholder、后端最终校验或组件库默认 formatter 替代 `numericInputState`。

## 数值草稿、解析和提交值

数字输入必须把 `draftText`、`parsedValue` 和 `committedValue` 分开。用户正在输入 `-`、`.`、`0.`、空字符串、`1,`、`￥` 或含单位的草稿时，可以继续编辑并显示温和提示，但这些草稿不得被静默解析成 0、空值或上一次合法值提交。

空值、0、负数和非法值不是同一件事。空值表示用户没有提供值；0 是明确业务值；负数是否允许由 `rangePolicy` 决定；非法值只能产生字段错误或阻止提交，不得自动改成最近合法值，除非产品明确提供可撤销的“已按规则修正”说明。

提交前必须冻结 `submitSnapshotPolicy`：包含规范数值、单位/币种、倍率、精度策略、舍入方式、原始文本、字段版本、权限版本和表单/筛选 owner 身份。展示格式改变、失焦格式化、单位切换和服务端回填不得改写已冻结的提交快照。

## 单位、币种、百分比和倍率

单位必须是字段值的一部分或明确绑定到不可变上下文。金额必须声明币种；百分比必须声明提交的是 `0.15`、`15` 还是 `15%` 的哪一种；存储容量必须声明 KB/MB/GB/TB 与 1000/1024 的换算；时长必须声明秒、分钟、小时或天；配额必须声明计量周期和刷新延迟。

单位切换不是视觉格式切换。若用户从“GB”切到“MB”、从“%”切到“小数”、从“月预算”切到“日预算”，必须声明是保留业务量、保留字面数字、重算草稿、清空并要求重填，还是禁止切换。不得静默改变实际提交值。

金额、折扣、税率、用量、额度、余额、超额费用和发票相关数字必须同时执行 `references/billing-subscription-invoices.md`。支付成功、保存成功、额度到账和用量刷新不是同一结果；不能只靠 Toast 或按钮 loading 告诉用户金额已生效。

## 精度、舍入、边界和步进

精度策略必须说明最大小数位、最小步长和舍入位置。展示保留两位不等于提交也保留两位；提交保留两位不等于计算过程只保留两位。金额、百分比、费率、汇率和权重不得因前端浮点误差出现 `0.3000000004`、多扣、多收、误触发阈值或错误排序。

硬边界阻止提交；软边界允许提交但必须说明风险、建议范围或影响。边界来源必须可追踪：产品常量、套餐限制、权限、服务端配置、当前数据范围、跨字段依赖或外部系统限制。边界变化后，旧错误、旧禁用、旧 stepper 状态和旧提示必须失效或重算。

Stepper、键盘上下和滚轮不得偷偷改变重要数字。默认禁止鼠标滚轮在聚焦数字输入时改值；若启用，必须有明确视觉反馈、可撤销路径和误触防护。长按步进必须有上限和取消路径，不能越过硬边界或隐藏错误。

## 格式化、粘贴和输入法

失焦格式化只能改变展示，不得让用户无法回到原始草稿语义。聚焦时应避免频繁插入千分位、货币符号或单位导致光标跳动；若产品选择实时格式化，必须验证光标、选区、删除、粘贴、IME composition 和读屏不被破坏。

粘贴必须按 `normalizationPolicy` 处理全角数字、空格、千分位、货币符号、百分号、单位后缀、本地化小数点和不可见字符。不能把 `1,000` 误读为 `1`，不能把 `10%` 在不同字段里有时提交 10、有时提交 0.1 而不说明。

中文输入法或其他 IME composition 未结束时，不得触发提交、格式化、清空、自动补零或强制报错。Enter 在 composition 期间只结束输入法候选，不得提交表单或应用筛选。

## 权限、安全和敏感数字

无权限、权限降级、租户/工作区切换、套餐变化、角色变化或对象版本变化后，旧数字、旧金额、旧额度、旧阈值、旧单位、旧错误、旧 tooltip、旧 aria-label、旧校验结果、旧 stepper 状态和旧提交快照必须失效或重算。

无权限状态不得泄露金额、余额、额度、用量、阈值、折扣、税率、单价、库存、成员数、计量周期、内部 ID、套餐限制、历史值、旧缓存或错误明细。若显示禁用数字输入会泄露敏感值，应隐藏或替换为安全说明。

无权限状态不得泄露金额、余额、额度、用量、阈值、单价、套餐限制、历史值、旧 aria-label 或错误明细。

## 移动端、可访问性和反馈

移动端不得删除单位、币种、错误、边界说明、精度说明、清空、恢复、保存、取消、只读原因或权限说明。可以把高级说明折叠、把单位选择放入 Drawer / Bottom Sheet、把长错误收纳到详情，但核心数字、单位和提交影响必须可达。

移动端不得删除单位、币种、错误、边界说明、清空、恢复、保存、取消、只读原因或权限说明。

数字字段必须有可见 label 和可访问名称；单位、格式示例、边界、错误和只读/禁用原因必须通过可见文本或稳定描述关联表达，不能只靠 placeholder、颜色、后缀图标、Tooltip 或 Toast。读屏应能区分“15%”与“15”、金额币种、空值和 0。

低高度、虚拟键盘、动态 viewport、四向 safe area、系统字体放大和 200% 缩放下，当前字段、单位、错误、保存区和恢复动作必须可达。移动端数字键盘类型必须与允许字符一致：允许小数时不能只给整数键盘；允许负数时不能无法输入负号；金额/百分号/单位后缀不能阻断编辑。

## 完成前检查

1. **owner 声明**：每个数字、金额、比例、配额、数量、阈值、权重、排序、时长、容量和费率字段声明 `numericInputState`。
2. **草稿/解析/提交分离**：`draftText`、`parsedValue` 和 `committedValue` 分离；`-`、`.`、`0.`、空字符串和非法草稿不会静默提交成 0 或旧值。
3. **单位与倍率**：金额声明币种；百分比声明提交倍率；容量、时长、配额声明单位和计量周期；单位切换策略明确。
4. **精度和舍入**：声明最大小数位、步长、舍入/截断方式和发生位置；没有前端浮点误差影响金额、费率、阈值、排序或提交。
5. **边界和步进**：硬/软边界、边界来源、0/负数允许性、滚轮和长按步进策略明确；不会越界或误触改值。
6. **格式化与粘贴**：千分位、货币符号、百分号、单位后缀、全角数字、本地化小数点和不可见字符处理稳定；格式化不破坏光标、选区、删除和读屏。
7. **IME 与键盘**：composition 未结束时 Enter 不提交、不格式化、不清空、不报错；移动端键盘允许输入业务需要的字符。
8. **表单和提交快照**：提交冻结规范数值、单位、精度、原始文本、字段版本、权限版本和 owner 身份；迟到校验、服务端回填和展示格式变化不得改写旧快照。
9. **权限无泄露**：无权限不泄露金额、余额、额度、用量、阈值、单价、套餐限制、历史值、旧 aria-label 或错误明细。
10. **运行时报告**：真实浏览器、键盘、读屏、移动端、输入法、粘贴、缩放、权限切换、服务端回填和计费/额度边界未执行时必须标为**未验证**，并写明所需环境。
