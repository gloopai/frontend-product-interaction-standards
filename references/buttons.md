# 按钮交互规范

适用于后台、管理台、控制台、SaaS console 和内部工具中的业务操作按钮。本文件是按钮语义、文案、层级、状态、禁用、异步、防重复、危险操作、图标按钮、按钮组、键盘和响应式行为的唯一事实来源。

## 范围与术语

本规范首版覆盖管理台和业务操作按钮，包括保存、提交、取消、重试、新增、编辑、复制创建、配置、删除、停用、启用、归档、导入、导出、行操作、批量操作、确认、任务操作、图标按钮、更多菜单和工具栏按钮。

本规范不定义品牌视觉 token，例如具体色值、圆角、字号、阴影、间距比例或主题变量；不覆盖营销页 CTA、官网导航、富文本工具栏、游戏控件、画布编辑器控件或底层组件库 API。后续若扩展到全站通用按钮，应在不削弱本文件业务操作规则的前提下新增范围。

按钮是触发动作的控件。只导航且不执行命令的入口优先是链接；展示状态而不触发动作的元素是状态标签；打开解释性内容但不执行动作的元素是 disclosure 或帮助入口。不得把这些元素随意伪装成业务按钮。

## 与现有 owner 的关系

- `forms.md`：字段值、dirty、校验、`submitSnapshot`、`submitId`、错误摘要和失败恢复仍归表单 owner；按钮只管触发入口、文案、状态、禁用、loading 和重复触发边界。
- `dialogs.md` / `drawers.md`：遮罩、关闭、焦点陷阱、右上角关闭按钮、动画和 disposal 仍归容器 owner；按钮补充操作文案、层级、状态和危险动作入口。
- `data-tables.md`：行操作、批量操作、选择快照、分页、排序和表格能力仍归数据表格 owner；按钮管按钮名称、图标按钮、禁用原因和触发去重。
- `admin-console.md`：权限、租户、风险、审计、任务和全局反馈仍归管理台 owner；按钮不得绕过这些 owner。
- `record-editing-surfaces.md`：新增/编辑入口可以是按钮，但按钮只能作为入口，不能把编辑字段放回列表。
- `responsive-adaptive.md`：断点、触摸、虚拟键盘、安全区域和能力折叠仍归响应式 owner；按钮声明在这些形态下的可达性要求。
- 搜索、清空、取消、重置和重试按钮若作用于关键词搜索输入，必须同时执行 `references/keyword-search-inputs.md`，并保留清空草稿、清空已提交关键词、重置默认关键词和取消输入的意图区分。

## BTN-SCOPE 按钮语义与原生优先

| 规则 ID | 规则 |
| --- | --- |
| `BTN-SCOPE-01` | 按钮必须代表明确动作，优先使用原生 `<button>`；使用非原生元素时必须提供等价角色、键盘触发、焦点、禁用和可访问名称。 |
| `BTN-SCOPE-02` | 触发导航且不执行命令的入口优先使用链接；既执行命令又导航时必须声明命令 owner、结果 owner 和导航时机。 |
| `BTN-SCOPE-03` | 按钮不得作为装饰、状态标签或 tooltip 触发器的伪装；没有动作的元素不得使用按钮语义。 |

业务操作按钮不得以组件库默认行为为理由降低语义。若第三方组件输出非原生元素，必须补齐等价语义、键盘、焦点、禁用、可访问名称和事件去重；无法补齐时应封装或替换。

## BTN-LABEL 文案与可访问名称

| 规则 ID | 规则 |
| --- | --- |
| `BTN-LABEL-01` | 按钮文案必须描述动作和对象，例如“保存模板”“删除用户”“导出当前筛选结果”。 |
| `BTN-LABEL-02` | 禁止脱离上下文的裸词按钮，如“确定”“提交”“操作”“更多”“处理”；只有容器标题和任务区已经唯一说明对象时才可使用短文案。 |
| `BTN-LABEL-03` | 图标按钮必须有可访问名称，名称包含动作和对象，且不能只依赖 tooltip。 |

按钮的可见文案、可访问名称、菜单项名称、确认标题和结果回执应描述同一个动作对象。loading、禁用、折叠和图标态也必须保留动作对象，不能退化为“加载中”“处理中”“确定”或只有图标。

## BTN-HIER 层级、主按钮和按钮组

| 规则 ID | 规则 |
| --- | --- |
| `BTN-HIER-01` | 同一任务区同一时刻最多一个 `primary` 按钮；多个主按钮并列时必须拆分任务区或降级层级。 |
| `BTN-HIER-02` | 危险动作不得与普通主操作共用同一主视觉层级；必须显式表达风险并进入对应风险 owner。 |

任务区可以是表单底部、Dialog 页脚、Drawer 页脚、表格工具栏、批量操作区、任务结果区或卡片操作区。按钮组顺序必须稳定：主操作、次操作、更多操作、危险操作应有清晰分区。取消、关闭、返回或放弃不应比提交更突出；危险确认中的焦点和视觉层级还必须服从 Dialog 和 Admin owner 的误触防护规则。

## BTN-STATE 状态模型、禁用和隐藏

每个业务按钮声明 `buttonActionState`：

| 字段 | 语义 |
| --- | --- |
| `buttonId` | 稳定按钮身份。 |
| `actionKind` | `command`、`submit`、`navigation`、`disclosure`、`toggle-command` 或 `composite-trigger`。 |
| `hierarchy` | `primary`、`secondary`、`tertiary`、`danger`、`link-like` 或 `icon-only`。 |
| `availability` | `enabled`、`disabled`、`read-only`、`hidden-by-permission` 或 `not-instantiated`。 |
| `disabledReasonOwner` | 禁用原因 owner，例如权限、数据状态、选择状态、表单校验、任务状态或业务规则。 |
| `asyncPhase` | `idle`、`validating`、`request-in-flight`、`succeeded`、`failed` 或 `unknown`。 |
| `requestIdentity` | 触发请求时的幂等键、权限版本、目标快照和来源按钮身份。 |
| `resultOwner` | 成功、失败、冲突、未知结果和恢复入口的 primary owner。 |
| `accessibleName` | 当前可访问名称；loading、图标态和折叠态也必须保留。 |

| 规则 ID | 规则 |
| --- | --- |
| `BTN-STATE-01` | 每个业务按钮声明 `buttonActionState`，包含 `buttonId`、`actionKind`、`hierarchy`、`availability`、`disabledReasonOwner`、`asyncPhase`、`requestIdentity`、`resultOwner` 和 `accessibleName`。 |
| `BTN-STATE-02` | 禁用按钮不得触发请求；禁用原因必须可发现、可访问，且不能只存在于 hover tooltip。 |

禁用、只读、隐藏和未实例化是不同状态。禁用表示按钮存在但当前不可执行；只读表示动作不允许改变数据但可读取；隐藏表示当前权限或上下文不应暴露入口；未实例化表示该能力未启用，DOM、state、handler 和 request 入口均为 0。

## BTN-ASYNC 异步、防重复和请求身份

| 规则 ID | 规则 |
| --- | --- |
| `BTN-ASYNC-01` | 接受按钮意图时必须冻结请求身份；点击、Enter、Space、触摸和事件重放必须进入同一去重门禁。 |
| `BTN-ASYNC-02` | loading 中按钮必须保留动作对象的可访问名称，例如“正在保存模板”，不能只剩 spinner 或“加载中”。 |

按钮触发异步请求时，`requestIdentity` 至少记录来源 `buttonId`、操作类型、幂等键、权限版本、目标快照和发起者。重复点击、键盘重复触发、触摸重复触发、重放事件和迟到响应都不得增加请求数或终态处理数。

loading 不得自动改写容器关闭路径。表单提交由 Form owner 决定 `submitPhase`；Dialog/Drawer 关闭由容器 owner 决定；任务取消由 Admin/Job owner 决定。按钮 owner 只负责触发入口、防重复、可访问状态和结果入口可达性。

## BTN-DANGER 危险按钮与风险操作

| 规则 ID | 规则 |
| --- | --- |
| `BTN-DANGER-01` | 删除、停用、清空、权限变更、敏感导出、批量修改、取消任务、重跑任务和不可逆配置变更默认是危险或高风险按钮。 |
| `BTN-DANGER-02` | 危险按钮不能只靠颜色表达风险，也不能只靠 Toast 表达结果；必须声明影响范围、确认策略、请求身份、结果回执和恢复路径。 |

危险按钮必须声明风险级别、影响范围、确认策略、请求身份、结果回执、审计回执和失败恢复。风险确认可能是普通确认、强确认、二次输入或进入独立任务流程；选择哪一种由 Admin、Dialog、Drawer 和具体业务 owner 决定。按钮颜色只能辅助风险表达，不能替代文案、确认和回执。

关闭确认、Escape、路由离开或客户端关闭只影响客户端确认或界面状态；已发送请求不得被按钮文案写成“已取消”。取消任务按钮必须等待服务端结果，且结果区分取消中、已取消、取消失败、未知和过期。

## BTN-PERM 权限、泄露防护和禁用原因

| 规则 ID | 规则 |
| --- | --- |
| `BTN-PERM-01` | 禁用不是安全边界；权限不足、租户变化或敏感对象不可见时必须执行对应权限 owner 的隐藏、失效或安全说明策略。 |
| `BTN-PERM-02` | 若显示禁用按钮会泄露敏感对象名称、数量或字段，应隐藏按钮或替换为安全说明。 |

权限、租户、工作区、角色或权限版本变化后，旧按钮、旧菜单、旧下载入口、旧确认和旧任务入口不得继续暴露。非敏感禁用原因应在页面内可发现，例如按钮旁文本、状态区、可访问描述、表格行内只读原因或 Alert；hover tooltip 只能作为补充。

## BTN-GROUP 图标按钮、更多菜单和工具栏

| 规则 ID | 规则 |
| --- | --- |
| `BTN-GROUP-01` | 更多菜单可收纳低频操作，但触发按钮必须说明对象，例如“更多用户操作”。 |
| `BTN-GROUP-02` | 危险操作进入菜单后仍保留风险标记、确认、请求身份和结果回执。 |

图标按钮、菜单触发按钮、批量工具栏按钮和折叠操作按钮都必须保留动作对象。更多菜单不得成为隐藏权限原因、错误、确认后果或唯一恢复入口的地方。移动端折叠按钮组时，核心操作、危险确认、错误恢复、审计回执和任务结果入口不能消失。

## BTN-A11Y 键盘、焦点和公告

| 规则 ID | 规则 |
| --- | --- |
| `BTN-A11Y-01` | 真实按钮支持 Enter 和 Space；焦点样式必须可见；鼠标、触摸和键盘触发同一业务意图时使用同一状态转换。 |
| `BTN-A11Y-02` | 完整错误、成功、冲突或未知结果消息只能由一个 primary owner 公告；按钮不得重复播报完整消息。 |

按钮应在自然 Tab 顺序中可达，焦点顺序与视觉任务顺序一致。禁用按钮是否可聚焦由具体语义决定：原生 disabled 不可聚焦；需要说明原因时应提供可达说明，不得依赖不可聚焦控件自身。按钮触发结果后，焦点恢复、保持或迁移必须由对应 owner 统一决定，按钮不得用延迟回调抢焦点。

## BTN-RSP 响应式、触摸和安全区域

| 规则 ID | 规则 |
| --- | --- |
| `BTN-RSP-01` | 移动端可折叠次要按钮，但核心操作、危险确认、错误恢复和审计回执不能消失。 |
| `BTN-RSP-02` | 低高度、虚拟键盘、200% 缩放和安全区域下，提交、取消、重试、危险确认和恢复按钮必须可达。 |

触摸目标不能依赖精确点击；拖拽、长按或滑动不能成为关键按钮动作的唯一路径。按钮组转为底部操作区、更多菜单或全宽布局时，必须保留相同业务语义、请求身份、禁用原因、风险等级、结果 owner 和验证边界。

## 可执行验收场景

### BTN-A1：按钮语义与键盘

- 初始状态：页面存在保存、删除、导出和行操作按钮。
- 事件序列：检查 DOM 语义，并分别用鼠标、触摸、Enter 和 Space 触发。
- 预期状态：业务按钮使用原生 `<button>` 或等价语义；所有输入方式进入同一状态转换和去重门禁。
- DOM/ARIA：按钮有可访问名称、可见焦点和正确禁用语义；假按钮验收失败。
- 事件日志：记录每种输入方式的 accepted intent、request count 和 duplicate count。

### BTN-A2：文案、对象和图标按钮名称

- 初始状态：页面包含文字按钮、图标按钮和更多菜单按钮。
- 事件序列：读取可见文本、accessible name、tooltip、菜单项和结果回执。
- 预期状态：每个按钮名称都包含动作和对象；图标按钮名称不只来自 tooltip；loading 或折叠后名称仍保留对象。
- DOM/ARIA：`accessibleName` 不为空，不只写“确定”“提交”“更多”。
- 事件日志：记录按钮 `buttonId`、可见文案、可访问名称和结果 owner。

### BTN-A3：主按钮唯一和按钮组层级

- 初始状态：表单页脚、Dialog 页脚、表格工具栏和批量操作区各有按钮组。
- 事件序列：统计每个任务区的 `primary`、`secondary`、`danger` 和 `tertiary`。
- 预期状态：每个任务区最多一个主按钮；危险动作与普通主操作分离；更多菜单只收纳低频操作。
- DOM/ARIA：按钮组顺序稳定，危险入口名称和分区可读。
- 事件日志：记录 taskAreaId、primary count、danger count 和分组结果。

### BTN-A4：禁用、隐藏和权限泄露

- 初始状态：权限不足、选择为空、表单 invalid、任务不可取消和敏感对象不可见五类场景同时存在。
- 事件序列：分别检查按钮 availability、禁用原因和权限变化后的旧入口。
- 预期状态：禁用按钮不触发请求；非敏感原因可发现且可访问；敏感按钮隐藏或替换为安全说明；旧入口失效。
- DOM/ARIA：禁用原因不能只在 hover tooltip；泄露敏感对象名称、数量或字段的禁用按钮数量为 0。
- 事件日志：记录 `disabledReasonOwner`、隐藏原因、request count 和权限版本。

### BTN-A5：loading、防重复和请求身份

- 初始状态：保存模板、导出当前筛选结果和重试任务按钮可用。
- 事件序列：点击后立刻重复点击、按 Enter、按 Space、触摸重复触发并交付迟到响应。
- 预期状态：每个合法意图只冻结一个 `requestIdentity`，请求数为 1；重复触发被忽略；loading 名称保留动作对象。
- DOM/ARIA：按钮 busy/loading 状态可读，名称不是仅 spinner 或“加载中”。
- 事件日志：记录 `requestIdentity`、duplicate ignored、终态 owner 和迟到响应丢弃。

### BTN-A6：危险按钮确认与回执

- 初始状态：删除用户、批量停用、敏感导出和取消任务按钮存在。
- 事件序列：尝试不确认直接提交、完成确认后提交、关闭确认、发送取消请求并等待结果。
- 预期状态：未满足确认策略时请求数为 0；确认后请求身份完整；结果有成功、失败、冲突、未知和审计回执；已发送任务不被客户端关闭伪装为已取消。
- DOM/ARIA：风险、影响范围、确认输入、结果回执和恢复入口可读。
- 事件日志：记录风险级别、影响范围、confirmationPolicy、requestIdentity、resultReceipt 和 auditReceipt。

### BTN-A7：批量、导出和任务按钮

- 初始状态：表格启用当前页选择、全部筛选结果选择、导出和异步任务。
- 事件序列：在空选择、待重新确认选择、权限变化、筛选变化和有效选择下触发批量按钮。
- 预期状态：空/失效/待确认选择请求数为 0；有效批量按钮绑定选择快照、权限版本、影响范围和幂等键；下载按钮重验权限。
- DOM/ARIA：批量按钮和导出按钮名称说明范围；不可用原因可达。
- 事件日志：记录 selectionSnapshotId、permissionVersion、impactScope、idempotencyKey 和 downloadIdentity。

### BTN-A8：响应式折叠与运行时验证边界

- 初始状态：桌面工具栏含主按钮、次按钮、危险按钮、错误恢复和任务结果入口。
- 事件序列：切换到窄屏、低高度、200% 缩放、虚拟键盘和安全区域视口。
- 预期状态：次要按钮可折叠；核心操作、危险确认、错误恢复、审计回执和任务结果入口仍可达；按钮语义和请求身份不变。
- DOM/ARIA：折叠入口有名称，触摸目标可用，焦点不被固定区域或键盘完全遮挡。
- 事件日志：记录 viewport、foldedActions、reachableCoreActions 和 runtimeVerification。

## 完成前检查

- 检查业务按钮是否使用原生 `<button>` 或等价语义、键盘和焦点。
- 检查按钮文案和可访问名称是否包含动作对象，图标按钮不能只靠 tooltip。
- 检查每个任务区是否最多一个主按钮，危险按钮是否与普通主操作分离。
- 检查禁用、隐藏、未实例化和只读状态是否区分，禁用原因是否可访问且不泄露敏感信息。
- 检查 loading 是否保留动作对象名称，重复点击、Enter、Space、触摸和事件重放是否去重。
- 检查危险按钮是否声明影响范围、确认策略、请求身份、结果回执、审计和失败恢复。
- 检查批量、导出和任务按钮是否绑定快照、权限版本、幂等和结果 owner。
