# 分步流程与配置向导交互规范

本文件是分步流程、配置向导、创建向导、导入向导、发布流程、分步表单、步骤条、步骤器、上一步、下一步、跳过步骤、保存草稿、恢复草稿、复核页、确认页、预览步骤、完成页、流程结果、多步骤提交、跨步校验和步骤错误的唯一 owner。

分步流程不是多个表单页面的简单拼接。它必须有一个流程 owner 统一管理步骤状态、跨步依赖、草稿、复核快照、最终提交、离开保护、结果回执和恢复路径。

## 状态模型

每个分步流程必须声明 `wizardState`，至少包含：

| 字段 | 要求 |
| --- | --- |
| `wizardOwnerId` | 流程 owner；一个业务流程只能有一个主 owner。 |
| `flowKind` | `create`、`edit`、`import`、`publish`、`configure`、`permissionChange`、`planChange`、`riskReview` 或 `asyncJob`。 |
| `stepRegistry` | 步骤 ID、标题、顺序、可选性、依赖、进入条件、完成条件和错误归属。 |
| `currentStepId` | 当前步骤 ID；不得只用数组 index 表示当前步骤。 |
| `stepStates` | `notStarted`、`current`、`complete`、`error`、`skipped`、`blocked`、`invalidated`、`validating` 或 `asyncPending`。 |
| `stepDrafts` | 各步骤字段、上传、选择器、预览和局部草稿。 |
| `committedStepValues` | 每步已提交业务值；只由明确下一步、应用、完成当前步或等价意图写入。 |
| `crossStepValidation` | 跨步依赖、冲突、失效、预检结果和可恢复错误。 |
| `progressPolicy` | 是否允许跳步、返回、跳过、保存草稿、恢复草稿、重开流程和直接完成。 |
| `reviewSnapshot` | 复核页展示并等待最终提交的不可变快照。 |
| `submitSnapshot` | 最终提交使用的不可变 payload、权限版本、幂等键、风险确认状态和请求身份。 |
| `asyncTaskBinding` | 异步任务 ID、任务状态、结果、取消边界、重试、任务中心入口和审计入口。 |
| `exitPolicy` | 取消、关闭、返回、路由离开、未保存保护、放弃草稿和恢复策略。 |
| `responsivePolicy` | 移动端步骤呈现、折叠策略、固定操作区、虚拟键盘和安全区域。 |
| `a11yPolicy` | 步骤导航语义、当前步骤公告、错误摘要、键盘顺序和焦点恢复。 |

## 原子规则

| ID | 规则 |
| --- | --- |
| WIZ-SCOPE-01 | Wizard、Stepper、多步骤表单、分步创建、配置向导、导入向导、发布流程和复核确认页必须声明 `wizardState`。 |
| WIZ-SCOPE-02 | 每个步骤可以拥有表单、上传、选择器或图表，但全局步骤状态、跨步依赖和最终提交由 wizard owner 管理。 |
| WIZ-SCOPE-03 | 流程不能由“当前页面 index + 若干局部表单状态”临时拼接。 |
| WIZ-SCOPE-04 | 分步流程的承载面仍读取 Dialog、Drawer、独立页、导航和响应式 owner；wizard owner 只负责流程语义。 |
| WIZ-SCOPE-05 | 未声明为分步流程的普通表单不得因为有多个区块就伪造 Stepper。 |
| WIZ-STEP-01 | 每个步骤必须有稳定 ID、标题、进入条件、完成条件和错误归属。 |
| WIZ-STEP-02 | 当前、完成、错误、跳过、阻塞、失效和异步等待必须可见且可访问。 |
| WIZ-STEP-03 | 步骤标题不能只显示数字；必须让用户理解每步任务。 |
| WIZ-STEP-04 | 步骤完成状态必须来自该步骤 owner 的合法提交值和跨步校验结果，不得只因用户访问过该步骤而完成。 |
| WIZ-STEP-05 | 跳过、阻塞和失效步骤必须说明原因、影响范围和恢复路径。 |
| WIZ-NAV-01 | 上一步、下一步、跳过、直接跳转、保存草稿、取消和完成必须是不同意图。 |
| WIZ-NAV-02 | 禁用下一步或完成时必须说明原因，不能只禁用按钮。 |
| WIZ-NAV-03 | 跳过步骤必须声明是否会产生默认值、空值、不适用状态或后续限制。 |
| WIZ-NAV-04 | 直接跳转步骤必须先验证进入条件；不得绕过必经步骤、权限复核、预检或风险确认。 |
| WIZ-NAV-05 | 上一步不得丢弃当前步骤草稿，除非 exitPolicy 明确要求并提示用户。 |
| WIZ-DRAFT-01 | `stepDrafts`、`committedStepValues`、`reviewSnapshot` 和 `submitSnapshot` 必须分离。 |
| WIZ-DRAFT-02 | 自动保存、手动保存草稿、恢复草稿和放弃草稿必须声明范围、时机、权限和过期策略。 |
| WIZ-DRAFT-03 | 恢复草稿必须重新校验权限、依赖、选项有效性、文件引用、时间范围和业务版本。 |
| WIZ-DRAFT-04 | 草稿保存成功不等于流程提交成功；必须用不同文案、状态和回执表达。 |
| WIZ-DRAFT-05 | 多设备、重复打开或旧草稿恢复冲突时，必须说明保留、覆盖、合并或放弃策略。 |
| WIZ-VALID-01 | 上游步骤变化后，依赖它的后续步骤、预检、预览、费用、权限、导出范围和确认摘要必须失效或重算。 |
| WIZ-VALID-02 | 跨步错误必须归属明确步骤、字段组或流程级 owner，并提供跳转修复路径。 |
| WIZ-VALID-03 | 异步预检和跨步校验的迟到结果不得写回新草稿或新步骤状态。 |
| WIZ-VALID-04 | 步骤内字段错误、跨步错误和流程级错误必须可区分，且完整错误不能重复播报。 |
| WIZ-VALID-05 | 后续步骤因上游变化失效时，用户必须知道哪些内容需要重新确认。 |
| WIZ-REVIEW-01 | 最终提交前的复核页必须展示会改变业务结果、权限、费用、数据范围、风险和审计的信息。 |
| WIZ-REVIEW-02 | 最终提交只能读取仍有效的 `reviewSnapshot` / `submitSnapshot`，不得读取正在编辑的草稿。 |
| WIZ-REVIEW-03 | 提交前必须冻结权限版本、目标快照、幂等键、风险确认状态和请求身份。 |
| WIZ-REVIEW-04 | 复核页中的“返回修改”必须回到对应步骤，并在修改后失效旧复核快照。 |
| WIZ-REVIEW-05 | 提交中必须防止重复提交；重复点击、Enter、触摸和事件重放只能复用同一 `submitSnapshot` 或被拒绝。 |
| WIZ-RESULT-01 | 完成状态必须区分成功、部分成功、失败、冲突、未知、异步处理中、已取消和过期。 |
| WIZ-RESULT-02 | 长耗时或异步流程必须提供任务中心、详情页、审计入口或结果页，不得只靠 Toast。 |
| WIZ-RESULT-03 | 取消客户端流程不等于取消服务端任务；必须说明取消边界。 |
| WIZ-RESULT-04 | 部分成功必须展示成功、失败、跳过、未知、影响范围、下一步和错误明细入口。 |
| WIZ-RESULT-05 | 结果页或回执必须绑定 `submitSnapshot`、任务身份、权限版本和审计状态。 |
| WIZ-PERM-01 | 权限、租户、工作区、角色或数据范围变化后，步骤、草稿、预检、预览、复核和提交入口必须重新证明安全。 |
| WIZ-PERM-02 | 无权限状态不得泄露对象名称、数量、字段、文件名、导入内容、费用、权限范围、内部 ID 或旧缓存。 |
| WIZ-PERM-03 | 权限变更、敏感导出、批量修改和不可逆发布必须进入 `risk-actions.md`。 |
| WIZ-PERM-04 | 恢复草稿和返回步骤时，旧选项标签、旧文件名、旧对象名和旧费用不得绕过权限重校验。 |
| WIZ-PERM-05 | 复核页和结果页不得显示用户当前无权查看的旧快照敏感内容。 |
| WIZ-RSP-01 | 移动端可以把横向 Stepper 转为垂直步骤、Accordion、分步全屏页或底部固定操作流程。 |
| WIZ-RSP-02 | 移动端不得删除步骤标题、当前进度、步骤错误、上一步、下一步、保存/放弃草稿、复核页、取消路径、结果回执或恢复入口。 |
| WIZ-RSP-03 | 低高度、虚拟键盘和安全区域下，当前字段、步骤错误、底部主操作和返回路径必须可达。 |
| WIZ-RSP-04 | 断点转换时必须保持同一 wizard owner、当前步骤、草稿、错误、预检、复核快照和提交状态。 |
| WIZ-RSP-05 | 移动端折叠步骤必须显示错误数量、阻塞原因或完成状态，不能把问题藏在不可见内容里。 |
| WIZ-A11Y-01 | Stepper 必须有可访问名称，当前步骤、完成步骤、错误步骤和禁用步骤必须可被辅助技术理解。 |
| WIZ-A11Y-02 | 键盘顺序必须覆盖步骤导航、当前步骤内容、错误摘要、上一步/下一步/取消/完成和恢复入口。 |
| WIZ-A11Y-03 | 步骤切换、跨步错误、保存草稿、恢复草稿、提交开始和结果状态必须由唯一 owner 公告。 |
| WIZ-A11Y-04 | 步骤错误摘要必须能跳转到对应步骤和字段组。 |
| WIZ-A11Y-05 | 当前步骤变化后焦点必须移动到合理目标，不能被旧步骤迟到回调抢走。 |
| WIZ-LIFE-01 | 步骤切换、保存草稿、预检、预览、提交、结果轮询和恢复回调必须绑定 live wizard owner、步骤 generation 和快照。 |
| WIZ-LIFE-02 | route/unmount、关闭容器、断点转换和权限变化必须清理仅属于该流程的监听、请求、轮询、草稿锁和焦点回调。 |
| WIZ-LIFE-03 | 旧步骤、旧草稿、旧预检、旧预览或旧提交的迟到响应不得覆盖当前流程状态。 |
| WIZ-LIFE-04 | 流程完成后再次打开必须创建新流程实例，除非产品明确选择继续旧草稿或查看旧结果。 |
| WIZ-LIFE-05 | 未执行真实浏览器、键盘、读屏、触摸、移动端、断点转换、权限变化和异步竞态检查时，必须标为未验证。 |

## 场景化要求

### 多步骤创建和配置

- 下一步只提交当前步骤的合法业务值，不等于最终提交。
- 返回上一步修改后，后续依赖步骤必须进入 invalidated 或重新计算。
- 完成前必须有复核页或等价复核区，展示关键配置、权限、风险、费用、范围和审计影响。

### 导入向导

- 文件选择、上传、预检、字段映射、复核、提交和结果页必须有独立步骤状态。
- 文件引用过期、字段映射变化或预检版本变化后，后续复核和提交快照失效。
- 导入结果影响列表或报表时，结果页必须说明刷新、跳转、下载错误明细和任务中心路径。

### 风险或权限流程

- 权限变更、敏感导出、批量修改、不可逆发布和套餐变更必须在复核页展示影响范围。
- 风险确认状态必须进入 `submitSnapshot`；确认前请求数为 0。
- 最终结果必须有页面内回执、审计或任务入口，Toast 只能辅助提示。

### 移动端分步流程

- 移动端可以采用单步全屏、垂直 Stepper、Accordion 或底部固定操作。
- 当前进度、步骤标题、错误、上一步、下一步、保存/放弃草稿、复核页、取消路径和结果回执必须保留。
- 虚拟键盘打开时，当前字段错误和底部主操作不得被完全遮挡。

## 完成前检查

1. 是否声明 `wizardState` 及全部必要字段。
2. 每个步骤是否有稳定 ID、标题、进入条件、完成条件和错误归属。
3. 上一步、下一步、跳过、直接跳转、保存草稿、取消和完成是否是不同意图。
4. `stepDrafts`、`committedStepValues`、`reviewSnapshot` 和 `submitSnapshot` 是否分离。
5. 恢复草稿是否重新校验权限、依赖、选项有效性、文件引用、时间范围和业务版本。
6. 上游变化后，依赖它的后续步骤、预检、预览、费用、权限、导出范围和确认摘要是否失效或重算。
7. 最终提交是否只读取仍有效的 `reviewSnapshot` / `submitSnapshot`。
8. 完成状态是否区分成功、部分成功、失败、冲突、未知、异步处理中、已取消和过期。
9. 移动端是否保留步骤标题、当前进度、步骤错误、上一步、下一步、保存/放弃草稿、复核页、取消路径、结果回执和恢复入口。
10. 未实际执行运行时检查时，是否明确标为未验证。
