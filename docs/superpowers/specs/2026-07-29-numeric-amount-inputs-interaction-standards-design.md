# 数字、金额、比例与配额输入交互规范设计

## 背景

管理台里数字字段的使用频率很高：金额、百分比、额度、阈值、排序、数量、时长、容量、折扣和预算都依赖它。但现有规范主要覆盖通用表单、字段说明、计费、按钮和权限，还缺少一个专门 owner 来约束数字字段的草稿、解析、单位、精度、边界、格式化和提交快照。

## 推荐方案

新增 `references/numeric-amount-inputs.md` 作为数字型输入 owner，并接入 `SKILL.md` 路由、`README.md`、`HANDOFF.md` 以及相邻 owner。该 owner 不替代 `forms.md`，只负责数字字段内部的语义正确性：`draftText`、`parsedValue`、`committedValue` 分离；金额/百分比/容量/时长/配额必须声明单位和倍率；精度、舍入、步进和边界必须可解释；移动端、IME、粘贴和读屏必须可验证。

相比只在表单规范里补几条规则，独立 owner 更适合管理台高频复用，也能避免金额、额度、阈值这类高风险字段被当成普通文本框。相比做组件库实现规范，本方案保持项目无关，只定义验收契约。

## 范围

覆盖数字输入、金额输入、百分比输入、费率、比例、配额、数量、排序、权重、阈值、折扣、税率、汇率、单价、余额、库存、并发数、超时时长、保留天数、存储容量、席位数、调用额度和预算上限。

不覆盖后端计费、数据库类型、真实财税规则、图表坐标轴展示或只读指标卡；这些只在提供可编辑数字入口时转交本 owner。

## 关键验收

- 数字字段必须声明 `numericInputState`。
- `draftText`、`parsedValue`、`committedValue` 必须分离。
- 空值、0、负数和非法值不得混用。
- 金额声明币种，百分比声明提交倍率，容量/时长/配额声明单位与周期。
- 精度、舍入、截断、步长、硬边界和软边界必须明确。
- `input[type=number]`、`Number(value)`、`parseFloat` 或组件库 formatter 不能替代 owner。
- 粘贴、全角数字、本地化小数点、百分号、货币符号、单位后缀和 IME composition 必须有策略。
- 无权限不得泄露金额、余额、额度、阈值、历史值、旧 aria-label 或错误明细。
- 移动端不得删除单位、错误、边界、保存/取消、恢复和权限说明。
- 未实际执行浏览器、读屏、移动端、输入法、粘贴、权限切换和服务端回填验证时，必须标为未验证。

## 测试策略

新增结构化审计脚本 `docs/testing/numeric-amount-inputs/numeric-amount-inputs-audit.rb`：

- 检查 owner 文档包含状态字段、硬性规则和完成前检查。
- 检查 `SKILL.md` 路由能命中中文与英文关键词。
- 检查 `README.md` 与 `HANDOFF.md` 接入。
- 检查相邻 owner 已引用本 owner 与 `numericInputState`。
- 使用 mutation 模式确认删除核心约束会失败。
- 执行项目泄漏扫描，防止出现具体业务项目、框架或本地路径。
