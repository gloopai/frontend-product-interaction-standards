# 图表与可视化创作配置交互规范设计

## 背景

现有 `charts-visualization.md` 已经约束图表作为数据展示时的口径、快照、视觉编码、tooltip、导出、移动端和可访问性；`complex-editors-builders.md` 已经约束复杂编辑器的通用草稿、预览、保存和发布边界。但管理台里还有一类高频场景位于两者之间：用户正在创建或编辑一个图表配置。

这类场景通常包含数据源选择、指标选择、维度选择、聚合方式、筛选绑定、图形类型切换、颜色/series/轴配置、预览、保存、发布、复制图表、加入仪表盘和导出配置。它比普通表单更复杂，也比通用编辑器更有图表专属风险。常见问题包括：预览成功被当成保存成功；切换图形类型静默丢失字段；保存读取 Select query 或筛选草稿；只校验当前可见配置面板；图形类型与指标/维度不兼容却仍能保存；保存后的配置与预览快照不一致；发布请求发送被当成仪表盘已生效；移动端删掉预览、错误定位或字段映射。

## 目标

新增 `references/chart-visualization-builders.md`，作为图表创建、图表编辑、可视化配置、报表图表配置、仪表盘图表配置、图表构建器和图表配置向导的专属 owner。

该 owner 约束：

- 图表配置器身份、数据源快照、字段能力、指标草稿、维度草稿、编码草稿、筛选绑定、图形类型和预览快照。
- 指标、维度、聚合、图形类型、轴、图例、颜色、tooltip、钻取、导出和明细能力的配置合法性。
- 草稿、预览、保存、发布、复制、加入仪表盘、导出配置、回滚和删除的意图边界。
- 预览数据、保存配置和已发布图表之间的版本与权限收敛。
- 移动端、低高度视口、虚拟键盘、拖拽配置、字段映射和错误定位的核心能力一致性。

## 非目标

- 不替代 `charts-visualization.md` 的图表展示语义；保存或发布后的图表仍必须执行展示 owner。
- 不替代 `complex-editors-builders.md` 的通用复杂编辑器生命周期；本 owner 提供图表配置器的专属状态和校验，通用编辑器规则仍兼容执行。
- 不替代 `query-filters.md` 的筛选草稿/已应用边界。
- 不替代 `data-tables.md` 的明细表规则。
- 不替代 `date-time-ranges.md` 的时间范围、时区、相对时间和数据延迟规则。
- 不定义具体 BI 引擎、图表库、SQL 编辑器、指标平台或数据建模方案。

## 方案比较

### 方案 A：增强 `charts-visualization.md`

优点是用户看到“图表”就读一个文件。缺点是展示和创作混在一起后，展示 owner 会被图表配置器的草稿、预览、保存、发布、字段映射和配置校验规则拖得过重；之后评审只读报表时也会读到大量不适用规则。

### 方案 B：增强 `complex-editors-builders.md`

优点是所有构建器规则集中。缺点是图表配置的专属风险很容易被通用规则稀释，例如图形类型与维度数量不兼容、聚合分母变化、预览快照与保存配置不一致、series 颜色映射迁移、钻取目标权限复核等。

### 方案 C：新增独立 `chart-visualization-builders.md`

优点是职责清晰：展示图表读 `charts-visualization.md`，通用复杂编辑器读 `complex-editors-builders.md`，图表配置器读本 owner 并兼容执行两者。缺点是新增一个路由和一套审计文件。

推荐方案 C。它保持单一事实来源，同时避免把“展示图表”和“编辑图表配置”混成一个大文件。这个边界有点像厨房和菜单：展示 owner 管上桌的菜是否可读可信，builder owner 管后厨配方、预览、保存和发布是否安全。

## `chartBuilderState`

每个图表配置器必须声明 `chartBuilderState`：

| 字段 | 含义 |
| --- | --- |
| `chartBuilderOwnerId` | 当前图表配置器实例身份，绑定对象、租户/工作区、权限版本、来源配置版本和承载面。 |
| `sourceConfigSnapshot` | 进入编辑时读取的已保存或已发布配置快照，包括版本、作者、更新时间、发布状态和只读状态。 |
| `dataSourceBinding` | 数据源、数据集版本、可用字段、字段类型、权限范围、刷新时间、数据延迟和不可用原因。 |
| `metricDraft` | 指标选择、聚合方式、单位、分母、过滤条件、比较基准、计算状态和口径说明草稿。 |
| `dimensionDraft` | x/y/color/size/facet/group 等维度草稿、排序、缺失值策略、Top N、其他项和权限过滤。 |
| `encodingDraft` | 图形类型、颜色、线型、堆叠、面积、轴、图例、tooltip、数据标签、参考线和阈值线草稿。 |
| `interactionDraft` | drilldown、legend toggle、brush、zoom、联动筛选、导出、查看明细和加入仪表盘能力草稿。 |
| `filterBindingDraft` | 图表内筛选、页面筛选绑定、时间范围绑定、URL 安全、默认值和应用边界。 |
| `previewState` | 预览请求身份、预览数据快照、样本/全量边界、权限过滤、错误、过期和与保存配置的一致性。 |
| `validationState` | 图形类型兼容、字段类型兼容、指标/维度数量、聚合合法性、口径缺失、权限缺失、钻取目标、导出范围和隐藏面板错误。 |
| `savePolicy` | 保存草稿、保存副本、覆盖配置、幂等键、防重复、保存结果回执和未知结果恢复。 |
| `publishPolicy` | 发布、加入仪表盘、替换已发布图表、撤销发布、发布结果未知、旧图表配置失效和审计入口。 |
| `permissionBoundary` | 数据源、字段、指标、预览、保存、发布、复制、导出、钻取和明细权限收敛。 |
| `responsivePolicy` | 移动端、虚拟键盘、字段面板、预览面板、拖拽配置、错误定位、底部操作和安全区域策略。 |

## 核心规则

### 草稿、预览、保存和发布分层

指标选择、维度选择、聚合方式、图形类型、编码、筛选绑定、钻取、导出和明细能力的编辑只能写入对应草稿字段。预览成功不等于保存成功；保存成功不等于发布成功；发布请求发送不等于仪表盘或外部嵌入已生效；加入仪表盘请求发送不等于仪表盘已更新。

保存和发布必须读取当前 `chartBuilderState` 的完整草稿、校验状态、权限版本、数据源版本、来源配置版本和幂等键。校验未完成、预览过期、权限不可证明、来源版本冲突或图形类型不兼容时，请求数为 0。

### 图形类型与字段兼容性

图形类型不能只按组件库默认值切换。每种图形类型必须声明可接受的指标数量、维度数量、字段类型、时间轴要求、是否允许多 series、是否允许堆叠、是否允许百分比、是否允许双轴和是否需要分母。切换图形类型时，不能静默删除不兼容配置；必须展示迁移摘要、待修复项、保留项、丢弃项和撤销/取消路径。

折线图、柱状图、饼图、散点图、热力图、漏斗图、排行图、组合图和迷你趋势图都必须由明确兼容规则决定是否可保存。不能让“预览能画出来”替代配置合法性。

### 数据源、指标和维度边界

数据源字段列表必须绑定数据集版本、权限范围、字段类型和刷新时间。无权限字段、不可用字段、已删除字段、类型变化字段和旧缓存字段不得进入可选列表、预览、保存配置、导出配置或错误详情。

指标草稿必须声明口径、单位、聚合、分母、排除项和比较基准。维度草稿必须声明分组语义、排序、缺失值策略、Top N 和“其他”项。保存时不得读取 Select query、active option、筛选草稿、hover 字段、预览高亮、当前可见结果或旧缓存。

### 预览可信边界

预览必须声明读取的是当前草稿、已保存配置还是已发布配置，并说明预览数据是样本、当前筛选全量、聚合后结果还是权限过滤后的结果。预览失败、预览超时、预览权限不足、预览过期或预览与保存配置不一致时，不能清空草稿，也不能允许发布绕过校验。

预览图表本身必须执行 `charts-visualization.md` 的展示规则：口径、单位、时间范围、图例、tooltip、空态、权限和移动端替代表达不能因为“只是预览”而省略。

### 完整校验和错误定位

配置器必须校验完整配置，而不是只校验当前可见面板。折叠面板、隐藏字段、高级配置、钻取目标、导出范围、tooltip 字段、颜色映射、双轴、Top N、权限不可见字段、旧数据源字段和旧图表类型残留都必须进入 `validationState`。

错误必须定位到字段、指标、维度、编码、轴、图例、tooltip、钻取、导出、筛选绑定、预览或发布设置。无法定位到具体控件时，错误摘要必须说明影响范围和下一步，不能只 Toast。

### 权限、版本和旧配置清理

权限、租户/工作区、数据源版本、字段版本、指标口径、来源配置版本、发布版本、仪表盘版本或会话状态变化后，旧字段列表、旧预览、旧保存按钮、旧发布按钮、旧导出配置、旧钻取目标、旧颜色映射、旧复制内容、旧焦点目标和旧 ARIA 引用必须失效或重新证明安全。

无权或未启用时，数据源选择、字段选择、指标选择、预览、保存、发布、复制、导出、钻取配置、加入仪表盘和查看明细配置的 DOM、state、handler、request 和快捷键入口为 0。

### 移动端和响应式承载

移动端不得删除数据源说明、指标配置、维度配置、图形类型、预览、完整校验、错误定位、保存草稿、发布/加入仪表盘、权限原因、版本冲突、恢复路径和离开保护。

复杂配置可以在移动端转为分步配置、全屏 Drawer、独立页或“配置 + 预览”切换视图，但必须保留同一个 `chartBuilderState`、同一个草稿、同一个校验状态、同一个预览身份和同一个保存/发布门禁。虚拟键盘、低高度、横竖屏、系统字体放大、拖拽排序、字段面板和底部操作出现后，关键配置、预览状态、错误摘要、保存、取消和发布仍必须可见或可滚动到达。

## 与现有 owner 的关系

- `charts-visualization.md`：负责图表展示。配置器的预览图表和已发布图表都必须执行展示 owner。
- `complex-editors-builders.md`：负责通用复杂编辑器生命周期。本 owner 是图表配置器专属细化，不能降低通用草稿、校验、预览、保存、发布和移动端规则。
- `forms.md`：负责字段级 dirty/touched、错误和提交边界。本 owner 负责跨字段图表配置合法性。
- `query-filters.md`：负责筛选草稿与已应用条件。图表配置保存不得读取未提交筛选草稿。
- `date-time-ranges.md`：负责时间范围、时区和相对时间。图表配置预览、保存和发布必须绑定明确时间快照或声明继承策略。
- `data-tables.md`：负责明细表和查看明细入口。
- `risk-actions.md`：负责覆盖发布图表、替换仪表盘图表、删除图表、撤销发布、敏感导出能力等高风险动作。
- `permissions-tenancy-visibility.md`：负责无权限、只读、隐藏、禁用、未启用和旧缓存无泄露。
- `exports-downloads-artifacts.md`：负责导出图表配置、导出预览数据、导出明细和下载结果产物。
- `responsive-adaptive.md`：负责移动端、虚拟键盘、触摸、缩放和安全区域。

## 审计设计

新增 `docs/testing/chart-visualization-builders/chart-visualization-builders-audit.rb`，采用现有 Ruby 静态审计模式。

审计需要验证：

1. owner 文件存在，且包含 `chartBuilderState` 与全部状态字段。
2. `SKILL.md` 包含图表创建、编辑、配置、图表构建器、指标配置、维度配置、聚合配置、图形类型切换、图表预览、保存/发布图表等中英文触发词。
3. `README.md` 和 `HANDOFF.md` 只保留摘要和 owner 路径，不重复完整规则。
4. RED/GREEN 证据覆盖预览即保存、保存即发布、图形类型静默丢配置、预览能画即合法、保存读取 Select query/筛选草稿、只校验可见面板、旧字段/旧权限泄漏、移动端删除核心能力、运行时验证伪装已通过和项目专属泄漏。
5. owner 不包含业务项目路径、客户名、具体框架或图表库例外。

## 验收清单

- 每个图表配置器声明 `chartBuilderState` 全字段。
- 指标、维度、聚合、图形类型、编码、筛选绑定、钻取、导出和明细能力只写入草稿。
- 预览成功、保存成功、发布成功、加入仪表盘成功和未知结果有不同回执。
- 图形类型切换有兼容规则、迁移摘要、待修复项、保留项、丢弃项和取消/撤销路径。
- 保存请求不读取 Select query、active option、筛选草稿、hover 字段、预览高亮、当前可见结果或旧缓存。
- 完整校验覆盖折叠面板、隐藏字段、高级配置、钻取目标、导出范围、tooltip 字段、颜色映射、双轴、Top N、权限不可见字段、旧数据源字段和旧图表类型残留。
- 预览图表执行 `charts-visualization.md` 的展示规则。
- 权限、租户/工作区、数据源版本、字段版本、指标口径、来源配置版本、发布版本或仪表盘版本变化后，旧入口和旧结果失效。
- 无权或未启用时相关 DOM、state、handler、request 和快捷键入口为 0。
- 移动端保留数据源说明、指标配置、维度配置、图形类型、预览、完整校验、错误定位、保存草稿、发布/加入仪表盘、权限原因、版本冲突、恢复路径和离开保护。
- 未执行真实浏览器、真实图表库、真实数据源、真实预览、真实权限切换、键盘、触摸、读屏和移动端视口检查时，必须标为未验证。

## 自检结论

本设计聚焦单一 owner：图表与可视化创作配置。它不替代图表展示、不替代通用复杂编辑器、不定义具体图表库或业务指标平台，而是定义图表配置器自己的草稿、预览、校验、保存、发布、权限和响应式边界。文档没有引入具体业务项目例外；真实浏览器、真实图表库、真实数据源、触摸、读屏和移动端运行时验证明确留到具体项目实现阶段。
