# 记录新增/编辑承载面规范设计

## 背景

当前规范已经分别覆盖数据表格、表单、Dialog、Drawer、响应式和管理台治理，但缺少一个明确 owner 来回答“列表里的新增/编辑记录应该放在哪里”。实际产品中如果把新增或编辑表单直接内嵌到列表行、表格行、卡片列表或列表页内容区，容易造成列表查询状态、表单 dirty、权限降级、焦点恢复、错误 owner、响应式转换和审计回执混在一起，Agent 也容易把“方便就地编辑”误判成合理方案。这里也包括常驻可编辑列表：每一行直接渲染标题输入框、描述 textarea、正文 textarea、分类输入框、状态下拉、排序输入和“保存”按钮的形态。

本设计新增一个职责单一的记录编辑承载面 owner：禁止列表内嵌新增/编辑，强制在 Dialog、Drawer 或独立页面之间按场景选择。

## 目标

- 明确禁止在列表、表格、卡片列表或列表项展开区内直接承载新增/编辑记录表单。
- 明确禁止常驻可编辑列表、表格编辑矩阵、单元格编辑、行内输入控件和每行保存按钮作为记录新增/编辑形态。
- 定义 Dialog、Drawer、独立页面三种编辑承载面的选择规则。
- 保持现有组件 owner 的边界：表单生命周期仍由 `forms.md`，Dialog 由 `dialogs.md`，Drawer 由 `drawers.md`，列表/表格由 `data-tables.md`，跨端由 `responsive-adaptive.md`，管理台权限/审计/风险由 `admin-console.md`。
- 让 Agent 在写交互方案、评审或实现时不能用“列表内展开表单”“表格行内编辑”“卡片内新增”等方案绕过容器选择。

## 非目标

- 不重新定义表单字段、校验、提交、错误恢复的细节。
- 不重新定义 Dialog 或 Drawer 的遮罩、动画、关闭顺序、焦点陷阱和 disposal。
- 不新增表格行内编辑、单元格编辑、常驻可编辑列表或 spreadsheet-like 编辑矩阵能力；本规范把新增/编辑记录视为列表外承载面行为。
- 不禁止只读详情展开、行详情预览、只读状态展示或风险操作确认；这些不是新增/编辑表单，也不得在列表行内暴露字段编辑控件。

## 核心决策

### 1. 完全禁止列表内嵌新增/编辑

列表、表格、卡片列表和管理列表只负责浏览、筛选、排序、分页、选择、行操作入口、状态反馈和只读详情预览。新增记录、编辑记录、复制后创建、批量配置编辑等会创建或修改业务记录的表单，必须离开列表内容流，进入 Dialog、Drawer 或独立编辑页。

这里的“内嵌”不仅指展开式表单，也包括常驻可编辑行：列表每一行直接展示 input、textarea、select、数字排序输入、开关、日期选择器或“保存”按钮，都视为列表内编辑。列表行只能展示只读值和操作入口；字段编辑控件必须归属于 Dialog、Drawer 或独立页。

禁止形态包括：

- 在表格行下方展开完整编辑表单。
- 在卡片列表项内部展开新增/编辑字段。
- 在列表顶部或底部直接插入“新增记录”表单并与查询结果共享滚动区域。
- 整张列表常驻编辑态，每行直接放标题、描述、正文、分类、状态、排序等输入控件。
- 每行提供独立“保存”按钮，或在列表容器内提供批量保存按钮，用列表本身承载记录编辑事务。
- 把排序、状态、分类、标签等字段做成列表单元格内直接可改控件。
- 把批量编辑字段直接放进批量工具栏或表格容器内。
- 在筛选区域旁边混入新增/编辑业务字段。

### 2. Dialog / Drawer / 独立页选择矩阵

默认选择独立页；只有满足更窄条件时才使用 Drawer 或 Dialog。原因是完整编辑会话需要明确 owner、URL/返回路径、dirty 离开保护、错误恢复和权限审计。

| 承载面 | 适用场景 | 禁用场景 |
| --- | --- | --- |
| Dialog | 低复杂度、短流程、少字段、提交快、无需深链、不需要长期引用列表上下文的轻量新增/编辑。 | 字段多、需要滚动长表单、多步骤、异步校验多、权限/审计强、移动端键盘遮挡明显、需要可分享 URL。 |
| Drawer | 需要保留列表上下文、边看当前记录摘要边编辑、详情与编辑一体、字段中等、提交后回到同一列表上下文。 | 多步骤复杂流程、高风险强审计、需要独立 URL/刷新恢复、移动端无法稳定承载时。 |
| 独立页 | 多字段、多步骤、复杂校验、强权限/审计、深链接、刷新恢复、协作、文件上传、复杂关联数据、移动端主流程。 | 只有极轻量短表单且不需要深链时可降级为 Dialog/Drawer。 |

### 3. 触发与返回

列表中的“新增”“编辑”“复制创建”“配置”“批量编辑”只能作为入口，不承载编辑状态。触发时必须创建独立的 `editSurfaceState`，包含来源列表快照、记录身份、权限版本、编辑模式、承载面类型和返回策略。

返回列表时必须重新校验权限、数据版本和列表查询位置；不得把编辑前的旧行、旧菜单、旧选择或旧下载入口直接回放。成功后列表刷新、局部更新或保持旧结果必须由产品明确声明，并标注运行时验证边界。

### 4. 与现有 owner 的关系

- `forms.md`：所有新增/编辑字段值、dirty、submitPhase、submitSnapshot、submitId、错误摘要、失败恢复和 route/unmount disposal 均执行表单 owner。
- `dialogs.md`：选择 Dialog 时完整执行遮罩、不可遮罩关闭、动画、焦点、背景隔离、关闭顺序和 disposal。
- `drawers.md`：选择 Drawer 时完整执行抽屉方向、固定关闭按钮、内容滚动、焦点、背景隔离、关闭顺序和 disposal。
- `data-tables.md`：列表只保留编辑入口和返回后的查询/焦点/实例隔离；不得新增行内编辑能力。
- `responsive-adaptive.md`：断点变化不得把同一编辑会话重建为列表内表单；Dialog/Drawer 和独立页之间的形态转换必须保持同一表单会话。
- `admin-console.md`：后台/管理台场景还要执行权限、租户、风险、审计、任务和反馈 owner。

### 5. 例外策略

本规范不允许“完整新增/编辑记录”的列表内嵌例外。即便只是状态、分类、排序、标签等小型字段，也不得在列表单元格中常驻可编辑控件。需要快捷修改时，列表只放操作入口，例如“修改状态”“调整排序”“编辑标签”，进入 Dialog、Drawer 或独立页完成；纯命令式行操作可以保留，例如“启用”“停用”“重新发送”，但不得暴露字段编辑控件。

这类纯命令式行操作必须满足：

- 不暴露完整表单。
- 不暴露 input、textarea、select、日期选择器、排序输入或行内保存按钮。
- 不产生 dirty 长会话。
- 不需要多字段校验或错误摘要。
- 有明确请求身份、结果回执和失败恢复。
- 如有风险，走 Dialog 确认或管理台风险 owner。

如果不满足以上条件，就必须使用 Dialog、Drawer 或独立页。

6. Drawer 编辑规则
7. 独立页面编辑规则

稳定规则族建议：

- `RES-SCOPE-*`：范围、禁止项、例外边界。
- `RES-CHOICE-*`：Dialog / Drawer / page 选择。
- `RES-STATE-*`：`editSurfaceState`、来源列表快照、权限版本。
- `RES-LIST-*`：列表入口、返回、刷新和焦点。
- `RES-FORM-*`：表单 owner 绑定。
- `RES-RSP-*`：移动端和断点。
- `RES-AUDIT-*`：管理台权限/审计/风险衔接。

## 测试与验证策略

采用 RED/GREEN 文档压力测试：

- RED：在没有 owner 的情况下，让 fresh 输出为管理列表设计新增/编辑，记录其是否倾向列表内嵌表单、行内编辑或卡片内编辑。
- GREEN：启用 owner 后，同样任务必须选择 Dialog / Drawer / 独立页，并说明选择依据、状态、返回策略和未验证边界。
- 审计脚本：检查 owner 规则、路由、三类承载面选择、禁止内嵌、`editSurfaceState`、现有 owner 引用、mutation 反例。

关键 mutation：

- 把 Drawer 改成列表行下展开表单，必须失败。
- 删除 `editSurfaceState`，必须失败。
- 把复杂多步骤编辑放入 Dialog，必须失败。
- 把移动端复杂编辑放入 Drawer 且不全屏/不独立页，必须失败。
- 把成功后旧列表行直接回放且不重校验权限，必须失败。
- 将只读列表单元格改成 input、textarea、select、数字排序输入并在每行放“保存”按钮，必须失败。
- 将状态、分类、排序或标签作为列表内直接可改控件，必须失败。

## 验收标准

- owner 明确禁止列表内嵌新增/编辑。
- 常驻可编辑列表、单元格编辑、每行保存按钮被明确禁止并可审计。
- Dialog / Drawer / 独立页选择规则可被审计。
- 列表入口和返回策略不破坏 data-table owner。
- 表单生命周期不被列表 owner 吞掉。
- 管理台场景权限、审计、风险和反馈不被编辑容器绕过。
- README/HANDOFF/SKILL 都只做摘要和路由，不复制 owner 细节。
- 未执行浏览器、屏幕阅读器、触摸设备或真实组件运行时时，所有证据必须标为未验证。
