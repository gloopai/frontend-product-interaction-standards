# 按钮交互规范设计

## 背景

当前规范已经覆盖 Dialog、Drawer、表单、数据表格、记录编辑承载面、响应式和管理台治理，但按钮规则分散在各 owner 中：Dialog 规定关闭按钮和确认操作，Form 规定提交生命周期，Data Table 规定行操作与批量操作，Admin Console 规定风险、权限、审计和回执。缺少一个职责单一的按钮 owner 来回答“按钮本身应该如何命名、分级、禁用、loading、防重复、承载危险动作和响应式折叠”。

按钮是管理台里最常触发变更的入口。若按钮规范缺位，Agent 容易把 `div` 做成假按钮、给图标按钮漏掉可访问名称、让 loading 后只剩 spinner、把危险按钮仅做成红色、让禁用原因只藏在 tooltip、或在批量操作中直接读取当前 UI 状态提交。它们看起来是局部 UI 细节，实际会影响权限、审计、重复提交、错误恢复和用户理解。

本设计新增一个首版聚焦管理台与业务操作按钮的 `buttons.md` owner。全站品牌视觉按钮、营销页 CTA、导航按钮和复杂设计系统 token 暂不纳入首版，但预留后续扩展边界。

## 目标

- 新增 `references/buttons.md`，作为按钮语义、层级、状态、键盘、可访问名称、异步、防重复、危险操作和响应式折叠的唯一事实来源。
- 首版优先覆盖管理台、后台、SaaS console 和业务操作按钮，包括保存、提交、取消、重试、新增、编辑、删除、导入、导出、批量操作、行操作、确认和任务操作。
- 明确按钮 owner 与 Form、Dialog、Drawer、Data Table、Admin Console、Record Editing Surfaces 的边界，避免重复定义容器生命周期和业务状态。
- 建立 RED/GREEN 文档压力测试和结构化审计，确保常见按钮违规形态可被抓住。

## 非目标

- 不定义品牌视觉 token，例如具体色值、圆角、字号、阴影、间距比例或主题变量。
- 不一次性覆盖营销页、官网 CTA、导航链接、富文本工具栏、游戏控件、低层设计系统组件 API。
- 不替代表单提交状态、Dialog/Drawer 关闭生命周期、表格选择快照、管理台风险审计或记录编辑承载面选择。
- 不规定某个框架、组件库或 CSS 实现方式；只定义可观察产品行为和验收条件。

## 推荐方案

采用独立 Button owner，首版聚焦管理台与业务操作按钮。

### 方案对比

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 独立 `buttons.md`，首版聚焦业务操作按钮 | 职责清楚；能统一按钮命名、层级、状态、loading、禁用、图标按钮和危险动作；后续可扩展全站按钮。 | 需要新增路由、摘要、审计和跨 owner 引用。 | 推荐。 |
| 把按钮规则分散写入 Form/Dialog/Table/Admin | 不新增 owner 文件。 | 规则重复、容易冲突；图标按钮、禁用原因、loading 名称等跨场景问题无统一入口。 | 不采用。 |
| 一次性做完整设计系统按钮规范 | 覆盖最广，能顺带定义视觉体系。 | 范围过大，容易偏视觉 token；会延缓最需要治理的管理台操作按钮。 | 暂不采用。 |

## 首版范围

首版覆盖这些按钮：

- 表单按钮：保存、提交、取消、重置、放弃更改、重试。
- 记录按钮：新增、编辑、复制创建、配置、删除、停用、启用、归档。
- 列表和表格按钮：行操作、批量操作、筛选应用、筛选重置、排序触发、分页操作、导入、导出。
- Dialog / Drawer 内按钮：确认、取消、关闭、危险确认、强确认提交。
- 管理台任务按钮：开始导入、取消任务、重试任务、下载结果、查看详情、重新生成。
- 图标按钮和仅图标业务操作按钮。
- 按钮组、工具栏、批量操作区和更多菜单中的按钮入口。

暂不覆盖这些按钮：

- 营销页 CTA、落地页 hero 按钮。
- 纯导航链接和站点主导航。
- 富文本编辑器工具栏内部的格式按钮。
- 画布、游戏、地图和拖拽编辑器里的专用控件。
- 底层组件库视觉 token。

## 核心设计

### 1. 按钮语义

按钮必须代表明确动作，优先使用原生 `<button>` 或具备等价语义、键盘和状态的控件。不能用 `div`、`span`、图标、颜色块或 tooltip 伪装按钮。导航到新页面且不触发命令的入口应优先使用链接；既触发命令又导航的入口必须声明命令 owner、结果 owner 和导航时机。

按钮文案必须描述动作和对象，例如“保存模板”“删除用户”“导出当前筛选结果”。禁止只有“确定”“提交”“操作”“更多”“处理”这类脱离上下文的裸词；只有当同一容器标题和上下文已经唯一说明对象时，才允许短文案。图标按钮必须有可访问名称，且名称包含动作对象。

### 2. 层级与布局

每个任务区同一时刻最多一个主按钮。多个主按钮并列表示任务边界不清，应拆分任务区或降级为次按钮。危险动作不能与普通主按钮使用同一主视觉层级；破坏性操作必须显式标记风险，并通过确认或风险 owner 处理。

按钮组应保持稳定顺序。普通表单建议主操作靠近提交区域，取消/返回不应比提交更突出；危险确认中默认焦点和视觉层级应优先降低误触风险，执行 Dialog/Admin owner 已有约束。列表和工具栏中的按钮顺序应按常用主任务、次任务、更多操作排列，低频操作可收纳，但核心任务不能消失。

### 3. 状态模型

按钮 owner 定义 `buttonActionState`，最少包含：

| 字段 | 语义 |
| --- | --- |
| `buttonId` | 稳定按钮身份。 |
| `actionKind` | `command`、`submit`、`navigation`、`disclosure`、`toggle-command` 或 `composite-trigger`。 |
| `hierarchy` | `primary`、`secondary`、`tertiary`、`danger`、`link-like`、`icon-only`。 |
| `availability` | `enabled`、`disabled`、`read-only`、`hidden-by-permission`、`not-instantiated`。 |
| `disabledReasonOwner` | 禁用原因的 owner；可以是权限、数据状态、选择状态、表单校验、任务状态或业务规则。 |
| `asyncPhase` | `idle`、`validating`、`request-in-flight`、`succeeded`、`failed`、`unknown`。 |
| `requestIdentity` | 触发请求时的幂等、权限版本、目标快照和来源按钮身份。 |
| `resultOwner` | 成功、失败、冲突、未知结果和恢复入口的 primary owner。 |
| `accessibleName` | 当前可访问名称；loading 和图标态也必须保留。 |

### 4. 禁用、隐藏与权限

禁用不是安全边界。权限不足、租户变化或敏感对象不可见时，必须执行 Admin/Data Table owner 的权限收敛：不能继续暴露旧按钮、旧菜单或旧下载入口。若显示禁用按钮会泄露敏感对象名称、数量或字段，应隐藏或替换为安全说明。

非敏感禁用原因必须可发现、可访问，并且不能只放在 hover tooltip。可用方式包括按钮旁文本、状态区域、禁用控件的可访问描述、表格行内只读原因或页面内 Alert。禁用按钮不能触发请求，也不能被键盘或脚本绕过。

### 5. Loading、异步与重复触发

按钮触发异步请求时，必须在接受意图时冻结请求身份。点击、Enter、Space、触摸和事件重放必须进入同一去重门禁，不能产生多个请求。loading 中按钮必须保留动作对象的可访问名称，例如“正在保存模板”，不能只剩 spinner 或“加载中”。

按钮 loading 不得自动改写容器关闭路径。表单提交由 Form owner 决定 `submitPhase`，Dialog/Drawer 关闭由容器 owner 决定，任务取消由 Admin/Job owner 决定。按钮 owner 只负责触发入口、防重复、可访问状态和结果入口是否可达。

### 6. 危险操作

删除、停用、清空、权限变更、敏感导出、批量修改、取消任务、重跑任务和不可逆配置变更默认是危险或高风险操作。危险按钮不能只靠颜色表达风险，也不能只用 Toast 作为结果。

危险按钮必须声明：

- 风险级别和影响范围。
- 是否需要普通确认、强确认或二次输入。
- 请求身份和幂等策略。
- 成功、失败、冲突、未知结果和审计回执。
- 失败恢复和重新确认路径。

### 7. 图标按钮、更多菜单与按钮组

图标按钮必须有可访问名称，且该名称不能只来自 tooltip。图标按钮的视觉图标、可访问名称、菜单项名称和结果回执应描述同一个动作。仅图标按钮不得作为唯一承载复杂后果说明的入口。

更多菜单可收纳低频操作，但菜单触发按钮必须说明对象，例如“更多用户操作”。危险操作进入菜单后仍保留风险标记、确认和回执。移动端折叠按钮组时，核心操作、危险确认、错误恢复和审计回执不能消失。

### 8. 响应式与触摸

按钮必须支持键盘、鼠标、触摸和辅助技术。Enter / Space 激活真实按钮；焦点样式必须可见；触摸目标不能依赖精确点击。移动端可把次要按钮折叠为菜单或底部操作区，但不能删除核心任务。虚拟键盘、低高度和安全区域下，提交、取消、错误恢复和危险确认仍需可达。

## 与现有 owner 的关系

- `forms.md`：表单字段、校验、`submitSnapshot`、`submitId`、错误摘要和失败恢复仍归 Form；Button 只管按钮语义、层级、可访问名称、禁用、loading 和重复触发入口。
- `dialogs.md` / `drawers.md`：遮罩、关闭、焦点陷阱、右上角关闭按钮、动画和 disposal 仍归容器；Button 补充按钮文案、状态和危险动作可访问性。
- `data-tables.md`：行操作、批量操作、选择快照、分页、排序和表格能力仍归 Table；Button 管按钮名称、图标按钮、禁用原因和触发去重。
- `admin-console.md`：权限、租户、风险、审计、任务和全局反馈仍归 Admin；Button 不得绕过这些 owner。
- `record-editing-surfaces.md`：新增/编辑入口可以是按钮，但按钮只能作为入口，不能把编辑字段放回列表。
- `responsive-adaptive.md`：断点、触摸、虚拟键盘、安全区域和能力折叠仍归 Responsive；Button 声明按钮在这些形态下的可达性要求。

## 新 owner 草案结构

计划新增 `references/buttons.md`：

1. 范围与术语
2. 按钮语义与原生优先
3. 文案与可访问名称
4. 层级、主按钮和按钮组
5. `buttonActionState` 状态模型
6. 禁用、隐藏、权限和原因说明
7. Loading、异步、防重复和请求身份
8. 危险按钮与风险操作
9. 图标按钮、更多菜单和工具栏
10. 响应式、触摸和键盘
11. 与现有 owner 的组合规则
12. 可执行验收

稳定规则族建议：

- `BTN-SCOPE-*`：范围、术语、原生语义。
- `BTN-LABEL-*`：文案、对象、图标按钮可访问名称。
- `BTN-HIER-*`：层级、主按钮、危险按钮、按钮组。
- `BTN-STATE-*`：状态模型、禁用、隐藏、loading。
- `BTN-ASYNC-*`：重复触发、请求身份、结果 owner。
- `BTN-DANGER-*`：危险操作、确认、回执、审计。
- `BTN-PERM-*`：权限、泄露防护、禁用原因。
- `BTN-GROUP-*`：工具栏、更多菜单、批量操作区。
- `BTN-A11Y-*`：键盘、焦点、可访问名称和公告。
- `BTN-RSP-*`：移动端、触摸、折叠和安全区域。

## 测试与验证策略

采用 RED/GREEN 文档压力测试：

- RED：在没有 Button owner 的情况下，让 fresh 输出后台用户列表、模板编辑表单、危险删除确认和导出任务设计，记录是否出现假按钮、图标无名、loading 丢名称、危险只靠红色、禁用只靠 tooltip、批量按钮无快照等问题。
- GREEN：启用 owner 后，同样任务必须声明按钮层级、文案、状态、请求身份、重复触发门禁、禁用原因、危险确认、回执、键盘和运行时验证边界。
- 审计脚本：检查 owner 规则、路由、`buttonActionState`、主按钮唯一、图标按钮名称、loading 名称、危险按钮确认和回执、禁用原因、批量快照、运行时未验证边界。

关键 mutation：

- 把真实按钮改成 `div` 假按钮，必须失败。
- 删除图标按钮 `accessibleName`，必须失败。
- loading 时只保留 spinner 并删除动作对象，必须失败。
- 同一任务区放两个 `primary` 按钮，必须失败。
- 删除危险操作确认、影响范围或回执，必须失败。
- 禁用原因只放在 hover tooltip，必须失败。
- 批量按钮删除选择快照或权限版本，必须失败。
- 将已发送任务的“取消”写成服务端已取消，必须失败。
- 移动端折叠后删除核心按钮或错误恢复入口，必须失败。

## 验收标准

- Button owner 首版范围清晰聚焦管理台和业务操作按钮。
- 按钮语义、文案、层级、状态、禁用、loading、异步、危险和响应式规则可被审计。
- 与 Form/Dialog/Drawer/Data Table/Admin/Record Editing Surfaces 的 owner 边界不冲突。
- README/HANDOFF/SKILL 只做摘要和路由，不复制 owner 细节。
- RED/GREEN 输出和审计 mutation 能覆盖核心反例。
- 未执行浏览器、屏幕阅读器、触摸设备或真实组件运行时时，所有证据必须标为未验证。
