# 分步流程、配置向导与 Stepper 交互规范设计

## 背景

管理台里经常出现多步骤创建、配置向导、导入向导、发布流程、权限配置、套餐变更、任务创建、API Key 创建、模板配置和风险操作复核。它们通常由多个表单、说明页、预览页和确认页拼起来，但用户体验和数据安全的关键并不在单个字段，而在“整个流程”的状态。

常见风险包括：

- 当前步骤是否合法、能否跳过、能否返回没有明确状态。
- 上一步改动后，后续步骤还保留旧结果、旧预检、旧预览或旧费用。
- 保存草稿、自动保存、恢复草稿和放弃草稿语义混乱。
- 最后一步提交读取了正在编辑的草稿，而不是用户复核过的快照。
- 导入/发布/权限变更等高风险流程只用一个“完成”Toast，没有结果页、任务中心或审计回执。
- 移动端把 Stepper 折叠后，步骤错误、复核页、取消路径和主操作不可见。

## 目标

新增 `references/wizards-steppers.md`，作为 Wizard、Stepper、多步骤表单、分步创建、配置向导、导入向导、发布向导、复核确认页、预览步骤、保存草稿和恢复流程的唯一 owner。

该 owner 负责跨步骤状态、步骤导航、草稿/快照、跨步校验、预检、最终提交、取消/离开、结果回执和移动端步骤承载。单字段校验仍归 `forms.md`，风险确认归 `risk-actions.md`，导入细节归 `uploads-imports.md`，导航离开归 `navigation-routing.md`。

## 范围

- Wizard、Stepper、多步骤表单、分步创建、分步编辑、配置向导、发布流程、导入向导、审批/复核流程。
- 步骤导航：上一步、下一步、跳过、跳转步骤、保存草稿、恢复草稿、取消、完成。
- 步骤状态：未开始、当前、已完成、有错误、被跳过、被阻塞、失效、等待异步预检。
- 跨步依赖：前一步改变导致后续步骤失效、预览重算、价格重算、权限重校验、导入预检重跑。
- 最终提交：复核页、提交快照、幂等、异步任务、结果页、审计/任务回执。
- 移动端：垂直步骤、折叠步骤、底部操作、全屏流程和断点转换。

## 非目标

- 不重写单字段状态、dirty/touched、错误摘要和表单提交生命周期。
- 不定义危险操作的确认文案、输入确认或撤销窗口。
- 不定义导入文件、字段映射或错误明细细节。
- 不定义流程编排器、低代码构建器或任意 DAG 工作流编辑器；那适合后续独立 owner。

## 设计原则

1. **分步流程必须有流程 owner**：不能让每个步骤各自管理局部状态，然后由“下一步”按钮猜测全局状态。
2. **步骤状态必须可观察**：当前、完成、错误、跳过、阻塞、失效和等待异步必须有可见且可访问表达。
3. **草稿、预检、复核和提交快照必须分离**：最终提交只能读取用户已复核且仍有效的快照。
4. **跨步依赖必须失效后续结果**：上游改变后，下游步骤、预览、费用、权限、预检和结果摘要不能继续装作有效。
5. **移动端改变布局，不改变流程语义**：折叠或全屏可以，但不能删除步骤导航、错误、复核、保存/放弃、结果和恢复路径。

## 状态模型

新增 `wizardState`，至少包含：

- `wizardOwnerId`：流程 owner。
- `flowKind`：create、edit、import、publish、configure、permissionChange、planChange、riskReview、asyncJob 等。
- `stepRegistry`：步骤 ID、标题、顺序、可选性、依赖、进入条件和完成条件。
- `currentStepId`：当前步骤。
- `stepStates`：notStarted、current、complete、error、skipped、blocked、invalidated、validating、asyncPending。
- `stepDrafts`：各步骤字段和局部草稿。
- `committedStepValues`：步骤已提交业务值。
- `crossStepValidation`：跨步依赖、冲突、失效和可恢复错误。
- `progressPolicy`：是否允许跳步、返回、跳过、保存草稿、恢复草稿和重开流程。
- `reviewSnapshot`：复核页展示并等待最终提交的不可变快照。
- `submitSnapshot`：最终提交使用的不可变 payload、权限版本、幂等键和请求身份。
- `asyncTaskBinding`：异步任务 ID、状态、结果、取消边界、重试和任务中心入口。
- `exitPolicy`：取消、关闭、返回、路由离开、未保存保护和放弃草稿。
- `responsivePolicy`：移动端步骤呈现、固定操作区、折叠策略和安全区域。
- `a11yPolicy`：步骤导航语义、当前步骤公告、错误摘要、键盘顺序和焦点恢复。

## 核心规则族

### WIZ-SCOPE：职责与范围

- 多步骤创建、配置向导、导入向导、发布流程和复核确认页必须声明 `wizardState`。
- 每个步骤可以拥有表单、上传、选择器或图表，但全局步骤状态、跨步依赖和最终提交由 wizard owner 管理。
- 流程不能由“当前页面 index + 若干局部表单状态”临时拼接。

### WIZ-STEP：步骤状态

- 每个步骤必须有稳定 ID、标题、进入条件、完成条件和错误归属。
- 当前、完成、错误、跳过、阻塞、失效和异步等待必须可见且可访问。
- 步骤标题不能只显示数字；必须让用户理解每步任务。

### WIZ-NAV：步骤导航

- 上一步、下一步、跳过、直接跳转、保存草稿、取消和完成必须是不同意图。
- 禁用下一步或完成时必须说明原因，不能只禁用按钮。
- 跳过步骤必须声明是否会产生默认值、空值、不适用状态或后续限制。

### WIZ-DRAFT：草稿与保存

- `stepDrafts`、`committedStepValues`、`reviewSnapshot` 和 `submitSnapshot` 必须分离。
- 自动保存、手动保存草稿、恢复草稿和放弃草稿必须声明范围、时机、权限和过期策略。
- 恢复草稿必须重新校验权限、依赖、选项有效性、文件引用、时间范围和业务版本。

### WIZ-VALID：跨步校验与失效

- 上游步骤变化后，依赖它的后续步骤、预检、预览、费用、权限、导出范围和确认摘要必须失效或重算。
- 跨步错误必须归属明确步骤、字段组或流程级 owner，并提供跳转修复路径。
- 异步预检和跨步校验的迟到结果不得写回新草稿或新步骤状态。

### WIZ-REVIEW：复核与最终提交

- 最终提交前的复核页必须展示会改变业务结果、权限、费用、数据范围、风险和审计的信息。
- 最终提交只能读取仍有效的 `reviewSnapshot` / `submitSnapshot`，不得读取正在编辑的草稿。
- 提交前必须冻结权限版本、目标快照、幂等键、风险确认状态和请求身份。

### WIZ-RESULT：结果与恢复

- 完成状态必须区分成功、部分成功、失败、冲突、未知、异步处理中、已取消和过期。
- 长耗时或异步流程必须提供任务中心、详情页、审计入口或结果页，不得只靠 Toast。
- 取消客户端流程不等于取消服务端任务；必须说明取消边界。

### WIZ-PERM：权限与安全

- 权限、租户、工作区、角色或数据范围变化后，步骤、草稿、预检、预览、复核和提交入口必须重新证明安全。
- 无权限状态不得泄露对象名称、数量、字段、文件名、导入内容、费用、权限范围、内部 ID 或旧缓存。
- 权限变更、敏感导出、批量修改和不可逆发布必须进入 `risk-actions.md`。

### WIZ-RSP：移动端与响应式

- 移动端可以把横向 Stepper 转为垂直步骤、Accordion、分步全屏页或底部固定操作流程。
- 移动端不得删除步骤标题、当前进度、步骤错误、上一步、下一步、保存/放弃草稿、复核页、取消路径、结果回执或恢复入口。
- 低高度、虚拟键盘和安全区域下，当前字段、步骤错误、底部主操作和返回路径必须可达。

### WIZ-A11Y：可访问性

- Stepper 必须有可访问名称，当前步骤、完成步骤、错误步骤和禁用步骤必须可被辅助技术理解。
- 键盘顺序必须覆盖步骤导航、当前步骤内容、错误摘要、上一步/下一步/取消/完成和恢复入口。
- 步骤切换、跨步错误、保存草稿、恢复草稿、提交开始和结果状态必须由唯一 owner 公告。

### WIZ-LIFE：生命周期与并发

- 步骤切换、保存草稿、预检、预览、提交、结果轮询和恢复回调必须绑定 live wizard owner、步骤 generation 和快照。
- route/unmount、关闭容器、断点转换和权限变化必须清理仅属于该流程的监听、请求、轮询、草稿锁和焦点回调。
- 未执行真实浏览器、键盘、读屏、触摸、移动端、断点转换、权限变化和异步竞态检查时，必须标为未验证。

## 与现有 owner 的关系

- `forms.md` 负责每步字段状态、校验和提交前字段错误；本 owner 负责跨步状态和最终提交快照。
- `record-editing-surfaces.md` 负责分步创建/编辑应该放在 Dialog、Drawer 或独立页；本 owner 负责进入承载面后的分步流程。
- `uploads-imports.md` 负责文件、预检、映射和导入结果；本 owner 负责导入向导的步骤状态和跨步依赖。
- `risk-actions.md` 负责危险确认；本 owner 负责风险复核步骤与最终提交快照。
- `navigation-routing.md` 负责离开和返回；本 owner 提供 exitPolicy、草稿保护和恢复状态。
- `responsive-adaptive.md` 负责断点转换；本 owner 规定移动端分步语义不丢失。

## 验收设计

新增 `docs/testing/wizards-steppers/wizards-steppers-audit.rb`：

- 检查 owner 文件包含 `wizardState` 和所有必要状态字段。
- 检查步骤状态、导航意图、草稿/快照分离、恢复草稿复校验、跨步失效、最终提交快照、结果状态、权限安全、移动端不丢步骤能力、可访问性和未验证边界。
- 检查 `SKILL.md` 路由包含中英文关键词并指向 `references/wizards-steppers.md`。
- 检查 `README.md` 和 `HANDOFF.md` 包含摘要与引用。
- 使用负向变异删除关键规则，确保审计失败。
- 使用项目泄漏扫描，确保 owner 不绑定具体业务项目。

## 明确非验证项

本次是规范与静态审计更新，不执行具体业务流程的浏览器、键盘、读屏、触摸、移动端、断点转换、权限变化、异步竞态或真实服务端任务检查。落地到项目时，所有未实际执行的运行时检查必须标为未验证。
