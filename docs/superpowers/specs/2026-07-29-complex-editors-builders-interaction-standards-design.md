# 复杂编辑器和构建器交互规范设计

## 背景

管理台里越来越多能力不再是简单表单：富文本公告、Markdown 帮助文档、JSON/YAML 配置、规则构建器、字段映射、流程编排器、模板构建器、自动化条件、报表配置、可视化画布和节点式编辑都属于“复杂编辑器和构建器”。

这类页面最容易被误做成“一个大表单 + 一个保存按钮”。常见问题包括：输入草稿直接污染正式配置；预览成功被当成保存成功；保存成功又被当成发布成功；折叠节点、隐藏条件、孤立引用和循环依赖没有校验；权限变化后旧草稿还能提交；移动端直接删掉预览、错误定位或恢复入口；复制粘贴、导入片段和 AI 生成内容绕过校验。它们需要一个独立 owner，而不是继续分散在 Forms、Buttons、Navigation 或 Page Action Bar 中。

## 目标

新增 `references/complex-editors-builders.md`，作为复杂编辑器、构建器、画布、规则编辑、模板编辑、代码/配置编辑和节点编排的唯一 owner。

该 owner 需要约束：

- 编辑器身份、来源快照、草稿模型、结构校验、预览、保存、发布和回滚。
- 草稿、预览、保存、发布、应用、测试运行、导入、导出、复制、AI 生成和版本切换的意图边界。
- 折叠内容、隐藏内容、不可见字段、权限降级、旧版本、旧预览、旧异步校验和旧协作状态的失效规则。
- 移动端、低高度视口、虚拟键盘、触摸拖拽、画布缩放和全屏承载的核心能力一致性。

## 非目标

- 不替代 `forms.md` 的字段校验、dirty/touched 和提交快照规则。
- 不替代 `page-form-action-bars.md` 的页面保存栏规则。
- 不替代 `uploads-imports.md` 的文件上传、模板下载、字段映射和导入执行任务规则；本 owner 只约束编辑器内导入片段、导入配置或字段映射画布。
- 不替代 `charts-visualization.md` 的图表呈现规则；本 owner 只约束图表配置器、报表构建器和可视化编辑工作台。
- 不定义具体代码编辑器、富文本编辑器或画布库的 API。

## 方案比较

### 方案 A：继续分散在现有 owner 中

优点是每个规则贴近已有文件，新增文件少。缺点也很明显：复杂编辑器跨越表单、按钮、导航、权限、导入、预览、版本和发布，靠分散规则很容易遗漏“预览/保存/发布分层”和“结构完整性校验”。

### 方案 B：新增独立复杂编辑器 owner

优点是边界清晰，把复杂编辑器当成一种工作台，而不是普通字段集合；可以统一草稿模型、版本、预览、结构错误、协作、移动端承载和恢复路径。缺点是需要新增路由、README/HANDOFF 摘要和可执行审计。

### 方案 C：只新增构建器 owner，不覆盖文本/代码编辑器

优点是范围更窄，适合规则构建器和流程编排器。缺点是富文本、Markdown、JSON/YAML、模板编辑器仍会继续踩“草稿即生效、预览即保存、复制绕过校验”的坑。

推荐方案 B。它更符合管理台的实际风险：复杂编辑器的难点不是控件类型，而是“用户正在编辑一个可执行/可发布/可复用的结构化产物”。把富文本、配置、规则、流程和画布放在同一个 owner 下，可以统一处理状态、版本、校验和发布边界。

## 状态模型

每个复杂编辑器或构建器必须声明 `editorBuilderState`：

| 字段 | 含义 |
| --- | --- |
| `editorOwnerId` | 编辑器实例身份，绑定页面、对象、租户/工作区、权限版本和来源版本。 |
| `sourceSnapshot` | 进入编辑器时读取的服务端或可信来源快照，包括版本、更新时间、作者、权限和发布状态。 |
| `draftModel` | 当前编辑草稿，包括文本、结构、节点、边、字段映射、条件、变量引用、附件引用和本地未保存变化。 |
| `validationState` | 同步校验、异步校验、结构校验、权限校验、引用校验、循环依赖、未完成校验和阻断级别。 |
| `previewState` | 预览输入、预览数据来源、脱敏策略、权限过滤、运行状态、错误、过期状态和与生产一致性的说明。 |
| `versionPolicy` | 保存版本、草稿版本、发布版本、回滚目标、冲突处理、版本对比和旧版本只读策略。 |
| `savePolicy` | 保存草稿、保存副本、自动保存、手动保存、幂等键、防重复提交和保存结果回执。 |
| `publishPolicy` | 发布、应用、启用、提交审核、上线、下线、回滚和审批前置条件。 |
| `importExportPolicy` | 导入片段、粘贴配置、导出配置、复制片段、模板下载和脱敏边界。 |
| `permissionBoundary` | 编辑、预览、保存、发布、导入、导出、复制、回滚和查看差异的权限收敛。 |
| `collaborationPolicy` | 多人编辑、锁定、只读接管、远端更新、冲突、游标/选区显示和迟到事件归属。 |
| `responsivePolicy` | 移动端、窄屏、低高度视口、虚拟键盘、触摸拖拽、画布缩放和全屏承载策略。 |

`editorBuilderState` 只负责复杂编辑器整体生命周期。字段控件仍归 Forms owner；页面保存栏仍归 Page Form Action Bar owner；危险发布、删除、回滚仍进入 Risk Actions owner；上传文件仍进入 Uploads owner。

## 核心规则

### 草稿、保存、发布分层

草稿、预览、保存、发布、应用、启用、提交审核、回滚、导入、导出和复制必须是不同意图。

输入、拖拽、节点连接、格式化、粘贴、AI 生成、导入片段和自动修复只能写入 `draftModel`，不能静默写入已保存版本、已发布版本、生产配置或外部系统。

保存草稿成功不等于发布成功。预览成功不等于保存成功。发布请求发送不等于发布已生效。发布结果未知不得伪装成成功或失败，必须提供刷新版本、查看发布状态、查看审计、重试或回滚路径。

### 结构完整性与错误定位

复杂编辑器必须校验完整结构，而不是只校验当前可见区域。

折叠节点、隐藏面板、未展开分支、不可见字段、禁用节点、孤立节点、断开的边、循环依赖、缺失变量、重复 key、非法表达式、未映射字段、权限不可见引用、旧版本引用和外部资源失效都必须进入 `validationState`。

错误必须能定位到具体文本范围、字段、节点、边、条件组、模板片段、变量引用或画布区域。无法定位到具体位置时，必须在错误摘要中说明影响范围和下一步，不能只 Toast。

### 预览可信边界

预览必须声明它读取的是 `draftModel`、已保存版本还是已发布版本。预览数据必须声明来源、时间、权限过滤、脱敏策略、样本限制和是否代表生产结果。

预览失败、预览超时、预览权限不足、预览数据过期、预览与生产不一致或预览结果未知时，不得清空草稿，不得阻断用户复制错误信息、查看错误定位、保存草稿或退出恢复。

### 版本、冲突和回滚

编辑器必须区分来源版本、草稿版本、保存版本、发布版本和回滚目标版本。

来源版本变化、权限版本变化、租户/工作区变化、远端发布变化、协作锁变化或对象状态变化后，旧草稿、旧预览、旧校验结果、旧保存按钮、旧发布按钮、旧快捷键、旧复制片段、旧导出链接和旧焦点目标必须失效或重新证明安全。

回滚、覆盖发布版本、丢弃草稿、删除节点、批量替换、导入覆盖、发布到生产、下线生产配置和撤销发布必须进入 `risk-actions.md`。确认完成前请求数为 0。

### 权限与敏感信息

无权或未启用时，编辑、预览、保存、发布、导入、导出、复制、回滚、查看差异和测试运行的 DOM、state、handler、request 和快捷键入口为 0。

无权限状态不得泄露配置名称、节点名称、变量名、字段名、表达式、模板内容、密钥片段、内部 ID、依赖关系、错误明细、预览数据、版本差异、协作者身份或旧缓存。

复制、导出、模板下载、查看真实值、AI 生成上下文和错误报告必须复核权限、租户/工作区、来源版本、脱敏策略和请求身份。

### 自动保存、AI 生成和外部输入

自动保存必须声明触发条件、节流策略、冲突策略、失败回执和离线恢复。自动保存失败不得让用户误以为草稿已保存。

AI 生成、自动补全、批量格式化、导入片段、粘贴 JSON/YAML、模板套用和示例填充都只是草稿来源，必须经过相同校验、差异说明、权限复核和保存/发布门禁。

外部输入不得绕过危险操作确认、敏感字段脱敏、权限过滤、结构完整性检查或审计绑定。

### 移动端与响应式

移动端不得删除编辑、预览、校验、保存草稿、发布/提交、错误摘要、错误定位、版本/冲突说明、权限原因、恢复路径和离开保护。

复杂画布或多面板编辑器在移动端可以升级为全屏 Drawer、全屏编辑页或分步编辑模式，但必须保留同一个 `editorBuilderState`、同一个草稿版本、同一个校验结果、同一个保存/发布门禁和同一个恢复路径。

虚拟键盘、触摸拖拽、缩放、横竖屏切换和低高度视口变化后，当前编辑位置、错误定位、预览入口、保存入口、发布入口、撤销/恢复入口和离开保护仍必须可见或可滚动到达。

## 与现有 owner 的关系

- `forms.md`：字段值、dirty/touched、校验消息和错误摘要继续执行 Forms 规则；本 owner 负责跨字段、跨节点、跨版本和结构完整性。
- `page-form-action-bars.md`：页面保存栏、取消、返回、放弃和底部避让继续执行保存区规则；本 owner 提供草稿、校验、预览、保存和发布状态。
- `buttons.md`：按钮语义、loading、禁用原因、主次关系和危险视觉继续执行 Button 规则。
- `navigation-routing.md`：未保存离开、返回、面包屑、浏览器 Back、Tabs 和外链离开保护继续执行 Navigation 规则。
- `risk-actions.md`：发布、回滚、覆盖、删除、丢弃、下线、导入覆盖和批量替换等高风险动作继续执行 Risk Actions。
- `permissions-tenancy-visibility.md`：权限、租户/工作区、只读、禁用、隐藏和无泄露继续执行 Permissions 规则。
- `uploads-imports.md`：文件上传和导入任务继续执行 Uploads 规则；本 owner 只约束编辑器内的导入入口和编辑结果归属。
- `exports-downloads-artifacts.md`：导出配置、下载模板、导出预览结果和领取文件继续执行 Exports 规则。
- `global-feedback.md` 和 `feedback-states.md`：Toast、Banner、状态区、空态、错误和恢复入口继续执行反馈 owner；复杂编辑器不得以 Toast 作为唯一回执。
- `responsive-adaptive.md`：移动端、触控、虚拟键盘和安全区域继续执行响应式规则。

## 可执行审计设计

新增 `docs/testing/complex-editors-builders/complex-editors-builders-audit.rb`，采用当前仓库已有 Ruby 静态审计模式。

审计需要验证：

1. owner 文件存在，且包含 `editorBuilderState` 与所有状态字段。
2. `SKILL.md` 包含复杂编辑器、构建器、规则构建器、流程编排器、代码/JSON/YAML/Markdown 编辑器、画布编辑、字段映射等中英文触发词。
3. `README.md` 和 `HANDOFF.md` 只保留摘要和链接，不重复完整规则。
4. RED/GREEN 证据能证明缺少 owner、意图混用、草稿污染正式配置、预览即保存、只校验可见区域、错误无法定位、权限幽灵入口、旧版本提交、自动保存误导、AI 生成绕过校验、移动端删除核心能力、运行时验证伪装已通过、项目专属泄漏等问题会被抓住。
5. owner 不包含业务项目专属路径、客户名或实现栈例外。

## 验收清单

- 每个复杂编辑器或构建器声明 `editorBuilderState` 全字段。
- 草稿、预览、保存、发布、应用、回滚、导入、导出和复制是不同意图。
- 输入、拖拽、粘贴、AI 生成和导入片段只进入草稿，不直接写正式配置。
- 保存成功、发布成功、预览成功和发布未知结果有不同回执和恢复路径。
- 校验覆盖折叠、隐藏、不可见、禁用、孤立、循环、缺失、重复、失效和无权限引用。
- 错误能定位到文本、字段、节点、边、条件组、模板片段、变量引用或画布区域。
- 预览声明数据来源、版本、权限过滤、脱敏和生产一致性边界。
- 权限、租户/工作区、版本、协作锁或对象状态变化后，旧入口、旧结果和旧焦点目标失效。
- 无权或未启用时编辑、预览、保存、发布、导入、导出、复制、回滚和测试运行入口为 0。
- 移动端保留编辑、预览、校验、保存草稿、发布/提交、错误定位、版本/冲突说明和恢复路径。
- 未执行浏览器、屏幕阅读器、真实触控、真实拖拽或真实编辑器运行时测试时，必须标记为未验证。

## 自检结论

本设计聚焦单一 owner：复杂编辑器和构建器。它不会替代已有 Forms、Buttons、Navigation、Risk、Permissions、Uploads、Exports、Feedback 或 Responsive owner，而是定义复杂编辑工作台自己的状态模型和跨 owner 交接边界。文档已写明完整范围与交付物，没有把任何具体业务项目作为规范例外；真实浏览器、屏幕阅读器、触控设备和具体编辑器运行时验证明确留到业务实现阶段。
