# 导出、下载与结果产物交付交互规范设计

## 背景

管理台里导出、下载和结果产物交付非常高频：列表导出、报表导出、图表导出、错误明细下载、导入结果产物、任务结果领取、审计导出、批量操作回执、CSV / Excel / PDF / 图片下载等。现有规范已经在表格、图表、异步任务、上传导入、审计、权限和按钮里分别约束了一部分，但还缺少一个独立 owner 统一回答：

- 导出范围到底来自哪个已应用快照？
- 文件生成和文件下载是不是同一个操作？
- 下载链接在权限变化、租户切换、过期、旧通知和旧缓存下是否仍安全？
- 结果产物成功、失败、部分成功、未知、过期和无权限时如何恢复？

没有独立 owner 时，常见错误包括：导出读取筛选草稿、旧 Notification 链接绕过权限、下载 URL 永久有效、敏感字段没有说明、错误明细下载不复核任务身份、Toast 是唯一下载入口、移动端删掉导出范围和重新生成入口。

## 目标

- 新增 `references/exports-downloads-artifacts.md` 作为导出、下载、结果产物、文件领取和下载链接交互的唯一事实来源。
- 明确 `exportState`、`artifactState`、`downloadIntent`、`scopeSnapshot`、`artifactIdentity`、`permissionBoundary`、`expiryPolicy`、`sensitiveFieldPolicy`、`deliveryReceipt` 和 `recoveryPolicy` 等核心状态。
- 区分创建导出、生成文件、领取产物、下载文件、复制链接、重新生成和查看错误明细。
- 约束导出范围必须绑定已应用筛选、时间范围、权限版本、租户/工作区、请求身份、敏感字段和结果 owner。
- 覆盖同步导出、异步导出、报表/图表导出、审计导出、错误明细下载、任务结果产物、链接过期、权限变化、旧缓存和移动端承载。

## 非目标

- 不定义后端文件存储、对象存储签名、加密、压缩、转码或下载 CDN 策略。
- 不规定某个业务项目的文件格式、字段清单、导出接口或文件命名规则。
- 不替代表格、查询筛选、日期时间、异步任务、审计日志、上传导入、图表、权限、危险操作或按钮 owner；这些仍按各自规则执行。
- 不要求所有导出都异步；同步和异步均可，但必须明确状态、权限和恢复。

## 设计方案

### 导出状态与结果产物模型

每个导出、下载、错误明细、结果产物或文件领取入口必须声明 `exportState` 或 `artifactState`。它们至少描述来源 owner、导出范围、结果身份、文件身份、生成状态、下载状态、权限边界、过期策略、敏感字段策略、请求身份、审计回执和恢复路径。

创建导出和下载文件必须分离。创建导出读取 `scopeSnapshot`；生成完成后产生 `artifactIdentity`；下载动作必须再创建 `downloadIntent`，重新复核权限、租户/工作区、有效期和请求身份。

### 范围快照与敏感字段

导出范围必须来自已应用筛选、已提交时间范围、当前权限版本、租户/工作区、数据范围、排序/列配置和结果 owner 快照。不得读取筛选草稿、Select query、active option、未提交日期范围、当前页面可见行或旧缓存来决定导出范围。

敏感导出必须说明敏感字段、脱敏策略、影响范围、文件格式、有效期和审计回执。高风险导出转交危险操作 owner；普通导出仍必须有清晰范围和权限复核。

### 下载链接和结果领取

下载链接不是权限本身。旧下载链接、旧 Notification、旧任务中心入口、旧邮件/站内信、旧 URL、旧缓存和旧文件名不得绕过当前权限复核。过期、权限变化、租户切换、任务身份失配、文件删除或请求身份不匹配时，下载必须被拒绝并提供恢复路径。

Toast、Snackbar、Notification 或浏览器下载提示不能作为唯一结果回执、唯一下载入口、唯一错误说明或唯一恢复路径。页面、任务中心、结果区或操作历史中必须有可恢复入口。

### 状态、错误和恢复

导出和产物交付必须区分 queued、processing、ready、downloaded、expired、failed、partial-success、permission-denied、unknown 和 unavailable。未知结果不得伪装成失败或成功；部分成功必须说明成功范围、失败范围、缺失范围、错误明细和下一步。

重新生成、重试下载、复制下载链接、下载错误明细和查看任务详情都必须重新复核身份和权限。重新生成必须说明是否复用原范围快照，还是读取当前已应用范围并创建新导出意图。

### 移动端与可访问性

移动端可以折叠低频字段、把导出详情放入 Drawer / Bottom Sheet / 独立页，或把下载入口收进任务中心，但不得删除导出范围、文件状态、格式、有效期、权限说明、敏感字段说明、错误明细、重新生成、查看任务、查看审计或恢复路径。

文件格式、状态、有效期、敏感性、错误和恢复不能只靠图标、颜色、hover、tooltip、Toast 或浏览器下载栏表达。状态变化和下载结果必须由唯一 owner 公告，焦点只迁移一次。

## 硬性红线

- 导出范围不得读取筛选草稿、未提交时间范围、Select query、active option、当前页面可见行或旧缓存。
- 创建导出、生成文件、领取产物和下载文件不得合并成一个含糊状态。
- 下载链接不得被当作权限证明；每次下载必须复核权限、租户/工作区、有效期、请求身份和产物身份。
- 旧 Notification、旧任务入口、旧 URL、旧缓存、旧文件名或旧下载链接不得绕过权限复核。
- Toast、Snackbar、Notification 或浏览器下载提示不得作为唯一下载入口、唯一结果回执、唯一错误说明或唯一恢复路径。
- 敏感导出、审计导出、错误明细下载和跨租户/工作区产物必须说明敏感字段、范围、有效期、权限边界和审计回执。
- 部分成功、未知、过期、无权限和文件不可用不得伪装成成功。
- 移动端不得删除导出范围、文件状态、格式、有效期、权限说明、敏感字段说明、错误明细、重新生成、任务详情、审计入口或恢复路径。
- 未实际执行浏览器下载、键盘、屏幕阅读器、触摸、权限切换、链接过期、任务结果和移动端视口检查时，必须标为未验证。

## 验收策略

新增 Ruby 结构化审计，验证：

- `SKILL.md` 具备 export、download、artifact、result artifact、CSV、Excel、PDF、错误明细、下载链接、文件有效期等路由关键词。
- `README.md` 和 `HANDOFF.md` 只写摘要和链接，不复制完整 owner。
- `references/exports-downloads-artifacts.md` 包含状态模型、范围快照、下载意图、权限复核、有效期、敏感字段、Toast 边界、旧链接失效、移动端保留和未验证边界。
- RED/GREEN 证据覆盖导出读取草稿、旧链接绕权限、永久链接、Toast-only 下载、无敏感字段说明、错误明细不复核、部分成功伪成功、移动端删恢复和 false verified。
- 全量维护审计、Markdown 相对链接和 `git diff --check` 必须通过后提交并推送。
