# 上传与导入交互规范设计

## 背景

当前规范已经覆盖 Dialog、Drawer、表单、数据表格、记录编辑承载面、按钮、响应式和管理台治理。管理台规范中已有导入、导出和异步任务的跨页面约束，但仍缺少一个专门回答“文件如何被选择、校验、上传、预检、确认导入、失败恢复和下载错误明细”的 owner。

上传和导入是管理台与业务系统里最高频、也最容易被 Agent 做坏的交互之一。常见问题包括：文件类型只靠浏览器 `accept`、大小超限后仍发送请求、重复点击导致多次上传、进度不可见、取消被误写成服务端取消、导入前没有预检、字段映射丢失、部分成功没有明细、错误明细下载权限未复核、弱网重试重复执行、表单提交时文件字段状态与脏状态不一致、移动端文件选择与安全区域不可达。

本设计新增 `references/uploads-imports.md`，作为上传与导入文件交互的唯一事实来源。它聚焦普通文件上传、表单内上传和结构化数据导入；文件库、媒体资产管理和复杂文件版本治理后续可单独扩展。

## 目标

- 新增 `references/uploads-imports.md`，覆盖文件选择、拖拽、类型大小校验、上传队列、进度、取消、重试、重复触发、删除已选文件和失败恢复。
- 覆盖表单内文件字段：文件字段值、上传会话、提交快照、dirty/touched、服务端错误归属、容器关闭和路由处置。
- 覆盖结构化导入：模板下载、文件上传、预检、字段映射、确认导入、异步任务、部分成功、错误明细、结果回执和任务中心衔接。
- 明确与 Form、Button、Dialog/Drawer、Data Table、Admin Console、Responsive owner 的组合边界，避免重复定义它们已有规则。
- 建立 RED/GREEN 文档压力测试与结构化审计，确保常见上传与导入违规形态可被抓住。

## 非目标

- 不定义底层存储、对象存储签名、病毒扫描、后端分片协议、CDN、转码服务或文件内容解析算法。
- 不覆盖完整文件与媒体管理系统，例如文件夹、版本、分享链接、在线预览、图片裁剪、音视频转码和素材库治理。
- 不替代表单提交、按钮防重复、Dialog/Drawer 关闭、管理台审计、异步任务中心或数据表格结果展示 owner。
- 不规定具体框架、组件库、上传 SDK 或视觉 token；只定义可观察产品行为、状态模型和验收条件。

## 推荐方案

采用独立 Upload / Import owner，并与现有 owner 明确组合。

### 方案对比

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 独立 `uploads-imports.md` owner | 能集中治理文件生命周期、导入预检、进度、取消、重试和结果明细；与表单、按钮、管理台边界清楚。 | 需要新增路由、README/HANDOFF 摘要和审计。 | 推荐。 |
| 只扩展 `admin-console.md` 的导入任务章节 | 少一个文件，任务中心衔接直接。 | 普通上传、表单内文件字段、移动端选择文件会被管理台语境绑死；非管理台项目难复用。 | 不采用。 |
| 把上传看作表单字段写进 `forms.md` | 能覆盖表单提交快照。 | 导入预检、异步任务、错误明细、文件队列和取消重试超出表单职责。 | 不采用。 |

## 首版范围

首版覆盖：

- 单文件上传、多文件上传、拖拽上传、重新选择和删除待上传文件。
- 表单内附件、头像、文档、CSV/XLSX/JSON 等文件字段。
- 管理台导入：模板下载、上传文件、预检、字段映射、确认导入、任务进度、结果和错误明细。
- 上传队列、每文件状态、整体状态、重复触发门禁、取消和重试。
- 权限、租户/工作区、文件访问过期、错误明细下载和审计回执。
- PC、移动端、触摸、键盘、低高度、虚拟键盘、安全区域和辅助技术可达性。

暂不覆盖：

- 文件夹、文件库、素材库、媒体资产管理。
- 在线预览、图片编辑、视频音频转码、断点续传协议细节。
- 后端解析、杀毒、内容审核、数据清洗算法。
- 纯视觉样式、组件库 API 和云厂商 SDK 用法。

## 核心设计

### 1. 文件选择与本地校验

上传入口必须说明接受的文件类型、大小、数量和业务含义。浏览器 `accept` 只能作为选择器提示，不能作为唯一校验；选择、拖拽、粘贴或程序传入文件后，都必须用同一套校验规则生成可见且可访问的结果。

文件校验至少区分：类型不支持、大小超限、数量超限、空文件、重复文件、文件名冲突、权限不足、租户不匹配和内容不可解析。无效文件不得进入待上传请求队列；若产品允许保留在列表中，也必须标记为 invalid 且提供删除或重新选择路径。

### 2. 上传状态模型

每个上传 owner 维护 `uploadSessionState`，至少包含：

| 字段 | 语义 |
| --- | --- |
| `sessionId` | 当前上传会话身份，路由、容器或字段重建时更新。 |
| `sourceOwner` | 触发来源，例如独立上传区、表单字段、Dialog、Drawer 或导入流程。 |
| `acceptedPolicy` | 文件类型、大小、数量、来源和业务约束快照。 |
| `fileItems` | 每个文件的稳定身份、名称、大小、类型、本地校验、上传阶段、错误和结果。 |
| `queuePhase` | `idle`、`validating`、`ready`、`uploading`、`paused`、`completed`、`partial-failed`、`failed`、`cancelled`、`disposed`。 |
| `requestIdentity` | 上传请求的幂等键、权限版本、租户/工作区、文件快照和来源操作。 |
| `resultOwner` | 成功、失败、部分成功、未知结果和恢复入口的 primary owner。 |

上传状态不能只绑定到按钮 loading 或表单 submitting。按钮可以触发上传，表单可以读取文件字段值，但文件队列、进度、错误和恢复必须有自己的 owner。

### 3. 进度、取消和重试

上传开始后必须展示整体状态；多文件上传还必须展示每个文件的状态。进度未知时不能伪造百分比，应显示排队、处理中或未知进度。完成、失败、取消和部分失败必须有可感知回执。

取消分为客户端取消意图和服务端确认结果。用户关闭 Dialog、离开页面或点击取消，只能说明客户端停止等待或发出取消请求；若请求已经发送，不得直接把服务端任务写成已取消。迟到结果必须通过 `sessionId`、请求身份和当前 owner 校验后才可写回。

重试必须说明重试范围：仅失败文件、全部文件、重新预检或重新提交导入任务。重试复用还是创建新幂等身份必须明确；不得因重复点击、Enter、Space、触摸或事件重放产生重复上传或重复导入。

### 4. 表单内上传

文件字段作为表单字段时，Form owner 仍负责字段 label、dirty/touched、提交快照、错误摘要和未保存更改；Upload owner 负责文件选择、上传队列、进度、文件级错误和上传结果。

表单提交前必须明确文件字段的提交策略：

- 先上传后提交：只有已成功上传且仍有效的文件引用进入 `submitSnapshot`。
- 提交时上传：上传请求与表单提交共享一次不可变快照，失败时保留草稿和文件队列。
- 仅本地草稿：文件只在用户显式提交后进入上传或导入流程。

删除已上传文件、替换文件、上传失败、服务端文件引用过期和权限变化都必须更新字段 dirty、错误归属和恢复路径。表单 reset 或 route/unmount 只能释放本表单会话拥有的上传资源，不能影响其他存活上传会话。

### 5. 导入流程

结构化导入必须显式分阶段：模板下载、文件选择、本地校验、上传、预检、字段映射或规则确认、确认导入、执行任务、结果回执。简单导入可以合并视觉步骤，但不能省略状态与决策边界。

预检结果必须区分：格式错误、字段缺失、字段映射不完整、重复数据、权限不可执行、将被跳过的数据、警告和可继续风险。存在阻断错误时不得进入确认导入；存在警告时必须说明影响范围，由用户显式确认后才继续。

字段映射和导入配置属于导入快照的一部分。确认导入后，后续编辑映射、切换租户、替换文件或权限版本变化都不得改写已发送任务；必须新建导入意图或终止当前候选。

### 6. 部分成功与错误明细

导入结果至少区分成功、部分成功、失败、取消、未知结果、过期和无权限查看结果。部分成功不能只用 Toast 表示；必须展示成功数、失败数、跳过数、影响范围、下一步和错误明细入口。

错误明细下载是敏感结果访问，不是普通静态链接。下载前必须复核权限、租户/工作区、任务身份和文件有效期；权限变化或任务过期后不得继续暴露旧链接。错误明细本身应避免泄露无权访问对象的敏感字段。

### 7. 权限、安全和审计

上传与导入必须绑定权限版本、租户/工作区、来源页面、发起者和目标范围。权限、租户、工作区或角色变化时，未完成上传、导入确认、错误明细和下载入口都必须重新证明安全；无法证明时先隐藏、失效或替换为安全说明。

高风险导入、覆盖导入、批量创建/更新/删除、权限相关导入和敏感文件上传必须接入管理台风险、确认和审计 owner。审计至少记录发起者、时间、目标范围、文件摘要或不可逆标识、配置快照、请求身份和结果。

### 8. 响应式与可访问性

上传入口必须可键盘操作，可见 label 与帮助文本说明文件要求，错误信息通过稳定描述关联到入口或文件项。拖拽上传不能是唯一入口；必须有等价的选择文件按钮。上传进度、失败、完成和部分成功应有非重复状态公告。

移动端、低高度、虚拟键盘、安全区域和 200% 缩放下，选择文件、删除文件、查看错误、重试、确认导入和下载错误明细都必须可达。低频说明可以折叠，但文件要求、阻断错误和恢复入口不能消失。

## 与现有 owner 的关系

- `forms.md`：字段 label、dirty/touched、submitSnapshot、错误摘要、未保存更改和失败恢复仍归 Form；Upload 负责文件队列、上传进度、文件级错误和文件引用有效性。
- `buttons.md`：选择文件、上传、取消、重试、确认导入和下载错误明细按钮遵循 Button 的文案、层级、loading、防重复和危险按钮规则。
- `dialogs.md` / `drawers.md`：上传或导入流程放入容器时，遮罩、关闭、焦点陷阱、滚动、动画和 disposal 仍归容器 owner。
- `data-tables.md`：导入预检表、错误明细表和结果明细表遵循 Data Table 的展示、筛选、分页、选择和导出规则。
- `admin-console.md`：权限、租户、风险、审计、任务中心、全局反馈和导入任务结果仍归 Admin；Upload / Import 不得绕过这些页面级 owner。
- `responsive-adaptive.md`：移动端、触摸、虚拟键盘、安全区域和能力折叠仍归 Responsive；Upload / Import 声明文件入口与恢复路径在这些形态下必须可达。

## 新 owner 草案结构

计划新增 `references/uploads-imports.md`：

1. 范围与术语
2. 文件选择、拖拽与本地校验
3. `uploadSessionState` 状态模型
4. 上传队列、进度、取消和重试
5. 表单内上传与文件字段
6. 导入流程、模板、预检和字段映射
7. 确认导入、异步任务和结果回执
8. 部分成功、错误明细和下载权限
9. 权限、租户、安全和审计
10. 响应式、键盘和可访问性
11. 与现有 owner 的组合规则
12. 可执行验收

稳定规则族建议：

- `UPL-SCOPE-*`：范围、术语和非目标。
- `UPL-PICK-*`：选择、拖拽、粘贴、类型、大小、数量和本地校验。
- `UPL-STATE-*`：上传会话、文件项、队列、进度和结果 owner。
- `UPL-ASYNC-*`：重复触发、请求身份、取消、迟到结果和重试。
- `UPL-FORM-*`：表单内文件字段、提交策略、dirty/touched 和 reset。
- `IMP-FLOW-*`：模板、上传、预检、映射、确认导入和执行任务。
- `IMP-RESULT-*`：成功、部分成功、失败、未知结果和错误明细。
- `UPL-PERM-*`：权限、租户、文件访问过期、下载复核和敏感信息。
- `UPL-A11Y-*`：键盘、焦点、状态公告、错误关联和拖拽替代。
- `UPL-RSP-*`：移动端、触摸、缩放、虚拟键盘和安全区域。

## 测试与验证策略

采用 RED/GREEN 文档压力测试：

- RED：在没有 Upload / Import owner 的情况下，让 fresh 输出管理台 CSV 导入、表单附件上传、批量图片上传和错误明细下载设计，记录是否出现只靠 `accept` 校验、重复上传、取消误写成服务端取消、无预检、部分成功只 Toast、错误明细下载不复核权限、移动端入口不可达等问题。
- GREEN：启用 owner 后，同样任务必须声明文件政策、上传会话、文件项状态、请求身份、防重复、取消语义、重试范围、预检、字段映射、确认导入、任务结果、错误明细权限、键盘和运行时验证边界。
- 审计脚本：检查 owner 规则、路由、`uploadSessionState`、本地校验、进度、取消/重试、表单提交策略、导入预检、字段映射、部分成功、错误明细权限、运行时未验证边界。

关键 mutation：

- 删除服务端前本地类型/大小/数量校验，必须失败。
- 把 `accept` 写成唯一校验，必须失败。
- 删除上传会话身份或文件项状态，必须失败。
- 重复点击产生多个上传或导入任务，必须失败。
- 把客户端取消直接写成服务端已取消，必须失败。
- 删除导入预检或阻断错误检查，必须失败。
- 部分成功只用 Toast 表示，必须失败。
- 错误明细下载不复核权限和任务身份，必须失败。
- 表单 reset 释放其他上传会话资源，必须失败。
- 移动端只保留拖拽入口或删除恢复入口，必须失败。

## 验收标准

- Upload / Import owner 首版范围清晰，覆盖普通上传、表单内上传和结构化导入。
- 文件选择、本地校验、上传状态、进度、取消、重试、导入预检、字段映射、结果明细和权限复核可被审计。
- 与 Form、Button、Dialog/Drawer、Data Table、Admin Console 和 Responsive owner 边界不冲突。
- README/HANDOFF/SKILL 只做摘要和路由，不复制 owner 细节。
- RED/GREEN 输出和审计 mutation 能覆盖核心反例。
- 未执行浏览器、屏幕阅读器、触摸设备或真实组件运行时时，所有证据必须标为未验证。
