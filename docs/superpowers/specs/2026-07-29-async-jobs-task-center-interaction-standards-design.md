# 异步任务与任务中心交互规范设计

## 背景

管理台中的导入、导出、批量操作、报表生成、AI 生成、外部系统同步、任务取消和任务重跑都可能进入长耗时、跨页面或未知结果状态。现有 `admin-console.md`、`risk-actions.md`、`uploads-imports.md` 和 `global-feedback.md` 已经约束了任务相关片段，但缺少一个职责单一的 owner 来统一回答：

- 请求已发送后，关闭 Dialog、Drawer、Toast、页面或浏览器是否等于取消任务。
- 任务创建、排队、运行、部分成功、失败、取消中、未知结果、过期和结果领取由谁持有。
- 任务中心、通知、来源页面、结果页和审计之间如何共享同一任务身份。
- 导出下载、错误明细、重试、取消、重跑、查看结果在权限变化后如何复核。

这类问题高频且高风险，适合新增独立 `references/async-jobs-task-center.md`，作为异步任务生命周期、任务中心恢复和跨页面任务结果的唯一事实来源。

## 目标

新增“异步任务与任务中心”规范 owner，覆盖 async job、background task、job center、task center、导入导出任务、批量任务、报表生成、AI 生成、同步任务、取消任务、重跑任务、结果领取、进度、部分成功、未知结果、过期和移动端恢复。

该 owner 的核心目标：

1. 固定任务状态模型，避免用 `loading`、Toast 文案或按钮 disabled 隐式表达任务生命周期。
2. 明确“客户端关闭/离开”和“服务端取消/完成”的边界。
3. 让任务身份、幂等键、权限版本、输入快照、来源页面、结果回执和审计绑定可追踪。
4. 要求任务中心或等价持久 owner 承担跨页面任务查看、恢复、领取结果和错误明细。
5. 约束移动端不能删除任务进度、任务中心入口、取消中、未知结果、错误明细、结果领取和恢复路径。

## 非目标

- 不重新定义文件选择、上传队列、导入预检、字段映射和文件级错误；这些继续由 `uploads-imports.md` 管理。
- 不重新定义危险操作确认、风险分级、输入确认、撤销窗口和审计回执；这些继续由 `risk-actions.md` 管理。
- 不重新定义 Toast、Notification、Alert、Banner 的通道选择；这些继续由 `global-feedback.md` 管理。
- 不重新定义数据表格选择、批量范围、分页和跨页选择；这些继续由 `data-tables.md` 管理。
- 不定义后端队列、重试算法、调度策略、任务 worker、对象存储或通知服务实现。

## 推荐方案

采用完整 owner 方案：新增 `asyncJobState`，并把 Skill 路由、README、HANDOFF 和结构化审计同步接入。

对比其他方案：

- 只补导入/导出任务：实现快，但批量操作、AI 生成、报表生成和同步任务仍没有统一生命周期，后续会继续散落。
- 只补任务中心页面：能规范展示页，但无法约束任务创建、关闭语义、取消请求、结果领取和来源页面恢复。
- 完整 owner：一次性解决跨页面长任务语义，成本略高，但边界最干净，最符合管理台高频风险场景。

## 规范结构

新增 `references/async-jobs-task-center.md`，建议结构：

1. 范围与边界。
2. `asyncJobState` 状态模型。
3. 任务创建、请求身份和幂等。
4. 排队、运行、进度和轮询/订阅。
5. 关闭、离开、取消、重跑和未知结果。
6. 任务中心、通知、来源页面和结果页的 owner 分工。
7. 部分成功、错误明细、结果领取和下载权限复核。
8. 权限、租户/工作区、安全和审计绑定。
9. 可访问性、焦点、公告和移动端承载。
10. 完成前检查与未验证边界。

`asyncJobState` 至少包含：

| 字段 | 语义 |
| --- | --- |
| `jobOwnerId` | 当前任务 owner 稳定身份。 |
| `jobId` | 服务端任务身份；任务创建前使用候选身份。 |
| `jobKind` | `import`、`export`、`bulk-action`、`report-generation`、`ai-generation`、`sync`、`webhook`、`scheduled-run`、`risk-action` 等。 |
| `sourceSurface` | 任务来源页面、Dialog、Drawer、列表、详情、任务中心或 API 回调。 |
| `requestIdentity` | 操作 ID、幂等键、权限版本、租户/工作区、输入快照、目标快照和发起者。 |
| `inputSnapshot` | 文件、筛选、选择、配置、提示词、时间范围、导出范围或同步范围快照。 |
| `jobPhase` | `draft`、`creating`、`queued`、`running`、`waiting`、`cancel-requested`、`cancelled`、`succeeded`、`partial-succeeded`、`failed`、`unknown`、`expired`。 |
| `progressState` | 百分比、阶段、已处理数量、总数、未知进度、数据延迟和最近更新时间。 |
| `resultState` | 成功、部分成功、失败、取消、未知、过期、无权限查看和结果领取状态。 |
| `cancelPolicy` | 是否可取消、取消请求语义、取消中展示、服务端回执要求和取消失败恢复。 |
| `retryPolicy` | 重试范围、幂等语义、是否会重复执行、成功项处理和权限复核。 |
| `artifactState` | 导出文件、错误明细、结果文件、报告、生成内容或外部同步回执的可见性、下载身份、有效期和权限。 |
| `notificationBinding` | Toast/Notification/任务中心/来源页面/结果页的 primary owner 与去重策略。 |
| `auditBinding` | 审计可用性、审计请求身份、写入结果、查看位置和审计失败说明。 |
| `permissionBoundary` | 查看、取消、重试、下载、领取结果、查看错误明细和查看审计的权限版本。 |
| `responsivePolicy` | 移动端任务入口、任务详情、底部操作、返回路径、恢复路径和安全区域策略。 |

## 关键规则

### 任务身份和创建

任务创建必须冻结 `requestIdentity` 和 `inputSnapshot`。重复点击、Enter、Space、触摸、网络重试和事件重放不能创建多个等价任务；要么复用同一幂等语义，要么明确拒绝重复意图。

任务创建成功前，UI 只能展示创建中、创建失败或未知创建结果；不能提前把任务写成排队或运行成功。任务创建失败必须保留来源上下文、输入快照和可恢复动作。

### 生命周期和取消边界

关闭 Dialog、Drawer、Toast、Notification、来源页面、浏览器 Tab 或移动端系统返回，只能表达客户端关闭或停止等待，不得伪装成服务端任务已取消。

取消请求已发送不等于任务已取消。必须区分不可取消、可请求取消、取消请求已发送、取消中、服务端已取消、取消失败、已完成无法取消和未知结果。

未知结果不得伪装成成功或失败。必须提供检查最新状态、进入任务中心、刷新任务详情、查看审计或联系支持路径。

### 任务中心和跨页面恢复

跨页面、长耗时、可取消、可重试、可领取结果或可能未知的任务，必须有任务中心、任务详情页、来源页面持久区域或等价持久 owner。Toast 和 Notification 只能辅助提醒，不能作为唯一状态、唯一错误、唯一下载入口或唯一恢复路径。

任务中心列表必须区分任务类型、来源、状态、进度、发起者、创建时间、更新时间、结果有效期、权限状态和可执行动作。任务详情必须展示输入快照摘要、当前状态、结果、错误明细、审计位置和恢复动作。

### 结果、产物和权限

导出文件、错误明细、结果文件、AI 生成内容、报表文件和同步回执都属于 `artifactState`。领取、下载、复制、重试和分享前必须复核任务身份、权限版本、租户/工作区、有效期和请求身份。旧链接、旧通知和旧缓存不得绕过权限复核。

部分成功必须说明成功、失败、跳过、冲突和未知的范围，并提供错误明细、重试失败项、下载结果或进入任务详情路径。不得只用 Toast 表示部分成功。

### 移动端和可访问性

移动端不得删除任务中心入口、任务状态、进度、取消中、重试、结果领取、错误明细、未知结果说明、权限说明或恢复路径。低频字段可以折叠，但必须可发现、可触达、可键盘/辅助技术访问。

进度、取消中、失败、部分成功、未知、过期和结果可领取必须有可见文本或可访问公告；不能只靠颜色、动画、spinner、图标或 Toast。

## 路由与集成

`SKILL.md` 需要新增路由，命中词包括：

- 中文：异步任务、后台任务、任务中心、任务详情、任务进度、任务取消、取消中、重跑任务、任务重试、导入任务、导出任务、批量任务、报表生成、AI 生成、同步任务、结果领取、错误明细、未知结果、过期任务。
- 英文：async job、background task、job center、task center、job detail、job progress、cancel job、cancelling、rerun job、retry job、import job、export job、bulk job、report generation、AI generation、sync job、result artifact、error report、unknown result、expired job。

`README.md` 需要加入摘要和链接；`HANDOFF.md` 需要说明该 owner 已新增，并标记详细规则只维护在 `references/async-jobs-task-center.md`。

## 审计设计

新增 `docs/testing/async-jobs-task-center/`：

- `green-summary.md`：记录正确实现必须覆盖的状态模型、关闭/取消边界、任务中心持久 owner、结果产物权限复核、部分成功、未知结果、移动端能力和未验证边界。
- `red-summary.md`：记录错误实现，包括 Toast-only、关闭即取消、取消请求即已取消、未知结果写成功、旧下载链接绕过权限、任务无 owner、移动端删除恢复路径等。
- `async-jobs-task-center-audit.rb`：检查 owner、Skill 路由、README、HANDOFF 和红绿证据；突变测试覆盖上述红线。

审计禁止出现业务项目特定路径或名称，保持规范不被某个项目污染。

## 验证计划

设计阶段完成后：

1. 提交设计文档。
2. 编写实施计划并提交。
3. 实现 owner、路由、README、HANDOFF、红绿证据和审计脚本。
4. 运行新增审计突变测试。
5. 运行全量已维护审计、Markdown 链接检查和 `git diff --check`。
6. 提交实现并推送 `main`。

## 自检

- 没有占位项、空白决策或未收束的小尾巴。
- 范围聚焦在异步任务生命周期，不替代导入、风险、反馈、表格和响应式 owner。
- 任务关闭、取消、未知结果、产物权限和任务中心持久 owner 的边界明确。
- 移动端能力保持与 PC 业务结果一致。
- 未声明真实运行时通过；后续实现必须保留“未验证”边界。
