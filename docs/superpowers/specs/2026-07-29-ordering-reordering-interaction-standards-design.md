# 排序与重排交互规范设计

## 背景

管理台中常见“排序值”“拖拽排序”“上移/下移”“置顶/置底”“调整展示顺序”等需求。现有记录编辑承载面已禁止列表内排序输入，但缺少正向规范说明应如何处理人工重排：什么时候进入排序模式，什么时候用 Dialog/Drawer/独立页，什么时候允许命令式上移下移，以及如何处理拖拽、键盘替代、分页、筛选、权限、冲突和移动端。

## 目标

- 新增 `references/ordering-reordering.md`，作为人工排序、重排、置顶、置底、上移、下移、拖拽排序、排序模式和顺序保存的唯一 owner。
- 明确 `orderingReorderingState`，要求排序范围、草稿顺序、提交快照、冲突处理、权限边界、反馈和运行时验证可观察。
- 禁止在列表、表格或卡片中常驻排序输入、每行保存按钮或 spreadsheet-like 排序矩阵。
- 明确拖拽不能是唯一方式，必须有按钮或键盘替代路径。
- 明确分页、筛选、搜索、权限和数据版本变化会影响排序范围，不能把当前页局部顺序伪装成全量顺序。

## 非目标

- 不替代数据表格的查询排序、列排序、服务端 sort 参数、分页或结果摘要。
- 不替代记录编辑承载面、表单字段校验、按钮、防重复、风险确认或管理台权限审计。
- 不定义具体拖拽库、动画库、CSS token、像素间距或后端排序算法。

## 推荐方案

采用独立 reorder owner。入口可以放在页面工具栏、行操作或卡片操作中，但一旦进入人工重排，必须创建 `orderingReorderingState`，并在显式排序模式、Drawer、Dialog 或独立页中维护草稿顺序和提交快照。

选择承载面：

- 单页、少量、低风险、无需深链：显式排序模式或 Dialog。
- 中等数量、需要保留列表上下文或解释冲突：Drawer。
- 跨页、跨筛选范围、多分组、强审计、协同或移动端主流程：独立页。

## 验证设计

新增 `docs/testing/ordering-reordering/ordering-reordering-audit.rb`：

- 检查 owner 文档完整字段。
- 检查禁止排序输入常驻列表、拖拽-only、当前页伪装全量、保存旧快照等硬规则。
- 检查 SKILL 路由、README、HANDOFF 和相邻 owner 引用。
- 检查 RED/GREEN 证据与项目泄漏扫描。
- 运行 mutation 证明核心句子、路由和证据缺失会失败。
