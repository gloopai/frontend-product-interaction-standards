# 管理台完整治理交互规范设计

## 背景

现有 Skill 已覆盖 Dialog、Drawer、Select / Combobox、表单、数据表格与响应式适配。这些 owner 能约束组件和局部流程，但管理台还需要一层跨页面治理：同一个后台系统里的导航、权限、危险操作、审计、导入导出、异步任务、报表口径和全局反馈必须一致，否则 Agent 容易把每个页面当成孤立组件来设计。

本阶段新增 `admin-console` 规范，作为后台、管理台、控制台、运营后台、SaaS console 和内部工具的跨页面 owner。

## 目标

- 建立管理台页面级能力声明，区分报表、列表、详情、设置、任务、审计日志、导入导出等场景。
- 约束导航、面包屑、Tabs、返回路径、路由恢复和离开确认。
- 约束权限、租户、工作区和能力降级，防止越权内容泄露或无解释消失。
- 约束危险操作、批量操作、强确认、提交门禁、结果回执和失败恢复。
- 约束审计留痕、操作回执、异步任务、导入导出和敏感下载边界。
- 约束报表和仪表盘的只读展示、指标口径、刷新状态、延迟数据、无权限和异常状态。
- 约束 Toast、Alert、Notification、Popover、Tooltip 在管理台中的使用边界。

## 非目标

- 不重新定义数据表格、表单、Dialog、Drawer、Select 或响应式细节；相关页面仍必须读取对应 owner。
- 不定义业务专属权限模型、审计字段枚举或具体指标口径；只规定必须声明、呈现和验证的边界。
- 不覆盖低代码搭建器、可视化报表编辑器、流程编排器、富文本 CMS、代码编辑器等复杂产品类别；这些以后应单独建 owner。
- 不要求所有管理台页面都有选择、批量、导入、导出或审计日志。能力必须由当前场景显式声明。

## Owner 定位

`references/admin-console.md` 是管理台跨页面规则的唯一事实来源。它负责判断页面级场景、能力、权限、风险、审计和全局反馈。组件级行为继续由现有 owner 管理：

- 表格、报表、列表、分页、筛选、排序、选择、批量操作读取 `data-tables.md`。
- 表单、设置页、编辑页和提交失败恢复读取 `forms.md`。
- 确认、详情、编辑或结果弹窗读取 `dialogs.md` / `drawers.md`。
- 选择器读取 `selects-comboboxes.md`。
- 跨端布局、导航折叠和安全区域读取 `responsive-adaptive.md`。

当 `admin-console` 与组件 owner 都适用时，两者都执行；冲突时停止并请用户裁决。

## 场景模型

每个管理台页面必须声明一个或多个 `consoleSurface`：

- `overview-dashboard`：概览、仪表盘、运营看板。
- `report`：只读报表、指标明细、统计页。
- `record-list`：资源列表、用户列表、订单列表、日志列表。
- `record-detail`：详情页、审阅页、只读实体页。
- `record-editor`：创建、编辑、配置表单。
- `settings`：系统设置、组织设置、个人设置。
- `job-center`：后台任务、导入导出、批处理进度。
- `audit-log`：审计日志、操作历史、访问记录。

页面可以组合场景，但必须声明主场景和每个子区域的能力边界。报表默认只读展示，不自动推导选择列、行操作或批量操作；列表是否支持选择、行操作、批量、导出或跳转必须由产品显式声明。

## 页面级状态

管理台页面至少区分以下状态 owner：

- `navigationState`：当前全局导航项、面包屑、页内 Tabs、返回目标、恢复策略。
- `permissionState`：当前用户、角色、租户/工作区、权限范围、能力开关、权限版本。
- `surfaceState`：主场景、子区域、加载阶段、空态、错误、只读/可操作能力。
- `riskState`：危险操作、影响范围、确认等级、提交门禁、幂等键和结果回执。
- `auditState`：操作主体、目标范围、请求身份、结果身份、可追踪回执和审计可用性。
- `taskState`：导入、导出、异步任务、队列、进度、取消边界、重试和结果文件。
- `feedbackState`：全局 Toast、Alert、Notification、页面内状态消息和公告 owner。

组件 owner 可以拥有自己的局部状态，但不得替代页面级权限、风险、审计和导航 owner。

## 导航与路由

管理台页面必须有稳定页面标题和可定位主内容。多层页面使用面包屑或等价路径说明当前位置；Tabs 只用于同一资源或同一任务上下文内的并列视图，不能隐藏互不相关的页面。

返回路径必须由产品声明：回到上一页、回到列表、回到固定父级或留在当前页。返回列表时可以恢复查询、分页、滚动和选中项，但必须重新校验权限、数据版本和范围有效性；旧菜单、旧弹窗、旧操作快照和旧错误不得回放。

Dirty 表单、未完成导入、危险操作确认中、不可安全中断的任务启动前，都必须在路由离开、浏览器返回、关闭容器或切换关键上下文前处理确认或安全中止。

## 权限、租户与能力降级

权限是安全边界，不是视觉开关。页面加载、租户/工作区切换、角色变化、权限版本变化和重新认证后，必须原子计算 `resolvedSurface`、可见数据范围、可执行操作和可导出范围。

越权内容不得在等待刷新时继续暴露。无法同步证明仍可见的数据、字段、操作或导出入口必须先隐藏或替换为安全占位，再按新权限范围刷新。权限不足状态必须解释原因和可恢复路径；但不能用禁用控件泄露敏感对象名称、数量或字段。

权限降级必须清理不再合法的选择、打开菜单、确认弹窗、操作快照、导入导出任务入口和敏感下载链接。焦点位于被移除控件时，只迁移一次到同级安全目标或页面状态消息。

## 危险操作与结果回执

删除、停用、权限变更、批量修改、敏感导出、重新同步、重跑任务、取消任务、清空数据和不可逆配置变更都属于风险操作。每个风险操作必须声明：

- `riskLevel`：普通、破坏性、高影响、不可逆或敏感。
- `impactScope`：单对象、当前页、全部筛选结果、当前租户、跨租户或系统级。
- `confirmationPolicy`：普通确认、强确认、输入数量/名称、二次审批或禁止前台直接执行。
- `requestIdentity`：操作 ID、幂等键、权限版本、目标快照和发起者。
- `resultReceipt`：成功、部分成功、失败、冲突、未知结果和审计回执。

风险操作不能只用 Toast 表示结果。成功或失败都必须在页面内留下可追踪回执或可恢复状态；Toast 只能作为辅助提醒。未知结果不得伪装成失败或成功，必须提供检查最新状态或进入任务中心的路径。

## 审计留痕

管理台的变更操作必须能追踪“谁、何时、在哪个租户/工作区、对哪些目标、以什么请求身份、得到什么结果”。界面不需要展示所有审计字段，但必须说明审计可用性、回执位置和失败时的恢复路径。

审计日志页面必须区分数据为空、无权限查看、筛选无结果、审计服务不可用和数据延迟。审计查询不得泄露无权访问的主体、对象或租户名称；导出审计日志必须执行导出权限和敏感字段边界。

## 导入、导出与异步任务

导入必须声明文件类型、大小、字段映射、预检查、提交快照、幂等键、部分成功、错误文件和重试策略。预检查失败不得创建执行任务；执行后失败必须保留可下载错误、可定位行号和下一步。

导出必须声明导出范围、筛选快照、权限范围、敏感字段、文件生成方式、过期时间和下载身份。敏感导出不得只靠隐藏按钮防护；下载链接必须绑定权限和请求身份，过期或权限变化后失效。

异步任务必须有任务中心或等价入口，展示排队、运行中、成功、部分成功、失败、取消中、已取消、未知结果和过期状态。关闭页面不能伪装成取消任务；取消请求也不能伪装成服务端已停止，除非任务结果明确确认。

## 报表与仪表盘

报表和仪表盘默认是只读展示。它们必须声明指标口径、时间范围、刷新时间、数据延迟、权限范围和过滤条件。缺少口径或延迟状态时，不得把数字写成可决策结论。

空态必须区分：当前权限下无数据、筛选无结果、指标尚未产生、数据服务失败、数据延迟和口径不可用。图表、指标卡和表格明细必须共享同一筛选/权限快照，不能让卡片和明细展示不同范围而不说明。

报表的钻取、导出和订阅是可选能力，必须显式声明。启用时执行数据表格、导出和权限规则；未启用时不得留下无效入口。

## 全局反馈组件

Toast 适合短暂辅助反馈，不适合作为唯一错误、唯一成功回执、唯一审计凭证或唯一恢复入口。Alert 适合页面内持续状态、阻断问题和重要恢复路径。Notification 适合跨页面异步任务和系统消息。Popover / Tooltip 只能补充说明，不能承载必读权限原因、错误文本、确认后果或唯一操作入口。

同一完整消息只能有一个 primary owner。页面内状态、Toast、实时区域和错误摘要不得重复播报同一完整错误。需要用户行动的失败必须有可聚焦、可键盘到达的恢复入口。

## 响应式与信息密度

管理台移动端可以折叠低频导航、筛选、列和次要操作，但核心任务、权限判断、错误恢复、审计回执和危险操作确认不能消失。导航 Drawer、底部动作条、更多菜单和页内 Tabs 必须保持当前页面上下文、焦点和可访问名称。

高密度后台页面应优先支持扫描、比较和重复操作，不使用营销式 hero 或装饰性大卡片承载主要工作区。布局变化不得改变业务语义或把报表只读页升级为可操作列表。

## 验收方向

实施时需要为以下场景建立 RED/GREEN 压力测试：

1. 报表页被错误加入选择列、批量操作或无口径数字。
2. 权限/租户变化后旧数据、旧菜单或敏感导出链接继续可见。
3. 危险操作只用 Toast 表示结果，缺少页面内回执或审计路径。
4. 导入预检查失败仍创建任务，导出权限变化后链接仍可下载。
5. 异步任务关闭页面后被伪装成取消成功。
6. 审计日志把无权限、无数据、筛选无结果和服务失败混成同一空态。
7. 移动端折叠后丢失恢复入口、权限原因或危险操作后果说明。
8. 全局反馈重复播报同一完整错误，或 Tooltip 承载唯一必读信息。

每个验收都必须记录初始状态、事件序列、预期状态、DOM/ARIA、键盘路径、焦点、公告、权限/审计事件和未验证边界。
