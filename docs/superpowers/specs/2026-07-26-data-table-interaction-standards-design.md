# 数据表格交互规范设计

## 目标

新增一套与框架无关的数据表格交互规范，统一表格、分页、筛选、排序、选择和批量操作。规范既要支持只读报表，也要支持管理列表，不能强迫所有表格都提供选择或批量能力。

## 架构与职责

`references/data-tables.md` 是本类别完整规则的唯一来源。`SKILL.md` 只负责将匹配的中英文任务路由到该文件；`README.md` 和 `HANDOFF.md` 只保留简要摘要与链接。

第一版覆盖：

- 数据表格结构和列行为；
- 展示型、单行操作型和批量操作型三种能力档位；
- 筛选、排序、页码分页和游标分页；
- 当前页选择，以及显式启用的“全部筛选结果”选择；
- 单行操作和批量操作，包括部分失败恢复；
- 加载、空状态、过期数据、错误、焦点、键盘、无障碍、响应式和卸载行为。

第一版不包含行内编辑、树形表格、拖拽行排序、透视表、加载更多、无限滚动、用户拖拽调整列顺序和个人布局持久化。

## 能力档位

每张表格必须显式声明一种能力档位：

- `display`：只读报表或分析结果，不渲染选择控件和批量操作界面。
- `row-action`：允许行跳转、行详情或单行操作，但不支持多选。
- `bulk-action`：显式启用选择与批量操作。

权限可以让表格降为更低的能力档位。降级时应完整移除不可用能力，不能留下空选择列、无内容工具栏或没有恢复路径的禁用控件。

## 状态模型

状态分成四组：

1. 查询状态：已应用筛选、排序规则、分页模式和位置、每页条数、不可变查询快照、数据集版本、请求代次、加载状态和请求错误。
2. 展示状态：可见列、固定列、受限列宽、密度和已解析的响应式形态。
3. 交互状态：当前焦点单元格或控件、展开行、已打开的行操作和选择范围。
4. 操作状态：不可变操作快照、执行中操作、成功项、失败项、错误归属和恢复入口。

每次查询都创建不可变快照。只有请求代次和查询快照仍与当前表格会话匹配时，响应才能更新表格。筛选、排序、每页条数或分页变化会创建新的数据视图，并明确处理页码、焦点和选择状态。

## 筛选

区分筛选草稿和已应用条件。低成本的简单筛选可以即时应用；复杂筛选使用明确的“应用”操作。“重置”恢复约定的默认筛选值，不能含糊地清空所有条件。

已应用条件应持续可见并可单独移除，让用户理解当前结果为何出现。支持刷新恢复或分享时，可以把适合公开的筛选状态写入 URL，但不能把敏感值写入 URL。

应用或移除筛选会创建新的查询快照。页码分页回到第一个有效页，游标分页回到初始游标。若筛选变化改变了选择范围的含义，必须清除选择或要求用户明确重新确认。

## 排序

必须声明可排序列、默认排序、当前方向，以及单列或多列排序模式。不可排序列不提供排序控件，也不暴露错误的排序 ARIA 状态。

排序必须稳定。主排序值相同时使用稳定次序键，避免记录跨页重复或遗漏。改变排序会创建新的查询快照，并把分页重置到第一个有效位置。

## 分页

支持两种显式模式：

- 页码分页：适用于总数可靠且需要直接定位的数据集。
- 上一页/下一页游标分页：适用于总数不可靠或记录频繁变化的数据集。

游标分页不能虚构总页数或不受接口支持的随机跳页。改变每页条数后回到第一个有效位置。删除数据导致当前页失效时，回到最近的有效页并播报结果变化。

翻页和改变每页条数时必须保持可预测的焦点，不能静默保留已经改变含义的选择范围。

## 加载、空状态、过期数据与错误

刷新期间保留仍可使用的旧行和上下文，把表格结果区域标记为忙碌，并阻止重复请求。只有首次加载且没有可用结果时才使用骨架屏。

首次加载失败时，用归属于结果区域的错误和重试入口替代不可用结果。刷新失败时保留旧数据，明确提示数据可能已过期，并提供重试。筛选导致零结果时，说明当前条件无匹配并提供调整或清除筛选入口；整个数据源为空时使用与能力档位相符的独立空状态。

## 选择范围

只有 `bulk-action` 表格暴露选择控件。默认范围是当前页中可选择的记录。表头复选框只表达当前页的未选、部分选择或全选状态。

“选择全部筛选结果”是可选且必须显式启用的模式：

1. 用户先选择当前页。
2. 界面再提供独立操作，允许选择全部 `N` 条筛选结果。

跨页选择必须保存查询快照、筛选范围、排除项和展示数量，并持续显示其作用范围。筛选、排序、权限或数据集变化导致范围含义变化时，必须清除旧选择或要求明确重新确认。普通翻页可以保留已经确认的全部结果范围。

## 单行操作与批量操作

单行操作必须与行跳转和行选择保持独立。包含多个交互控件的整行不能被制作成一个巨大的链接。

批量操作基于不可变选择快照。确认界面必须显示操作类型、预计影响数量、已应用筛选范围、排除项和不可操作项。破坏性操作需要明确确认；不可逆或高影响操作根据风险使用更强确认。

执行期间阻止重复提交，同时保留状态反馈和安全退出路径。终态分为：

- 全部成功：移除已完成选择并刷新受影响数据；
- 部分成功：区分成功项和失败项，保留失败原因与重试入口；
- 全部失败：保留选择和上下文以便恢复；
- 权限或数据版本冲突：重新核对可操作范围，不能继续使用过期快照。

完成后的焦点根据结果可预测地移动到批量工具栏、结果摘要或第一个失败项。

## 列行为

第一版支持显示或隐藏列、固定列和有边界的宽度调整，不支持拖拽改变列顺序和个人布局持久化。

当隐藏关键标识列或主要任务列会导致任务无法完成时，这些列不能被隐藏。固定列不能遮挡焦点、菜单、错误或横向滚动内容。宽度调整必须有最小值和最大值，并提供键盘可操作的替代方式。

若准备隐藏的列承载当前排序、焦点或已打开操作，必须先显式解除或迁移该依赖。

## 语义、键盘与焦点

普通只读表格和包含常规控件的数据表格使用原生 `<table>`。只有产品确实需要单元格级键盘导航或选择时才使用 ARIA Grid，不能只为样式改用 Grid。

原生表格中的交互控件遵循浏览器正常 Tab 顺序。Grid 使用单一 Tab 入口和确定性的方向键导航，并根据适用范围明确 Home、End、Page Up 和 Page Down 行为。

表头与单元格保持明确关联。排序、筛选、分页、选择、加载、结果数量和批量结果具有可访问名称和状态。状态播报应简洁且只播报一次，不能重复朗读完整行内容。

刷新后应尽量通过稳定记录标识和列标识保留焦点目标。目标消失时，将焦点移动到最近的有意义控件或结果摘要，不能落到文档根节点。

## 响应式行为

桌面、平板和移动端保持核心任务与已启用能力档位一致。核心列保持可见，次要信息进入可访问的行详情或列控制。

必要时允许表格容器内部横向滚动，但页面本身不能横向溢出。滚动边界应可感知，且不能遮挡焦点。

只有经过明确业务设计且语义等价时，才允许切换为卡片列表。表格与卡片转换时保留查询、分页、选择、展开状态、焦点意图和操作快照，不重复发起请求或执行操作。

在 200% 缩放、字体放大、低高度视口、长翻译文本、触摸输入、动态视口、虚拟键盘和安全区域场景下，筛选、数据行、分页和错误恢复仍然可达且可操作。

## 生命周期与卸载

路由变化或 owner 卸载时，旧查询、分页、菜单、焦点、批量操作和公告回调全部失效。只释放当前表格实例拥有的资源，并保证幂等。已卸载表格不能移动焦点或修改另一张仍存活的表格。

返回页面时是否恢复查询和滚动位置由产品显式决定。恢复时不能回放过期选择、权限或操作快照。

## 错误归属

筛选字段错误归属于对应筛选控件；查询和刷新错误归属于结果区域；单行操作错误归属于受影响行或操作面；批量错误归属于操作结果摘要，并在需要时提供逐项详情。

每条完整错误消息只有一个主要 owner 和一条公告路径。修复某一行或某一项时，不能清除无关失败。

## 验收模型

owner 中的每条硬规则都必须映射到可观察检查。验收至少覆盖：

1. 三种能力档位只暴露各自启用的控件。
2. 快速连续筛选、排序和翻页时丢弃迟到响应。
3. 稳定排序保证跨页没有重复或遗漏记录。
4. 页码失效、游标边界、首次失败、刷新失败、筛选零结果和空数据集。
5. 当前页三态选择，以及带排除项和重新确认的“全部筛选结果”选择。
6. 批量重复提交、全部成功、部分成功、全部失败、权限变化和过期快照。
7. 隐藏列、固定列遮挡、键盘调整宽度，以及焦点和排序依赖迁移。
8. 原生 Table 与 ARIA Grid 各自正确的语义和键盘模型。
9. 响应式横向滚动、移动端行详情、明确的卡片等价转换、200% 缩放、长文本、低高度、触摸、虚拟键盘和安全区域。
10. 路由或卸载 disposal、迟到回调失效、焦点所有权和两张表格之间的实例隔离。
11. 未执行浏览器、屏幕阅读器、触摸设备或真实组件测试时，明确报告运行时未验证。

## 前向测试

使用新鲜代理执行 RED/GREEN 场景：

1. 展示型报表：包含排序、筛选、页码分页、长内容和移动端查看。
2. 单行操作型管理列表：包含游标分页、刷新失败、行菜单、焦点恢复和权限变化。
3. 批量操作型表格：包含当前页选择、可选的全部筛选结果、排除项、筛选变化、部分成功、重试和路由卸载。

owner 创建前记录各代理的决策分歧。实现后，用相同的用户式任务重新运行场景，并在不提供预期答案的情况下验证结果收敛。
