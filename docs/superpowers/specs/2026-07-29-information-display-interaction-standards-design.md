# 详情页、信息展示、描述列表与指标卡交互规范设计

## 背景

管理台中大量页面不是编辑页，而是详情页、概览页、描述列表、信息卡片、状态区、指标卡、审计摘要和对象元数据展示。它们看起来“只是展示”，但实际上常承担权限判断、风险提示、状态解释、导航入口、导出/复制、编辑入口和审计追溯等关键任务。

现有规范已经约束了表格、查询条件、记录编辑承载面、按钮、危险操作、反馈状态、日期时间与管理台治理，但缺少一个 owner 来回答这些问题：

- 只读字段展示时，字段名、值、单位、空值、未知值和无权限值如何区分？
- 详情页是否可以直接塞 input/select 做“顺手编辑”？
- 状态标签、指标卡、头像、徽标和颜色是否足以表达业务状态？
- 移动端折叠描述列表时，哪些信息不能被隐藏或丢失？
- 详情页中的编辑、复制、导出、删除、启停用等操作如何与展示快照绑定？
- 审计时间、创建人、更新时间、权限范围和数据延迟如何展示才不含糊？

## 目标

新增 `references/information-display.md`，作为详情页、信息展示、描述列表、只读字段、信息卡、指标卡、状态标签和元数据展示的唯一 owner。该 owner 只负责“信息如何被展示、解释、保护和关联操作”，不重写表单编辑、风险确认、导航返回、筛选查询或图表分析规则。

## 范围

- 详情页、对象详情、概览页、只读配置页、只读报表摘要。
- Description List、Key-Value List、Metadata Panel、Info Card、Summary Card。
- 指标卡、状态标签、徽标、头像/对象标识、只读字段、长文本展示、代码/ID 展示。
- 创建时间、更新时间、创建人、操作人、审计摘要、权限范围、数据延迟、刷新时间、过期状态。
- 详情页内的复制、跳转、编辑入口、导出入口、危险操作入口与结果回执。
- 移动端、窄屏、折叠区、Tabs、卡片重排和只读信息压缩。

## 非目标

- 不定义字段编辑生命周期；编辑仍读取 `forms.md` 和 `record-editing-surfaces.md`。
- 不定义危险操作确认；删除、停用、启用、归档、重置密钥等仍读取 `risk-actions.md`。
- 不定义报表图表视觉编码；图表后续可由独立 owner 约束。
- 不定义导航返回；来源恢复、面包屑和路由仍读取 `navigation-routing.md`。

## 设计原则

1. **展示必须有语义 owner**：详情页不是“随便排字段”。每块信息必须有 `informationDisplayState`，声明对象、字段、可见性、来源快照和刷新状态。
2. **只读不是禁用编辑控件**：只读展示不得用 disabled input/select/textarea 冒充文本展示；需要编辑时进入 Dialog、Drawer 或独立页。
3. **空、未知、无权限、未配置要分开**：`-`、空字符串、0、未知、加载失败、无权限和未配置不能混为一谈。
4. **状态不能只靠颜色**：状态标签、指标卡、徽标、趋势和风险级别必须有文本、说明、单位和必要的时间/口径。
5. **移动端可以折叠，但不能丢关键信息**：身份、状态、风险、权限、错误、刷新/延迟、操作入口和恢复路径不得因卡片重排或折叠消失。

## 状态模型

新增 `informationDisplayState`，至少包含：

- `displayOwnerId`：展示区域 owner。
- `subjectIdentity`：被展示对象身份、类型、安全可见名称和权限版本。
- `displaySnapshot`：字段值、指标值、状态值、来源数据版本和刷新时间。
- `fieldSemantics`：字段 label、值类型、单位、格式、空值策略和敏感边界。
- `visibilityPolicy`：可见、脱敏、只读、无权限、条件可见、已删除或不可用。
- `freshnessState`：loading、fresh、stale、refresh-error、partial、unknown、permission-denied。
- `statusSemantics`：状态 key、状态文案、颜色/图标辅助、严重度、下一步和来源。
- `actionBinding`：复制、跳转、编辑、导出、危险操作等入口绑定的对象快照和权限。
- `copyPolicy`：允许复制的字段、复制格式、脱敏规则和回执。
- `responsivePolicy`：移动端分组、折叠优先级、固定摘要和不可隐藏信息。
- `a11yPolicy`：区域名称、字段名称、状态说明、键盘路径和公告策略。
- `auditBinding`：创建/更新/操作人、时间、请求身份、审计入口和可追溯性。

## 核心规则族

### IDS-SCOPE：职责与范围

- 信息展示 owner 管“用户看到的信息是否准确、可解释、可追溯、安全”；不管具体编辑提交流程。
- 详情页、描述列表、指标卡和信息卡必须声明展示对象、数据来源、权限版本和刷新状态。
- 只读页面中的操作入口必须显式声明动作对象、权限、结果 owner 和目标承载面。

### IDS-READONLY：只读展示边界

- 详情页不得直接内嵌 input、textarea、select、可编辑表格或行内保存按钮来完成编辑。
- 只读状态不得用 disabled 表单控件充当展示文本；否则读屏、复制、布局和语义都会变差。
- 新增、编辑、复制创建和批量配置必须进入 `record-editing-surfaces.md` 规定的承载面。

### IDS-FIELD：字段语义

- 每个字段必须有明确 label、值、单位、格式、帮助说明或来源说明。
- 空值、未配置、未知、加载失败、无权限、已删除和不适用必须可区分；不得统一显示 `-`。
- ID、密钥、邮箱、手机号、文件名、金额、时间和权限字段必须声明脱敏、复制和展示格式。

### IDS-STATUS：状态与标签

- 状态标签、徽标、颜色、图标和趋势箭头不能是唯一语义来源。
- 状态必须包含文本、严重度、来源、刷新时间或适用时间，并在需要时提供下一步。
- 风险、失败、部分成功、未知结果、权限降级和过期必须接入对应 owner，不得只展示一个标签。

### IDS-METRIC：指标卡与摘要

- 指标卡必须声明指标名、口径、单位、时间范围、数据延迟、刷新时间和权限范围。
- 指标为 0、空、无权限、未产生、计算失败和数据延迟必须分开展示。
- 指标卡默认只读；选择、钻取、导出、刷新和跳转能力必须显式声明。

### IDS-ACTION：展示区操作

- 复制、打开详情、编辑、导出、删除、停用、启用、归档、刷新和重试按钮必须绑定当前展示快照。
- 复制操作不得复制脱敏或无权限字段的真实值，且需要可感知回执。
- 危险操作必须进入 `risk-actions.md`；编辑入口必须进入 `record-editing-surfaces.md`；按钮语义必须进入 `buttons.md`。

### IDS-PERM：权限与敏感信息

- 无权限展示不得泄露对象名称、字段值、数量、文件名、内部 ID、筛选值或旧缓存。
- 权限降级、租户切换、对象删除或数据范围变化后，旧详情字段、旧标题、旧状态和旧操作入口必须重新证明安全。
- 脱敏值必须标注脱敏状态；复制、导出、跳转和审计入口必须复核权限。

### IDS-LAYOUT：布局、分组与长内容

- 字段分组必须按任务语义组织，不得只按接口返回顺序铺开。
- 长文本、代码、JSON、URL、邮箱、文件名和路径必须有换行、展开、复制和溢出策略。
- 重要字段不能只放在 hover tooltip、popover、更多菜单或右侧隐藏区域。

### IDS-RSP：移动端与响应式

- 移动端可以把描述列表变成卡片、分组、Accordion、Tabs 或独立区块。
- 折叠默认态必须保留对象身份、主状态、关键指标、风险/错误、权限说明、刷新/延迟和主要操作入口。
- 移动端不得删除字段 label、单位、状态说明、错误/权限说明、复制/恢复路径或审计入口。

### IDS-A11Y：可访问性

- 详情区域、信息卡、指标卡、状态区和操作组必须有可访问名称。
- 字段 label 与值必须在读屏中保持关联；状态不能只靠颜色、位置或图标。
- 可复制字段、展开长文本、跳转链接和操作按钮必须可键盘访问，并有清晰动作对象。

### IDS-LIFE：生命周期与刷新

- 展示区刷新前后必须保留旧内容、标记 stale 或 loading 策略，不得闪成空白误导用户。
- 迟到响应只能写回匹配 `displaySnapshot` 和权限版本的展示区。
- 未执行真实浏览器、读屏、触摸、缩放、刷新和权限切换检查时，必须标为未验证。

## 与现有 owner 的关系

- `record-editing-surfaces.md` 负责新增/编辑承载面；本 owner 负责只读展示和编辑入口边界。
- `forms.md` 负责字段编辑和校验；本 owner 负责只读字段标签、值、单位、空值和脱敏展示。
- `buttons.md` 负责按钮语义；本 owner 负责详情展示区中按钮绑定当前对象快照。
- `risk-actions.md` 负责危险确认；本 owner 负责危险入口在详情上下文中展示风险与影响对象。
- `feedback-states.md` 负责 loading/empty/error/stale；本 owner 负责详情字段、指标卡和描述列表如何呈现这些状态。
- `date-time-ranges.md` 负责时间值、时区、范围和刷新时间；本 owner 负责这些信息在详情/指标区可见且可理解。
- `admin-console.md` 负责管理台治理；本 owner 负责详情/概览类页面的信息展示原子规则。

## 验收设计

新增 `docs/testing/information-display/information-display-audit.rb`：

- 检查 owner 文件包含 `informationDisplayState` 和所有必要状态字段。
- 检查只读展示禁止 disabled input 冒充文本、禁止详情内嵌编辑、空值/未知/无权限分离、状态不能只靠颜色、指标口径、权限脱敏、移动端不可丢失关键说明和未验证边界。
- 检查 `SKILL.md` 路由包含中英文关键词并指向 `references/information-display.md`。
- 检查 `README.md` 和 `HANDOFF.md` 包含摘要与引用。
- 使用负向变异删除关键规则，确保审计失败。
- 使用项目泄漏扫描，确保 owner 不绑定具体业务项目。

## 明确非验证项

本次是规范与静态审计更新，不执行具体业务页面的浏览器、读屏、触摸、缩放、刷新、权限切换和真实数据检查。落地到项目时，所有未实际执行的运行时检查必须标为未验证。
