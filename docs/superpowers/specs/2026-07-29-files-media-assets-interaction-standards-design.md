# 文件与媒体资产管理交互规范设计

## 背景

现有 `references/uploads-imports.md` 已经覆盖文件如何被选择、校验、上传、预检、导入、取消、重试和查看导入结果。它也明确排除了文件库、媒体资产管理、在线预览、图片裁剪、音视频转码、对象存储协议、病毒扫描和 CDN 策略。

这个缺口很容易在业务系统里反复出问题：上传成功被当成资产可用；缩略图能显示就被当成有权限；旧预览 URL、旧下载 URL、旧分享链接或旧 CDN 地址在权限变化后继续暴露；图片裁剪、视频转码、替换版本和发布/下架混成一个“保存成功”；删除文件只 Toast，没有恢复路径；移动端直接删掉预览、替换、下载、删除恢复或分享管理。

因此下一阶段应新增一个独立 owner：文件与媒体资产管理。它接管“文件已经进入系统之后”的资产生命周期，而不是重复定义上传流程。

## 目标

新增 `references/files-media-assets.md`，作为文件库、附件管理、媒体资产、素材库、资产详情、在线预览、缩略图、图片裁剪、音视频转码、替换文件、资产版本、发布/下架、分享链接、权限访问、删除恢复和资产使用关系的唯一 owner。

该 owner 需要约束：

- 上传完成、资产入库、扫描完成、转码完成、预览可用、发布可用、分享可用和 CDN 生效的状态分层。
- 资产身份、版本、变体、衍生产物、预览 URL、下载 URL、分享链接、发布状态、删除状态和引用关系。
- 替换、裁剪、转码、重新生成缩略图、发布、下架、公开分享、删除、恢复和永久删除等高风险意图。
- 权限、租户/工作区、对象版本、文件版本、链接有效期、CDN 缓存和旧 URL 失效。
- 移动端、触摸、虚拟键盘、预览器、播放器、裁剪器和安全区域下的核心能力一致。

## 非目标

- 不替代 `uploads-imports.md` 的文件选择、上传队列、上传进度、导入预检和导入任务结果。
- 不替代 `exports-downloads-artifacts.md` 的导出文件生成、结果产物领取和下载意图。
- 不定义对象存储签名、CDN 缓存策略、病毒扫描算法、转码服务实现、图片处理算法或文件内容解析算法。
- 不定义业务领域的资产分类法、内容审核政策或品牌素材规范。
- 不替代具体播放器、图片编辑器、PDF 预览器或文档预览组件的底层 API。

## 方案比较

### 方案 A：扩展上传与导入 owner

优点是少一个文件，所有“文件相关”内容集中。缺点是上传动作和资产生命周期会混在一起：上传成功不等于扫描完成，不等于预览可用，不等于转码完成，不等于发布/CDN 生效，也不等于分享链接安全。长期看会让 `uploads-imports.md` 变成巨大杂物间。

### 方案 B：新增文件与媒体资产 owner

优点是边界清楚：上传 owner 管文件如何进入系统；资产 owner 管文件成为资产之后如何被查看、管理、使用、发布、分享和回收。它能统一处理预览可信边界、旧 URL 失效、版本替换、媒体转码、删除恢复、移动端预览和权限无泄露。缺点是需要新增路由、README/HANDOFF 摘要和可执行审计。

### 方案 C：拆成文件管理 owner 与媒体管理 owner

优点是更细；缺点是现在会过早拆分。文件库和媒体资产在权限、版本、预览、下载、分享、删除恢复和旧链接失效上高度重叠，先合并更实用。

推荐方案 B。它与现有上传/导出/复杂编辑器 owner 的职责关系最干净，也最适合管理台和内容型产品的高频场景。

## 状态模型

每个文件或媒体资产管理场景必须声明 `assetState`：

| 字段 | 含义 |
| --- | --- |
| `assetOwnerId` | 资产 owner 身份，绑定页面、资产、租户/工作区、权限版本、文件版本和当前承载面。 |
| `assetIdentity` | 资产 ID、文件 ID、版本 ID、变体 ID、文件名、类型、大小、摘要、来源和不可逆标识。 |
| `assetLifecycle` | `upload-received`、`stored`、`scanning`、`scan-failed`、`processing`、`ready`、`published`、`unpublished`、`archived`、`deleted`、`purged`、`unknown` 等状态。 |
| `variantState` | 原始文件、缩略图、预览图、裁剪版本、转码版本、水印版本、低清/高清版本、字幕和其他衍生产物状态。 |
| `previewPolicy` | 预览 URL、预览类型、可预览范围、脱敏、水印、过期、权限过滤、播放器/阅读器状态和预览失败恢复。 |
| `downloadPolicy` | 下载入口、下载 URL、文件名、有效期、权限复核、敏感字段、下载审计和旧链接失效。 |
| `sharePolicy` | 分享链接、公开链接、访问范围、密码/过期/撤销、外部访问、复制链接和分享审计。 |
| `editPolicy` | 替换文件、裁剪、旋转、重命名、改分类、改描述、重新生成缩略图、重新转码和保存版本。 |
| `publishPolicy` | 发布、下架、重新发布、CDN 生效、缓存刷新、未知结果、审计和回滚。 |
| `usageBinding` | 当前资产被哪些对象、页面、模板、内容、消息、配置、报表或外部系统引用。 |
| `permissionBoundary` | 查看、预览、下载、编辑、替换、裁剪、转码、发布、分享、删除、恢复和永久删除的权限收敛。 |
| `retentionPolicy` | 归档、删除、恢复窗口、永久删除、保留策略、法务保留和不可恢复说明。 |
| `feedbackBinding` | 资产状态、转码状态、预览失败、分享撤销、删除恢复、未知结果和审计回执的承载 owner。 |
| `responsivePolicy` | 移动端预览、裁剪器、播放器、文件详情、分享管理、批量操作和安全区域承载策略。 |

`assetState` 只负责资产生命周期。文件如何被选择和上传仍由 Upload owner 维护；导出产物如何生成和下载仍由 Exports owner 维护；复杂编辑器中的图片裁剪或素材选择仍必须同时读取 Complex Editors owner。

## 核心规则

### 上传完成不等于资产可用

上传完成、资产入库、扫描完成、转码完成、缩略图生成完成、预览可用、下载可用、发布可用、CDN 生效和分享链接可用必须是不同状态。

上传成功只能说明文件内容或引用进入系统；不能自动写成资产已可预览、已发布、已分享、已扫描安全、已转码完成或已被下游使用。扫描、转码、预览生成、CDN 生效或外部同步未知时，必须展示未知或处理中状态，并提供刷新、查看任务、重试或联系支持路径。

### 预览和缩略图不是权限证明

缩略图、预览图、播放器 poster、PDF 首页图、波形图和已缓存媒体片段不能作为权限证明。每次查看预览、下载、复制链接、打开分享、替换、裁剪、转码、发布、删除或恢复都必须复核权限、租户/工作区、资产版本、链接有效期和请求身份。

无权限状态不得泄露文件名、缩略图、预览内容、尺寸、时长、页数、波形、字幕、EXIF、内部 ID、路径、引用关系、分享范围、下载 URL、CDN URL、错误明细、旧缓存或旧可访问名称。

### 版本、变体和旧 URL 失效

资产必须区分资产版本、文件版本、预览版本、缩略图版本、裁剪版本、转码版本、发布版本、CDN 版本和分享链接版本。

替换文件、重新裁剪、重新转码、重新生成缩略图、权限变化、租户/工作区切换、发布/下架、删除/恢复、分享撤销或资产被归档后，旧预览 URL、旧下载 URL、旧分享链接、旧 CDN 地址、旧缩略图、旧播放器状态、旧复制内容、旧焦点目标和旧 ARIA 引用必须失效或重新证明安全。

### 编辑、裁剪、转码和发布意图

替换文件、重命名、改描述、改分类、裁剪图片、旋转图片、重新转码、重新生成缩略图、发布、下架、撤销发布、删除、恢复和永久删除必须是不同意图。

裁剪成功不等于保存成功；保存裁剪不等于发布成功；转码任务创建不等于转码完成；发布请求发送不等于 CDN 生效；删除请求发送不等于文件已不可恢复。未知结果不得伪装成成功或失败。

影响已发布资产、已分享资产、被其他对象引用的资产、批量资产、公开链接、不可恢复删除或法务保留的操作必须进入 `references/risk-actions.md`，确认完成前请求数为 0。

### 使用关系和影响范围

资产被页面、模板、内容、消息、配置、报表、自动化、外部系统或公开链接使用时，替换、删除、下架、权限收紧、重新转码和永久删除必须说明影响范围。

无法完整证明引用关系时，不能把“未发现引用”写成“没有引用”；必须标为未知或仅当前范围，并提供刷新、查看使用关系、查看审计或联系管理员路径。

### 分享链接和公开访问

分享链接、公开链接、嵌入链接和外部访问必须声明访问范围、有效期、密码或访问条件、是否允许下载、是否允许预览、是否记录审计、是否可撤销和撤销后旧链接失效策略。

复制分享链接不能只 Toast。成功后必须提供可见状态、有效期、访问范围和撤销入口；失败时必须说明权限、过期、网络、未知或外部访问受限原因。公开分享、跨租户分享、敏感文件分享和可下载分享默认是风险动作。

### 删除、恢复和保留

删除、归档、移入回收站、恢复、永久删除和法务保留必须分开表达。删除成功不等于永久删除；恢复成功不等于旧分享链接、旧 CDN、旧预览和旧引用都恢复。

有恢复窗口时必须说明恢复期限、恢复入口和哪些内容会恢复；无恢复或永久删除前必须说明不可恢复范围、影响对象、备份/审计边界和请求身份。

### 移动端与响应式

移动端不得删除预览、下载、替换、删除/恢复、转码状态、权限原因、分享管理、使用关系、版本说明、错误恢复和审计入口。

移动端可以把文件详情、预览器、裁剪器、分享设置、使用关系和版本历史放入全屏 Drawer、独立页或分步模式，但必须保留同一个 `assetState`、同一个资产版本、同一个权限边界、同一个删除/恢复策略和同一个错误恢复路径。

虚拟键盘、横竖屏、低高度视口、播放器控制条、图片缩放、裁剪手柄、底部操作、安全区域和系统字体放大后，预览内容、文件状态、错误说明、下载、替换、保存裁剪、发布、删除、恢复、撤销分享和返回路径仍必须可见或可滚动到达。

## 与现有 owner 的关系

- `uploads-imports.md`：负责文件选择、上传、预检、导入、上传队列和导入任务；本 owner 负责上传后的资产身份、版本、预览、分享、发布、删除和恢复。
- `exports-downloads-artifacts.md`：负责导出文件生成、结果产物领取和下载意图；本 owner 负责用户管理的文件资产和媒体资产。
- `complex-editors-builders.md`：编辑器内素材选择、图片裁剪或配置引用同时读取 Complex Editors owner；资产生命周期由本 owner 提供。
- `information-display.md`：资产详情页字段展示、只读元数据、状态标签、脱敏展示和复制字段继续执行信息展示规则。
- `buttons.md`：下载、替换、裁剪、转码、发布、分享、删除和恢复按钮继续执行 Button owner。
- `risk-actions.md`：公开分享、替换已发布资产、删除被引用资产、永久删除、批量删除、撤销公开链接和跨租户分享继续执行 Risk Actions。
- `permissions-tenancy-visibility.md`：权限、租户/工作区、只读、隐藏、禁用和无泄露继续执行 Permissions。
- `async-jobs-task-center.md`：转码、病毒扫描、缩略图生成、CDN 刷新、批量处理和外部同步等后台任务继续执行 Async Jobs。
- `global-feedback.md` 和 `feedback-states.md`：Toast、Banner、状态区、空态、错误和恢复入口继续执行反馈 owner；资产状态不能只 Toast。
- `responsive-adaptive.md`：移动端、触控、虚拟键盘、播放器控制条、裁剪手柄、缩放和安全区域继续执行响应式规则。

## 可执行审计设计

新增 `docs/testing/files-media-assets/files-media-assets-audit.rb`，采用现有 Ruby 静态审计模式。

审计需要验证：

1. owner 文件存在，且包含 `assetState` 与全部状态字段。
2. `SKILL.md` 包含文件管理、文件库、附件管理、媒体资产、素材库、在线预览、图片裁剪、视频转码、分享链接、删除恢复等中英文触发词。
3. `README.md` 与 `HANDOFF.md` 只保留摘要和 owner 链接。
4. RED/GREEN 证据能证明缺少 owner、上传完成即资产可用、缩略图当权限证明、旧 URL 未失效、裁剪/转码/发布意图混用、分享链接 Toast-only、删除无恢复边界、引用关系未知伪装为空、移动端删除核心能力、运行时验证伪装已通过、项目专属泄漏等问题会被抓住。
5. owner 不包含具体业务项目路径、客户名或技术栈例外。

## 验收清单

- 每个文件或媒体资产场景声明 `assetState` 全字段。
- 上传完成、扫描完成、转码完成、预览可用、下载可用、发布可用、CDN 生效和分享可用分开表达。
- 缩略图、预览、播放器缓存和 CDN 缓存不能作为权限证明。
- 权限、租户/工作区、资产版本、发布状态或分享状态变化后，旧预览 URL、旧下载 URL、旧分享链接、旧 CDN 地址和旧缩略图失效或重新证明安全。
- 替换、裁剪、转码、发布、下架、分享、删除、恢复和永久删除是不同意图。
- 公开分享、跨租户分享、替换已发布资产、删除被引用资产和永久删除进入风险 owner。
- 删除、恢复、永久删除和法务保留分开表达，并说明恢复窗口和不可恢复边界。
- 使用关系未知时不能伪装成没有引用。
- 移动端保留预览、下载、替换、删除/恢复、转码状态、权限原因、分享管理、使用关系、版本说明、错误恢复和审计入口。
- 未执行真实浏览器预览、真实下载、真实播放器、真实裁剪、真实转码任务、真实权限切换、真实链接过期和真实移动端视口时，必须标记为未验证。

## 自检结论

本设计聚焦一个 owner：文件与媒体资产管理。它不重复上传、导入、导出或复杂编辑器规则，而是补齐上传完成后的资产身份、预览、版本、分享、发布、删除恢复和移动端承载。文档已写明范围、非目标、状态模型、验收清单和交付物，没有把任何具体业务项目作为规范例外；真实浏览器、播放器、裁剪器、转码任务、权限切换、链接过期和移动端设备验证明确留到业务实现阶段。
