# 表单字段、校验、提交与错误恢复规范设计

## 背景与目标

现有 Skill 已覆盖 Dialog、Drawer、可搜索单选 Select / Combobox，以及响应式与自适应交互。下一阶段新增一份通用表单规范，统一字段状态、校验时机、错误归属、提交边界、失败恢复和未保存变更处理，并与现有专项规范形成闭环。

规范面向不同技术栈，只描述用户可观察行为、状态边界、无障碍语义和验收条件。

## 范围

第一版覆盖：

- 字段标签、必填/可选说明、帮助文本和单位。
- 字段及表单状态模型。
- 同步、异步、字段级和表单级校验。
- 字段错误、错误摘要、服务端错误及焦点引导。
- 防重复提交、提交快照、失败恢复和成功反馈。
- dirty 表单的离开确认与明确放弃。
- Dialog、Drawer、Select、响应式和路由卸载的交叉行为。
- 键盘、辅助技术、缩放、虚拟键盘和移动端验收。

第一版不深入文件上传、富文本、日期、树形或级联字段、多步骤向导，以及业务专属复合字段。这些能力后续以专项规范扩展；若作为普通字段参与表单，仍执行本规范的值、错误和提交边界。

## 文件组织

- 新增 `references/forms.md`，作为表单状态、校验、错误、提交和恢复的唯一事实来源。
- 在 `SKILL.md` 增加中英文触发词及路由，不复制完整规则。
- 在 `README.md` 增加简短用户摘要和完整规范链接。
- 检查 `agents/openai.yaml` 是否仍准确；定位未变化时不为制造差异而修改。
- 在 `HANDOFF.md` 更新已完成规范、下一优先级和验证状态。

## 状态模型

### 表单级状态

- `pristine`：所有当前字段值都与明确的当前初始基线一致。
- `dirty`：至少一个当前字段值与初始基线不同。
- `validating`：至少一个当前适用校验尚未完成。
- `submitting`：已创建提交快照且提交请求尚未结束。
- `submitError`：最近一次适用提交失败产生的表单级错误。
- `submitSucceeded`：最近一次适用提交已成功，并已执行产品明确的成功策略。

### 字段级状态

每个字段至少区分：当前值、初始值、值来源、`touched`、`dirty`、同步错误、异步错误、服务端字段错误、错误是否已暴露，以及校验代次。

### 核心不变量

- `dirty` 由当前值与明确初始值比较得出；恢复初始值后重新成为非 dirty。
- `touched` 与 `dirty` 独立。用户聚焦/失焦、用户输入、预填、程序赋值、重置和服务端回填必须有可区分来源。
- 错误状态与错误可见性分离，避免未操作字段过早显示错误。
- 服务端字段错误绑定到提交快照中的字段值。字段值改变后可撤销旧错误展示，但不能把旧错误归给新值。
- 提交失败保留输入、dirty、touched 和恢复上下文。
- 提交成功后，产品必须明确重置、停留、关闭或跳转策略；继续编辑时，成功结果成为新的初始基线。
- 复合字段的草稿不是表单已提交值；Select 的 `query` 和 `activeOption` 不能成为字段值。

## 默认校验策略

采用“提交前温和、提交后及时”的默认策略：

1. 首次提交前，不因用户尚未操作而展示错误。
2. 字段失焦后，对已 touched 字段执行字段级校验并展示适用错误。
3. 首次提交执行所有字段及表单级校验。
4. 首次提交后，已暴露错误的字段在输入时及时重新校验。
5. 异步校验采用防抖、取消或校验代次；旧值结果不得覆盖新值。
6. 提交必须等待当前适用校验完成，不得携带已知无效值请求服务端。

产品可以针对明确字段改变校验时机，但必须说明原因，不得降低错误可理解性、竞态安全或提交正确性。

## 错误模型

- 字段错误显示在字段附近，并通过原生语义、`aria-invalid` 与 `aria-describedby` 或等价方式关联。
- 表单级错误进入可聚焦错误摘要；能归属字段的条目可跳转并聚焦对应字段。
- 网络、权限、乐观锁或跨字段业务冲突不得伪装成单字段格式错误。
- 一个问题只有一个主要归属；字段附近、错误摘要、Toast 和实时区域不得重复播报同一完整错误。
- 字段修改只撤销与旧值绑定的错误，不清除其他字段错误或仍适用的表单级错误。
- 错误文本说明问题与恢复动作，不只使用颜色、图标、位置或 Tooltip。

## 提交与恢复

- 提交创建不可变快照；防止重复提交、重复回调和重复成功动作。
- 提交期间是否允许编辑由业务风险决定。若允许编辑，响应只能应用到匹配的提交快照；旧响应不得覆盖新值或错误状态。
- 同步或异步校验未完成、存在已知无效字段或提交状态不可用时，不发送提交请求。
- 失败后保持当前界面和用户输入，显示可理解错误，并提供重试、修改或重新认证等适用恢复路径。
- 成功反馈必须可感知；重置、继续编辑、关闭或跳转由业务显式决定，不能由组件默认行为猜测。
- dirty 表单离开当前任务前进行确认；提交成功、明确放弃或恢复到初始基线后解除确认。
- 路由或 owner 卸载时，使旧校验、提交、错误和焦点回调失效，并且只清理当前实例拥有的资源。

## 跨组件与跨端规则

- 位于 Dialog 或 Drawer 的表单同时执行对应模态规范。loading 不自动改变关闭路径；提交中能否退出必须明确并向用户说明。
- Select / Combobox 等复合字段继续执行专项规范；表单只消费其已提交值和归属到字段的有效性状态。
- Dialog 与 Drawer 实时转换时，字段值、初始基线、dirty、touched、可见错误、校验代次、提交快照及请求保持，不重复校验或提交。
- 响应式变化可以调整列数、分组和低频内容入口，但不能删除字段、错误、帮助、恢复操作或改变业务语义。
- 标签、帮助、单位和错误关系在布局变化后仍明确；字段顺序、错误摘要跳转和键盘顺序保持合理。
- 200% 缩放、长文本、字体放大、低高度、动态视口、虚拟键盘和安全区域下，当前字段、错误及提交操作可到达且不被固定区域遮挡。

## 焦点与状态播报

- 首次提交失败后，焦点移到错误摘要或首个无效字段；采用哪一项必须由一致规则决定，并让用户能从摘要跳转到各错误字段。
- 异步校验、提交进度、失败和成功通过适度的状态消息传达，避免每次按键重复朗读。
- 字段修复后，不把焦点强制移走；错误消失或更新应保持当前编辑上下文。
- 路由卸载不向即将移除的旧字段或触发器恢复焦点；新路由提交后由其焦点策略接管。

## 验收设计

至少覆盖：

- pristine、dirty、touched、恢复初始值、预填与程序赋值。
- 首次提交前、失焦后、首次提交后的错误展示和重新校验。
- 异步校验防抖、取消、乱序结果和字段值变化。
- 字段错误、错误摘要、服务端错误、错误跳转和避免重复播报。
- 完整校验、重复提交、提交快照、提交期间编辑和旧响应。
- 失败保留、重试、认证恢复、成功反馈和新初始基线。
- dirty 离开确认、明确放弃、路由卸载和旧回调失效。
- Dialog / Drawer 跨形态保持及 Select 草稿与已提交值边界。
- 键盘、辅助技术语义、200% 缩放、移动端、低高度、虚拟键盘、安全区域、长文本和 reduced motion。

文档验证包括官方 Skill 校验、相对链接、占位符和 `git diff --check`。规范仓库没有真实表单组件；浏览器、屏幕阅读器、触控设备和真实视口测试必须标为未验证，并在具体实现中完成。

## 完成标准

- `references/forms.md` 对状态、校验、错误、提交和恢复给出唯一、无冲突的结果。
- `SKILL.md` 能在中英文表单任务中准确路由到表单规范，并与 Select、Dialog、Drawer、响应式路由同时适用。
- 所有新增硬规则均有可执行验收。
- `README.md` 与 `HANDOFF.md` 只提供摘要和入口，不复制完整规则。
- 独立基线与修订后应用测试证明新 Skill 能减少表单交互决策分歧。
- 静态验证与未执行的运行时验证边界准确记录。
