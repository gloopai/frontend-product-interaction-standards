# 用户侧附件与内容提交上传 GREEN 证据摘要

- 已补齐 `attachmentSubmissionState`，并要求每个用户侧附件提交场景声明 `attachmentSubmissionOwnerId`、`contentDraftBinding`、`inputSourcePolicy`、`localAttachmentDrafts`、`uploadBinding`、`submitSnapshot`、`sendPolicy`、`postSubmitState`、`revisionPolicy`、`permissionBoundary`、`feedbackBinding` 和 `responsivePolicy`。
- 选择文件、生成本地预览、完成裁剪/压缩、上传成功、消息已发送、评论已发布、头像已生效和资产已入库必须分开表达。
- 上传成功只能说明文件引用可用于当前提交候选，不能自动说明消息已发送、评论已发布、头像已生效、内容已审核通过或资产已入库。
- 发送按钮不得读取本地文件名，必须绑定文本草稿、附件草稿、上传状态、必填规则、权限、会话、内容版本和提交策略。
- 发送时冻结附件项身份、上传引用候选、权限版本、内容版本和幂等键；重复点击、Enter、快捷发送、触摸、拖拽完成回调、自动重试和离线恢复不得生成重复消息、重复评论、重复工单、重复头像更新或重复投稿。
- 本地文件被替换后，旧裁剪、旧压缩、旧上传、旧扫描或迟到结果不能写入新草稿、新消息、新评论、新工单或新头像。
- 发送前删除附件只删除当前草稿的附件项和上传候选；发送后删除附件、撤回附件或编辑附件必须说明内容版本、附件可见性、审计、接收方已读状态、通知状态和恢复边界。
- 裁剪成功不等于头像已生效；头像/封面选择、裁剪、预览、上传、保存、生效、审核、缓存刷新和旧图片失效必须分层。
- 文本发送成功但附件失败、附件上传成功但文本发送失败、部分附件失败、审核中、未知结果、离线队列和接收方无权必须可区分。
- 无权或未启用时，附件选择、相机/相册、录音录像、粘贴、拖拽、预览、上传、发送、重试、删除、撤回、下载和查看原图的 DOM、state、handler、request 和快捷键入口为 0。
- 附件预览、文件名、缩略图、EXIF、语音时长、视频时长、地理位置、内部 ID、下载链接、错误明细和旧缓存不得在无权限、被删除、已撤回、被审核拦截或会话失效状态下泄露。
- 移动端必须保留相机、相册、文件选择、录音录像、附件预览、文件级错误、上传进度、删除/替换、重试、发送状态、离开保护、权限原因、失败恢复和已发送附件状态。
- 附件错误不能只挂在缩略图红框或 Toast；同一完整错误消息只能由一个 primary owner 播报，并提供可访问文本、文件级定位和恢复动作。
- 真实浏览器、真实移动端设备、相机/相册/录音权限、真实上传、真实弱网/离线、真实后台切换、键盘、触摸和读屏未执行时，必须标为未验证。

对应静态审计入口：`ruby docs/testing/user-attachment-submission/user-attachment-submission-audit.rb --mutations`。
