# 用户侧附件与内容提交上传 RED 证据摘要

- 缺少 `attachmentSubmissionState`，或者缺少 `attachmentSubmissionOwnerId`、`contentDraftBinding`、`inputSourcePolicy`、`localAttachmentDrafts`、`uploadBinding`、`submitSnapshot`、`sendPolicy`、`postSubmitState`、`revisionPolicy`、`permissionBoundary`、`feedbackBinding`、`responsivePolicy`。
- 文件已选就允许发送，选择文件、生成本地预览、裁剪/压缩、上传成功、消息已发送、评论已发布、头像已生效和资产已入库没有分层。
- 上传成功被写成消息已发送、评论已发布、头像已生效或资产已入库。
- 发送按钮只读取本地文件名，不绑定文本草稿、附件草稿、上传状态、必填规则、权限、会话、内容版本和提交策略。
- 发送时没有发送时冻结附件项身份、上传引用候选、权限版本、内容版本和幂等键。
- 重复点击、Enter、快捷发送、触摸、拖拽完成回调、自动重试或离线恢复生成重复消息、重复评论、重复工单、重复头像更新或重复投稿。
- 本地文件被替换后，旧裁剪、旧压缩、旧上传、旧扫描或迟到结果写入新草稿、新消息、新评论、新工单或新头像。
- 发送前删除附件误删已发送附件，或者没有区分发送前删除附件和发送后删除附件。
- 发送后删除附件、撤回附件或编辑附件没有说明内容版本、附件可见性、审计、接收方已读状态、通知状态和恢复边界。
- 裁剪成功被当成头像已生效，头像/封面选择、裁剪、预览、上传、保存、生效、审核、缓存刷新和旧图片失效混在一起。
- 文本发送成功但附件失败、附件上传成功但文本发送失败、部分附件失败、审核中、未知结果、离线队列和接收方无权被合并成一个成功或失败。
- 无权或未启用时，附件选择、相机/相册、录音录像、粘贴、拖拽、预览、上传、发送、重试、删除、撤回、下载和查看原图没有做到 DOM、state、handler、request 和快捷键入口为 0。
- 附件预览、文件名、缩略图、EXIF、语音时长、视频时长、地理位置、内部 ID、下载链接、错误明细或旧缓存发生权限泄露。
- 移动端删除相机、相册、文件选择、录音录像、附件预览、文件级错误、上传进度、删除/替换、重试、发送状态、离开保护、权限原因、失败恢复或已发送附件状态。
- 附件错误只挂在缩略图红框或 Toast，缺少可访问文本、文件级定位和恢复动作。
- 同一完整错误消息由多个 owner 播报，缺少唯一 primary owner。
- 真实浏览器、真实移动端设备、相机/相册/录音权限、真实上传、真实弱网/离线、真实后台切换、键盘、触摸和读屏未执行时，不能写成已验证，必须标为未验证。
