# 回收站恢复保留规范 RED 复核

在新增 `references/trash-restore-retention.md` 之前，删除后生命周期只能分散依赖危险操作、状态流转、列表、权限和审计规范，无法强制表达以下问题：

- 没有 `trashRestoreState`，无法证明对象删除后在哪里、是否可恢复、保留多久、何时永久删除。
- soft delete、archive、disable、restore、permanent delete、purge、retention expired 和 legal hold 可能被混成一个状态标签。
- Toast 撤销可能成为唯一恢复入口。
- 保留期可能只写“30 天后删除”，没有绝对时间、时区、起算点、规则来源和到期动作。
- 恢复前可能不检查父级、唯一键、权限、状态机、保留期、关联对象和冲突。
- 删除后旧列表行、详情、预览、下载、复制、菜单、批量选择、导出、搜索、URL、ARIA 和焦点目标可能继续可用。
- 无权限可能泄露已删除对象名称、数量、字段、文件名、路径、删除原因、操作者、删除时间、保留期、内部 ID 或旧缓存。
- 批量删除、批量恢复和永久删除可能没有部分成功恢复路径。
- 真实浏览器、键盘、读屏、移动端、权限切换、迟到响应、保留期到期、批量部分成功和审计追溯未执行时，容易被误写成已验证，而不是标为未验证。
