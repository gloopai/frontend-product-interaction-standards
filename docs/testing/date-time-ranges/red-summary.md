# 日期时间与时区规范 RED 摘要

本审计覆盖 `dateTimeState`、`displayTimezone`、`storageTimezone`、`relativeAnchor`、`[start, end)`、DST、`urlSafe`、`data latency`、移动端不得删除清空、以及运行时检查未验证边界。

负向变异会删除或替换以下关键约束，并要求审计失败：

- 删除 `dateTimeState` 或必要状态字段。
- 删除“日期时间值必须声明展示时区、存储/请求时区、边界语义和粒度”。
- 删除“不得使用含糊本地字符串”。
- 删除“范围推荐使用 `[start, end)`”。
- 删除“快捷范围必须冻结应用时的 `relativeAnchor`”。
- 删除“今天、昨天、本周、本月、近 7 天和近 30 天不得在同一已应用查询中随时间漂移”。
- 删除“部分范围不得触发查询”。
- 删除“只有明确 `urlSafe` 的日期时间值可以进入 URL”。
- 删除“报表、导出和审计必须携带范围快照、时区、数据延迟和刷新时间”。
- 删除“移动端不得删除清空、重置、快捷范围、错误说明或时区说明”。
- 把“未验证”改成“已验证”。
- 删除 `SKILL.md` 中指向 `references/date-time-ranges.md` 的路由。
- 注入 `fex-admin` 等项目专属词。

这些 RED 变异确保规范不会退回到含糊本地时间、漂移快捷范围、缺失时区、缺失 URL 恢复或移动端能力缩水。
