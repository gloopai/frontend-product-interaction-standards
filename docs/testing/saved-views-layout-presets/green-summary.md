# 保存视图、视图预设与个性化布局 GREEN 证据摘要

当前规范和审计证明以下结构已经就位：

- 保存视图、视图预设与布局预设必须声明 `savedViewState`，并包含 `appliedSnapshot`、`layoutSnapshot`、`draftBinding`、`defaultPolicy`、`sharePolicy`、`applyIntent`、`permissionBoundary`、`resultReceipt`、`auditBinding` 等状态字段。
- 保存视图只能读取已应用快照和明确允许持久化的布局快照。
- 筛选草稿、Select query、active option、未提交日期范围、当前页码、展开行、hover、高亮、焦点、loading、错误状态和旧结果缓存不得进入正式保存视图。
- 保存视图前必须明确保存的是已应用条件，或要求用户先应用/确认草稿。
- 应用视图必须创建 `applyIntent`，说明将替换哪些查询、筛选、排序、列布局、密度、展示模式、URL 或当前视图标签。
- Query Filters、Data Table、Toolbar、URL、结果摘要和焦点必须读取同一视图版本。
- 个人视图、共享视图、默认视图、团队默认、个人默认、角色默认和系统预设分开表达，不能混用一个“默认”或“共享”状态。
- 共享视图不得泄露无权限字段、筛选值、对象名称、数量、列名、内部 ID、成员、客户、文件名、金额、发票、密钥、审计字段或旧缓存。
- 权限、租户/工作区、角色、字段可见性、功能开关或数据范围变化后，旧视图必须失效、过滤、降级或要求重新确认。
- 覆盖、删除、共享、设默认、取消共享、恢复默认和批量管理视图必须说明影响范围、视图版本、权限版本、请求身份和未知结果恢复。
- 高影响视图管理动作需要进入风险确认，确认前请求数为 0。
- 未知结果不能伪装成已保存、已覆盖、已删除、已共享、已设为默认或已恢复默认，并需要刷新视图列表、检查当前视图、查看审计、重试或联系支持路径。
- 移动端不得删除视图切换、当前视图说明、保存视图、覆盖视图、恢复默认、权限原因、冲突恢复、错误回执和审计入口。
- 真实浏览器、移动端、屏幕阅读器、权限/租户切换、URL 恢复、多人共享、默认冲突、审计写入和表格/筛选联动在本轮文档工作中仍是未验证，需要在具体项目落地时补充。

对应静态审计入口：`ruby docs/testing/saved-views-layout-presets/saved-views-layout-presets-audit.rb --mutations`。
