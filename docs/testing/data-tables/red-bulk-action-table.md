# Bulk-action 数据表格设计说明

## 1. 设计目标与核心约束

表格提供两级选择能力：

1. **当前页选择**：选择当前已加载页面中可操作的行。
2. **全部筛选结果选择**：在后端能力允许时，选择某次筛选快照中的全部可操作结果，并允许排除个别项。

核心原则：

- 选择对象必须由不可变、稳定的行 ID 标识，不能使用行号、DOM 索引或当前排序位置。
- “当前页全选”不等于“全部结果全选”，两者必须有不同文案和状态反馈。
- “全部筛选结果”必须绑定明确的查询快照，不能仅在客户端保存一个 `allSelected=true`。
- 批处理提交后，其目标集合不可再被表格后续的筛选、翻页或勾选变化修改。
- 服务端必须在执行时重新检查权限、对象存在性和业务状态；客户端选中不代表必然执行成功。
- 路由卸载后，旧实例不得再更新界面、恢复焦点或释放其他实例拥有的资源。

## 2. 能力边界

### 2.1 最低可用能力

若后端只支持 ID 列表批处理，则仅提供：

- 当前页逐行选择；
- 当前页全选；
- 对已选 ID 执行批处理；
- 按失败 ID 重试。

此时不得展示“选择全部筛选结果”，也不得由前端翻页枚举所有结果来模拟该能力。

### 2.2 启用“全部筛选结果”的后端条件

后端至少需要支持：

- 根据规范化查询生成不可变的 `queryToken` 或等价快照标识；
- 返回该快照中候选项总数，以及总数是精确值还是估算值；
- 接受 `{ queryToken, excludedIds }` 形式的批处理目标；
- 为每次提交接受幂等键；
- 返回或可查询逐项执行结果；
- 在执行时重新校验权限、存在性、租户边界和操作资格；
- 明确快照有效期及过期错误；
- 明确排除项数量上限。

如果只能在执行时重新运行实时查询，产品必须明确写成“执行时仍符合当前条件的项目”，不能宣称选择了一个固定集合。涉及删除、权限变更等高风险操作时，优先要求服务端快照能力。

### 2.3 不作默认承诺的能力

以下能力必须由后端明确提供后才能展示：

- 撤销已完成操作；
- 取消已被服务端接受的任务；
- 跨登录会话恢复选中项；
- 无限数量的排除项；
- 对所有失败类型一键重试；
- 在数据持续变化时保证显示计数与最终成功数完全一致。

## 3. 选择模型

建议将选择状态建模为判别联合，而不是多个相互影响的布尔值：

```ts
type SelectionState =
  | { mode: "none" }
  | {
      mode: "page";
      pageKey: string;
      selectedIds: Set<RowId>;
    }
  | {
      mode: "allQuery";
      queryToken: string;
      queryKey: string;
      total: number;
      totalAccuracy: "exact" | "estimated";
      excludedIds: Set<RowId>;
      expiresAt?: string;
    };
```

其中：

- `pageKey` 包含筛选、搜索、排序、分页位置、页大小及数据作用域。
- `queryKey` 只包含会改变结果成员关系的条件，如租户、搜索词、筛选、数据范围和权限上下文；分页、页大小不属于查询成员关系。排序仅在确实不会影响成员关系时排除。
- `queryToken` 是服务端创建的不可变快照标识，客户端不能根据 `queryKey` 自行伪造。
- `excludedIds` 只存在于 `allQuery` 模式。
- 当前页模式永远保存显式 ID。刷新后新出现的行不会因之前点过“全选本页”而自动被选中。

当前选中数量：

- `none`：0；
- `page`：`selectedIds.size`；
- `allQuery`：`total - excludedIds.size`，估算总数必须显示“约”。

## 4. 选择交互

### 4.1 行选择

每行提供独立复选框。点击行内链接、按钮、菜单或行本身都不应隐式切换选择，避免打开详情时误选；选择只由复选框或明确的“选择”操作触发。

不可参与批处理的行：

- 复选框禁用；
- 显示或可访问地说明原因；
- 不计入“本页可选择项”数量；
- 即使前端判断可操作，服务端仍须二次校验。

### 4.2 表头复选框

表头复选框仅描述当前可见页：

- 当前页无已选项：未选中；
- 当前页部分可选行已选：混合态；
- 当前页全部可选行已选：选中；
- 当前页无可选行：禁用。

在 `page` 模式：

- 从未选中或混合态点击：选中当前页所有可选行；
- 从选中态点击：清除当前页选择。

在 `allQuery` 模式：

- 取消某行：把该 ID 加入 `excludedIds`；
- 重新选择某行：从 `excludedIds` 移除；
- 取消选中整个当前页：把当前页所有可选 ID 加入排除项；
- 重新选中整个当前页：移除当前页对应的排除项。

### 4.3 从当前页提升为全部筛选结果

选择当前页全部可选项后，在表格上方显示稳定的选择摘要：

> 已选择本页 20 项。选择符合当前筛选条件的全部 1,248 项

“选择全部 1,248 项”必须是按钮。创建查询快照期间：

- 按钮显示局部加载状态；
- 当前页选择继续保留；
- 用户仍可取消当前页选择；
- 不阻塞表格阅读和翻页之外的无关操作。

创建成功后进入 `allQuery`：

> 已选择此次筛选快照中的 1,248 项。已排除 0 项。清除选择

如果总数是估算值，使用“约 1,248 项”。若快照有显著有效期，可显示过期时间或在临近过期时提醒。

创建快照失败时保留当前页选择，在提升按钮附近展示错误和“重试”，不能把已有选择一并清除。

### 4.4 排除项

进入 `allQuery` 后，取消任一行即形成排除项。摘要持续显示：

> 已选择 1,245 项，已排除 3 项

应提供“查看排除项”入口；排除项不在当前筛选结果中可见时，也不能无入口地隐藏。排除列表至少展示稳定身份字段、移除排除操作和加载失败恢复。

达到服务端排除项上限时：

- 禁止继续新增排除；
- 明确说明上限；
- 提供“清除全部选择”；
- 若业务允许，可提供“改为仅选择这些项目”，但不能静默改变模式。

排除到剩余数量为 0 时，自动归一为 `none`，避免保留“全选但实际为零”的矛盾状态。

## 5. 选择与查询的关系

### 5.1 筛选或搜索变化

筛选、搜索、租户、数据范围或其他成员关系条件变化时：

- 立即使当前选择失效；
- 取消尚未完成的查询快照创建；
- 选择状态归零；
- 用礼貌状态消息告知“筛选条件已变化，已清除原选择”；
- 焦点留在用户正在操作的筛选控件，不抢焦点。

不得把旧 `queryToken` 重用于新筛选条件。

### 5.2 排序、翻页和页大小

- `page` 模式是当前页作用域；分页、页大小或排序导致 `pageKey` 改变时清除选择，并告知用户。
- `allQuery` 模式绑定查询成员集合；如果排序不改变成员关系，可在排序和翻页后保留，并按新页面计算复选框状态。
- 如果某类排序会改变查询成员或采用排名截断，则必须计入 `queryKey`，变化时清除选择。

### 5.3 同查询刷新

同一页刷新时：

- `page` 模式只保留仍存在且仍可操作的显式 ID；
- 新出现的行不自动加入；
- 消失或变为不可操作的 ID从选择中移除，并汇总播报；
- `allQuery` 模式继续使用原快照，刷新后的新对象不自动加入；页面应明确这是“筛选快照”，避免用户误以为是动态集合。

### 5.4 URL 与返回恢复

筛选、分页可以按产品规则进入 URL；批量选择默认不进入 URL，也不写入长期存储。离开页面再返回时默认无选择，避免恢复过期权限或危险操作上下文。

如果产品确需短期恢复，必须同时校验用户、租户、`queryKey`、快照有效期和权限版本，并给选择设置短 TTL。

## 6. 状态转换

### 6.1 选择状态

| 当前状态 | 事件 | 下一状态 | 必要处理 |
|---|---|---|---|
| `none` | 勾选一行 | `page` | 记录 ID 与当前 `pageKey` |
| `none` | 全选当前页 | `page` | 记录当前页所有可选 ID |
| `page` | 勾选/取消行 | `page` 或 `none` | 集合为空时归一为 `none` |
| `page` | 请求全部筛选结果 | `page` + 局部加载 | 选择保持可见，创建快照 |
| `page` | 快照创建成功 | `allQuery` | 使用服务端 token 和计数 |
| `page` | 快照创建失败 | `page` | 保留选择，显示可重试错误 |
| `allQuery` | 取消行 | `allQuery` | 加入排除项 |
| `allQuery` | 重新选择行 | `allQuery` | 移除排除项 |
| 任意已选状态 | 查询成员条件变化 | `none` | 失效旧 token，播报清除原因 |
| `page` | `pageKey` 变化 | `none` | 清除页级选择 |
| 任意已选状态 | 清除选择 | `none` | 取消未提交的选择相关请求 |
| 任意状态 | 路由卸载 | `disposed` | 进入幂等处置流程 |

### 6.2 批处理任务状态

批处理任务与表格选择状态分离：

```text
idle
  → preflighting（可选）
  → submitting
  → accepted/running
  → succeeded | partial | failed | cancelled
partial/failed
  → retrying
  → succeeded | partial | failed
```

规则：

- 用户点击执行后，立即冻结一份 `TargetDescriptor`；之后的勾选、筛选变化不能改变该任务。
- `submitting` 阶段禁用重复提交及选择变更。
- 服务端接受任务后，清除表格选择；任务转入独立的任务状态区或全局任务中心。
- 如果提交明确失败且服务端确认未受理，恢复原选择。
- 如果因超时或断网无法确定是否受理，不得直接再次提交；先通过幂等键查询任务状态。
- 所有状态更新必须携带任务 ID、尝试 ID和单调递增版本，忽略乱序旧事件。

## 7. 批处理结果、部分成功与重试

结果至少区分：

- 成功；
- 失败且可重试；
- 失败且不可重试；
- 跳过，如权限变化、对象已删除、状态不再满足；
- 状态未知，需要重新查询任务。

部分成功摘要示例：

> 已处理 1,248 项：1,210 项成功，18 项可重试失败，12 项不可重试，8 项跳过。

结果区要求：

- 每种结果都有数量和文本含义，不能只靠颜色或图标；
- 失败明细按稳定 ID列出，显示对象身份、原因、是否可重试及建议动作；
- 明细过多时服务端分页，不能把所有失败项一次塞入 DOM；
- 支持下载失败明细时，要说明文件生成状态、有效期和错误恢复；
- 表格数据刷新失败不能覆盖或隐藏批处理结果。

“重试失败项”只能提交上一次结果中的**可重试失败 ID**：

- 不重新执行已成功项；
- 不重试不可重试项和跳过项；
- 生成新的尝试 ID和幂等键；
- 在结果中保留原尝试与重试尝试的关联；
- 重试前再次检查权限和当前业务状态。

网络错误发生在提交响应丢失时，先用原幂等键查询；只有服务端确认未创建任务，才允许重新提交。

## 8. 加载、错误与空状态

### 8.1 首次加载

- 保留表头、列结构和可预期布局，显示骨架或加载说明；
- 选择控件不可用；
- 不显示“0 项”或空结果文案；
- 表格区域标记忙碌状态，但页面标题和筛选仍可访问。

### 8.2 同查询刷新

- 保留已有行，避免整表闪空；
- 表格区域显示非遮挡式刷新状态；
- 继续显示已选状态；
- 返回后按稳定 ID对选择进行协调；
- 刷新失败时保留旧数据并显示“数据可能不是最新”的行内错误及重试。

### 8.3 筛选变化加载

新查询尚未返回时：

- 立即清除旧选择；
- 可以保留旧行作视觉过渡，但必须明确其正在更新且不可继续选择；
- 新查询成功后一次性替换；
- 旧查询响应即使后到也不得覆盖新结果。

### 8.4 空状态

分别处理：

- **系统无任何数据**：说明数据尚未创建，并提供有权限的主要创建入口；
- **筛选无结果**：展示当前条件无匹配，并提供清除或调整筛选；
- **删除后当前页变空**：自动请求前一有效页，不把分页尾部误报成全局空状态；
- **当前页无可操作项**：仍展示数据，但禁用全选并说明原因；
- **全部筛选结果经排除后为零**：归一为未选择状态。

### 8.5 错误分层

数据查询错误、快照创建错误、批处理提交错误、任务进度错误和失败明细错误必须独立显示和重试；一个区域失败不能无条件清空其他区域的有效内容。

## 9. 键盘操作

优先使用原生语义表格和原生复选框，不把普通数据表格强行实现成 `grid`：

- `Tab` / `Shift+Tab` 只在复选框、链接、按钮和其他交互元素间移动；
- `Space` 切换当前聚焦的行复选框或表头复选框；
- `Enter` 激活按钮、链接和批处理操作；
- 不使用方向键模拟单元格导航，除非产品确实实现完整 ARIA Grid 模式；
- 不设置全局单键快捷键，避免与读屏、浏览器和输入法冲突；
- 不把长按、拖拽、滑动或悬停作为唯一操作路径；
- `Escape` 不默认清空选择，避免误操作；提供明确的“清除选择”按钮。

如未来增加 Shift 范围选择，只能作用于当前稳定渲染顺序，并提供不依赖 Shift 的等价路径；虚拟列表、排序或刷新后不得沿用旧索引范围。

## 10. 焦点管理

- 勾选行或全选后不自动移动焦点，以状态消息反馈数量变化。
- 选择摘要出现时不抢焦点；触发“选择全部结果”的按钮在加载和成功后尽量保持同一 DOM 节点。
- 若状态变化必须移除当前聚焦按钮，将焦点移动一次到等价控制，如“清除选择”，并给出可访问说明。
- 筛选变化清除选择时，焦点保留在筛选控件。
- 行因刷新或操作成功被移除，且焦点原本在该行时，依次移动到下一行对应控件、上一行、表格标题或空状态主操作。
- 批处理开始后，如果触发按钮被替换，将焦点移到任务状态标题；若用户已主动把焦点移到别处，任务完成时不抢回，只使用实时区播报。
- 部分失败后，从结果摘要提供直接进入失败明细的按钮；不要自动把焦点塞到第一条失败记录。
- 清除选择后，若操作来自选择摘要，可把焦点移到表头复选框；若表格已空，则移到表格标题或空状态入口。
- 路由卸载时绝不将焦点恢复到即将消失的表格、触发按钮或旧页面；新路由提交后只由新页面焦点策略移动一次到页面标题、主内容或首要操作。

## 11. ARIA 与语义

桌面表格优先使用原生：

- `<table>`、`<caption>`、`<thead>`、`<tbody>`；
- 列标题使用 `<th scope="col">`；
- 行标题列使用 `<th scope="row">` 或通过可访问名称建立行身份；
- 不因加入复选框而改成 `role="grid"`。

具体要求：

- 行复选框名称包含稳定、可辨识身份，如“选择订单 A-1024”，不能全部只叫“选择”；
- 表头复选框名称为“选择当前页所有可操作项目”；
- 混合态必须在无障碍树中暴露为 `mixed`；
- 禁用复选框通过 `aria-describedby` 关联不可操作原因；
- 选择摘要放在有名称的区域中，例如“批量选择与操作”；
- “选择全部结果”“清除选择”“重试失败项”使用原生按钮；
- 表格刷新时在表格容器设置 `aria-busy="true"`，但不隐藏仍有效的旧内容；
- 数量变化、筛选导致的选择清除、任务进度和完成摘要通过持久的 `aria-live="polite"` / `role="status"` 区域简洁播报；
- 无法确认提交是否受理、批处理整体失败等需要立即处理的错误可使用 `role="alert"`，但逐行失败不得形成大量 alert；
- 可视选中状态不能只靠行底色，必须保留复选框状态；
- 图标按钮必须有名称，状态不能只靠颜色、图标或位置表达。

移动端若改成卡片列表，应使用有名称的列表/条目结构，并保留同等复选框名称、状态摘要和批处理能力；不得给卡片伪造表格语义。

## 12. 桌面与移动端适配

### 12.1 桌面

- 选择列与主要身份列保持容易定位；宽表可使用受控横向滚动，但关键身份和选择入口不能无提示消失。
- 批处理工具条放在表格上方或页面固定区域，避免覆盖表头、聚焦控件或错误。
- 主要批处理操作直接展示；低频操作可进入有明确名称的“更多批量操作”菜单。
- 固定表头或工具条时，必须保证浏览器缩放和低高度视口下聚焦元素不会被遮挡。

### 12.2 移动端

- 可改为卡片列表、优先级字段加详情展开，或保留受控横向滚动；字段和操作不得彻底消失。
- 提供显式“进入选择模式”或始终可见的复选框，不能要求长按进入。
- 选择模式中的卡片仍可清楚识别对象身份；详情导航与选择区域分离，降低误触。
- 批处理操作可转为底部操作栏，但必须考虑动态视口和四向安全区域，并给列表留足底部空间。
- 底部栏不能遮挡最后一项、错误、键盘焦点或系统虚拟键盘。
- “选择全部筛选结果”、排除项、失败明细与重试能力在移动端必须仍然可发现；可以折叠，但不能删除。
- 触摸目标建议至少约 44×44 CSS px，并留出防误触间距。
- 横竖屏、断点实时变化时保持同一选择和任务实例，不重复请求、清理或播报。

### 12.3 跨端共同要求

需要覆盖 200% 浏览器缩放、字体放大、长文本、翻译扩展、高对比度、Reduced Motion、平板、低高度视口、横屏手机、动态浏览器工具栏和虚拟键盘。关键流程不应要求双向滚动。

## 13. 路由卸载与 disposal

表格实例具有唯一 `instanceId`。路由变化或拥有组件卸载时立即进入不可逆的 `disposed` 状态，不等待退场动画。

处置流程必须幂等，并按实例所有权执行：

1. 标记实例已处置并递增生命周期 generation。
2. 取消或失效：
   - 表格查询请求；
   - 查询快照和计数请求；
   - 失败明细请求；
   - 未执行的自动重试；
   - 搜索防抖和节流回调；
   - 任务轮询、定时器、SSE、WebSocket 或订阅；
   - Resize/Intersection/Mutation Observer；
   - 窗口、文档及媒体查询监听器；
   - 动画完成处理器；
   - 此实例创建的临时对象 URL 和其他缓存资源。
3. 移除此实例 DOM。
4. 每项资源只释放一次，且只释放当前 `instanceId` 拥有的资源。
5. 不恢复焦点到旧页面。
6. 清除组件本地选择；已被服务端接受的任务转由独立全局任务存储管理，而不是随表格取消。

每个异步响应至少携带或闭包捕获：

- `instanceId`；
- 生命周期 generation；
- `queryKey`；
- 请求序号；
- 对批任务还包括 `jobId`、`attemptId` 和事件版本。

提交状态前必须同时验证实例仍存活、generation 一致、查询仍匹配且响应不旧于当前版本。仅依赖 `AbortController` 不够，因为请求可能无法真正取消或响应已进入回调队列；即使 abort 失败，旧响应也必须被逻辑失效。

若批处理已被服务端接受：

- 卸载只停止当前表格的等待和展示，不尝试假定服务端任务已取消；
- 全局任务中心可继续接收该任务状态；
- 若提交响应丢失，后续使用幂等键查询，而非新建重复任务；
- 旧表格实例不能借全局任务更新重新挂载自己的 UI。

## 14. 实现不变量

实现和测试中应持续保证：

- 任一时刻只有一个选择模式；
- `allQuery` 必须有服务端 token；
- 页面变化不会把旧页 ID 误认为当前页选择；
- 查询成员条件变化不会保留旧全选；
- 提交目标在点击执行时冻结；
- 已成功项不会被失败重试再次执行；
- 乱序任务事件不会回退状态；
- disposal 后任何旧回调都不能改变新页面或新实例；
- 同一资源不会被清理两次；
- 移动端与桌面端具有相同业务能力和风险等级；
- 所有数量、错误、选择和任务状态不只通过视觉颜色表达。
