# 只读数据报表实现设计

## 1. 能力声明

本实例采用以下固定能力配置：

| 能力 | 配置 |
| --- | --- |
| `capabilityTier` | `display` |
| `resolvedTier` | `display`；权限解析不得提升档位 |
| 筛选 | 启用，`applyMode: explicit` |
| 排序 | 启用，服务端单列业务排序，并追加稳定键 |
| 分页 | 仅 `numbered` 页码分页 |
| 页大小 | 默认 25，可选 25 / 50 / 100 |
| 行选择、全选、全部筛选结果选择 | 不启用 |
| 单行业务操作、批量操作 | 不启用 |
| 行内编辑 | 不启用 |
| 列显示控制、固定列、拖动调宽、拖拽换序、布局持久化 | 不启用 |
| 长内容展开 | 启用，仅改变展示，不构成业务操作 |
| 响应式形态 | 启用；宽屏原生 Table，窄空间使用完整字段映射的卡片列表 |

DOM、状态、事件处理器和请求层均不得出现选择、编辑、行操作或批量操作入口。首版也不提供树表、透视表、加载更多、无限滚动和导出。

## 2. 数据与列契约

报表行使用不可变、全局唯一的 `recordId`，不得以数组索引作为记录身份。基线字段为：

- `recordId`：记录编号，关键身份字段。
- `occurredAt`：发生时间。
- `status`：状态。
- `subjectName`：主体名称。
- `ownerName`：负责人。
- `metricValue`：指标值。
- `summary`：长摘要。

真实业务可以替换显示名称，但必须保留稳定 `recordId`、字段标签、排序语义和响应式完整映射。

宽屏表格中，`recordId` 使用 `<th scope="row">`；其他表头使用 `<th scope="col">`。记录编号、时间、状态不得截断到无法识别。名称和普通文本允许换行，并设置适当的断词规则以处理长单词和无空格文本。

`summary` 默认显示三行预览，紧邻一个具名按钮，例如“展开记录 R1024 的完整摘要”。按钮使用 `aria-expanded` 和 `aria-controls` 关联完整内容；展开后显示原始全文，焦点保持在触发按钮。不得以 Hover、`title` 属性或复制操作作为查看全文的唯一方式。

首版不使用行虚拟化，以避免可变行高、长内容和焦点恢复之间的冲突。

## 3. 筛选

筛选区采用原生 `<form>`，包含：

- 发生日期范围：默认最近 30 天，开始日期不得晚于结束日期。
- 状态：原生 `<select>`，默认“全部状态”。
- 关键字：搜索记录编号、主体名称和摘要，最多 100 个 Unicode 字符。
- “应用筛选”和“重置筛选”按钮。

状态必须分离：

- `filterDraft`：字段已提交但尚未应用的业务值。
- `appliedFilters`：当前结果实际使用的条件。
- 原生控件的临时编辑状态不得直接改写结果标题、总数、URL 或请求参数。

所有筛选器均使用显式应用模式。点击“应用筛选”或在表单内按 Enter 时：

1. 执行字段及跨字段校验。
2. 有错误时不发请求，显示字段错误和可聚焦错误摘要。
3. 合法且与当前条件语义不同时，更新 `appliedFilters`。
4. 页码回到第 1 页。
5. 创建新的不可变查询快照并发出一次请求。

“重置筛选”恢复 `{日期范围: 最近30天, 状态: 全部, 关键字: 空}`，不是无条件清空；与当前已应用条件相同时不发请求。

已应用条件在结果上方持续显示为摘要，每项均有具名移除按钮。筛选面板在移动端折叠时，已应用条件仍须在折叠区外可见并可单独移除。移除条件同样回到第 1 页并创建新查询。

URL 规则：

- 日期范围和状态标记为 `urlSafe`，可进入查询参数。
- 关键字按敏感值处理，不进入 URL、页面标题或分析日志。
- 未明确标记 `urlSafe` 的新筛选字段默认不得序列化。

字段错误归字段 owner：使用可见 `<label>`、`aria-invalid="true"` 和稳定的 `aria-describedby` 错误关联。查询网络错误不得写成字段格式错误。若将原生 `select` 替换为自绘 Select/Combobox，必须另行实现其草稿、弹层、键盘和 ARIA 生命周期，不能把搜索词当作筛选业务值。

## 4. 稳定排序

排序为服务端单列模式。当前默认顺序明确为：

```text
occurredAt DESC NULLS LAST,
recordId ASC
```

其中 `recordId` 是不可变、唯一的稳定次序键，始终追加在业务排序键之后。

可交互排序列及比较语义：

| 列 | 初始方向 | 比较规则 |
| --- | --- | --- |
| `occurredAt` | 降序 | UTC 时间戳；空值始终置后 |
| `subjectName` | 升序 | Unicode NFC；`zh-CN`、大小写不敏感、自然数字排序；空值置后 |
| `metricValue` | 降序 | 数值比较；空值置后 |

表格形态下，可排序表头内使用真实 `<button>`；不可排序列不渲染按钮，也不设置 `aria-sort`。当前业务排序列的 `<th>` 设置 `aria-sort="ascending|descending"`，稳定键不伪装成第二个交互排序。表格说明中应可感知地注明“相同业务值按记录编号升序稳定排列”。

卡片形态下提供等价的原生“排序字段”选择器和“升序/降序”按钮，写入同一 `sortRules`，不得改变排序语义。

提交新排序时替换旧业务排序、回到第 1 页、创建新查询快照。点击、Enter 和 Space 激活同一排序意图必须得到相同结果，不能重复发请求。排序请求发出时不抢走仍存活的排序控件焦点。

跨页无重复或遗漏只在所有页面绑定同一不可变 `datasetVersion` 或等价服务端快照时承诺。服务端不提供该能力时，只能保证每次请求内部按稳定比较值排序，不能承诺动态数据下跨页零重复遗漏。发现版本变化时将分页链标记为过期，停止继续导航并从第 1 页重新开始。

## 5. 页码分页

页码分页依赖服务端提供可靠总数；如果接口只能提供游标或近似总数，不得虚构总页数，本设计需重新裁决分页模式。

分页区域必须显示：

- 当前结果范围，例如“第 26–50 条，共 238 条”。
- 当前页与总页数。
- 直接页码按钮。
- 具可见标签的跳页输入。
- 上一页、下一页。
- 每页条数选择器。

分页使用 `<nav aria-label="报表分页">`。当前页设置 `aria-current="page"`；首页的“上一页”和末页的“下一页”使用原生 `disabled`。跳页值必须是 `1..totalPages` 的整数，非法或越界值不发请求，并在输入旁显示错误。

改变页大小回到第 1 页。删除或数据变化导致当前页超过最新末页时，只请求一次最近有效页，最小为第 1 页；成功后简短公告新位置，不循环恢复。

用户主动翻页或改变页大小后，匹配响应提交时焦点移动一次到结果摘要。自动失效页恢复不得产生第二次焦点移动。

移动端保留相同分页能力：显示上一页、下一页、当前页、首末页或邻近页按钮，并在“跳页与每页条数”区域提供完整跳页和页大小控制，不得以空间不足删除随机跳页能力。

## 6. 状态模型与请求门禁

实例使用稳定 `ownerId` 和不可复用的 `lifecycleToken`。

`queryState` 至少包含：

```text
appliedFilters
sortRules
page
pageSize
querySnapshot
snapshotId
datasetVersion
permissionScope
requestGeneration
requestPhase
queryError
stale
```

`viewState` 至少包含当前行、总数、展示形态和按稳定 `recordId` 保存的长内容展开状态。`interactionState` 保存 `focusIntent`、`recordId`、`columnId`、`controlId` 和回退目标。由于本实例为 `display`，不创建选择或操作状态槽。

每次查询先冻结不可变 `querySnapshot`，内容包括已应用筛选、完整排序、空值/区域规则、页码、页大小、权限范围和适用的数据版本，再生成 `snapshotId` 并递增 `requestGeneration`。

响应只有同时满足以下条件才可提交：

```text
owner 仍 live
ownerId 匹配
lifecycleToken 匹配
snapshotId 匹配
requestGeneration 匹配
```

取消旧请求仅用于节省资源，不能替代门禁。迟到、被取代或已取消响应不得修改行、总数、错误、焦点、`aria-busy` 或公告区域。

同一查询意图仍在途时，重复点击刷新、按 Enter 或事件重放合并到当前请求，不创建新快照或新公告；筛选、排序、页码、权限范围等意图发生变化时，即使旧请求仍在途，也必须创建新请求。

状态转换如下：

| 当前状态 | 事件 | 下一状态与界面 |
| --- | --- | --- |
| `idle` | 首次查询 | `initial-loading` |
| `initial-loading` | 成功 | `ready`，显示结果 |
| `initial-loading` | 失败 | `initial-error` |
| `ready` | 筛选、排序、翻页、页大小或刷新 | `refreshing`，保留旧结果 |
| `refreshing` | 成功 | `ready`，替换结果并清除 `stale` |
| `refreshing` | 失败 | `refresh-error`，保留旧结果并设 `stale=true` |
| 任意 live 状态 | 数据版本失配 | 分页链失效，标记过期并从第 1 页重新查询一次 |
| 任意状态 | route/unmount | `disposed`，不可再接受工作 |

刷新期间已应用条件可以更新，但旧行必须明确标为“上次结果，正在按新条件更新”，不能伪装成新条件的匹配结果。

## 7. 加载、错误和空状态

首次加载且没有可用结果时：

- 显示与最终列结构相符的非交互骨架。
- 结果容器设置 `aria-busy="true"`。
- 骨架不得包含链接、按钮、假数据或可选择内容。

已有结果刷新时：

- 保留旧行、分页、展开状态和焦点意图。
- 显示“正在更新报表”。
- 设置 `aria-busy="true"`。
- 匹配响应提交后一次性更新结果。

首次加载失败时，以结果区域内的文本错误和具名“重试加载报表”按钮替代空表格。刷新失败时保留旧结果和分页，显示“数据可能已过期”及重试入口。

空状态分为两种：

- `no-matches`：当前已应用条件无匹配，显示调整或清除筛选入口。
- `dataset-empty`：数据源本身为空，说明当前没有可报告记录。

两者不得共用“暂无数据”。服务端应返回可信的 `emptyReason`，前端不得仅根据当前筛选是否为默认值推断。

查询错误只由结果 owner 完整展示和公告一次；筛选字段、结果摘要和全局 live region 不得重复朗读同一完整错误。

## 8. 键盘与焦点管理

本报表使用原生 Table，不使用 ARIA Grid，因为不存在单元格选择或二维导航需求。

键盘顺序按视觉任务顺序经过：

1. 筛选字段。
2. 应用和重置按钮。
3. 已应用条件移除按钮。
4. 排序按钮或卡片排序控件。
5. 长内容展开按钮。
6. 分页和错误恢复控件。

原生 Table 不接管方向键、Home、End、Page Up 或 Page Down；静态单元格不设置 `tabindex="0"`。按钮遵循原生 Enter/Space 语义，表单内 Enter 等价于“应用筛选”。

焦点策略：

- 初次加载、后台刷新、应用筛选和排序请求本身不主动移动焦点。
- 原目标仍存活且语义未变时保持焦点。
- 翻页响应提交后移动一次到可聚焦的结果摘要。
- 当前焦点目标被结果替换时，依次回退到同记录等价控件、同列最近记录、结果摘要、当前分页控件。
- 初次错误替换了当前焦点所在结果节点时，移动一次到错误标题或重试按钮。
- 响应式切换时，精确逻辑控件仍存在则保持焦点；否则移动一次到表格/卡片中的等价控件。
- 最终焦点不得落到 `document.body`、文档根节点或已移除元素。

`focusIntent` 必须使用稳定 `recordId + columnId + controlId`，不能依据“第几行、第几个按钮”恢复。

## 9. ARIA 与状态公告

表格形态：

- 结果区使用 `<section aria-labelledby="report-heading">`。
- `<table>` 具有可区分的 `<caption>` 或 `aria-labelledby`。
- 使用正确的列头和行头关联。
- 排序状态只设置在当前业务排序列。
- 结果容器在请求期间设置 `aria-busy="true"`。

卡片形态：

- 使用具名 `<ul>` / `<li>` 列表。
- 每张卡片使用 `article`，以记录编号和主体名称作为可访问名称。
- 字段使用 `<dl><dt><dd>` 或等价标签关系，不能仅靠位置表达字段含义。

分页、筛选、排序、长内容展开和重试控件的名称必须同时说明对象和动作。加载、过期、错误和空状态均使用文本表达，不得只依赖颜色或图标。

结果 owner 维护一个实例级、唯一的礼貌公告通道。以下事件各公告一次简短消息：

- 被接受的查询开始。
- 改变结果数量或页码的响应。
- 查询失败。
- 成功的失效页恢复。

被合并、丢弃、被新请求取代或 disposal 后到达的事件不公告。不得在公告中串读整行数据、全部筛选条件或重复完整错误。

同页存在多个报表时，每个实例必须有唯一的名称、DOM ID、`ownerId`、`lifecycleToken` 和 `announcementOwnerId`。

## 10. 桌面、200% 缩放与移动端

响应式判断基于报表容器可用空间，不依赖设备名称或 User-Agent。基线内容断点为 60rem，最终数值应以真实长文本实测校准：

- 容器宽度足够时渲染原生 Table。
- 容器不足、200% 缩放后发生重排，或字体放大使关键列不可用时，切换为卡片列表。
- Table 与卡片不得作为两个活动数据实例同时存在。
- 转换保持同一 `ownerId`、查询、筛选草稿、已应用筛选、排序、分页、展开状态和在途请求，不重新查询。

卡片完整映射所有七个字段。记录编号、状态、时间直接可见；负责人、指标值和摘要可以进入有名称的“更多字段”区域，但不得无入口隐藏。

桌面筛选区可多列排列；移动端改为单列，并可由“筛选，已应用 N 项”披露按钮折叠。折叠只改变布局，不清除草稿、字段错误或已应用条件。

200% 缩放及移动端必须满足：

- 页面根不产生横向滚动，核心流程不要求页面与数据容器同时双向滚动。
- 长标签、长翻译和字体放大后允许自然换行。
- 固定标题、浏览器工具栏和虚拟键盘不得完全遮挡焦点、错误、应用按钮或分页。
- 使用动态视口单位时提供回退。
- 页面内边距纳入四向 `safe-area-inset-*`。
- 触摸目标基线不小于 44×44 CSS px，并留有避免误触的间距。
- Hover 不承载独占信息。
- 屏幕旋转、缩放和断点切换不丢失筛选、排序、页码、展开状态或在途请求。

## 11. 生命周期与恢复边界

路由提交离开或报表 owner 卸载时，实例立即且幂等地进入 `disposed`，不等待请求或动画结束。处置过程必须：

- 取消或失效查询、重试、防抖和失效页恢复。
- 失效排队中的焦点与公告任务。
- 注销该实例的监听器、计时器、观察器和订阅。
- 移除自身 DOM 和 ARIA 引用。
- 仅释放由自身 `ownerId` 持有的资源一次。
- 拒绝所有迟到响应的 DOM、状态、焦点和 live-region 写入。

离开页面时不得把焦点返回即将删除的筛选、排序或分页控件。新路由提交后，由新页面独立决定焦点目标。

本实例首版使用 `restorePolicy: none`：离开并返回页面时不自动恢复旧查询和滚动位置；URL 中安全的日期和状态条件可以作为新实例初始值重新应用。不得恢复旧 owner、焦点引用或敏感关键字。

| 稳定排序、交互语义和跨页版本边界 | 适用 |
| 可靠总数的页码分页、跳页、页大小和失效页恢复 | 适用 |
