# 只读数据报表交互设计说明

## 1. 产品定位与能力边界

报表实例固定声明：

- `capabilityTier: display`
- `sortMode: single`
- `paginationMode: numbered`
- `responsivePresentation: table-card`
- 查询、排序和分页均作用于完整服务端数据集，不得只处理当前页。

允许的能力包括筛选、移除已应用条件、稳定排序、页码导航、切换页大小、显式刷新、查看完整长内容及错误恢复。

首版不提供：

- 行内编辑、创建、删除或任何数据变更。
- 行选择、表头全选、批量操作及其空工具栏。
- 单行操作菜单、整行点击跳转。
- 无限滚动、加载更多、树表、透视表、行拖拽。
- 列拖拽、固定列、用户布局持久化。

“展开完整内容”和“查看更多字段”属于只读呈现控制，不属于行操作。

## 2. 后端与数据契约

每条记录必须提供不可变且唯一的 `recordId`。页码分页必须取得可靠的 `totalCount`；否则不得显示总页数、直接页码或跳页控件。

每次查询冻结不可变 `querySnapshot`，至少包含：

- 已应用筛选 `appliedFilters`
- 完整排序规则 `sortRules`
- 当前页 `page`
- 页大小 `pageSize`
- 权限范围 `permissionScope`
- 数据版本或服务端快照令牌 `datasetVersion`
- `snapshotId` 和严格递增的 `requestGeneration`

稳定排序由服务端完成。完整排序必须是“业务排序键 + 唯一稳定次序键”，例如：

```text
金额 DESC，recordId ASC
```

空值位置、大小写、区域语言及自然排序规则必须由产品和服务端共同声明并写入查询快照，不能依赖数据库偶然顺序。

稳定次序键只能保证同一数据快照内的确定顺序。只有服务端提供不可变 `datasetVersion` 或等价快照能力时，才能承诺跨页无重复、无遗漏；没有该能力时必须明确该边界，检测到数据变化后使当前分页链失效并从第 1 页重新开始。

```text

+ ownerId 匹配
+ lifecycleToken 匹配

+ snapshotId 匹配
```

## 3. 页面结构

页面按以下顺序组织：

1. 报表标题与简短说明。
2. 筛选区域。
3. 已应用条件摘要。
4. 结果摘要、刷新入口和数据状态。
5. 数据表格或移动端卡片列表。
6. 页码分页和页大小控制。

筛选采用显式应用模式：

- `filterDraft` 与 `appliedFilters` 分离。
- 用户编辑草稿时不改变结果数量、URL 或请求参数。
- 点击“应用筛选”且字段合法后，才更新 `appliedFilters`、回到第 1 页并发起查询。
- “重置”恢复产品声明的 `defaultFilters`；若与当前已应用条件语义相同，不发请求。
- 每个已应用条件持续显示为带名称的摘要，并可单独移除；移除条件同样回到第 1 页并查询。
- 只有标记为 `urlSafe` 的条件可进入 URL。敏感自由文本、账号、令牌或个人识别信息不得进入 URL、标题和分析日志。

筛选字段必须有可见标签。首次应用前采用温和校验；应用时若存在错误，不发请求，显示可聚焦的错误摘要并链接到具体字段。字段错误紧邻字段展示，设置 `aria-invalid="true"` 并通过 `aria-describedby` 关联；查询网络错误不得伪装成字段格式错误。

## 4. 排序与分页

### 排序

桌面端每个可排序表头包含真实 `<button>`；不可排序列不显示按钮，也不设置 `aria-sort`。

单列排序规则为：

- 激活当前排序列：在升序、降序之间切换。
- 激活其他排序列：替换原业务排序。
- 稳定次序键始终自动追加，不作为可单独移除的视觉排序条件。
- 提交新排序后回到第 1 页并建立新查询快照。
- 排序按钮焦点在结果更新期间保持不变；只有该节点被移除时才迁移。

移动端没有表头，使用内联“排序方式”区域呈现字段和方向选项，显示当前排序及稳定次序说明。它与桌面表头共享同一 `sortRules`，切换形态不得重新查询或重置排序。

### 页码分页

分页区域必须显示：

- 当前结果范围，例如“第 41–60 条，共 237 条”。
- 当前页和总页数。
- 首页、上一页、下一页、末页。
- 当前页附近的直接页码。
- 窄屏下的“跳转到页”数字输入和提交按钮。
- 当前页大小及产品允许的白名单值。

当前页使用 `aria-current="page"`。首页的“首页/上一页”和末页的“下一页/末页”使用原生 `disabled`。越界页码只显示字段错误，不发请求。

筛选、排序和页大小变化回到第 1 页；普通翻页进入目标页。若数据变化导致当前页超过最新末页，只自动恢复到最近有效页一次，并简短公告新位置，禁止循环恢复。

## 5. 状态模型与转换

查询状态至少包含：

```text
idle
initial-loading
ready
refreshing
initial-error
refresh-error
```

另维护 `stale`、结果类型、当前行、总数、分页位置、展示形态、长内容展开状态和 `focusIntent`。不得用单一 `loading` 或 `error` 合并首次加载、刷新和字段错误。

| 事件 | 状态转换 | 结果与焦点 |
| --- | --- | --- |
| 首次进入 | `idle → initial-loading` | 无可用结果时显示非交互骨架 |
| 首次成功 | `initial-loading → ready` | 提交行、总数、版本和分页 |
| 首次失败 | `initial-loading → initial-error` | 不渲染假表格，显示错误和重试 |
| 编辑筛选草稿 | 查询状态不变 | 不请求、不改结果摘要 |
| 合法应用/移除/重置筛选 | `ready → refreshing`，页码归 1 | 保持触发控件焦点 |
| 提交排序 | `ready → refreshing`，页码归 1 | 排序按钮焦点保持 |
| 翻页 | `ready → refreshing` | 响应提交后聚焦结果摘要一次 |
| 改变页大小 | `ready → refreshing`，页码归 1 | 响应后聚焦结果摘要 |
| 显式刷新 | `ready → refreshing` | 保留旧行、分页和焦点意图 |
| 刷新成功 | `refreshing → ready` | 替换结果并清除 `stale` |
| 刷新失败 | `refreshing → refresh-error` | 保留旧行，设置 `stale: true` |
| 页间版本失配 | `ready → refreshing/stale` | 停止继续导航，从首个有效位置重启 |
| 路由离开/卸载 | `live → disposed` | 失效请求、公告和焦点回调 |

应用新条件、排序或页码期间可以保留上次结果，但必须明确标记“正在更新；下方为上次结果”，不得把旧行表述为已经匹配新查询。

## 6. 加载、错误和空状态

- 首次加载：结果容器设置 `aria-busy="true"`；骨架与最终列结构相近，但骨架不包含按钮、链接或假数据。
- 刷新：保留上次成功结果、分页和焦点；显示可见“正在更新”状态并设置 `aria-busy="true"`。
- 首次失败：结果区域显示具体错误、建议和可聚焦“重试加载报表”按钮，不保留不可用空表格。
- 刷新失败：保留旧结果，显示“数据可能已过期”和“重试更新”；不得清空分页或抢走仍存活的焦点。
- 筛选无结果：显示“当前筛选条件无匹配记录”，提供“调整筛选”和“恢复默认筛选”。
- 数据源为空：显示独立的“当前数据集尚无记录”状态；由于报表只读，不提供“新建记录”入口。
- 非法筛选或跳页：错误归对应字段，修正前请求数为零。
- 同一错误只有一个完整错误 owner；筛选字段、结果区域和全局公告不得重复朗读同一完整消息。

每个被接受的查询开始、改变结果数量或页码的成功响应、失败及成功页码恢复，各由结果区域简洁公告一次。合并请求、被取代请求、迟到响应和 disposal 后响应不公告。

## 7. 长内容处理

记录身份、状态、错误和控件名称不得使用仅省略号、仅 Hover 或无替代入口的截断。

桌面表格中：

- 身份列允许换行并使用 `overflow-wrap:anywhere` 处理长单词和技术标识。
- 描述类长字段可以显示可读摘要，但必须提供“展开〔记录身份〕的〔字段名〕完整内容”按钮。
- 展开内容在文档流中自然增高，不使用单元格内部纵向滚动。
- 展开按钮使用 `aria-expanded` 和 `aria-controls`；完整内容可再次折叠。
- 展开状态以 `recordId + columnId` 保存，响应式切换和同记录刷新后继续有效。

首版不采用固定列，避免横向滚动、长内容和 200% 缩放时遮挡焦点或相邻数据。

## 8. 桌面、200% 缩放与移动端

### 桌面

空间充足时使用原生 `<table>`。如列宽确实无法容纳，横向滚动仅发生在具有名称的结果容器内，页面根不得产生横向溢出。容器需通过边缘阴影或等价非颜色单一提示表达仍可滚动的方向。

### 200% 缩放

响应式切换依据容器可用宽度和内容最小宽度，不依据设备名称。浏览器缩放到 200% 后，如果表格会导致页面与表格同时双向滚动，应切换为卡片形态：

- 页面保持单一、可预期的纵向主滚动。
- 控件和分页允许换行，不做固定底栏。
- 标签、错误、完整内容和恢复入口均不得被裁切。
- 当前焦点、错误和分页不得被浏览器工具栏或固定区域遮挡。

### 移动端及窄屏

移动端使用经过完整字段映射评审的卡片列表：

- 每张卡片直接显示记录身份和主要状态。
- 其他字段按确定顺序放入带名称的“查看更多字段”区域。
- 使用字段标签和值组成的 `<dl>` 或等价语义。
- 所有桌面列都必须在卡片直接区域或详情区域中可访问。
- 筛选、排序、刷新、页码跳转和错误恢复能力与桌面一致。
- 触摸目标建议不小于 `44×44 CSS px`，关键任务不依赖拖动、滑动或精确点击。
- 处理动态视口、虚拟键盘及四向 `safe-area-inset-*`，确保筛选提交、分页和重试能够滚动到可视区域。

表格和卡片不能同时作为两个活动数据根存在。断点切换保持同一 `ownerId`、查询、分页、筛选草稿、已应用条件、排序、长内容展开状态和焦点意图；切换本身不得创建请求。

## 9. 键盘与焦点管理

本报表使用原生 Table，不使用 ARIA Grid，因此：

- 静态单元格不设置 `tabindex="0"`。
- 表格不接管方向键、Home、End、Page Up 或 Page Down。
- Tab/Shift+Tab 只依次进入真实控件：筛选字段、应用/重置、排序按钮、长内容展开、刷新、重试和分页。
- Enter/Space 按原生语义激活按钮；筛选表单中的 Enter 提交筛选，跳页输入中的 Enter 提交目标页。
- 若桌面表格容器确有横向溢出，容器仅在溢出时成为一个有名称的键盘滚动目标；不得把内部静态单元格加入 Tab 序列。
- 所有焦点具有清晰且不被遮挡的可见样式。

焦点策略：

- 合法筛选和排序发请求时不抢走仍存活的触发控件焦点。
- 筛选校验失败时聚焦错误摘要；摘要链接可将焦点移到具体字段。
- 用户翻页或改变页大小后，在匹配响应提交时仅一次聚焦结果摘要/标题。
- 重试成功后若重试按钮被移除，聚焦结果摘要一次。
- 刷新后按 `recordId + columnId + controlId` 恢复逻辑目标，绝不按旧数组索引恢复。
- 精确目标消失时依次选择：同记录等价控件、同列最近记录、结果摘要、当前分页。
- 断点切换时，目标仍存活则不产生额外 focus；表头排序按钮转换为移动端排序控件时，只迁移一次到语义等价目标。
- 最终焦点不得落到 `document.body`、文档根、隐藏节点或已移除元素。

## 10. ARIA 与结构语义

桌面结构使用：

- `<main>` 和唯一页面标题。
- 筛选区域使用具名称的 `<form>`，字段使用 `<label>`、`fieldset/legend` 或 `aria-labelledby`。
- 表格使用 `<table>`、可见或屏幕阅读器可读的 `<caption>`。
- 列标题使用 `<th scope="col">`；记录身份单元格优先使用 `<th scope="row">`。
- 只有当前主排序表头设置 `aria-sort="ascending|descending"`；其他表头不伪造排序状态。
- 排序按钮名称同时说明对象、当前状态和下一动作。
- 结果容器具有可区分名称，并在查询期间设置 `aria-busy="true"`。
- 分页使用 `<nav aria-label="报表分页">`，当前页设置 `aria-current="page"`。
- 一个由结果 owner 管理的 `aria-live="polite"`、`aria-atomic="true"` 区域负责简洁状态公告，避免与错误文本重复。

移动端卡片使用 `<ul>`/`<li>` 与记录级 `<article>` 或等价结构；每张卡片通过记录身份获得可访问名称，字段标签和值保持明确关联。

加载、过期、空、失败和排序状态都必须有文本或语义表达，不能只依赖颜色、位置、图标或 Hover。
