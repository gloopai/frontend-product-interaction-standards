## 2. 页面结构

页面按以下任务顺序组织：

1. 页面标题和报表说明。
2. 筛选区。
3. 已应用条件摘要。
4. 结果摘要与查询状态。
5. Table 或卡片列表。
6. 页码分页和每页数量。

结果区使用独立标题，例如“交易报表结果”，同页出现多个报表时，各结果区、Table、卡片列表和状态公告必须有不同的可访问名称。

桌面 Table 与移动卡片不是两个并存的数据实例。断点变化只替换展示根，继续使用同一 `ownerId`、查询状态、分页、展开状态和焦点意图；任一时刻只能有一个活动数据根。

## 3. 状态归属

### 3.1 筛选字段 owner

筛选字段维护当前值、初始值、`touched`、`dirty`、字段错误及 `validationGeneration`。字段输入只是草稿，不直接改变结果。

每个字段必须有可见 `<label>`。字段错误紧邻字段，由该字段作为唯一 primary owner，通过 `aria-invalid="true"` 和 `aria-describedby` 关联；查询失败不得写成字段错误。

### 3.2 报表查询 owner

`queryState` 至少包括：

- `appliedFilters`
- `sortRules`
- `pagination: { mode: "numbered", page }`
- `pageSize`
- `querySnapshot`
- `snapshotId`
- `datasetVersion`
- `permissionScope`
- `requestGeneration`
- `requestPhase`
- `queryError`
- `stale`

`requestPhase` 必须区分：

- `idle`
- `initial-loading`
- `ready`
- `refreshing`
- `initial-error`
- `refresh-error`

不得以单一 `loading` 或 `error` 同时表示首次查询和已有结果刷新。

### 3.3 展示与交互 owner

`viewState` 保存当前结果、总数、结果范围和按稳定 `columnId` 定义的展示映射。

`interactionState` 至少保存：

- `focusIntent`
- 当前 `recordId`
- 当前 `columnId`
- 当前 `controlId`
- 已展开的长内容字段集合

本报表不创建选择状态和操作状态，也不渲染空选择列、空批量工具栏或隐藏的操作 handler。

## 4. 查询快照与竞态门禁

每次合法查询先冻结不可变 `querySnapshot`，至少包含：

- 已应用筛选
- 完整排序规则
- 页码位置
- 页大小
- 权限范围
- 适用的数据版本
- 查询原因

之后生成新的 `snapshotId`，并将 `requestGeneration` 严格加一。请求发出后，字段草稿、焦点或后续查询不得修改旧快照。

响应只有同时满足以下条件才可写入结果、总数、错误或状态：

- owner 仍为 live；
- `ownerId` 匹配；
- `lifecycleToken` 匹配；
- `requestGeneration` 等于当前代次；
- `snapshotId` 等于当前快照。

不匹配响应只记录为 discarded，不得写 DOM、状态、焦点或 live region。取消旧请求仅用于节省资源，不能代替上述门禁。

显式刷新使用筛选、排序、页码、页大小、权限和版本组成 `intentKey`。相同意图仍在请求中时，重复点击、Enter 或事件重放合并到当前请求，不创建新快照、请求或开始公告；意图键不同则必须接受为新查询。

## 5. 筛选

筛选采用 `filterDraft` 与 `appliedFilters` 分离：

- 编辑字段只更新草稿。
- “应用筛选”先完成字段和跨字段校验；无效时请求数为零，显示错误摘要并聚焦摘要或第一个错误字段。
- 有效时把已提交业务值复制为新的 `appliedFilters`，页码回到第 1 页，再创建查询快照。
- “重置”恢复产品声明的 `defaultFilters`，不是无条件清空；与当前已应用条件语义相同时不发请求。
- 每个已应用条件持续显示为有名称的摘要项，并提供“移除条件：字段名，当前值”按钮。移除条件等同重新应用筛选，回到第 1 页。
- 折叠在筛选区中的条件仍必须出现在已应用摘要中。

只有显式标记 `urlSafe` 的条件可以进入 URL。账号、令牌、个人识别信息、自由文本敏感值及标记为 `sensitive` 的条件不得进入 URL、页面标题或分析日志。需要浏览器返回恢复的敏感条件只可保存在当前导航会话的临时状态中，不得持久化到地址栏。

请求开始后如果继续显示旧结果，结果区必须明确写出“正在按新条件更新；下方暂为上次结果”，并通过 `displayedSnapshotId` 区分旧结果与当前请求，不能让旧行看起来已经匹配新条件。

## 6. 稳定排序

本报表采用单列排序：

- 产品配置明确可排序列和默认排序。
- 当前列按钮再次激活时在升序、降序之间切换。
- 激活其他列时替换原业务排序。
- 不允许出现“完全无排序”状态；始终保留默认业务排序。
- 提交新排序后回到第 1 页并创建新查询快照。

完整比较规则必须由前后端共同实现并冻结进快照：

1. 按用户选择的业务列和方向比较。
2. `null` 始终置于末尾，不因升降序改变位置。
3. 文本先做 Unicode NFC 规范化，使用产品配置的 locale；本报表默认 `zh-CN-u-kn-true`、自然数字排序、大小写不敏感。
4. 数字按数值比较，日期时间统一转换为 UTC 时间戳比较。
5. 业务比较结果相同时，追加不可重复且不可变的稳定记录键 `recordId ASC`。

Table 中可排序表头使用真实 `<button>`。只有当前主排序 `<th>` 设置正确的 `aria-sort="ascending|descending"`；不可排序表头不渲染按钮，也不设置 `aria-sort`。按钮名称应说明对象、当前方向和下一动作，例如“按创建时间排序，当前降序；激活后改为升序”。

卡片模式不使用 `aria-sort`，而是在列表上方提供同一组可排序字段按钮和当前排序摘要。排序字段、方向和请求结果必须与 Table 完全一致。

只有所有页面绑定同一不可变 `datasetVersion` 时，界面才可承诺跨页无重复、无遗漏。发现后续页版本变化时，立即将当前分页链标为 `stale`，停止继续导航，提示数据已变化并从第 1 页重新开始。无版本能力时只能保证同一次响应内的确定顺序，不得承诺跨页完整性。

## 7. 页码分页

默认 `pageSize=25`，可选 25、50、100；页大小使用原生单选组或等价按钮组，不使用无名称的自绘下拉。

分页区域持续显示：

- 当前结果范围，例如“第 51–75 条”；
- 可靠总数；
- 当前页和总页数；
- 首页、上一页、页码窗口、下一页、末页；
- 带可见标签的页码跳转输入和“跳转”按钮。

当前页使用 `aria-current="page"`。首页的首页/上一页、末页的下一页/末页使用原生 `disabled`，不得只通过样式禁用。非法、非整数或越界跳转不发请求，并在跳转控件附近显示可感知错误。

状态转换如下：

| 事件 | 页码变化 |
| --- | --- |
| 应用、移除、重置筛选 | 回到第 1 页 |
| 提交新排序 | 回到第 1 页 |
| 改变页大小 | 回到第 1 页 |
| 普通翻页或页码跳转 | 使用目标页 |
| 显式刷新 | 保持当前有效页 |
| 当前页因数据变化失效 | 只恢复一次到最新有效末页，且不小于第 1 页 |

失效页恢复成功后只公告一次新位置，不得因重复迟到响应循环恢复。

## 8. 长内容

记录身份、主要状态、关键金额和错误含义不得只显示省略号。实现规则如下：

- 身份和主要状态直接换行显示，使用 `overflow-wrap:anywhere`，不得截断。
- 次要长文本可显示三行预览，但必须紧邻提供“展开字段名完整内容”按钮。
- 展开按钮使用稳定 ID、`aria-expanded` 和 `aria-controls`；收起后焦点仍停留在该按钮。
- 展开内容保留原始换行，长单词、URL 和连续字符可断行；不得撑破页面根宽度。
- 完整内容按原文本提供选择和复制。
- 展开状态按 `recordId + columnId` 保存，刷新后目标仍存在则保留；记录消失则清理对应展开状态。
- 展开或收起只改变 `interactionState`，不建立查询快照。

## 9. 加载、错误和空状态

### 首次加载

没有可用结果时显示与最终列或卡片结构相符的非交互骨架。结果容器设置 `aria-busy="true"`，骨架不包含可操作假按钮、链接或假数据。

### 已有结果刷新

保留上次成功的行、分页和焦点意图，设置 `requestPhase="refreshing"` 与 `aria-busy="true"`。结果区显示更新状态；新结果提交后替换行并解除 busy。

### 首次失败

进入 `initial-error`，以结果区域内的文本错误和可聚焦“重试加载报表”按钮替代不可用 Table。重试创建新快照和新代次。

### 刷新失败

保留旧结果和分页，进入 `refresh-error`，设置 `stale=true`，显示“数据可能已过期”及重试入口。不得清空旧结果或把焦点移到页面顶部。

### 空状态

必须区分：

- 已应用筛选后无匹配：显示“当前筛选条件无匹配结果”，提供调整筛选和清除筛选入口。
- 数据源本身为空：显示“当前报表尚无数据”，不显示误导性的清除筛选入口。
- 无读取权限：不创建报表实例，显示页面级权限说明。

查询错误只由结果 owner 显示；字段错误仍归筛选字段。相同完整错误不得在字段、结果摘要和全局 live region 重复播报。

## 10. 键盘操作

本报表使用原生 `<table>`，不使用 ARIA Grid：

- Tab 只进入筛选字段、应用/重置按钮、条件移除按钮、排序按钮、长内容展开按钮、分页控件和重试入口。
- 静态单元格不设置 `tabindex="0"`。
- Table 不接管方向键、Home、End、Page Up 或 Page Down。
- Enter 或 Space 激活按钮。
- 页码跳转输入中 Enter 等同激活“跳转”，且必须经过同一合法性检查。
- 横向溢出的 Table 容器仅在确有溢出时成为一个可聚焦滚动区域，并具有“报表可横向滚动”的名称与方向提示；按键使用浏览器原生滚动，不建立单元格导航。
- 卡片模式按 DOM 与视觉任务顺序遍历，不逐字段制造额外 Tab 停靠点。
- 鼠标、触摸和键盘触发同一筛选、排序、分页或展开意图时，必须得到相同状态转换和重复请求保护。

## 11. 焦点管理

`focusIntent` 至少记录：

```text
{ sourceEvent, recordId?, columnId?, controlId?, fallbackId }
```

不得用数组索引或“第几个元素”恢复焦点。

- 编辑筛选、应用筛选和提交排序时，只要触发控件仍存在，发请求和提交结果都不抢焦点。
- 刷新后精确的 `recordId + columnId + controlId` 仍存在时保持焦点；记录排序位置变化不能把焦点落到原索引的另一条记录。
- 精确目标消失时，只移动一次，依次选择同记录等价控件、同列最近记录、结果摘要或分页控件。
- 用户翻页后，匹配响应提交时把焦点移动一次到结果标题/摘要；产品若选择保留仍存活且语义未变的分页触发器，必须统一执行该策略。失效页自动恢复不得再产生第二次移动。
- 长内容展开/收起不移动焦点。
- Table 与卡片实时转换时，精确等价控件仍存活则不移动；若原控件随形态替换消失，只移动一次到相同记录、字段和动作的卡片/Table 控件。
- 最终焦点不得落到 `document.body`、文档根、已移除节点或无名称元素。
- 路由离开时不把焦点返回即将移除的报表控件；新路由提交后由新页面策略移动一次到主标题、主内容或主要操作。

## 12. ARIA 与公告

### Table

- 使用原生 `<table>`。
- 提供 `<caption>` 或通过 `aria-labelledby` 关联结果标题。
- 列标题使用 `<th scope="col">`；若存在行标题，使用 `<th scope="row">`。
- 结果容器使用 `aria-busy` 表达首次加载和刷新。
- 排序只按前述规则设置 `aria-sort`。

### 卡片

- 外层使用有名称的列表。
- 每条记录使用 `<li><article>`，并通过记录身份标题提供记录级名称。
- 字段使用 `<dl><dt><dd>` 或等价的明确标签和值关联。
- 所有 Table 字段都必须映射到卡片中的直接字段或有名称的“展开全部字段”区域，不得用 `display:none` 无入口隐藏。

### 状态公告

结果 owner 是查询公告唯一 primary owner。每个被接受且需要反馈的事件只公告一次，例如：

- “正在加载报表。”
- “已显示第 3 页，共 237 条结果。”
- “筛选完成，没有匹配结果。”
- “刷新失败，当前显示的数据可能已过期。”
- “数据已变化，已返回第 1 页。”

被合并、丢弃、取代、处置后到达或静默失效的事件公告数必须为零。公告只提供简洁状态，不朗读整行、全部筛选条件或重复完整错误。

## 13. 桌面、200% 缩放与移动端

采用容器宽度而非 User-Agent 决定形态。首版产品配置为：

- 容器宽度大于 720 CSS px：Table。
- 容器宽度不大于 720 CSS px：卡片列表。
- 若实际字段映射尚未完整评审，不得启用卡片；应保留原生 Table 和受控横向滚动。

在常见桌面浏览器 200% 缩放后，布局可用宽度通常会进入卡片形态，从而避免页面与 Table 同时出现双向滚动。

桌面行为：

- 筛选区可多列排列，但 DOM 顺序与视觉任务顺序一致。
- Table 容器只允许横向滚动，页面保留唯一纵向主滚动。
- 不使用固定列，避免缩放和长内容下遮挡焦点、错误或边界。
- 横向滚动区显示首尾边界及仍可滚动方向提示。

移动端和窄屏行为：

- 筛选区重排为单列；应用、重置和已应用条件摘要保持可见可达。
- 结果使用卡片，记录身份、主要状态和关键指标置于卡片顶部。
- 次要字段进入标签明确的字段区或“展开全部字段”，不删除字段。
- 排序按钮组、页码跳转、上一页/下一页、当前页/总页数和页大小控制全部保留。
- 分页控件允许换行，不制造页面横向溢出。
- 关键触摸目标采用至少 44×44 CSS px 的点击区域及足够间距。
- 页面内边距包含 `safe-area-inset-*`；底部控件、焦点和错误不得被系统手势区遮挡。
- 低高度、横屏、动态浏览器工具栏或虚拟键盘出现时，筛选提交、结果、分页和重试仍能通过页面主滚动到达。

实时断点切换保持同一 `ownerId`，不得重发查询、改变页码、清除筛选、重建展开状态或重复公告。

## 14. 生命周期与实例隔离

每个报表实例拥有唯一 `ownerId`、不可复用的 `lifecycleToken` 和独立 `announcementOwnerId`。

路由提交离开或 owner 卸载时立即进入 `disposed`：

- 不等待请求、滚动观察器或动画。
- 拒绝新的查询、分页、焦点和公告工作。
- 取消或失效查询、重试、防抖、分页恢复和排队焦点回调。
- 注销自身监听器、计时器、观察器和订阅。
- 只释放自身资源一次。
- 移除自身 DOM 与 ARIA 引用，不影响同页其他报表。
- 所有迟到响应仍经过完整提交门禁，失败后不得写入任何状态或公告。

返回页面采用显式 `restorePolicy="query-and-scroll"`：恢复前重新校验权限、数据版本和页码位置；恢复筛选、排序、页大小、有效页码与页面滚动意图，并使用全新的 `ownerId` 和 `lifecycleToken` 发起查询。不得复用旧请求、错误或已展开的临时内容。
