# 只读数据报表设计说明

## 1. 产品目标与能力边界

该报表只承担“查询并阅读数据”的任务。用户可以：

- 设置、应用和清除筛选条件。
- 对允许排序的字段执行单字段稳定排序。
- 使用明确的页码分页查看结果。
- 阅读、复制和展开长内容。
- 通过 URL 恢复或分享当前筛选、排序和页码状态。
- 在桌面端、移动端及浏览器 200% 缩放下访问同一组数据字段和核心能力。

首版不包含行内编辑、行选择、批量操作、拖拽排序、无限滚动、用户自定义列、多字段组合排序或客户端导出。移动端可以折叠次要字段，但任何有业务含义的字段都必须有可发现的查看入口。

排序和分页必须由服务端统一执行，前端不能只重排当前页。接口至少返回：

- 每行稳定且唯一的 `rowId`。
- 精确的 `totalRows` 或可用于计算总页数的精确总量。
- 当前查询对应的 `snapshotId` 或 `dataVersion`。
- 服务端实际采用的筛选、排序、页码和页大小。

稳定排序采用“业务排序字段 + 唯一字段”的完整排序键，例如：

```text
ORDER BY created_at DESC, id ASC
```

服务端还须明确空值顺序、大小写、语言排序规则和时区。同一个数据快照内，完整排序键必须产生唯一且确定的顺序。

仅添加唯一字段作为并列项，不能保证持续变化的数据集跨页不漂移。如果数据会在翻页期间插入、删除或更新，必须由服务端提供一致性快照或版本化查询；否则只能承诺“单次请求结果顺序确定”，不能承诺用户翻页期间绝无重复或遗漏。若服务端不能提供精确总量，也不能宣称支持精确的末页和任意页跳转。

## 2. 页面结构

页面按以下顺序组织：

1. 页面标题和报表说明。
2. “跳到报表结果”的跳转链接。
3. 筛选区域。
4. 已应用条件摘要、结果数量和更新时间。
5. 独立的状态消息区域。
6. 结果区域。
7. 分页导航。

筛选条件分为两层状态：

- `draftFilters`：用户正在填写、尚未应用的值。
- `appliedQuery`：已经发起查询的筛选、排序、页码和固定页大小。

点击“应用筛选”或在筛选表单内按 Enter 时，先校验筛选条件；通过后把草稿提交为已应用条件，并将页码重置为第 1 页。点击“清除筛选”恢复产品定义的默认条件，也将页码重置为第 1 页。

活动筛选必须显示为可读摘要，例如“地区：华东；日期：2026-07-01 至 2026-07-31”，不能只用颜色或图标表示。筛选项较多时允许折叠筛选面板，但“筛选”入口、活动条件数量和已应用摘要始终可见。

查询状态写入 URL 查询参数。筛选条件使用稳定字段名和规范化值；排序使用 `sort` 与 `direction`；页码使用 `page`。浏览器前进、后退和刷新应恢复同一查询。不得把敏感值、令牌或未经允许的个人信息写入 URL。

## 3. 排序规则

桌面表格中，可排序列的表头包含真实的 `<button>`。点击后：

- 未选中列按该列定义的默认方向排序。
- 再次点击同一列切换升序和降序。
- 点击另一列切换为该列排序。
- 每次更换排序字段或方向都返回第 1 页。
- 请求期间保留当前可见数据，直到新结果成功替换。

只允许一个业务主排序字段，唯一行 ID 作为不可移除的服务端并列排序键。列头需要同时以文字、图标和 ARIA 表达当前方向，不能只依赖箭头朝向或颜色。

移动端不依赖表头交互，使用带可见标签的原生排序控件，例如“排序方式”选择器，选项明确包含字段和方向：“创建时间，从新到旧”。桌面表头和移动端排序控件读写同一个排序状态，切换断点不得重置排序。

## 4. 页码分页

首版使用固定页大小，避免页大小变化带来额外状态复杂度。桌面端显示：

- 首页、上一页。
- 当前页附近的有限页码窗口。
- 非交互的省略标记。
- 下一页、末页。
- “第 N 页，共 M 页”和总记录数。

移动端显示上一页、下一页、当前页与总页数，并提供带标签的“跳转到页码”数字输入和确认按钮，确保仍然具备真正的页码访问能力，而不是退化为无限滚动。

规则如下：

- 当前页使用 `aria-current="page"`。
- 不可用的首页、上一页、下一页、末页采用原生 `disabled` 按钮；不能用仅降低透明度的可点击元素模拟禁用。
- 页码输入只接受 `1…totalPages`；越界时显示就地错误，不发请求。
- 筛选后总页数减少、当前页越界时，服务端返回有效范围，前端跳到新的末页并明确播报。
- 空结果时不显示无意义的分页导航。
- 每次分页请求都带完整筛选、排序、页码、页大小和快照信息。

## 5. 状态模型与转换

| 当前状态 | 事件 | 后续状态 | 界面行为 |
|---|---|---|---|
| 未加载 | 首次查询 | 初始加载 | 显示结构化骨架和加载公告 |
| 初始加载 | 成功且有数据 | 成功 | 显示结果、总量和分页 |
| 初始加载 | 成功但无数据 | 空状态 | 显示对应空状态 |
| 初始加载 | 失败 | 初始错误 | 不显示伪结果，提供重试 |
| 成功/空状态 | 应用筛选 | 刷新中 | 页码归 1，保留已有结果 |
| 成功/空状态 | 更改排序 | 刷新中 | 页码归 1，保留已有结果 |
| 成功 | 更改页码 | 刷新中 | 保留当前页直到新页成功 |
| 刷新中 | 新请求发生 | 刷新中 | 取消旧请求或使旧响应失效 |
| 刷新中 | 成功 | 成功或空状态 | 原子替换结果和查询元数据 |
| 刷新中 | 失败 | 刷新错误 | 保留上一次成功结果并标为旧结果 |
| 任意可重试状态 | 重试 | 加载或刷新中 | 使用同一查询重新请求 |
| 任意状态 | 浏览器前进/后退 | 加载或刷新中 | 从 URL 恢复完整查询 |

每次请求分配递增的 `requestId`。只有最新请求可以更新结果、总量、错误和加载状态；旧响应即使稍后返回也必须被忽略。路由离开或组件卸载时取消请求、防抖任务和待执行的焦点任务。

结果数据和查询元数据应一起提交，不能出现“新页码配旧数据”或“新排序图标配旧结果而没有说明”的中间状态。刷新失败但保留旧结果时，必须显示“更新失败，以下仍是上一次成功加载的结果”，并保留上次成功查询摘要和更新时间。

## 6. 加载、错误和空状态

### 初始加载

- 结果区域设置 `aria-busy="true"`。
- 使用与最终表格或卡片结构相近的骨架，骨架本身 `aria-hidden="true"`。
- 独立状态区域礼貌播报“正在加载报表”。
- 不循环播报进度，也不把每个骨架单元暴露给辅助技术。

### 刷新加载

- 保留现有内容，避免页面高度和阅读位置突然跳变。
- 在结果标题附近显示“正在更新”。
- 状态区播报一次更新原因，例如“正在加载第 3 页”。
- 用户可以继续修改筛选草稿；新的已应用查询取代旧请求。
- 不使用覆盖整页的遮罩，不隐藏错误恢复路径。

### 初始错误

- 显示清晰标题、可执行说明和“重试”按钮。
- 保留筛选控件，让用户能够修改可能导致错误的条件。
- 用户可理解的错误信息与内部错误码分离；如需支持排障，可显示可复制的关联编号。
- 不自动反复重试非瞬时错误。

### 刷新错误

- 保留上一次成功结果。
- 在结果前显示持久错误提示、失败查询摘要和“重试”按钮。
- 明确说明当前结果不是刚才请求的结果。
- 错误出现时不抢夺用户当前焦点。

### 空状态

区分两种情况：

- 数据源本身为空：“暂无可显示的数据”，说明数据产生条件或更新时间。
- 筛选无匹配：“没有符合当前筛选条件的结果”，显示当前筛选摘要，并提供“清除筛选”操作。

空状态不使用成功表格的空白框架，也不把无匹配当成错误。

## 7. 长内容

字段按内容类型制定展示规则，不能对所有单元格统一强制单行省略：

- 名称、标题、状态等关键字段默认换行，确保完整含义可读。
- URL、哈希、代码和无空格长串使用 `overflow-wrap: anywhere` 或等价策略。
- 保留换行的日志或说明文本使用安全的预格式化换行，不允许撑破容器。
- 非关键超长说明可以显示受控摘要，但必须提供有名称的“展开完整内容/收起内容”按钮。
- 展开按钮使用 `aria-expanded` 和 `aria-controls` 关联完整内容。
- 完整文本只有在展开后才同时向视觉用户和辅助技术用户呈现，避免视觉截断与屏幕阅读器读取内容不一致。
- 不用 `title` 属性或仅 Hover 的 Tooltip 承担完整内容查看。
- 所有服务端文本按纯文本或经严格白名单清洗后渲染，禁止直接注入 HTML。

同一页刷新时，仍存在的 `rowId + fieldKey` 可保持展开状态；翻页或更改筛选后清理已不在结果中的展开项。

## 8. 桌面、200% 缩放与移动端行为

### 桌面端

数据字段数量必须经过产品筛选，避免把任意宽数据集直接塞进表格。宽屏使用原生语义表格：

- 关键身份字段靠前。
- 可排序列有明确表头按钮。
- 单元格允许合理换行。
- 不固定行高。
- 不以整行点击作为隐藏操作。
- 固定表头仅在不遮挡焦点、结果标题和状态信息时启用；低高度视口下关闭固定。

若字段数量过多，次要字段进入该行的“查看详细字段”展开区，而不是制造页面横向滚动。结构本身确实需要横向对比时才允许受控横向滚动，并应保留关键身份字段的定位提示；该版本默认不依赖横向滚动完成主要阅读任务。

### 200% 缩放

断点由可用 CSS 空间决定，不按设备名称判断。桌面浏览器放大到 200% 后，当表格无法在单向纵向滚动中保持可读，应自动切换到移动卡片布局，而不是缩小文字或要求页面同时横向、纵向滚动。

筛选、排序、结果、展开内容和分页在 200% 下必须仍可访问。固定区域不得遮住焦点、错误信息或分页操作；为锚点和焦点滚动预留 `scroll-margin`。

### 移动端

结果转换为卡片列表，而不是把桌面表格等比例压缩：

- 每张卡片以主要身份字段作为标题。
- 常用字段直接显示。
- 其余字段通过“查看全部字段”展开，使用 `<dl>` 表达字段名和值。
- 所有桌面字段均可从卡片直接或展开后找到。
- 排序改用外部的原生排序选择器。
- 筛选可以折叠，但活动筛选摘要和筛选入口常驻。
- 分页提供上一页、下一页、页数信息和页码跳转。
- 点击目标具备足够尺寸与间距，不依赖精确触摸。
- 处理长文本、系统字体放大、横屏、低高度、动态浏览器工具栏和四向安全区域。
- 页面保持一个清晰的主滚动容器，不在卡片内部制造嵌套滚动。

桌面表格与移动卡片共享同一份查询和行数据状态。断点切换不重新请求，不重置筛选、排序、页码、展开项或错误状态。

## 9. 键盘操作

该报表不是电子表格编辑器，不使用 `role="grid"`，也不截获方向键做单元格导航。键盘行为遵循原生网页模型：

- Tab 和 Shift+Tab 按视觉与 DOM 顺序访问筛选控件、排序按钮、内容展开按钮和分页控件。
- Enter 提交筛选表单、页码跳转表单，或激活当前按钮。
- Space 激活获得焦点的原生按钮。
- 排序按钮通过 Enter 或 Space切换方向。
- Escape 只关闭当前明确打开的非模态筛选浮层或详情浮层；不能清空已应用查询。
- 方向键保留给原生输入、选择器和页面滚动，不被表格全局捕获。
- 页面顶部提供“跳到报表结果”链接；结果后可提供“返回筛选条件”链接。
- 所有交互元素必须显示高对比度焦点指示，不能只靠颜色变化。

若使用自绘选择器，必须完整实现相应 Combobox/Listbox 键盘和 ARIA 模式；首选原生 `<select>`，避免为普通筛选引入不必要的复合控件。

## 10. 焦点管理

- 初次加载、后台刷新、排序成功和筛选成功不自动移动焦点；通过状态区播报结果数量和变化，避免异步响应抢走用户焦点。
- 筛选校验失败时，显示错误摘要，并把焦点移动到错误摘要或首个无效字段；每个错误与对应字段建立描述关系。
- 分页属于明确的内容导航。新页成功渲染后，将焦点移动到带 `tabindex="-1"` 的结果标题，并播报“第 N 页，共 M 页，显示 X 条结果”。
- 分页失败时焦点保留在原分页控件，错误提示和重试按钮进入后续 Tab 顺序。
- 展开或收起长内容后，焦点保留在原按钮。
- 切换桌面和移动布局时，若当前焦点元素仍存在则保持焦点；若元素被替换，则只移动一次到语义等价控件，例如桌面排序表头映射到移动端排序选择器。
- 若翻页导致当前焦点所在行被移除，成功提交新页后由结果标题接管焦点。
- 浏览器前进、后退时优先保留浏览器正常焦点行为；若恢复查询导致当前节点被移除，焦点移到结果标题。
- 固定栏、虚拟键盘或安全区域不得完全遮挡已聚焦控件。

## 11. HTML 与 ARIA 语义

### 筛选

- 使用原生 `<form>`、可见 `<label>`、`<fieldset>` 和 `<legend>`。
- 必填、帮助文本和错误通过原生属性及 `aria-describedby` 关联。
- 无效字段设置 `aria-invalid="true"`。
- 筛选折叠按钮使用 `aria-expanded` 和 `aria-controls`。
- 活动筛选数量不能只放在无名称徽标中。

### 桌面结果

- 使用原生 `<table>`、`<caption>`、`<thead>`、`<tbody>`。
- 列表头使用 `<th scope="col">`。
- 当前排序列的 `<th>` 使用 `aria-sort="ascending"` 或 `aria-sort="descending"`；非当前排序列移除该属性。
- 排序动作由 `<th>` 内的 `<button>` 承担。
- 行标题适用时使用 `<th scope="row">`，帮助屏幕阅读器建立字段与记录的关系。
- 不为纯阅读表格添加 `role="grid"`、`tabindex` 单元格或虚构的行列键盘操作。

### 移动结果

- 使用有名称的列表，每项是独立 `<article>` 或列表项。
- 主身份字段为卡片标题。
- 字段和值使用 `<dl><dt><dd>`。
- 展开按钮使用稳定的 `aria-controls` ID 和正确的 `aria-expanded`。

### 动态状态

- 结果容器在请求期间设置 `aria-busy="true"`。
- 在结果容器之外设置单一的 `role="status"`、`aria-live="polite"`、`aria-atomic="true"` 状态区，用于播报加载、结果数量、页码和排序变化。
- 错误使用持久可见文本；需要即时播报时使用一个受控的 `role="alert"`，避免同一错误被多个 live region 重复读取。
- 视觉骨架、装饰图标和排序装饰箭头对辅助技术隐藏。
- 分页使用 `<nav aria-label="报表分页">`，当前页使用 `aria-current="page"`。
- 结果数量、当前排序和筛选摘要以可见文本呈现，不能只存在于 ARIA 标签中。

## 12. 尚未通过真实运行环境验证的结论

以上内容是设计约束，不代表已经在运行产品中通过。当前尚未验证：

- 服务端是否真正执行了完整稳定排序、固定空值顺序和唯一并列键。
- `snapshotId` 或等价机制能否在数据持续变化时防止跨页重复和遗漏。
