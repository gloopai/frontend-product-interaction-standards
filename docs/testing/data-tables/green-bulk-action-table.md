# Bulk-action 数据表格设计说明

## 1. 能力声明与首版边界

| 项目 | 设计决定 |
| --- | --- |
| `capabilityTier` | 固定为 `bulk-action` |
| `resolvedTier` | 有批量权限时为 `bulk-action`；权限降级时可原子降为 `row-action` 或 `display` |
| 筛选 | 启用；筛选表单与表格查询分别管理草稿和已应用值 |
| 排序 | 启用单列交互排序，并始终追加稳定次序键 |
| 分页 | 仅启用 `numbered` 页码分页；默认每页 25 条，可选 25/50/100 |
| 当前页选择 | 启用 |
| 全部筛选结果 | 产品配置 `enableAllFilteredSelection` 控制；满足后端契约时启用 |
| 排除项 | 全部筛选结果模式中启用 |
| 行操作 | 启用“查看详情”，与行选择控件相互独立 |
| 列控制 | 首版不启用隐藏、固定、调宽、拖拽换序和个人布局持久化 |
| 响应式形态 | 宽屏使用原生 Table；窄屏使用显式配置的等价卡片列表 |
| 首版排除 | 行内编辑、树形表格、透视表、拖拽行排序、加载更多、无限滚动、Shift 连续范围选择 |

具体查询配置如下，属于本表的产品配置，不替代通用规则：

- 默认筛选：`status=active`；关键词为空。
- 筛选统一采用显式“应用”；“重置”恢复上述默认值。
- 默认排序：`updatedAt DESC NULLS LAST`，随后追加不可重复、不可变的 `recordId ASC`。
- 时间字段不适用大小写、locale 和自然排序。若用户切换到名称排序，则采用 `zh-CN-u-kn-true`、大小写不敏感、自然排序、`NULLS LAST`，再追加 `recordId ASC`。
- 只有 `status` 等明确标记 `urlSafe` 的条件可进入 URL；关键词和可能包含个人信息的自由文本不得进入 URL、页面标题或分析日志。

首版不满足以下任一后端条件时，必须关闭“全部筛选结果”能力，同时不渲染入口、状态槽或隐藏事件处理器，只保留当前页选择：

- 返回可靠的可操作总数 `eligibleTotal`。
- 提供稳定 `recordId`、权限范围、`rangeKey` 和 `datasetVersion` 或等价不可变数据快照。
- 批量接口原生接受“筛选范围 + 排除 ID”，不能要求前端枚举全部记录。
- 能证明裁决身份集合与操作目标集合精确相等；大批量可使用不可变目标/结果清单与摘要证明，但不能只有成功、失败计数。
- 支持幂等键、逐项失败原因、可重试性以及操作状态核对接口。

## 2. 状态与快照模型

表格实例创建唯一 `ownerId` 和不可复用的 `lifecycleToken`，状态分为五个互不替代的 owner：

| 状态组 | 核心字段 |
| --- | --- |
| `queryState` | `filterDraft`、`appliedFilters`、`sortRules`、`pagination`、`pageSize`、`querySnapshot`、`snapshotId`、`requestGeneration`、`datasetVersion`、`requestPhase`、`queryError`、`stale` |
| `viewState` | 当前行、总数、可操作总数、当前页范围、响应式呈现、展开卡片 |
| `selectionState` | `selectionMode`、`selectedIds`、`selectionSnapshot`、`selectionGeneration`、选择有效性 |
| `operationState` | `operationPhase`、`operationSnapshot`、`operationId`、`operationGeneration`、幂等键、成功项、失败项、冲突和恢复入口 |
| `lifecycleState` | `live` 或 `disposed`、owned resources、待取消或失效的异步工作 |

所有查询、选择范围和操作快照均不可变。后续变化创建新快照或新代次，不得原地改写已发出的语义。

查询响应只有以下条件全部匹配才能提交：

`live + ownerId + lifecycleToken + requestGeneration + snapshotId`

操作响应使用唯一完整门禁：

`live + ownerId + lifecycleToken + operationId + operationGeneration + operationSnapshotId`

取消请求只用于节省资源，不能代替上述门禁。

## 3. 查询、筛选、排序与分页

筛选字段 owner 负责字段内部值、校验、dirty/touched 和错误；表格只接收字段已提交的合法业务值。编辑字段内部草稿不会改变结果、URL、选择或触发查询。

用户点击“应用”时：

1. 比较新条件与 `appliedFilters`；语义相同则不发请求。
2. 清除当前页选择；全部筛选结果选择立即失效并清除。
3. 页码回到第 1 页。
4. 冻结新 `querySnapshot`，递增 `requestGeneration` 后请求。
5. 同步更新可见的已应用条件摘要；不能把旧结果标成已匹配新条件。

每个已应用条件必须持续可见、具有独立移除按钮和可访问名称；隐藏在折叠筛选区内的条件仍要出现在摘要中。字段错误归筛选表单，查询错误归结果区域。

排序按钮是表头内的真实按钮。提交新排序时回到第 1 页并建立新查询快照。当前页选择清除；全部筛选结果选择进入 `pending-reconfirmation`，操作按钮禁用。用户确认新排序下的范围、数量和数据版本后，创建新的选择快照；取消则清除选择。

页码分页仅在总数可靠时启用，必须显示当前范围、当前页和总页数，并提供：

- 直接页码。
- 有标签并校验范围的跳页输入。
- 原生禁用的首页、末页边界按钮。
- 有可访问名称的页大小控件。

页大小改变回到第 1 页。当前页因删除等原因失效时，只恢复一次到最近有效页；成功后播报新位置，不得循环请求空页。

显式刷新使用查询意图键合并同一个在途意图；不同筛选、权限或版本形成的新意图即使旧请求仍在途也必须发出新请求。

## 4. 加载、错误与空状态

| 状态 | 呈现与恢复 |
| --- | --- |
| `initial-loading` | 没有旧结果时显示与最终列结构一致的非交互骨架；结果区域 `aria-busy="true"`，不渲染可操作假复选框 |
| `ready` | 显示表格或卡片、结果摘要、分页和适用的选择入口 |
| `refreshing` | 保留旧行、分页和焦点意图，显示刷新状态并设置 `aria-busy="true"`；旧行明确为上次成功结果 |
| `initial-error` | 结果区域用文本错误和可聚焦“重试加载”替代表格；重试创建新代次 |
| `refresh-error` | 保留旧行，标记 `stale=true`，显示“数据可能已过期”和重试入口 |
| 筛选无匹配 | 显示“当前条件无匹配”，提供调整或清除筛选入口 |
| 数据源为空 | 显示独立的“尚无记录”状态；不渲染选择列、空批量工具栏或无意义分页 |
| 有行但无可选记录 | 不是空状态；表头选择框保持未选且禁用，并说明当前页无可操作记录 |

查询错误不得覆盖批量操作错误，批量错误也不得写入 `queryError`。

## 5. 选择模型

### 当前页模式

初始 `selectionMode="page"`。`selectedIds` 只能包含当前页可操作记录的稳定 ID。

表头复选框永远只控制当前页：

- 当前页所有可操作项已选：选中。
- 仅部分已选：混合态。
- 有可操作项但未选择：未选。
- 没有可操作项：未选且禁用，并关联原因说明。

不可操作行的复选框禁用，名称包含记录身份，并通过描述文本说明原因；不可操作项不进入已选数量。

当当前页全部可操作项已选且全部筛选结果能力启用时，在选择摘要中显示独立操作：

> 本页 25 项已选择。选择符合“状态：启用”等当前条件的全部 1,248 项。

点击“选择全部 1,248 项”即为明确的二次范围确认。

### 全部筛选结果模式

确认后创建不可变 `selectionSnapshot`，至少包含：

```text
selectionSnapshotId
sourceQuerySnapshot
rangeKey
appliedFilters
permissionScope
datasetVersion
eligibleTotal
excludedIds = []
```

不得使用单一 `allSelected=true` 或单独数量代表该模式。界面持续显示：

- “已选择全部筛选结果”。
- 当前已选数量。
- 排除数量。
- 当前筛选摘要。
- “清除选择”入口。

取消某行选择时，递增 `selectionGeneration` 并创建后继选择快照，把该 ID 加入快照内部的 `excludedIds`；重新选择时创建另一后继快照并移除该 ID。旧快照保持不变。

已选数量为：

`selectionSnapshot.eligibleTotal - 当前仍有效的 excludedIds 数量`

全部筛选结果模式中的表头复选框仍只反映当前页。取消表头复选框会把本页可操作 ID 批量加入排除项；重新选中则从排除项移除。

### 选择与查询的转换关系

| 事件 | 当前页模式 | 全部筛选结果模式 |
| --- | --- | --- |
| 编辑未应用筛选草稿 | 保留 | 保留 |
| 普通翻页 | 清除 | 范围键、权限和版本相同时保留同一选择快照 |
| 改变页大小 | 清除 | 允许保留范围，但当前页表头按新页重新计算 |
| 应用、移除、重置筛选 | 清除 | 立即失效并清除 |
| 权限范围变化 | 清除 | 立即失效并清除 |
| `datasetVersion` 变化 | 清除 | 立即失效并清除 |
| 排序变化 | 清除 | 进入待重新确认，确认前禁止操作 |
| 同范围资格变化 | 移除变为不可操作的 ID | 创建后继快照，更新总数并清理已失效排除 ID，简短公告一次 |
| 仅刷新且范围、权限、版本未变 | 保留 | 保留 |

异步选择协调结果必须匹配 `live + ownerId + lifecycleToken + selectionGeneration`。迟到结果只记录丢弃，不得改变选择、DOM、焦点或公告。

## 6. 批量操作与结果恢复

只有非空、有效且不处于待重新确认状态的选择可以启动操作。启动时创建不可变 `operationSnapshot`，冻结：

- owner、生命周期、操作类型和操作代次。
- 当前选择代次、选择模式。
- 当前页稳定 ID，或全部筛选结果快照及排除项。
- 预计影响数量。
- 权限范围和数据版本。
- 服务端目标清单身份或等价集合证明。

破坏性操作使用模态确认对话框，明确展示操作名称、预计数量、筛选范围、排除数量和不可操作数量。不可逆或高影响操作采用更强确认。

确认对话框必须：

- 使用原生 `<dialog>`，或 `role="dialog" aria-modal="true"`。
- 使用可见标题提供名称。
- 遮罩点击不关闭。
- 固定标题和操作区，仅内容区滚动。
- 初始焦点放在风险最低的“取消”操作。
- `Tab`/`Shift+Tab` 限制在对话框内。
- 提供始终可见的右上角“关闭”按钮；不可中断阶段禁用时必须说明原因。
- 普通关闭完成退出动画并卸载 DOM 后，再释放模态保护并恢复焦点。

提交进入 `submitting/in-flight` 后，点击、Enter、Space 和事件重放都不得产生第二个请求。请求必须携带 `operationSnapshotId` 和本次尝试的幂等键。

响应先验证裁决数量和身份集合。成功与失败集合必须不重叠，且并集精确等于操作目标：

| 结果 | 处理 |
| --- | --- |
| 全部成功 | 仅在选择代次仍匹配时清除已完成选择；创建一次新查询快照刷新数据 |
| 部分成功 | 成功项永不进入重试；选择代次匹配时从当前选择移除成功项；刷新成功子集，同时保留失败项、原因和恢复入口 |
| 全部失败 | 保留选择和操作快照；显示完整错误与适用重试入口 |
| 权限冲突 | 重新解析可操作范围，移除越权项，显示新数量并要求用户重新确认；不得自动重试越权项 |
| 数据版本冲突 | 旧操作快照立即失效，刷新数据并要求重新选择或重新确认 |
| `outcome-unknown` | 裁决少量、超量、重复、重叠、含外部 ID 或缺项时进入；保留选择和操作快照，只允许“核对处理结果”，不得直接重发业务操作 |

失败项记录 `recordId`、显示身份、失败原因、`retryable` 和恢复动作。点击“重试可重试的 N 项”时：

- 只选择 `retryable=true` 的失败项。
- 创建新的 `operationId`、操作代次、不可变操作快照和幂等键。
- 已成功项与不可重试项请求数必须为零。
- 原操作结果保留为只读审计上下文。
- 迟到的旧尝试响应不得覆盖新的失败集合或选择。

确认对话框在部分成功、全部失败或核对未知结果时保持打开并显示结果；错误内容较长时仅内容区滚动。用户关闭后，页面结果区域保留持久的批量结果摘要和重新打开入口。

## 7. 键盘、焦点与 ARIA

宽屏使用原生 `<table>`，不使用 ARIA Grid，因为本表不需要单元格级二维导航：

- `<caption>` 或关联标题为表格提供名称。
- `<th scope="col">` 建立表头关联。
- 排序表头内使用真实按钮；只在当前排序表头设置正确 `aria-sort`。
- 不接管方向键、Home、End、Page Up/Down。
- 静态单元格不设置 `tabindex="0"`。
- `Tab` 只进入筛选、排序、复选框、行操作、分页、批量操作和恢复入口。
- Space 切换原生复选框；Enter/Space 激活按钮。
- 整行不得包装为一个大链接。

选择框名称示例：

- 表头：“选择本页可操作记录，已选择 12/25 项”。
- 行：“选择记录‘客户 A’”。
- 禁用行：“记录‘客户 B’不可选择”，并通过 `aria-describedby` 关联具体原因。

原生复选框使用 `checked` 和 `indeterminate` 表达三态；不能只以图标或颜色表达。

焦点规则：

- 勾选或取消选择不主动移动焦点。
- 筛选、排序请求发出时不抢走仍存活的触发器焦点。
- 用户翻页且响应提交后，焦点移动一次到结果摘要或标题；自动恢复失效页不得再次移动。
- 响应提交后，原 `recordId + controlId` 仍存在且语义未变时保持焦点。
- 精确目标消失时，依次选择同记录等价控件、同列最近记录、结果摘要或分页控件；不得落到 `body`、文档根或已移除节点。
- 操作结果提交前记录当前焦点。目标仍存活且语义未变时不移动；目标消失时只移动一次到结果摘要、首个失败项、重试按钮、重新确认入口或结果核对入口。
- 迟到响应和后续刷新不得产生第二次焦点迁移。

查询、选择和操作各有唯一公告 owner。建议分别使用简洁的 `role="status" aria-live="polite" aria-atomic="true"` 通道：

- 查询：“正在加载结果”“已显示第 26–50 项，共 1,248 项”。
- 选择：“已选择全部 1,248 项，排除 3 项”。
- 操作：“处理完成：成功 20 项，失败 5 项”。

同一事件只公告一次；不得逐行朗读、重复完整筛选条件或在摘要与全局 live region 重复完整错误。合并、丢弃、被取代和 disposal 后到达的事件不公告。

## 8. 桌面与移动端适配

断点由所需内容无法保持可用的实际宽度决定，不依据 User-Agent。

桌面端显示五列：选择、记录身份、状态、更新时间、查看详情。必要横向滚动仅发生在表格容器内，页面根不得横向溢出；容器需提供滚动方向和边界提示。

窄屏采用显式 `responsivePresentation="cards"`：

- 每张卡片的可访问名称包含记录身份。
- 直接展示选择框、记录身份、主要状态、更新时间和主要操作。
- 次要字段进入有名称的“查看更多字段”内联展开区，并以确定顺序显示标签和值。
- 当前页全选控件放在卡片列表上方，语义仍仅作用于当前页。
- 筛选使用内联可折叠区域，不转换为新的 Drawer 实例。
- 批量摘要和主要操作可置于底部粘性操作区，但必须包含安全区域内边距，且不能遮挡焦点、错误或分页。

Table 与卡片不能同时作为两个活动实例存在。断点转换保持同一 `ownerId`，并原样保留查询、分页、选择、排除项、焦点意图和操作快照；不得新增查询、重放操作或递增操作代次。精确控件消失时，只向卡片中的同记录等价控件迁移一次焦点。

在 200% 缩放、字体放大、低高度、横屏、动态浏览器工具栏、虚拟键盘和四向安全区域下，筛选、结果、选择摘要、分页、错误和恢复动作都必须可达。关键任务不得要求页面与表格同时双向滚动。

## 9. 路由卸载、旧响应与资源处置

路由提交离开或表格 owner 卸载时，实例立即、幂等地进入 `disposed`，不等待请求、操作结果、菜单动画或对话框退出动画。

处置顺序：

1. 将实例标记为非 live，拒绝新的查询、分页、选择、操作、焦点和公告工作。
2. 取消或失效查询、分页恢复、结果核对、重试、防抖和选择协调任务。
3. 关闭行菜单和 popup，取消定位、动画完成及延迟焦点回调。
4. 注销该实例持有的计时器、监听器、观察器和订阅。
5. 如果确认对话框仍打开，立即移除其 DOM，不执行普通关闭动画或旧触发器焦点恢复；只释放该实例自己的遮罩、`inert`、滚动锁和焦点约束。
6. 移除表格或卡片 DOM、popup 及相关 ARIA 引用。
7. 每项资源按 `ownerId` 只释放一次，不影响新路由或同页其他表格。

`AbortController.abort()` 失败或服务端操作已经开始时，界面不得声称业务操作已取消。所有迟到回调仍需通过完整提交门禁；不匹配时只能记录 discarded，DOM、组件状态、共享可见缓存、焦点和 live region 写入均为零。底层缓存若保留响应，只能按不可变查询快照隔离，不能未经新 owner 校验驱动新页面提交。

新路由提交后仅由新路由焦点策略移动一次焦点到页面主标题、主内容或主要操作。返回列表时只有产品显式声明 `restorePolicy` 才可恢复查询和滚动，并必须重新校验权限、版本和分页位置；旧选择、排除项、权限结果、菜单和操作快照一律不回放，新实例必须获得新的 `ownerId` 和 `lifecycleToken`。

## 10. 实现适用性清单

| 规则族 | 适用性与可观察依据 |
| --- | --- |
| 能力与状态 | 适用：显式 `bulk-action` 档位和五组独立状态 |
| 查询 | 适用：所有请求使用不可变快照、代次和完整提交门禁 |
| 筛选 | 适用：存在筛选 DOM、草稿、应用、默认重置、摘要、移除和 URL 安全策略 |
| 排序 | 适用：存在单列排序按钮、明确比较值、稳定 ID 和回第 1 页转换 |
| 分页 | 适用：仅 numbered；存在可靠总数、页码、跳页、页大小、边界禁用及失效页恢复 |
| 数据状态 | 适用：区分首次加载、刷新、首次错误、刷新错误、无匹配和空数据源 |
| 选择与批量操作 | 适用：当前页、可选全部结果、排除项、部分成功及失败项重试 |
| 列显示/固定/调宽 | 不适用：配置关闭，DOM、状态槽和 handler 均不存在 |
| Table/Grid | 原生 Table 适用；ARIA Grid 不适用，因为没有二维单元格导航需求 |
| 焦点 | 适用：按稳定记录/控件 ID 恢复，并定义目标消失的唯一迁移 |
| 响应式 | 适用：显式 Table/卡片映射，同 owner 单活动实例 |
| ARIA 与公告 | 适用：表格、选择、状态、错误和批量结果均有唯一语义 owner |
| Disposal 与实例隔离 | 适用：路由离开、卸载、迟到响应和多实例资源均需隔离 |
