# 表格列布局密度规范 RED 复核

在新增 `references/table-column-layout-density.md` 之前，表格列设置只能分散依赖数据表格、保存视图和工具栏规范，无法强制表达以下问题：

- 没有 `tableColumnLayoutState`，无法证明列显隐、顺序、宽度、固定、密度和持久化由谁拥有。
- 列配置可能只依赖 localStorage、CSS class 或组件库默认 column picker，而没有 owner、权限收敛和生命周期清理。
- `draftLayout`、`appliedLayout` 和 `persistedLayout` 可能混在一起，取消列设置也可能改变表格或保存视图。
- 列顺序可能没有稳定列 ID，而是基于数组下标、可见 index 或 DOM 顺序，权限隐藏后容易错位。
- 用户隐藏列、权限隐藏列和必显列可能混用。
- 无权限列可能出现在列设置、列数量、已隐藏列表、保存视图、导出字段、ARIA、Tooltip、旧布局、URL 或缓存。
- 列宽和固定列可能遮挡内容、浮层、焦点环或移动端安全区域。
- 紧凑密度可能删除状态、错误、单位、禁用原因、行操作、选择摘要或恢复入口。
- 重置草稿、恢复个人默认、恢复团队默认、恢复系统默认和清空本地布局可能混用。
- 保存视图可能静默保存未应用列草稿。
- 真实浏览器、键盘、读屏、触摸、拖拽、横向滚动、固定列、缩放、移动端、权限切换和视图恢复未执行时，容易被误写成已验证，而不是标为未验证。
