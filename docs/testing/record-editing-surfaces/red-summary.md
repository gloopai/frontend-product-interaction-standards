# 记录编辑承载面 RED 基线总结

在没有记录编辑承载面 owner 时，Agent 容易把“就地编辑”视为高效方案，典型问题包括：

- 在表格行下展开完整编辑表单。
- 在卡片列表项内部放新增或编辑字段。
- 在列表顶部或底部插入新增记录表单，并与查询结果共享滚动区域。
- 把批量配置字段直接放进批量工具栏或表格容器。
- 把标题、描述、正文、分类、状态和排序都做成列表单元格内的 input、textarea、select 和数字输入，并在每一行放“保存”按钮。
- 把报表明细自动推导为可编辑列表，给展示型报表加选择、编辑或批量保存入口。

这些方案的问题不是视觉样式，而是 owner 混乱：列表查询状态、表单 dirty、权限版本、返回焦点、错误摘要、保存回执和审计边界被塞进同一行或同一滚动区域。新增 owner 的目标是把这类形态统一判定为失败，并强制进入 Dialog、Drawer 或独立页。
