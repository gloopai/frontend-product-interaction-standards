# RED 应用输出：多租户用户与角色管理

> 记录时间：2026-07-27。以下为在不存在管理台跨页面 owner 时，对原始任务的直接中文交互方案；保留其未解决问题，作为 RED 基线，不是推荐实现。

## 页面能力与导航

页面左侧提供租户切换器和“用户、角色、审计”导航。用户列表支持搜索、筛选、分页、选择多个用户后批量停用；每行更多菜单可编辑角色、重置密码和删除。点击角色名称在右侧抽屉中打开角色详情与权限列表。

租户切换后立即跳转到该租户的用户列表；为减少闪烁，保留旧租户的数据、已展开的更多菜单、已选择用户和已打开的删除确认框，直到新接口返回。若新角色没有某个菜单权限，只隐藏菜单图标，不影响已经打开的抽屉或弹窗。

## 权限降级与展示

没有“删除用户”权限时，仍展示禁用的“删除张敏（12 个关联项目）”按钮，帮助管理员理解哪些对象不能删除；Tooltip 写明“请联系超级管理员获取删除权限”。没有查看角色权限时，抽屉仍展示角色名和成员数量，但把具体权限项隐藏。

权限变更成功后 Toast 提示“权限已更新”，页面保留原筛选和已选用户；下一次手动刷新时再请求最新能力。切换租户后，旧租户的导出文件链接继续可在通知中心下载，方便用户回顾操作结果。

## 危险操作、审计与恢复

删除用户、批量停用和修改角色均先显示确认弹窗，文案说明会影响登录。点击确认后立即关闭弹窗并 Toast 提示“操作已提交”；失败也以 Toast 提示“操作失败，请重试”。页面不额外显示处理状态，用户可在需要时刷新列表确认结果。

确认框右上角关闭、按 Escape、浏览器后退或离开页面都视为“已取消本次操作”，并在审计中记录取消成功；对于已发出的删除或停用请求也沿用该提示，避免用户担心后台状态。

审计页记录操作者、时间、目标用户和结果；没有审计权限时显示“暂无审计记录”。系统错误时同样显示该文案，并提供刷新按钮。

## Toast、焦点、键盘、ARIA 与响应式

Toast 作为所有结果的统一反馈，设置 `role="status"`。确认弹窗打开时焦点放在确认按钮，Escape 关闭；抽屉用 `aria-label="角色详情"`。键盘用户可以 Tab 浏览列表、菜单和弹窗，并用 Enter 执行当前按钮。

移动端把用户列表变为卡片，批量停用位于底部浮动操作栏；租户切换、角色抽屉和删除确认继续以全屏层展示。
